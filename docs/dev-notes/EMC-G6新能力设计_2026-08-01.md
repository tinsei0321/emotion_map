## G6b · 搜索能力（纯问答·依据 2）

### 目标
纯问答两大缺口：① 大问题（情绪地图概念/理念）→ 宏观背景 + 四领域前沿政策；② 聚焦问题（策略/作用/应用场景）→ 宜昌实际（新闻/公开资料）。**禁假大空·给真实启发**。

### 触发范围（两组共识·限窄）
- **触发**：仅 `intent=general`（纯问答）两类——大问题词（情绪地图/产品/理念/定位/概念）+ 聚焦词（策略/作用/应用场景/怎么办）；
- **不触发**：GIS 操作（依据 1）·情绪分析（依据 3·有数据即可）——不干扰执行链·不引入搜索延迟。

### 流程（diagnose → search → finalStep）
```
general 短路 → 命中大问题/聚焦词 → 调搜索（新端点 POST /api/v1/search 或复用 provider API）
  → 结果 top 3·截断 → 注入 finalStep context（【外部资料】段·附信息截至标注）
  → 失败 try/catch → 退回本地背景注入（不阻塞回答）
```
- 前端 `_quickIntent` general 路径扩展：命中词 → ctx.context 前置「【外部资料参考】…」或异步 fetch 后端搜索端点。
- 后端新端点：调智谱 web-search-prime / DeepSeek 搜索（确认 API/成本/合规——Codex 需补充信息 3）。
- **防新谎报面**：结果标注「信息截至 YYYY-MM」或作参考引用；搜索失败降级无搜索（不编造）。

### 成本/延迟控制
- 只 general 触发·搜索结果 top 3 截断·注入 context 不独立渲染·失败不阻塞。

## G6c · 连问拆解最简版（依据 4）

### 目标
一个输入多问（「…；…」/「…。…」）→ agent 拆解分布执行 → 合并结论。

### 方案（Codex 最简版 = glm组 自认的最简版·趋同·用户拍板）
1. **分句**（代码确定性·不做 LLM 拆解）：按 `？/。/！/；` + 换行切分·**句数上限 2-3**（防拖死）·>3 句取前 3 或提示一次一问；
2. **逐句复用现有 `orchestrate`**——每子问独立 diagnose+执行（自动继承 R9/诚实观测/N-M 防线·不新造执行管线）；
3. **汇总 finalStep**：各子问结论拼接为结构化结论（### 分节·每节一子问答案）。

### 约束
- 60s 门槛按句计数放宽（每子问独立计时·总预算 = 句数 × 单句门槛）；
- 不做并行（Flash 单 call 限制·glm组 Q4）·不做意图队列；
- 追问胶囊替代方案保留（用户可点胶囊逐问·两轨共存）。

### 实现位置（G6c 时）
- `orchestrate` 入口前：分句（纯函数 `splitQuestions(text)`）→ 循环逐句调 orchestrate（内部现有）→ 收集各 final → 汇总渲染。
- 风险：orchestrate 主循环（承重）——改前先扩 eval·每次一处。
