## 三、架构层面发现

### FC 诊断瓶颈（核心矛盾）
FC 诊断（Flash function calling）只能可靠产出 **1 个 tool_call**。多步骤依赖 `_autoExpandOverlays`（heuristic 补丁），只识别特定模式（"X区内Y1+Y2+…用地"）。换一种问法就失效。

**方案A Planner 的后端已验证通过**（Pro 正确输出 4 步 JSON），但因前端缓存 + where 格式 bug 未完整验证。Planner 是根治多步骤问题的正解。

### Pro 路由原则
- **FC 诊断**：永 Flash（工具选择 = 快分类任务）
- **agent_step**：用户选择
- **finalStep**：用户选择（当前代码 `answerModel = ctx.model`，在回退版本中不包含此改动）
