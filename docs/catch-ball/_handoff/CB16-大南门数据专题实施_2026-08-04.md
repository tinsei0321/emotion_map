背景：Wave 0 出口卡片完整链路已闭环（build_outlet_schema → /outlet_card 端点 → harness 接线 →
panel 渲染 → 词表守卫·pytest 242 passed）。演示数据场景未接通——探索发现 3 缺口：
1. `DATA/performance/ermawu_l3l4_T{1,2,3}_result_csv.csv` **无 lon/lat 列**（坐标只在同名 geojson）
2. ermawu 三层**未注册进 `core/geo_registry.py` 的 `_POINT_LAYERS`** → EMC 问答 `resolve_points` 无法加载
3. 大南门边界 `大南门二马路滨江片区.geojson` **不在 range presets manifest** → `/geo/catalog` boundaries 不含它

本轮实施（数据接入·非新契约/非新 LLM 阶段·不碰承重路径）：

① CSV 补坐标列（数据准备·确定性）
- 一次性脚本（`SCRIPT/backfill_ermawu_coords.py`·可审计）：从同名 geojson 提取 coordinates（顺序与 CSV 行一一对应）→ 追加 `lon`/`lat` 列（保留 utf-8-sig BOM）
- **不动生成器、不重新模拟**（保 T1/T2/T3 已有数据不变·seed 2606 确定性）

② 注册点层（`core/geo_registry.py`）
- `_POINT_LAYERS` 追加 `ermawu_l3l4_t{1,2,3}`（标签「大南门·二马路 L3L4 · T1/T2/T3」·level='L3L4'）
- 保持 yichang L2 在前（默认 L2 选择不变）；富归因列（aspect/policy_seed/project_seed/matrix_multi）随 CSV 原样保留（tools.js:958 已识别）

③ 边界登记（`DATA/boundaries/presets/manifest.json`）
- 「城市更新单元」组加 `{"id": "damanmen_area", "label": "大南门·二马路滨江片区", "file": "大南门二马路滨江片区.geojson", "nameField": "name"}`（已确认单要素·属性字段 name）

④ 回归测试 + 端到端验证
- `tests/test_geo_registry.py`：resolve_points('ermawu_l3l4_t3') 返回含坐标 GeoDataFrame·行数=900·富归因列存在
- `tests/test_outlet_schema.py` 补 1 例：真实 ermawu 聚合产物 + 问句"大南门·二马路片区更新需求分析" → 命中 renewal_demand·需求强度有值
- POST /aiqa/outlet_card 真实端点 + 浏览器 EMC 问答出卡

请预检：
1. **level='L3L4' 是否会被下游 level 检查误伤？** 我的判断：R5 胶囊防线（harness.js:384）只过滤 UI 追问胶囊（`c.level !== 'L1' && c.level !== 'L2'` 丢胶囊），`resolve_points` 不查 level——数据层加载不受影响。请两组核验还有无其他 level 消费点。
2. **补坐标列方式**：一次性 backfill 脚本 vs 改生成器重跑（用户倾向不动生成器·保已有数据不变·时间轴 manifest 也后置）——是否对路？
3. **边界登记进 presets manifest**：与既有 manifest 机制（行政区/更新单元/用地·nameField）兼容性是否 OK？
4. **时间轴 manifest 本次不做**（用户定·时间轴与需求分析是两件事·后置）——是否影响 ermawu 数据被 EMC 问答发现？（当前 `_time_manifest.json` 缺失·问答走 /geo/catalog 不依赖 manifest）
