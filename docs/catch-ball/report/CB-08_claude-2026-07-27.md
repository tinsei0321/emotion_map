## 二、用户校准（关键·否定"0 LLM 通道"）

**用户原话**：
> "不能去掉 LLM·即使是简单问题也要通过 LLM（简单问题通过 LLM 也可以速度很快）·因为很难判断简单/复杂边界·最后会混乱。但可以**把控 LLM 思维链路·让简单问题走简单链路**·这同样体现 LLM/Agent 的灵活性。"

**我方影响**：放弃 DeepSeek 的"0 LLM 通道"（代码 diagnose + 模板结论）·改"**LLM 简化链路**"——保 LLM（diagnose + finalStep 都走·保灵活·不分简单/复杂边界）·但**瘦 finalStep prompt**（MANIFESTO_LIGHT + 跳 industry_kb）让 LLM 快。

**用户核心逻辑**：
- 简单/复杂边界难判断 → "0 LLM 通道"需判边界 → 会混乱
- LLM 灵活性是 Agent 价值 → 不能为快牺牲
- 简单问题 LLM 也可以很快（如果 prompt 不重）→ 瘦 prompt 即可·不需去 LLM

## 三、我方方案（CB-08·LLM 简化链路）

### Phase 1（P0·消矛盾·让 LLM 不误判）
- **observation 改"网格单元"+cell_size**（[tools:1155](../../frontend/js/ai_qa/tools.js#L1155)）：mode='3d' 时 `${N} 网格单元（${cellSize}m）` 非 `${N} 点`·明示实际分辨率。
- **SKILL_DEFS radius 按 mode 条件**（[stages:45](../../frontend/js/ai_qa/stages.js#L45)）：mode='3d'（grid）时不注入 radius（无意义·治 LLM 锚定 300m）。
- **单技能注入 formatRegistry**（[harness:380](../../frontend/js/ai_qa/harness.js#L380)）：与 ReAct 路径 :787 对齐·`【地图实际产出图层】...严禁编造`强约束·给 finalStep LLM 正确 grounding。

### Phase 2（P0·LLM 简化链路·治慢·核心·用户要）
- **finalStep light prompt**（[build_final_prompt:159](../../ai_qa/prompts.py#L159) + [manifesto.py](../../ai_qa/manifesto.py)）：
  - 加 `light` 参数（phase='answer' 时 light=True）
  - `MANIFESTO_LIGHT` = 保 answer 必需节（**七演示链 / 八回答策略 / 九同步 / 十公约 / 十一尺度**·answer 直接依赖）·去概念节（一/二/三/五/六·diagnose 已用）+ 六场景（diagnose 映射用）
  - industry_kb 条件移除（answer 阶段未必需领域政策全文·省 5-20KB）
  - system prompt **20-44KB → 8-15KB**·prefill 20-35s → 8-15s·**总 15-30s（< 45s timeout）**
  - 保 LLM（用户要）·瘦 prompt·简单请求 LLM 也快
- **answer phase timeout 回 45s**（[api.js:33](../../frontend/js/ai_qa/api.js#L33)）：light 后 finalStep 快·不需 60s。

### Phase 3（P1·EMC 组 0 条·用户选保留+修）
- **focusLayer 修**（[state:797](../../frontend/js/state.js#L797)）：父组 FC 空（features=[]）时返**子层自身**（非空 FC 组）→ Overview 读子层 features（正确条数）。

### Phase 4（P2·跳组 enforceMutualExclusion 评估）
- 评估 EMC 组图层豁免互斥 / 保留设计。本次先评估不定。
