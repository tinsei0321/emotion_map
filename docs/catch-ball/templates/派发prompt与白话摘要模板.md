# 派发 prompt 模板 + 白话摘要模板（PT-CB18 W2-3 · 2026-08-26）

> 变更履历：2026-08-26 v1.0 首版。
> 使用约定：模板定稿后首次派发按模板逐字段核对（验收口径）。

## 白话摘要

两份写作模板：一份是「派活单」格式——目标、边界、验收三要素齐，材料只给路径不贴正文；一份是「人话摘要」格式——比喻一句、数字一句、建议一句，150 字封顶。都带一条红线：省字不能省掉「目标/边界/验收」三要素。

---

## 模板一：派发 prompt

```
【派发】{批次号} {业务名}（对象：{执行组}）

背景（≤3 行·只给结论·不贴正文）：
1. ...
2. ...
3. ...

材料路径（同仓直接读文件·勿粘贴正文进对话）：
1. {路径}（{一句话说明·哪份是唯一依据}）
2. ...

任务：
{动词开头·做什么·按什么顺序}

约束：
1. {文件范围与不可动清单——边界红线}
2. {与其他在途批的错开要求}
3. {commit 前缀·add 方式·push 归属}
（注：不重复要求读默认机制已加载的文件；额外材料只点名路径）

验收要求（逐条可判真伪）：
1. ...
2. ...

注意：{开工登记要求·未覆盖决策点的停步要求}
```

**字段核对清单**（首次派发验证用）：背景 / 材料路径 / 任务 / 约束（含不可动清单）/ 验收（可判真伪）/ 注意——六段齐。

**防过度精简红线**：省字只省过程叙述与重复材料；「目标 / 边界（文件范围与不可动清单）/ 验收」三要素任何情况下不得以精简为名删减；验收判据必须写出「如何判真伪」。

---

## 模板二：白话摘要

```
## 白话摘要

{比喻一句：用生活场景类比本件事} + {关键数字一句：规模/工期/数量} + {建议/结论一句：用户需要做什么或不用担心什么}
（上限 150 字·零专业术语·编号必须翻译为业务名）
```

**口径**：
1. 面向用户的报告/汇总/摘要/收敛文档**必须**以白话摘要开篇（硬条款·根手册用户沟通纪律 3b）；
2. 三句式缺一即打回：比喻缺=看不懂，数字缺=没分量，建议缺=不知道要我干嘛；
3. 防过度精简红线：比喻不许省成结论直陈——「改了 6 个文件」不是白话，「给规矩手册做了一次瘦身体检」才是。
