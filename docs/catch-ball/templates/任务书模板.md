# 任务书模板（PT-CB18 W2-2 · 2026-08-26）

> 变更履历：2026-08-26 v1.0 首版（新增「风险档位」必填字段）。
> 配套：档位定义见 `docs/catch-ball/templates/review-tiers.md`；派发用 `派发prompt模板.md`。

## 白话摘要

任务书是「派活合同」。这份模板固定了合同条款：干什么、不干什么、干完怎么验收，外加一个必填的「这活算哪档风险」——档位决定要出多少文书，防止小事也写长篇汇报。

## 模板

```
# {批次号} {业务名} · 任务书 v{版本}（{日期}）

> 变更记录（近 3 条）：
> 1. {日期} v{版本}：{一句话}

## 白话摘要
（零术语·比喻+数字+建议·≤150 字·硬条款不可省）

## 风险档位（必填）
{高档/中档/低档} —— 定档理由一行（判据见 templates/review-tiers.md）

## 一、目标与边界
- 目标：（要达成什么·可量化）
- 边界（本批不做）：（明确列出不做的事）
- 红线：（不可动清单·文件/数据/契约）

## 二、用户拍板记录
（已决事项逐条：日期 + 结论 + 依据；未决进 _board.yaml decisions 区）

## 三、任务拆解
（每件：执行路径 + 验收硬判据——判据必须可机器或第三方判真伪）

## 四、验证法
（总验收口径·数据项优先）

## 五、双环境同步
（生成物重建命令·配方占位符·禁硬编码路径）

## 六、commit 与记录纪律
（前缀·显式路径 add·执行记录落点）

## 七、风险与依赖
（在途冲突·第三方工具·改造者悖论·用户义务）

## 八、执行记录（执行方填写）
（开工时间 + 批次划分 → 实际工时 → 偏离字面的工程判断 → 未自改观察项 → 门禁结果）
```

## 使用口径

1. 验收判据写不出「如何判真伪」= 任务书不合格，打回；
2. 「风险档位」空缺 = 派发不合格；
3. 一事一档（RULES §4.8）：回应追加 §小节、收敛就地改稿、头 3 行变更记录。
