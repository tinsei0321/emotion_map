# 评审三档定义表（PT-CB18 W2-2 · 2026-08-26）

> 治「每件事都全套重型评审」的消耗病：评审深度与风险匹配，文书量随档位走。
> 变更履历：2026-08-26 v1.0 首版（PT-CB18 W2-2）。

## 白话摘要

以前不管大事小事都走「全套体检」，现在分三档挂号：大事全套检查，中事医生看一眼写 20 行意见，小事当场口头确认不留单子。派活时在任务书里必填「这活算哪档」，干活的人按档位出文书，不多写一页。

## 三档定义与触发判据

| 档位 | 文书要求 | 触发判据（满足任一即升档） | 典型场景 |
|------|----------|---------------------------|----------|
| **高档（全套制衡）** | 任务书 + 派发 + 执行记录 + 独立评审 + 验收判据全链 | ①控制流/核心管道/追踪基建改动 ②跨 3+ 文件或跨模块 ③涉及数据口径/契约/渲染规则 ④用户明示重要 | 任务书批次（如 PT-CB18 本身）、数据治理重构、契约变更 |
| **中档（20 行复核意见）** | 执行者自述 + 一份 ≤20 行复核意见（结论+证据+异议） | ①2 文件以内逻辑改动 ②文档规范/流程规则新增 ③生成器/工具新增但不入核心链路 | 本批 W2 规范件、gen_* 生成器、规则条款增补 |
| **低档（零文书）** | 仅 commit message 一行结论 | ①纯文案/注释/格式 ②单文件配置微调 ③生成物重跑 | 错别字、样式微调、`gen_progress.py` 重跑 |

## 使用口径

1. 派发方在任务书「风险档位」字段定档（必填）；执行者不得自行降档，升档需回报。
2. 档位争议 → 就高不就低。
3. 学习报告回应频率调整：**月度批量回应**——当月学习报告汇总为一次批量回应（四档裁决照旧：吸收/并入排期/暂缓/反对），不再逐篇当轮回应；紧急方向性报告例外，可当轮回应。
