## 一、架构

```
用户 NL
  │
  ▼
┌─ Stage 1: 0LLM ──────────────────────────────
│  纯规则·本地 JS·<100ms                           
│  ├─ 字段识别：field_dictionary 扩展              
│  │   └─ FIELD_TO_TOOLS + GEOMETRY_TO_TOOLS 映射  
│  ├─ 关键词预判：NL 关键词 → 缩小候选集            
│  ├─ 候选工具集：字段角色 ∩ 几何类型 ∩ 关键词       
│  │   └─ 控制在 1-4 个（≥5 视为异常·收紧规则）     
│  └─ 接地上下文：精简版·字段名+角色+1-2样本值      
│  产出：{ candidate_tools, grounding }             
└─────────────────────────────────────────────────┘
  │
  ▼
┌─ Stage 2: Flash LLM ──────────────────────────
│  匹配+填卡·不推理·不计划·不选工具                   
│  Prompt: ~1-3.5KB（工具schema + 三态判据 + 卡格式   
│          + 接地 + 可选1 few-shot）                  
│  耗时: <5s                                         
│                                                     
│  对每个候选工具填一张信息卡：                         
│  {                                                   
│    tool,                                              
│    params: { 按工具schema填值 },                      
│    confidence: high|medium|low,                       
│    rationale: "...",                                  
│    data_status: ready|fallback|request_upload         
│  }                                                    
│                                                     
│  产出: 1-4 张信息卡                                   
└─────────────────────────────────────────────────┘
  │
  ├── 1 张卡 ──→ 直传编排器（跳过 Pro）
  ├── 2-4 张卡 → Stage 3: Pro
  └── 0 张卡 ──→ 降级（请求用户澄清）
  │
  ▼
┌─ Stage 3: Pro LLM ────────────────────────────
│  推理+计划·仅在多卡时触发                           
│  Prompt: ~6-10KB（工具能力字典 + 编排规则            
│          + MANIFESTO §7 + 信息卡 + 接地）            
│  耗时: 5-10s                                        
│                                                     
│  推理: 从2-4张卡中选最优方案（互斥→选一·互补→组合）  
│  计划: 编排单步参数或多步 chain                       
│                                                     
│  产出: 执行计划 { template, params, chain }          
│         chain 结构: [{step,tool,params,depends_on}]   
└─────────────────────────────────────────────────┘
  │
  ▼
编排器（模块二）
```

## 二、关键决策

| ID | 决策 | 理由 |
|----|------|------|
| D001 | 三阶段低耦合：0LLM→Flash→Pro | 各司其职·任务不重叠不干扰 |
| D002 | Flash 只匹配填卡·不推理不选工具 | 发挥 Flash 速度优势·减轻认知负担 |
| D003 | 信息卡绑定工具 schema | 每卡结构固定·Flash 填空即可 |
| D004 | 单卡→编排器·多卡→Pro·零卡→降级 | 卡片数 = 自然路由信号 |
| D005 | 单卡 confidence=low 也直接执行 | Pro 无替代方案可选·无需介入 |
| D006 | Flash prompt 1-3.5KB·<5s | 从当前 30-54KB/25-45s 缩减 80% |
| D007 | 0LLM 字段识别纯规则 | 0LLM = 零 LLM |
| D008 | 数据三态归 Flash | 匹配型判断·非推理 |
| D009 | Pro prompt 统一轻量·不分 intent | 单问深度控制·复杂问题由 CPD 多轮拆解 |
| D010 | Pro 不深入归因/领域出口 | CPD 负责拆解复杂意图为多轮简单问题 |
| D011 | 工具能力字典 13 工具 | 维护列入 EMC 自我成长 |
