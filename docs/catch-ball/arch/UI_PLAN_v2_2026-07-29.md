## Feature 3：三阶段管线 — 理解 → 思考 → 生成

### 3.1 设计理念

> **从"技术流程名"改为"用户体感阶段"。三个阶段分别映射 EMC 的核心模块，颜色和视觉截然不同，让用户清楚感知"现在在干什么"。**

### 3.2 阶段定义与 EMC 模块映射

| 阶段 | 图标 | 颜色 | EMC 模块 | 实际发生什么 | 典型耗时 |
|------|:---:|------|------|------|:---:|
| **理解** | ◉ 圆环 | 暖橙 `#D97757` | FC 诊断（Smart 入口） | LLM 选工具 + 填参数 + 判断数据缺口 | 3-6s |
| **思考** | ◆ 菱形 | 深蓝 `#4796E3` | 工具执行（Dumb 执行） | 确定性计算：生成图层/聚合/裁剪 | 0.5-3s |
| **生成** | ■ 方块 | 森绿 `#2E8B57` | finalStep + 质量防线（Smart 出口） | LLM 写结论 + 图层卡片确认 + 防御检查 | 4-10s |

**为什么是 3 个而不是 5 个**：

| 旧阶段 | 问题 | 新阶段 |
|------|------|:---:|
| 诊断 | 与"思考"边界模糊（都是 LLM 在做） | → **理解** |
| 思考 | 用户无法感知"思考"和"检索"的区别 | → **思考**（工具执行部分） |
| 检索 | 实际无独立"检索"步骤 | → 合并入思考 |
| 生成 | 概念正确 | → **生成** |
| 审查 | CB-05 已删除（改为代码防线 <20ms），不存在 | → 删除 |

### 3.4 关键设计决策

**决策 A：图层在"思考"阶段产出，但聊天卡片延迟到"生成"阶段显示**

- 工具执行完成后，图层立即落地到 MapLibre（地图上可见）
- 但聊天中的 `{{show:}}` 图层卡片**不在"思考"阶段渲染**
- 等到"生成"阶段 finalStep 产出结论文字后，卡片随文字一起出现
- **效果**：用户看到"思考完成·地图已更新"的提示 → 注意力转到地图 → 然后结论文字流式出现 + 卡片确认

**决策 B：每个阶段有独立的完成标记**

- 阶段完成后：阶段头收缩为一行小字 `✓ 理解完成（3.2s）`
- 当前活跃阶段：高亮、展开、带动画
- 未来阶段：灰显、折叠

**决策 C：阶段过渡有微动画**

- 阶段切换时：0.3s 滑动过渡
- 阶段头颜色渐变（橙→蓝→绿）
- 进度条重置并重新开始填充

### 3.8 为什么"思考阶段结论就已经生成"——根因与解决

**根因**：工具执行（<3s）产出图层 → 地图上立即可见。但 finalStep LLM 调用需要 4-10s。用户看到地图有图层但聊天还在"转圈"。

**解决**（两个层面）：
1. **视觉层面**：三个阶段明确展示 → 用户知道"思考完成了，现在在生成文字" → 等待有预期
2. **体验层面**：思考完成后显示 `✓ 思考完成·地图已更新` → 引导用户先看地图 → 同时"生成"阶段流式出字

## 附录：我的补充建议

### 建议 1：图层卡片在"生成"阶段的呈现方式

当图层在"思考"阶段产出后，**地图上立即可见**。在"生成"阶段，可以加入一个短暂的地图闪烁动画（highlight/flash the new layer on the map）来连接"思考"和"生成"两个阶段——"看，这就是刚才提取出来的）。

### 建议 2："生成"阶段的进度条可以做成"token 预算剩余"

用 `max_tokens` / `completion_tokens` 来驱动进度条，让用户知道"还有多少字要生成"。这比假的 indeterminate 进度条更有信息量。

### 建议 3：概念问短路时的三阶段简化

当 `_quickIntent` 检测到概念问/闲聊时，直接从"理解"跳到"生成"（跳过"思考"）。三个阶段看起来像：理解（识别为概念问）→ 生成（直接作答）。这保持了 UI 一致性。

### 建议 4：错误/降级时的阶段显示

如果 FC 诊断返回 `request_upload` 或 `degraded`，三个阶段缩减为一个："理解"阶段显示为黄色警告状态，内容直接展示数据缺口。不进入"思考"和"生成"。
