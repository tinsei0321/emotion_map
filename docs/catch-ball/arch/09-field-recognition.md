# 模块九：字段识别（0LLM）— v2 简化版

> **状态**：✅ 已决议（v2 简化）  
> **日期**：2026-07-28  
> **关联决策**：D063（全注入）·D064（0LLM 简化）  
> **变更说明**：v2 原设计的 tools_hint/tools_fallback 机制，经实测（13 工具全注入仅 7.4KB/2.7s）后废弃——全注入更简单更可靠。

---

## 一、v2 → v2 简化的变更

| 维度 | v2 原设计 | v2 简化（当前） | 变更理由 |
|------|------|------|------|
| 工具注入 | tools_hint 子集 + tools_fallback 提及 | **全注入 13 工具完整 schema** | 测试3: 7.4KB/2.7s·子集选择多余 |
| 0LLM 工具筛选 | FIELD_TO_TOOLS + KEYWORD_TOOLS | **废弃** | LLM 自己从 13 个选·无漏选风险 |
| 候选≥5 追问 | 6 场景追问 | **废弃** | 不再做候选筛选·无需追问 |
| 0LLM 保留职能 | 字段识别 + 接地 + 筛选 | **字段识别 + 接地 + 数据缺失检测** | 精简到核心 |

## 二、0LLM 简化后的职责

| 0LLM 做什么 | 0LLM 不做什么 |
|------|------|
| ✅ 字段识别 → 语义角色 | ❌ 工具筛选（废弃 FIELD_TO_TOOLS） |
| ✅ 构建接地上下文（元数据·不发原始数据） | ❌ 候选≥5 追问（废弃） |
| ✅ 数据缺失检测（无数据→短路提示导入） | ❌ 任何 LLM 推理 |

## 三、v2 简化后的数据流

```
0LLM 产出:
  grounding: { 图层名 + 字段角色 + 值域样本 }    ← 注入 LLM system prompt

LLM 收到:
  tools 参数: 全部 13 工具的完整契约 Schema（~7.4KB）
  system prompt: 接地上下文 + 用户 NL
  
LLM 自己从 13 个工具中选择 + 填参数 + 产 plans[]
```

**0LLM 不再决定 LLM 能看到哪些工具——LLM 看到全部，自己选。**
