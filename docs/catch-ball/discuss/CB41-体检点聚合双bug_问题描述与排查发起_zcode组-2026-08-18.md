## 一、问题 A（台账 B013）· 聚合 choropleth 颜色与点数语义相反

### 1.1 复现数据与步骤

- 点层：`DATA/analysis/77项量化/checkup_qty_合并_全覆盖.geojson`（**2296 点**·民生 5 类 + 安全 3 类合并·属性仅 `指标/中类/board/类/来源`——**没有极性列、没有 score 列**·前端分层归 L0 量化点）
- 聚合面域：预设 `checkup_cfg_community174` = `DATA/boundaries/presets/checkup_配置_社区174.geojson`（**174 社区**·属性仅 `社区`）
- 工具：聚合工具的「指定单元」路径（grid 工具 zonal 分支，层 `_ui.tool='grid'`）。工具箱「面域聚合」（zonal-tool）是同族另一入口，见 1.4。

### 1.2 后端计数是对的（已用真实数据复算验证）

直接调 `core/spatial_analysis.py aggregate_by_polygons`（`py -X utf8`·附录 A 脚本）：

### 1.3 根因链（zcode组 初步定位·待 dsh 独立验证）

```
体检点无极性/无score → 后端 aggregate_by_polygons 不产 polarity_index
  （core/spatial_analysis.py:312-341：极性统计整段在 _pol_col=None 时跳过）
→ 前端 grid-tool：
  · preprocessGrid：_grid_h = heightOf(point_count, max)（offset+sqrt 点数高度曲线）
  · gridStyle(level='L0')：level!=='L2' → 色带 grid-warm + 字段 _grid_h
    （frontend/js/grid-tool.js:81-88）
→ grid-wamp 色带方向：0=#8B0000 暗红 → 0.5≈#FF9900 橙黄 → 1.0 金黄（浅）
  （frontend/js/state.js HEATMAP_RAMPS['grid-warm']）
→ 渲染：fill-color = interpolate(_grid_h over grid-warm)
  （frontend/js/map.js _gridColorExpr + addPolygonPaint）
```

**结果：点数最多（112）= 色带 1.0 端 = 最浅金黄；零点社区 `_grid_h=0` 钳到 0 端 = 最深暗红。** 与截图「中心浅金、边缘深红」完全一致，与用户语义（点越多越深）**正好相反**；且「无数据」被渲染成「最严重」双重反语义。

### 1.4 同族第二入口（工具箱面域聚合 zonal-tool）——另一种失败形态

`toolbox/zonal-tool.js _execute` → `/geo/zonal_stats` → rows（无 polarity_index）→ `toolbox/shared.js buildZonalFc:56-61`：`_grid_norm = pi!=null ? piToNorm(pi) : 0.5` → **174 社区全部 0.5 → terrain-9 红绿发散色带的中点中性浅色 → 整层同色**（密集社区自然「很浅」，全部都浅）。`defaultPaint('zonal')` 也硬接 `polarityStops('overall')`（shared.js:130-137）。toast 文案还自称「极性 choropleth」（zonal-tool.js:233）。

### 1.5 历史修复脉络（为何反复发作）

- CB-23（08-12）：给 gridStyle 加了 `reverse` 参数（高值深色），代码注释原话「用户觉得默认『高浅黄低深红』怪」——但**默认仍 false**，本次复现即默认态；
- CB-23 A4/A5：后端排序补 `_sum`/count fallback（治 mean 颠倒总量）——修了**排序**没修**填色**；
- 本次 B013 第 2 次实测落台账。

**架构级根因**：聚合工具族（grid-zonal / toolbox-zonal）的填色管线按**情绪轨**（L2 极性均值 → 发散色带）单一设计；对**无极性的量化/体检轨**（点数语义）没有第二条着色语义，静默降级（一个借热度色带但方向反、一个全员 0.5）。用户会话已明确定语义：**点数决定颜色深浅**。

## 二、问题 B（台账 B012·第 3 次复现）· 悬停 tip 社区名与 Table 不一致

### 2.1 现象（文字）

聚合层生成后，右侧面板 Table 标签页列出 174 行「名称/点数…」（数据正确）。鼠标悬停地图上某社区，浮动 tip 卡里「社区」行显示的却是**别的社区名**（或干脆不显示社区行）。用户核对 Table 行与 tip 行，发现张冠李戴。

### 2.2 机制链（zcode组 定位 + 全量复算）

```
grid 系层（含指定单元社区聚合层）绑定 tip-popup（frontend/js/map.js:592-596）
→ 悬停 fillContent(feat)（frontend/js/tip-popup.js:402-435）
→ 社区行 = fillCommunity(centroidOf(feat))（:433-435）
→ centroidOf：无 _center 预计算字段时 = 几何 bbox 中心（:522-539）
   （社区面要素正是无 _center → bbox 中心）
→ fillCommunity：拿这个**中心点**对 checkup_cfg_community 174 面做
   point-in-polygon（外环射线法 :358-364），文件序**首命中即返**（:378-400）
```

**归属点=要素中心而非鼠标位置**。弓形/L 形/沿河社区 bbox 中心常落到邻居面或河流空白 → 显示邻居名或不显示。**与 Table（直读 feature.properties，天然正确）必然不一致**。

## 附录 B · tip 错配全量复算（只读·复刻 tip-popup fillCommunity 算法）

```bash
py -X utf8 -c "
import json
def bbox_center(geom):
    acc=[float('inf'),-float('inf'),float('inf'),-float('inf')]
    def walk(a):
        if isinstance(a[0],(int,float)):
            acc[0]=min(acc[0],a[0]);acc[1]=max(acc[1],a[0]);acc[2]=min(acc[2],a[1]);acc[3]=max(acc[3],a[1])
        else:
            for x in a: walk(x)
    walk(geom['coordinates']); return ((acc[0]+acc[1])/2,(acc[2]+acc[3])/2)
def pip(x,y,ring):
    ins=False
    for i in range(len(ring)):
        j=(i-1)%len(ring); xi,yi=ring[i]; xj,yj=ring[j]
        if ((yi>y)!=(yj>y)) and (x<(xj-xi)*(y-yi)/(yj-yi)+xi): ins=not ins
    return ins
lib=[(f['properties']['社区'],f['geometry']) for f in json.load(open('DATA/boundaries/presets/checkup_配置_社区.geojson',encoding='utf-8'))['features']]
agg=[(f['properties']['社区'],f['geometry']) for f in json.load(open('DATA/boundaries/presets/checkup_配置_社区174.geojson',encoding='utf-8'))['features']]
def first_hit(x,y):
    for nm,g in lib:
        polys=[g['coordinates']] if g['type']=='Polygon' else g['coordinates']
        for poly in polys:
            if poly and poly[0] and pip(x,y,poly[0]): return nm
bad=[]
for nm,g in agg:
    x,y=bbox_center(g); hit=first_hit(x,y)
    if hit!=nm: bad.append((nm,hit))
print('mismatch:',len(bad),'/',len(agg))
[print(f'  {n} -> {h}') for n,h in bad]
"
```
