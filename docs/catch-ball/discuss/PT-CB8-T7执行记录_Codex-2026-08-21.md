## 二 rc.8 适配过程中的三次修正

### 修正 1：MCP client 改指 rc.8 已构建包

初次启动失败：

```text
Cannot find module ...\dsh-mcp-client\lib\index.js
```

原因：`D:/Github/dsh/packages/mcp/mcp-client` 是源码 checkout，rc.8 更新后该目录缺少 `lib/index.js`；全局 rc.8 dsh 自带完整构建版。

处置：两个新 profile 的 MCP client junction 改指：

```text
C:/Users/Administrator/AppData/Roaming/npm/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-mcp-client
```

未修改 `D:/Github/dsh` 源码。

### 修正 2：profile 专属 settings 必须显式挂路径

仅在 profile 目录放 `settings.yaml` 时，`reasoningEffort: low` 未生效；首轮包含地图渲染的完整任务耗时 122.834 秒，超过 2 分钟。

原因：rc.8 settings 插件默认读全局 `~/.dsh/settings.yaml`，不会自动识别 profile 目录内 settings 文件。

处置：在两个 profile 的 `cordis.patch.yml` 增加：

```yaml
- id: settings
  config:
    path: 'C:/Users/Administrator/.dsh/profiles/<profile>/settings.yaml'
```

修正后快分析任务降至 29.730 秒。

### 修正 3：headless 不挂 agent preset，guard 改挂 host 层

初次 marker 测试返回 `PRESET_POLICY_MISSING`，说明自定义 agent preset 没进入 headless 会话。

原因：rc.8 `dsh-headless` bundle 本身不挂 agent preset roster，headless runner 直接从 host plane 组装模型工具。

处置：

1. 在 `emc-analysis` profile 中新增本地包 `emc-analysis-guard`；
2. 通过 `cordis.patch.yml` 直接挂到 host 层；
3. 复测返回 `PRESET_POLICY_PRESENT`。
