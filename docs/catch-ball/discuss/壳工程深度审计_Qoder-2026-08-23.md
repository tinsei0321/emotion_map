## 白话摘要

把今天新装好的「换脑系统」从头到脚体检了一遍，结论一句话：**骨架健康、血管通畅，但发电机的插座没装保险丝，三台发电机同时插电会把整栋楼的电路拖垮**——架构本身（事件分层、诚实降级、主路零注入）经得起审；真正要紧的是三件运维工程事。

逐条说：①每次问答都开一条专属广播线、用完即弃，收音机（渲染器）不会越积越多——**没有内存泄漏**，这点放心；②主路调 dsh 走的是「直接把问题当货物递给司机」（argv 传参），不走「贴纸条让命令行解释器读」，**问句里藏特殊字符也翻不起浪**——注入面已封；但有一条备用的「贴纸条」小路在 Windows 上其实是走不通的坏路，而且真走上去会把服务器吓出 500 错误——建议直接封掉这条死路（发现 QA-04）。③最要紧的：dsh 一次问答最长占一个工位 240 秒，而全楼总共 40 个工位还兼着别的服务——**几个人同时问，别的服务全排队**（QA-01）；也没人管「同时只许一台 dsh 开工」（QA-02）。④诚实性过关：模拟进度全部盖了「模拟」章，dsh 挂掉时出固定道歉卡绝不编答案；小遗憾是道歉卡太笼统，用户看不出是「dsh 没装」还是「网络断了」（QA-12）。⑤测试面：前端事件流测得很全（65+3 项），但后端那台「发电机」本身（超时、并发、命令解析）**一个自动测试都没有**（QA-08）。

总裁决：**有条件通过**——不退、不搁；QA-01/02 两个 P1 进下一批必修，其余 P2 限期修，P3 记账。

## 五 四档总裁决

### 裁决：**有条件通过**

**条件（进修复批的口径）**：
- 必修（下批·建议 SHELL2(FIX) 前缀）：QA-01 有界并发（信号量 1-2 + async 化）·QA-02 单飞闸·QA-04 fallback fail-closed·QA-08 端点单测（随修复件同批补）。
- 限期修：QA-03（前端看门狗）·QA-05（输出上限+消毒边界独立件）·QA-06（_summary 廉价化）·QA-07（8600 依赖入体检清单）·QA-15（分发矩阵单测）。
- 记账：QA-09/10/11/12/13/14/16/17/19/20（P3·随相关批次顺手治理）。
- 升级触发：若联网实测发现 dsh 并发下 profile 竞争出错 → QA-02 升 P1 立即单飞；若消毒面被证明可实际注入 → QA-05 升 P1。
