## 三、用户四类判断依据（原意 · 作为体验验收标尺）

> 以下为用户原话的整理。**宏观/中微观指分析内容/分析目的，非产品定位**——产品宏观定位由数据源（12345/社交/点评等多元评论大数据）决定；分析粒度可指向微观（公厕/口袋公园等·参考 4×5 归因矩阵），微观「归因」结论 = 四领域落实的**客观数据支撑**（过去靠问卷+专家经验·低效主观）。

### 依据 1 · 纯 GIS 操作（只列数据·不做进一步分析）

- **准确判断上传的数据**，运用正确工具，基于**默认图例样式**生成要求的结论图层；
- 数据流按**计划与执行流水线**完整运作（过程顺序不重要）；
- **高效完成**——不涉及分析和复杂思考，思考只用于工具筛选和路径计划；通常一个问题**即使多步也不应超过 60 秒**。
- → 需评估是否还有优化空间。

### 依据 2 · 纯问答

- **通用问题**（如"星期几"）：必须**快速**作答，不长篇大论；
- **「情绪地图」大问题**（概念/产品定位/产品理念等不聚焦问题）：结合背景（尤其「人民城市」宏观背景）+ 当前四领域（规划/更新/运营/治理）**前沿政策（需搜索）** 分析作答；
- **略微聚焦的问题**（策略/作用/应用场景等）：**不要假大空**，最好结合宜昌实际（新闻/公开资料）作答，给用户真实启发；
- **表达要求高**：不能只给一段话——通过**排版、字体样式、符号**突出关键信息；语气**生动且专业、理性**。

### 依据 3 · 情绪分析 = 空间尺度 × 分析工具（多维度分型灵活处理）

- 拆解：**空间尺度（宏观/中微观）× 分析工具（固化）** 分型灵活处理；
- 关键前提：**意图理解 Agent 能否正确理解「用户到底要什么尺度下的分析」**，然后才到工具选择（返回纯 GIS 操作）；
- **出口须随尺度差异化**——不能因分析类型一致+数据相同，宏观/中微观结论就「一竿子插到底=一样」；
- **用户示例**（已上传宜昌全域情绪点 + 中心城区范围）：

| | 提问 | 正确意图判断+计划+执行 |
|---|------|------------------------|
| ① | 中心城区范围内消极情绪的**分布情况** | 意图=**宏观尺度**（分布把控·粗粒度·不到归因）+ 核密度分析工具 → 计划：中心城区范围筛出情绪点 → 筛消极点 → 消极点 KDE 分析 → 出图 → 按 KDE 热点 + 消极评论 + POI 信息 → LLM 生成**结构性结论（不涉及归因）** |
| ② | 中心城区**哪里情绪最差、原因是什么** | 意图=**中微观尺度**（某个/多个区域·细粒度·要归因）+ grid 工具 → 计划：范围筛点 → 筛消极点 → grid（默认 400m）→ 出图 → 按 grid 结果筛目标聚合域（**如何筛合适聚合域→需展开讨论·列入后续计划**）+ 消极评论 + POI → LLM 生成**结构性结论（不涉及归因）** |

- → 用户问：**当前架构能实现吗？** 需要调整/优化/增加哪些环节？可参考业界做法或相似目标的实现手段。

### 依据 4 · 复合问题连问

- 一个对话输入「连问」多个问题；
- 需要架构发挥 Agent 灵活性，**将需求拆解并分布**；
- → 用户问：目前能实现吗？还需要做什么？业界怎么做的？

| 要求 | 现状 | 差距 |
|------|------|------|
| 尺度-方法-范式矩阵 | `paradigm.py` SCALE_PARADIGM（macro/meso/micro·方法/出口/禁止/典型问）| ✅ 设计已有 |

| **出口随尺度差异化** | `select_template` 按 scale→template→出口 | ❌ **未闭环**——「一竿子插到底」同构结论风险（结论形态差异无执行层强制） |
| 示例①（宏观·分布） | KDE→结构性结论（不归因） | ⚠️ 意图理解+计划可达·**无测试断言** |
| 示例②（中微观·归因） | grid→归因 | ⚠️ 可达·**无测试断言** |

**架构结论（核实后）**：用户示例①/② 的链路**架构上可达**（范式层已具备），但：
1. **scale 判定是断点**——FC prompt 没教「先判用户要什么尺度」，且默认值硬编码 macro → 「一竿子插到底」的根；
2. **出口差异化未闭环**——scale→template 有映射，但「宏观→结构性结论不归因 / 中微观→归因+单元排序」这种结论形态差异没有执行层保证；
3. **零测试断言**——B0-B3 是信号级（工具触发+渲染），不验「结论形态是否随尺度变」。
