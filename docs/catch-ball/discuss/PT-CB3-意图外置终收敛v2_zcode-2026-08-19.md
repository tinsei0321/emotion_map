## 二、EMC 终态定义（定稿）

> **EMC = 一大堆契约的集合体（壳子）**：四类契约 + 两类补充 + Dumb 工具集 + 守卫验证器 + 制式化输出器。
> 思考（开放决策：怎么分析/用哪些工具/什么颗粒度）**全部外置**给 LLM+Harness 宿主；壳子内只存在闭包校验与模板填充。

**"零思考"的操作性定义**（dsh 判定标准·采纳）：
- 思考 = 不可枚举的决策空间（同一输入可有不同输出）——壳内**禁止**；
- 校验 = 闭包规则（同一输入恒有同一输出：查表/schema/枚举/正则）——壳内**保留**；
- **红线**：校验器必须纯规则；任何模糊语义匹配（LLM 纠错/模糊归类）显式标注"软校验（提示级·不阻断）"，不得悄悄升级为决策。

## 三、契约体系（四类 + 两补充·载体落位定稿）

| 契约类 | 内容 | MCP 载体（dsh 实测结论） |
|---|---|---|
| 工具调用类 | 参数/默认值/别名/输出 schema（`tool_contracts.py` 已有） | **tools**（inputSchema 派生） |
| **方法论类** | paradigm.py 知识转译：尺度→工具→颗粒度**推荐路径** | **双写**：prompts 详版 + **工具描述内嵌摘要**（实测：宿主对 prompts 消费率低，工具描述是 planner 必读——"只写 prompts 是最常见失败形态"） |
| 回答范式类 | 出口卡三段式/结论结构（CB-18 雏形） | prompts 结构模板 + 关键工具 output.schema；**制式组装留 EMC**（宿主给内容素材，不给版面） |
| 意图理解类 | 意图卡 schema（尺度/主题/时点/区域/期望结论形态） | prompts 引导模板（含示例）+ resources（schema 本体·程序化读取） |
| 补①数据口径类 | 数据集注册/口径语义/caliber（B3 注册表） | **resources**（按需读取·不进自动上下文·控 token） |
| 补②安全权限类 | 只读/脱敏/白名单 | **工具 security 字段**（server 侧强制·不依赖宿主自觉） |

## 四、设计纪律清单（新增三条·dsh 贡献）

- **D-a 结构化打回**：出口验证的错误信息必须结构化（错误码 + 缺失项 + 修正示例）——护栏充分性取决于"打回时给不给可操作的修正指引"，不是"能不能打回"；
- **D-b 最粗分流器（采纳·极轻形态）**：请求带 `em:mode ∈ {analysis, qa, outlet…}` 枚举——**宿主填、EMC 只验枚举合法性、绝不推断 mode**（推断=思考）。EMC 按 mode 查表分派出口范式族（闭包），显著降低打回率；
- **D-c 方法论契约双写**：凡引导性知识必须同时进工具描述摘要（v1 漏了此杠杆）。

## 五、过渡路线（四步·v2 补三护栏）

**冻结 → 契约转译 → 外置验证 → 切换拆旧**

1. **冻结期**：ai_qa 只修 CRIT 级 bug（明确预算·不增强）；
2. **转译期**：paradigm.py → 方法论契约；**行为对拍**——取现有链路典型问答做回归集，验证新链路与旧链路输出口径一致（口径级·非字面级）；
3. **外置验证期**：实连测试；**回滚开关**（feature flag）常开——切换不是单行道；
4. **切换判据（可操作四条·全达才拆旧）**：①工具面全通；②意图契约 schema 冻结；③外置实连 30 个典型问题、出口验证打回率 < 20%；④静态演示场景双轨均出图。
