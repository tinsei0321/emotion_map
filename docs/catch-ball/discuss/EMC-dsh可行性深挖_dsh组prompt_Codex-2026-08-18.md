## 2. dsh组需要挑战的既有假设

1. **“dsh 原生 MCP 支持意味着 EMC 工具面可直接消费。”**  
   请检验配置面、schema 词汇、outputSchema、审批、长任务、错误语义、Windows 启动、全局 profile 等真实约束。

2. **“形态3 是 EMC 的正确终局。”**  
   请从 dsh 产品哲学与工程节奏判断：领域平台 + 通用 harness 是否真的优于薄 UI plugin、Web Host 深嵌或暂缓集成。

3. **“外挂大脑 B 变体技术前提已证实。”**  
   ACP/headless/session 复用确实存在，不等于产品化稳定。请区分“机制存在”与“可维护运行”。

4. **“B 变体实验保留是当前最保守正确策略。”**  
   请判断该定位是否合理：是否应该更早转正、永久搁置，或只作为用户个人工作流而非 EMC 产品能力。

5. **“render contract 可由 EMC 单方面定义。”**  
   请从 dsh ConversationNode / Web Client 消费者视角评估契约是否足够，缺哪些事件、状态或资源模型。
