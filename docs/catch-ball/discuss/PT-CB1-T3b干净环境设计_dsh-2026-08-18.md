## 〇 一句话结论

专用干净环境 = dsh 的一个独立瘦 profile（`emc-slim`），只装配基础底座 + 情绪地图 MCP 工具，不装配文件系统、命令行、浏览器与日常插件；审批统一走「ask + 桥侧按白名单自动应答 allowed-once」的三档策略，并以 E8 的 `--dump-config` 可审计组装作为验收基线。

---

## 一 目标与边界

### 1.1 目标

为「外挂大脑」实验、朋友链路评审、未来实验环境提供一部**工作手机**：

1. 只装情绪地图只读数据工具；
2. 只装知识查询与地图结果说明；
3. 有明确的审批规则；
4. 所有工具调用可审计、可重建。

### 1.2 边界

- 本稿只覆盖 dsh 侧 profile 与审批策略；情绪地图 MCP server 本体由 G10 交付，本稿不实现 server。
- 不建 dsh plugin / ConversationNode 工程。
- 不做「全 allow」默认（对应安全条款 C12-⑩）。
- 不挂用户日常 profile；日常环境里的文件读写、命令行、浏览器、个人插件一律不进入该 profile。

## 二 dsh 瘦 profile 配置草案

### 2.1 位置与文件

- 目录：`~/.dsh/profiles/emc-slim/`
- 关键文件：
  - `package.json`：`dsh.profile.bundles` 装配清单；
  - `cordis.patch.yml`：loader 覆盖层，同时是 MCP server 注册位（profile 级全局生效）。

### 2.2 `package.json` 草案

```json
{
  "name": "dsh-profile-emc-slim",
  "private": true,
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-mcp-client"
      ]
    }
  }
}
```

说明：

- `@deepseek-ai/dsh-base`：基础底座，提供会话、工具管线、审批门、日志等必需能力；
- `@deepseek-ai/dsh-mcp-client`：MCP 客户端，用于加载情绪地图 MCP server；
- 不加入 `dsh-web-app`、`dsh-better-sidebar`、`dsh-review-skills`、`dsh-security-scan` 等日常插件；
- 若后续采用 ACP 系，运行入口使用 dsh 自带 `demo:acp` 组合，不在 bundles 中额外挂日常能力。

### 2.3 `cordis.patch.yml` 草案

```yaml
# 只注册情绪地图 MCP server；禁止追加任何 fs/shell/browser/日常插件条目
mcp:
  servers:
    emc:
      transport: stdio
      command: py
      args:
        - "D:/Github/emotion_map/emc_mcp_server.py"   # G10 落地后替换为真实入口
      # 如需 rag_query synthesize，可在此注入 DeepSeek key 引用；禁止硬编码
      # env:
      #   DEEPSEEK_API_KEY: "${EMC_DEEPSEEK_API_KEY}"
```

说明：

- `command: py` 与 EMC 既有 Python 3.14 启动方式对齐，避免 Windows 多解释器坑；
- 上述字段名为草案形态，最终以 dsh config-catalog（stdio/streamable-http/reconnect 配置节）与 G10 spike 实测为准；
- 版本锁定：bundle 用固定版本 / tarball / junction 锁定，升级 = 显式动作，避免 preview 破坏性变更静默侵入。

## 三 最小权限矩阵

| 能力面 | 是否挂载 | 说明 |
|---|---|---|
| 基础底座（base） | 挂载 | 必须：会话、工具管线、审批门、日志 |
| 情绪地图 MCP 工具（七工具） | 挂载 | 只读 + dataset_id 白名单；server 侧脱敏；G10 交付 |
| 文件系统 | 不挂载 | 不提供 fs 工具；MCP server 自身路径白名单另由 EMC 侧保证 |
| 命令行 / Shell | 不挂载 | 不提供 bash / pty / shell 工具 |
| 浏览器 / Web / HTTP | 不挂载 | 瘦 profile 不挂 Web Host、API Gateway、浏览器插件 |
| 日常插件 | 不挂载 | sidebar / review / security-scan 等一律不装 |
| 模型适配器 | 保留 base 默认 | 模型按 `~/.dsh/settings.yaml` 锁定，不额外加第三方 provider |
| 审批门 | 显式配置 | ask + 桥侧自动应答 allowed-once（见第四节） |
| 会话日志 / 审计 | 保留 | Model-visible means logged，工具调用入 session log |
| 网络出口 | 默认关闭 | 仅 MCP stdio 本地进程；streamable-http 需单独评审 |
| 写操作 | v1 无 | v2 若加写路径，仅限 EMC 指定输出目录且必须过脱敏；不写 raw/ |

## 四 审批策略：allowed-once 唯一 grant 下的桥侧自动应答三档

### 4.1 dsh 审批事实

- 当前 dsh 审批策略为 `ask | never` 两态；
- `allowed-once` 是唯一放行形态，不存在「会话级永远放行」；
- 因此三档策略都是「policy=ask + 桥客户端按策略自动应答/拒绝」的组合，不是把策略设为全 allow。

### 4.2 三档定义

| 档位 | 适用场景 | 自动应答规则 | 非白名单处理 | 状态 |
|---|---|---|---|---|
| A 仅只读 | 外挂大脑实验、评审、默认 v1 | 对情绪地图只读工具自动应答 allowed-once | reject（不假成功） | v1 默认 |
| B 白名单写 | 需要导出/生成产物时 | 只读同 A + 白名单写操作（如导出到 EMC 指定输出目录）按路径/参数校验后 allowed-once | reject | v2 候选 |
| C ask 透传 | 有人在场的调试/正式联调 | 桥侧不自动应答，将 `request_permission` 转发给最终用户；无人应答 = 拒绝（fail-closed） | reject | v2 / 人工场景 |

### 4.3 配套约束

- 禁「全 allow」默认（安全条款 C12-⑩）；
- 所有自动应答必须留审计记录（session log）；
- 白名单由 EMC 侧定义（工具名 + 参数约束），不放在 dsh 侧自由配置；
- 非白名单请求必须显式拒绝，不得静默降级为「放行」。

## 五 验收概念（对齐 E8 Profile 组装）

### 5.1 E8 思想

profile = 具名组装（组合包按序叠加 + patch 层层覆盖）；`--dump-config` 可见全部条目且皆可替换。干净环境的验收不是看「宣称没装什么」，而是看**实际装配清单可枚举、可审计**。

### 5.2 验收清单

1. `dsh --profile emc-slim --dump-config` 只出现 base + mcp-client + 情绪地图 MCP server 条目；无 fs / shell / browser / 日常插件；
2. 启动后 MCP 工具列表 = 情绪地图 v1 工具集（七工具），无本地文件/命令工具；
3. 审批三档可切换且生效：白名单自动 allowed-once，非白名单 reject，无全 allow；
4. 每次情绪地图工具调用在 session log 可溯源；结果无 PII（server 侧脱敏）；
5. 版本锁定：升级需显式动作，`--dump-config` 可见固定版本；
6. 最小环路验收（若 ACP 系）：建会话 / 白名单审批 / 取消无孤儿 / 日志溯源四条件全过；若 headless：一次真实任务跑通且无越权工具；
7. 朋友成品评审：对照本 profile 与审批三档检查其实现，重点看是否存在「全 allow」或绕过白名单。

### 5.3 一句话验收

**这部工作手机里只装情绪地图插座，钥匙串不借人，每一次插拔都有记录。**
