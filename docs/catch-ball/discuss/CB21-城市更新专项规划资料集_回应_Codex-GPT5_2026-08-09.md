## 焦点 2 · 知识库层级：L0 放 docs/urban-renewal-plan/ — agree

**理由（代码级）**：

- `industry_kb/` 是 `.py` 单一权威源，专供 EMC 运行时注入（`ai_qa/prompts.py:253` 注入 diagnose brief；`:122` 注入 agent_step 全量附录；`:177` 注入 finalStep 精简速查）。原始资料（原文/PDF/页码/长归纳）进 `.py` 会让注入体积失控且不可维护——L0 放 docs/ 零注入成本。
- docs/ 在 git 中、无运行时依赖，zcode 独立项目可直接读取——满足"打包汇总资料集"用途。
- 与运行时关系应固定为**单向提炼**：L0（原文）→ L1（浓缩）→ L2（出向契约），L1 条目标注 L0 来源引用，反向不依赖。

**1 条收紧建议**：在 `docs/industry-knowledge-base.md` 明确三层定义 + 提炼规则（现在只有 L0 国标层指 `landuse_codes_2023.py`，需扩成 L0=资料库/L1=industry_kb/L2=outlet_kb 三行表），并让 `urban_renewal.py` docstring 的"做厚路径"指向 `docs/urban-renewal-plan/_INDEX.md`（`ai_qa/industry_kb/urban_renewal.py:1-14` 已写明"做厚路径见 docs/industry-knowledge-base.md"，链路补上即可）。

## 焦点 3 · 防张冠李戴：元数据 — partial（补 4 字段 + 各城差异对照矩阵）

**现有字段基本够**（完整名称含文号/层级-城市/机构+链接/本地位置/参考位置/归纳/EMC 对应），**建议补 4 个**：

| 补字段 | 为什么 |
|---|---|
| **文档类型** | 政策/条例/指标/指南/案例/新闻/体检报告/规划——防"条例当规划""新闻当政策"（文档性质维度目前隐含在目录里，但目录可移动、索引要自足） |
| **状态** | 正式发布/试行/征求意见稿/草案——专项规划常有"修编/试行"状态，草案当定稿是张冠李戴高发源（发起文档已核实宜昌为"2025 修编"、湖北为"试行"，应落成字段） |
| **采集状态** | 原文已下载 / 仅链接+摘要 / 待核实——用户要求"严格标注来源+参考位置"，但网络动荡下大量条目只有链接摘要；不标采集状态会把摘要当原文 |
| **指标口径基准** | 各城体检指标差异的标注方式（见下） |

**体检指标各城差异标注方式（建议）**：

1. `_INDEX.md` 顶部固定放「已核实差异矩阵」：行 = 城市/层级（住建部基础框架 / 恩施 76 / 武汉细化 / 杭州 86 / 宜昌本地），列 = 差异类型（指标总数 / 增设项 / 调整项 / 依据文件）。发起文档 2.3 那三条差异直接落成这个矩阵，后续扩展。
2. 指标类文件内部**每个指标条目带「来源=城市+文件+页码/条目号」**（如 `来源：杭州体检 86 项·第 3 节·指标 12`），杜绝"杭州 86 项里某条被当成宜昌体检标准"。
3. `02-指标体系` 每个子目录 README 顶部写警示行：`本目录 = {城市/层级} 专属指标，勿与 {其他城市} 混用`。

## 焦点 5 · 打包形式：目录 + _INDEX — partial（补 3 点即可满足 zcode 独立读取）

目录自包含 + `_INDEX.md` 提取清单 + README 打包指引，形式可行。**补 3 点**：

1. **稳定 `id`**：每个文件登记 `URP-###` id，`_INDEX` 引用 id 而非仅路径（路径移动/改名不破坏引用）。
2. **统一 front-matter**：每个 markdown 顶部放统一元数据块（与 _INDEX 列一致：id/名称/文号/类型/层级-城市/机构/日期/状态/来源链接/本地路径/参考位置/采集状态/EMC 对应），zcode 可程序化解析，防"文件名漂移 + 内容对不上"。
3. **打包命令写进 README**：给出 PowerShell `Compress-Archive` 示例 + 目录树说明；PDF 原文统一放 `_raw/` 子目录并由 _INDEX 链接（README 注明"原文不移动"）。

可选低优先：`_EXPORT.ps1` 一键打包脚本（非必需，zcode 直接读目录也行）。

## 焦点 6 · 收集优先级 — agree（取舍合理 + 杭州分层做厚）

**首轮聚焦（国家/湖北/宜昌政策 + 体检指标 + 杭州案例）取舍合理**，网络动荡下"链接+摘要为主、尽力下载"是正确策略。建议内部排序：

1. 国家层（优先级最高）：城市更新行动意见（2025）/ 防止大拆大建 63 号 / 城市体检评估管理办法（2024）/**《城市更新规划编制导则》建办科〔2025〕46号**——注意 `urban_renewal_outlets.py:1-8` 的出向契约已引用该导则（更新对象识别/更新时序等 5 契约的依据），它是 L1→L2 的直接源头，应最先收原文
2. 湖北省级指引（试行）+ 宜昌专项规划（2025 修编）+ 宜昌城市体检报告（如有）——研究主战场
3. **杭州（用户指定必含）**，建议四层做厚：
   - 制度层：杭州城市更新条例/实施办法（如有）——地方立法代表
   - 规划层：杭州城市更新专项规划（2024-2035）——发起文档已核实存在，优先下原文
   - 项目层：3~5 个代表案例（历史街区活化：小河直街/桥西/德寿宫周边；老旧小区：馒头山等；未来社区：缤纷/亚运村类）——**每个案例必须带可验证来源**，优先选有民意/感知数据（满意度/活力/烟火气）的，与 EMC"可感知指标"对接口强相关
   - 指标层：杭州 86 项 vs 住建部基础框架差异对照（入 _INDEX 差异矩阵）
   - 注意：杭州深案例进 `case_library.py` 需真实数据（该文件铁律"仅收录已核实真实数据·不编造"·`case_library.py:3-6`）；首轮若来源不足，先进 L0 案例资料 + L1 CASES 三元组简版，深案例后置
4. 其他案例城市（上海/广州/北京/武汉）：每城 1~2 份代表（条例/导则/规划/案例）做对标，不贪多
5. **新闻类降最后**：首轮网络时间不要耗在新闻上，政策/指标/案例价值密度高得多
