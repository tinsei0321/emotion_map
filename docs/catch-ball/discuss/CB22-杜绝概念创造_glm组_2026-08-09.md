### 焦点 1：修改计划够治本吗？— **partial（治标·缺 LLM 自创防线）**

**claude 计划**：改笔记段落 + 全仓断言 + 重建索引。

**glm 核实**：
- **codex 笔记 :43 仍是硬造分类源**（`'典型片区类 43 个...机制建设类 12 个'`）——**根因确认**（fact 改了 note 没改·检索 Top-5 全 note → LLM 看到）。
- **URP-P01 已改**（罗列式 ✅）——但**note 是独立数据源**（rag_index _load_notes 索引 note 段落）。

**glm 判定**：**partial——改笔记 + 断言是治标（清已有残留）·缺 LLM 自创防线**：
- 改笔记段落 = **清这一处残留** ✅（必要·但只治已知）
- 全仓断言 = **清全仓同类残留** ✅（必要·但只治已有）
- **缺：LLM 综合时自创概念**——素材全干净·LLM 仍可能从"55 个 = 43+12"推断"前 43 是一类·后 12 是另一类"→ 自创分类名/解释（焦点 2 深层）

**glm 结论**：修改计划**治标到位**（清残留）·**治本不足**（防 LLM 自创·焦点 2）。

### 焦点 2：深层——LLM 综合自创概念 — **agree（核心根因·须指令扩展）**

**问题**：素材干净后·LLM 综合时仍可能自创概念（从数字推断分类/解释）。

**glm 实证**：
- 用户报告回答含"侧重制度与保障机制搭建"——这是 LLM **顺着「机制建设类」标签自创的解释**（素材无此表述）。
- 即使素材去掉了"机制建设类"·LLM 看到"55 个 = 前 4 组 43 + 其他 12"→ 可能推断"43 是片区项目·12 是非片区/其他类型"→ 自创分类解释。

**glm 判定**：**agree 这是核心深层根因**——指令 3（harness.js:155）当前约束：
```
每个具体数字/名词必须紧跟 [来源] 锚点·禁止自行拆分/合并/编造数字
```
- **只约束"数字"（拆分/合并/编造）**·**未约束"概念/分类推断"**（LLM 可从数字推断分类·不算"编造数字"）。

**glm 治本建议（指令 3 扩展）**：
```javascript
// harness.js _assembleKnowledgeQA 注入指令 3 扩展
'3. 每个具体数字/名词必须紧跟〔来源：可读名称〕锚点·禁止自行拆分/合并/编造数字·'
'**禁止从数字推断/归纳分类术语或概念解释**（如素材写"43+12"不得推断"43 是片区类/12 是机制类"）·'
'素材未明确表述的分类/解释/归纳一律不得输出·如需概括须标注"以下为回答者概括·非源文档用语"；\n'
```

**即指令 3 从"禁编造数字"扩展为"禁编造数字 + 禁推断分类/解释"**——堵 LLM 自创概念的深层路径。

**补充防线（黄金集断言）**：
- 黄金集加 1 条"概念清洁"断言：检索"宜昌有哪些更新项目" → 回答**不含**"典型片区类/机制建设类/侧重制度保障"等**素材未明确**的分类术语/解释。
- 断言用关键词黑名单（源文档无的归纳标签）+ 人工抽查（LLM 可能换词自创）。

### 焦点 3：「检索全 note」—— note 提炼是创造源 — **agree（治本须 note 纪律 + 混合检索）**

**问题**：fact 卡命中率低（短文本信号弱）·用户看到的是 note 段落（提炼者归纳）—— note 提炼本身是创造源。

**glm 核实**：
- glm 上轮复验已预警（search "宜昌有哪些更新项目" Top-10 全 note）—— fact 不命中此 query。
- note 段落（codex_0819:43）由 codex 提炼·含归纳标签"典型片区类/机制建设类"——**note 提炼就是创造源**。

**glm 治本 2 层**：

**① note 提炼纪律（KNOWLEDGE 扩展覆盖 note）**：
- 现状 KNOWLEDGE :51-52 术语纪律三分只说"素材卡"——**未说"L0 笔记段落也是素材"**。
- **扩展**：术语纪律三分覆盖**全部向量化素材**（fact 卡 + note 段落 + concept 卡）—— note 提炼时同样禁硬造分类。

**② 混合检索提升 fact 命中率（glm 上轮 P1 建议·此处重申）**：

- **混合检索**：rag_search 对知识查询·同时跑向量（note）+ 关键词 WHERE（fact·如 `topic='project'`）→ 合并 Top-K。
- fact 命中后注入结构化精确数据（"55 个·51.33 亿"）·**降低 note 段落占比** → 减少 LLM 接触提炼归纳的机会。
- **这是 P1 优化**（混合检索实现成本中等）·但**与 note 纪律互补**（纪律防新创造·混合检索降 note 占比）。
