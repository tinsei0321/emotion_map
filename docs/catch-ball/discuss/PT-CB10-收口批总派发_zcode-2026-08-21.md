## A-3 MCP stdio 协议纯度修复（Codex 执行·dsh 复验·新增 P0）

**问题**：`core/tracker.py` 的 `@track` 装饰器经 `_emit`→`safe_print`（`core/utils.py`）→ `print()`（stdout）输出 `[TRACE]` 行。MCP stdio server 启动时预热函数（`tools/mcp_server_emc.py:760-788`）触发 `@track`，非法 stdout 行污染 JSON-RPC 流。dsh rc.8 客户端容忍（无 onerror 处理），**严格 MCP 客户端（Python mcp SDK 1.29）连接即失败**。

**修法（最小侵入·不动 tracker 架构）**：
1. 在 `tools/mcp_server_emc.py` 的 `main()` 或模块级——**在 FastMCP 启动前重定向 stdout 到 stderr**：
   ```python
   import sys
   # MCP stdio 协议纯度：stdout 专属 JSON-RPC·一切 trace/debug 走 stderr
   # 只在作为 stdio server 启动时重定向（import 时不重定向·保测试/直接调用不受影响）
   if __name__ == '__main__':
       import os
       if os.environ.get('EMC_MCP_STDIO', '1') != '0':   # 环境变量逃生门
           sys.stdout = sys.stderr
   ```
2. 已在 stderr 的预热输出（`mcp_server_emc.py:767-776` 的 `file=sys.stderr`）无需改动——重定向后 stdout=stderr 双保险；
3. `[OK] EMC MCP server stdio 启动` 这行也走 stderr（D4 已裁决·确认在本修法中一并覆盖）。

**白名单**：`tools/mcp_server_emc.py` + `tests/test_mcp_server_emc.py`（+1 用例）。

**验收**：
1. `py -m pytest tests/ -q` 全绿（442+2+新增）；
2. **严格 client 测试**（dsh 复验项）：`py -c` 用 `mcp` SDK 1.29 标准 stdio client 连接 → initialize 成功 → list_tools 返回 **10 件**（list_data/rag_query/kb_facts/outlet_card/zonal_stats/buffer/rank/render_spec/render_file/emc_status）；
3. dsh rc.8 客户端同时验证（双客户端兼容）。

**三件**：

### A-4a 服务端 /version 端点

- 文件：`api/render_routes.py`（现有 render 路由文件·追加端点）
- 规格：`GET /api/v1/version` 返回：
  ```json
  {"commit": "<git rev-parse --short HEAD>", "startup": "<ISO 时间>", "branch": "<分支名>"}
  ```
- git commit 获取：`subprocess.run(['git','rev-parse','--short','HEAD'], cwd=REPO)`——启动时缓存一次（不每请求跑 git）；
- 分支：`git rev-parse --abbrev-ref HEAD` 同缓存。

- 文件：`frontend/js/render_client.js`（追加·白名单内）
- 规格：页面加载时 fetch `/api/v1/version` → 在地图容器左下角（attribution 上方）显示 `v<commit 前 7 位>` 小字角标（CSS 内联·不新增文件）；
- 服务不可达时不显示（静默降级）。
