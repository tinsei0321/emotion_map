## 二 高优先级发现

### H1 · 前端 usage 守卫缓存没有初始化，通道 B 实际不生效

**严重级别：High / Required**

#### 代码事实

`frontend/js/ai_qa/tools.js`：

- `getGeoCatalog()` 在成功后调用 `_buildUsageBlocked(c)`；
- `_guardUsageRef(v)` 在 `_usageBlocked === null` 时直接 return；
- `invalidateGeoCatalog()` 只清空缓存，不构建缓存。

关键代码：

```text
frontend/js/ai_qa/tools.js:45-51   getGeoCatalog() → then(_buildUsageBlocked)
frontend/js/ai_qa/tools.js:55       invalidateGeoCatalog() → 只置 null
frontend/js/ai_qa/tools.js:60-68   _usageBlocked 初始为 null
frontend/js/ai_qa/tools.js:70-75   _usageBlocked === null → 直接放行
frontend/js/ai_qa/tools.js:223-253 ref() → 字符串与已加载层两处调用 _guardUsageRef
```

但当前仓库全前端搜索结果显示：

> 除 `getGeoCatalog` 定义本身外，没有任何调用方。

唯一相关引用是 `range-presets.js` 调 `invalidateGeoCatalog()`。历史上 `buildContext` 曾移除 `formatGeoCatalog` / catalog 注入以避免 registry 全量泄漏；这使 `getGeoCatalog()` 成为此前的遗留导出，本轮守卫错误地假设它会被调用。

#### 后果链

1. 用户从 Range 面板加载结论层；
2. `range-presets.js` 正确写入 `L.presetId`；
3. AI 工具 `ref()` 匹配到该层；
4. `_guardUsageRef(l.presetId)` 被调用；
5. 但 `_usageBlocked === null`，直接放行；
6. `ref()` 返回该层 GeoJSON；
7. 后端只看到 dict，无法识别其来源；
8. 除 `hotspot` 外的多数端点因其他逻辑可能报错，但这不是 usage 语义拒绝；`hotspot` 则会直接成功。

#### 判定

T2 执行记录声称：

> “catalog 未就绪时跳过 → 后端权威兜底”

这个说法只对 **preset_id 字符串直传** 成立；对 **已加载 preset 层转 GeoJSON** 不成立。后端无法从匿名 GeoJSON 还原 `presetId`，因此没有权威兜底。

#### 建议修复方向（不在本轮实施）

任选其一，或组合：

1. **加载时持久语义**：`range-presets.js` 除 `L.presetId` 外再写 `L.presetUsage = item.usage`；`ref()` 匹配到已加载层时直接根据 `l.presetUsage` 拒绝，不依赖 catalog 初始化。该方案最小、最稳。
2. **工具调用前强制初始化 catalog**：在 AI buildContext 或工具调度前调用 `getGeoCatalog()`；但要处理失败态，不能失败后静默放行。
3. **保留来源元数据直到后端**：对 preset 转出的 GeoJSON 附带受控 source metadata，由后端统一校验。该方案更适合未来 MCP，但对当前改动更大。

**Codex 推荐方案 1 + 后端 hotspot 补闸。**

### H2 · 后端 hotspot 端点漏挂 usage 守卫

**严重级别：High / Required**

#### 代码事实

`api/geo_routes.py` 的消费型端点与挂闸状态：

| 端点 | 消费参数 | 守卫状态 |
|---|---|---|
| filter_attr | layer / range | ✅ |
| clip | layer / range | ✅ |
| extract_feature | layer | ✅ |
| merge | boundary / layers | ✅ |
| area_stats | boundary | ✅ |
| zonal_stats | layer / range / boundary | ✅ |
| grid_pois | 忽略 layer/range，仅 cell 参数 | 不需要 |
| rank | layer / range / boundary | ✅ |
| buffer | center / layer / range | ✅ |
| overlay | layer_a / layer_b | ✅ |
| nearest | layer / target | ✅ |
| **hotspot** | **layer / range** | **❌ 漏挂** |

`hotspot` 直接调用 `_prepare_points(req.layer, req.range, req.pre_filter)`，但 `_prepare_points()` 本身不做 usage 校验。

#### 实测反例

审计组用 FastAPI TestClient 实测：

```text
POST /api/v1/geo/hotspot
{"layer":"yichang_l2_t1","range":"base_174_aggregate_area","value_col":"score"}
```

结果：

```text
200 Success
```

并实际执行了热点分析。相同结论层用于 `zonal_stats(boundary=...)` 时能返回 400 三段式拒绝。

#### 判定

执行记录写“十端点挂闸”，但实际消费图层引用、需要挂闸的端点是 11 个；`hotspot` 被漏掉。该端点在前端工具清单中真实存在（`TOOLS.hotspot` / `generateHotspotForAI`），不是死代码。

#### 建议修复

在 `hotspot` try 块首行补：

```python
_guard_usage_refs(req.layer, req.range)
```

并新增 API 级测试：

```text
hotspot(range=analysis_output preset) → 400 + analysis_output + 铁律7
```

## 四 开放裁决点审计

### 裁决一：拒绝范围 = 全参数位

**Codex 判定：PASS，采纳全参数位拒绝。**

理由：

1. manifest note 的语义是“结论层禁作空间操作输入”，不限于数据位；
2. 结论层出现在 `boundary`、`range`、`center`、`target`、`layer_a/b` 等位置同样是语义误用；
3. 全参数位拒绝能把“未知点层/面层类型错误”前置为更准确的口径错误，降低 AI 试错成本；
4. 控制参数（如 `by='worst'`、字段名、cell id）不是图层引用，当前不拦，正确。

边界：

- 必须只扫描图层引用参数位；
- 不能把普通字段名/枚举值误认为 preset id。

### 裁决二：多步链 `$n` 中间结果放行

**Codex 判定：PASS，维持放行。**

理由：

1. `$n` 是本轮工具产物，携带运行时上下文，不是 manifest 结论层按钮；
2. rank 等工具对已聚合结果再排序是既有设计内用法；
3. 一律拦截会造成既有用例退化，违背“既有功能零回归”验收；
4. 中间产物是否需要携带 provenance / caliber，应在未来工具面设计中增强，但不能通过一刀切拒绝解决。

建议：

- 未来结果层可附带来源与口径元数据；
- 若中间产物本身是“最终结论层”再被当作原料，可再按语义细分，但当前不必扩大复杂度。
