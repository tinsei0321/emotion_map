1. **根因上溯一层**。Codex 归因到通道层（watcher 竞态），我上午的复核也只到通道层（TTL/水位线）；Qoder 挖到生命周期层——「停止只停了传菜，没停厨师」。源头不断，通道层过滤做得再好也只是在给幽灵当门卫。这一层是治本与治标的分水岭。
2. **证据全部可复核**。每个论断带文件+行号，且主动区分「实证」与「未实证」（登记项②明确标注串流风险未实证、建议 interrupt 落地后回归验证）——R8 纪律（验证忌与实现同构）的正面示范。
3. **方案克制**。SSE 首帧 hello（约 8 行，实测落地 render_routes +2 / render_client +6，估算准）、不补空 manifest（防「404 变 200 掩盖从未生成」）、不硬禁 dataset_id（防误伤演示流）——每个「不做」都有理由，符合 YAGNI 与数据红线纪律。
4. **分歧点表述干净**。四条分歧逐条给「Codex 方案 / 我的意见 / 理由」，不模糊不人身，CB 讨论的范本格式。

## 三、弱点与可质疑处（两条实质 + 一条形式）

1. **turn_ref 链有自相矛盾的成分**。报告分歧点 1 批评 Codex「约束写 AGENTS.md 无效——模型读不到」；但 P1-A 的 turn_ref 注入同样依赖模型忠实执行指令前缀（`[render_ctx] turn_ref=…` 须原样传进 render_spec 参数）——**约束写在模型可见层，模型不配合就失效**，这与被批评的对象是同构的软机制。缓解项：宽松规则（不带 turn_ref 照常渲染）使失效退化为现状而非更坏，blast radius 受控——但作为「第二道防线」，它的防线强度取决于模型心情，不如闭包校验硬。
2. **非 Codex 生产者的迟到 spec 无防护**。宽松规则下，dsh 桌面/脚本产出的 spec（无 turn_ref）全数放行；登记项①虽提到 dsh 引擎超时重试的副作用，却定性低优先。**我在复核报告里提的 watcher 端 TTL（落盘超 300s 首扫即归档）恰好补这个洞**——两者不是竞争关系：interrupt 断源头、hello 锁协议、turn_ref 管同页跨轮、TTL 兜一切迟到底。f234bab3 未含 TTL，建议作为下一件补入。
3. **形式瑕疵：行号取证未注明基线 commit**。报告行号基于修复前版本，落地后全部漂移——我复核时先 grep 到 interrupt 已存在，差点误判其根因声明失实，查 git log 才还原时间线。建议以后评估报告在文首注明「取证基线 commit=<hash>」，一行成本，复核者省半小时。
