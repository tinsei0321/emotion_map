## 〇、一句话结论

**用户判断正确：根因不是「地点判断不精准」，而是 EMC 把追问「能在地图上标记吗」当成「需要已有图层的操作」，落入 C2 数据闸门报 request_upload——它从未进入「把上轮文字答案升级为点位图层」这条决策路径。缺的是意图路由 + 一个「批量项目名→点图层」工具（渲染样板/地点解析均已就绪·纯装配）。**

## 一、用户复现场景

| 轮 | 用户问 | EMC 行为 | 预期 |
|---|---|---|---|
| 1 | 宜昌市城市更新项目有哪些？ | 知识问答 → RAG 检索 → LLM 综合文字回答（55 项目/51.33 亿·葛洲坝片区 12 个·红星路-二马路街区…） | ✅ 符合预期 |
| 2 | 能在地图上标记出这些项目的位置吗？ | **无法完成**（报需上传数据 / 无图层） | 应识别项目名 → 匹配地点 → 生成点/面图层 |

## 二、根因分析（claude组 取证·请两组独立验证）

### 2.1 意图层：追问被当「全新问题」+ 路由落空

- **续作未触发**：[`_isResumeCue`](panel.js:1629) 正则 `/继续|接着|续做|补充|那个|上一个|把刚才/` **不含「标记/地图/这些」** → 用户句「能在地图上标记出这些项目的位置吗？」`ctx.resume=false`（[panel.js:1696](frontend/js/ai_qa/panel.js#L1696)）→ 当全新问题
- **_quickIntent 词表 miss**：[`_quickIntent`](harness.js:60) 的 `GEO_VERB_KW`（核密度/热力/裁出/缓冲…）**不含「标记/点位/出图」**·`RAG_QUERY_KW`（有哪些项目/体检指标…）也不含「标记这些项目」→ 返回 null → 落 diagnose LLM
- **diagnose 判定偏 gis_operation**：LLM 见「在地图上标记位置」判操作 → 模板表（SKILL_DEFS）**无「项目名→点位」技能** → 选需已有图层的工具（clip/filter_attr/density）

### 2.2 数据闸门：误选需点层工具 → request_upload

- [stages.js:362](frontend/js/ai_qa/stages.js#L362) `_NEEDS_POINT = density|hotspot|rank|zonal_stats|clip|buffer|nearest` 且 `layerMeta.has_point=false` → `strategy='request_upload'`
- 上轮知识问答**没产生任何图层** → has_point=false → 报「需上传数据」。**用户看到的是数据缺口，但真缺口是决策路径**

### 2.3 工具层：无「批量项目名→点图层」工具

- [`TOOLS`](tools.js:823) 19 工具全要求「已有图层或单点/单区名」：`extract_feature/clip/filter_attr/merge/buffer` 都在已有层上操作；`lookup_place`（tools.js:1295）单点查询**不产图层**
- 无任何工具接收「names 数组 → 逐名 search_place → 合成 point fc → 落图层」

### 2.4 数据层：项目无坐标 + 项目库未抽取

- RAG 素材 55 项目是**聚合文字口径**（`urban_renewal_knowledge.py`：「2025-2027 拟实施城市更新项目 55 个·总投资 51.33 亿元：污水厂网一体示范区 16 个/葛洲坝片区 12 个…」）——**片区分类名·非坐标点**
- 项目库原文存在（`{URENEWAL_ROOT}/1 宜昌市城市体检/3-附件/附件5-城市更新项目库.docx`）**未抽取坐标**
- `search_place`（geocode.py:188）检索**通用 POI 库**（4310 条）·拿「葛洲坝片区」这类片区名 fuzzy 匹配大概率不对

## 三、用户的核心洞察（三组须锚定）

> 1）前答含项目名（部分含详细地点）→ 通过项目名可判断地点（葛洲坝xxx老旧小区、红星路-二马路街区改造）·**即使模糊也可判断大致范围/区域**。但 EMC 无法完成的根因**不是地点判断精准度**，而是**根本没理解这个提问该怎么处理**。
> 2）这个问题直接给 deepseek 描述解答很轻松（识别地点 → 匹配地点信息 → 生成点或面图层·任意匹配一个 toolbox 内的样板图例样式）·但 EMC 里的 deepseek 却不知道怎么办。

**锚定**：用户不是在要求「精准地理编码」——而是要求 EMC **理解「把文字答案里的项目/地点升级为地图标记」这个意图**。模糊地点也应给出**大致区域/面**而非拒答。

## 四、候选解决方向（claude组 初判·请两组评估）

### 方向 A：知识问答追问 → 图层升级（意图贯通）
- 让「把上轮项目标记到地图」这类追问**识别为续作/图层升级意图**，从 knowledge_qa 的文字出口切换到图层出口
- 复用时序指代（resolveCoref「这些/刚才」→ priorTurn）+ 新意图枚举或模板

### 方向 B：新工具 generate_point_layer（批量地名→点/面图层）
- 接收「项目名/地点名列表」→ 逐名 `search_place`（geocode.py:188）解析 → 命中者合成 point fc → `addToolboxLayer`/`defaultPaint`（toolbox/shared.js:130/176）落图层
- **渲染样板 + 地点解析均已就绪·纯装配**（Explore 取证：约 30 行·镜像 lookup_place 的 HTTP 模式 × N）
- 未命中地点 → 标注「该地点未匹配到坐标·以文字显示」/ 面化（模糊区域 → 大范围面）

### 方向 C：项目库坐标抽取（数据补全）
- 从 `附件5-城市更新项目库.docx` 抽项目地址 → geocode → 建「城市更新项目点位」数据源（入 place_layer 或独立 layer）
- 与方向 B 可叠加：B 给通用地名，C 给项目专属坐标
