## 一 讨论定位与边界（先把「接入」翻译清楚）

用户问点还原：不是「把 dsh 的代码搬进 EMC」，而是——**dsh 这类 harness 之所以强的那些根本设计（精髓），哪些能转化成 EMC 的能力**。

边界三条（既有裁定·本轮不翻案）：
1. 形态3（平台化）已收敛预备：EMC 的对话路由层冻结为演示壳，对话智能归通用助手；
2. 「自研入口聪明化」三条（追问澄清/多步计划/体内代码执行）已停投；
3. dsh 处于开发者预览期（破坏性变更活跃），任何深绑都不做。

所以「接入」= **思想与机制的移植，不是运行时的合并**。

## 三 harness 精髓清单（十条·源码证据 + 白话 + EMC 落法判定）

### E1 模型可见即已记录（日志=唯一事实源）

- **源码证据**：架构文档原文「**模型可见即已记录**。抵达模型请求的一切都必须能从日志重建，并由一项运行时不变量断言」——`deriveMessages()` 从追加式会话日志投影出模型历史，回放/持久化/遥测全部派生自事件流。
- **白话**：AI 每一眼看到的东西都有存档，事后能一帧不差地重放——所以永远可以回答「你当时到底看到了什么才做的这个决定」。
- **EMC 落法：平台资产化**。不给冻结的 QA 装 session log（原 G6 已降权的正确性）；改为**工具面版**：标准插座七件工具每次调用自带完整 trace（后端追踪已有基础）+ 结果可重放——「工具可见即已记录」。验收考试（真实任务重放）由此成为可能。

### E2 能力接缝三元组（定义/实现/消费）

- **源码证据**：`capability-seams.zh.md`——一个 seam = Service Definition（声明接口）+ Provider（实现）+ Consumer（消费·通常是面向模型的工具）；「seam 正是替换一个提供方就能改变整个产品的原因」（例：文件系统指向远程沙箱，Bash/PTY/LSP 整体搬家·无需专用 fork）。
- **白话**：每项能力都定义成「插排+电器+用户」三件套，换一个供电方全屋电器照用。
- **EMC 落法：平台资产化（直接落地）**。渲染契约（render spec）就是接缝：样式令牌=定义、前端渲染器=第一实现、任何第三方渲染器=后续实现。同理标准插座工具面=EMC 能力的 Consumer 端暴露。**这条是「资产没有稳定对外接口就会被锁死」教训的机制化答案**。

### E3 一切皆插件·注册可撤销（无特权内核）

- **源码证据**：「产品的每一部分都是插件，包括模型适配器、工具注册表、会话日志以及 agent loop 本身」；注册是副作用，插件卸载即撤销。
- **白话**：房子没有承重墙内嵌设备，所有家具都是标准化卡扣安装，拔掉就走。
- **EMC 落法：不借鉴运行时形态**（底稿反对项维持：单一演示产品上运行时可替换性=过度工程）。**轻吸收其注册思想**：图层注册本（usage 标注）与工具注册表已是同族做法——登记即声明、字段可审计。

### E4 工具执行流水线（五道闸·post 四态）★本轮最强借鉴点

- **源码证据**：`tool-execution-pipeline.md` 全链——`tools/pre-execute`（钩子/权限/沙箱·waterfall）→ 单调守卫（deny/abstain·身份受保护）→ 一次性审批（缺位或无人可答=拒绝·fail-closed）→ `tools/execute`（超时/重试/指标）→ 工具体+文件系统写门 → **`tools/post-execute`（accept/block/replace/add-context 四态）** → 归一化（异常转 isError）→ `finalizeContent` 最后一道内容不变量 → 冻结的权威 `tools/result`。
- **白话**：每个工具调用要过五道关卡——进门查证件、专职保安否决、一次性放行条、执行有监理、出门再验货（验货员可以放行/拦下/改写/补注意事项）。
- **EMC 落法：本体吸收（与在途工作直接合流）**。CB-39 D1 批的「结论白名单」（治假结论 bug）按此流水线化=守卫管线：finalStep 前挂 post-execute 型守卫（四态语义照搬）——这是**输出诚实度机制而非路由智能，不踩停投边界**。平台工具面 v2 亦可加同构 post 守卫（自动附加口径标签/脱敏断言）。

### E5 轮次/步骤生命周期（欠工作的窗口）

- **源码证据**：架构文档轮次流程图——「一个**步骤**=一次模型请求+它调用的工具；一个**轮次**在领取首条输入前打开、不再欠任何工作时关闭」；inbox 唤醒、pre-step 拒绝也留持久轮次记录。
- **白话**：干活的记账单位不是「一句话」而是「一个责任窗口」——从接活到活清，中途拒绝和失败都记账。
- **EMC 落法：语义参考**。EMC 本体不引入多轮（停投不变）；但「轮次=责任窗口」是**外挂大脑遥控协议**（大脑端口契约）状态机设计的现成词典——status/stop 语义按此定义。

### E6 上下文压力管理（压缩前置+结果剪枝+溢出）

- **源码证据**：`agent-lifecycle.zh.md`——压缩组件在派生请求**之前**（pre-step）处理压力；工具结果剪枝（model-free pruner）先行、摘要兜底；恢复发生在失败步骤后、轮次结束前。
- **白话**：书包快满时先把旧笔记摘要腾地方，而不是等装不下才报错重来。
- **EMC 落法：平台侧吸收·v2**。工具面结果尺寸纪律（小工具+摘要+引用）已在深挖报告确认；**工具结果剪枝**思想留作大结果场景的 v2 机制。EMC 本体零投入。

### E7 子代理接口统一（fresh child / delegated turn 同接口）

- **源码证据**：架构文档——「subagent 提供方在同一个接口之后千差万别，从新建一个子 agent 到把一个轮次委托出去」。
- **白话**：请帮手有两种（新开一个助理/把这一轮话转给同事），但对调用方看起来是同一个按钮。
- **EMC 落法：语义参考**。多步计划引擎复活维持停投；但接口统一思想 = 外挂大脑「大脑端口」契约的验证——协议定义好后，接 dsh 还是接别的助手是提供方的事。

### E8 Profile 分层组装（干净环境的机制）

- **源码证据**：架构文档——profile=具名组装（组合包按序叠加+patch 层层覆盖）；`web`/`headless` 模板随发行版交付；`--dump-config` 可见全部条目且皆可替换。
- **白话**：同一套家具可以拼成书房版/客厅版/工地版，配置清单全透明。
- **EMC 落法：语义参考**。五项决策之「专用干净环境」的机制载体就是 dsh 的精简 profile（只挂基础包+EMC 工具）；评审朋友链路与未来实验环境时按此概念验收。

### E9 事件三域分离（持久事实/实时控制/能力策略）

- **源码证据**：架构文档「事件」节——会话事件（持久·重载仍在）/ agent 事件（实时控制）/ 能力事件（免导入循环附加策略）；「选对事件域是大多数改动的第一个决定」。
- **白话**：账本（永久）、对讲机（即时）、规章制度（谁都能挂条）分三类管理。
- **EMC 落法：平台侧吸收**。EMC 已有同构分层（trace 持久 / 前端事件 / 契约策略）；工具面日志设计沿用此纪律：调用记录=账本域、状态查询=对讲机域、脱敏口径=规则域。

### E10 防御性模式七条（实战缺陷规则库）

- **源码证据**：`defensive-patterns.zh.md`——七条全是实际发布或差点发布的缺陷教训：①正交结果独立上报 ②公共约定两侧规范化 ③异步状态≠同步状态 ④dispose 必须完全停稳 ⑤分发器隔离回调异常 ⑥**绝不把环境变量/可预测路径暴露给不可信输出**（KEY/SECRET/TOKEN/PASSWORD 清洗+私有随机临时文件）⑦链接形态路径用 unlink 删。
- **白话**：老兵的伤疤手册——每条都是真出过事的坑。
- **EMC 落法：本体吸收（即刻可用的工程纪律）**。①②③对 EMC 后端并发/LLM 适配层直接适用；⑥与密钥纪律同源且更具体（清洗清单可直接抄）；建议并入 `docs/debug-memory.md` 踩坑规则库。

| 落法 | 精髓 | 与在途工作的关系 |

| **①本体吸收**（EMC 内部机制） | E4 工具流水线→守卫管线；E10 防御模式→踩坑库 | E4=CB-39 D1 白名单的终态形态（合流不新增排期）；E10 零成本并入文档 |
| **②平台资产化**（插座/契约） | E1 工具日志+重放；E2 能力接缝→渲染契约与工具面结构；E9 事件三域→工具面日志纪律 | 全部落在既有批次内·**不加新批** |
| **③语义参考**（设计词典） | E5 轮次→遥控协议状态机；E7 子代理接口→大脑端口验证；E8 profile→干净环境验收 | 服务外挂大脑观察项与朋友链路评审·零排期 |
| **不借鉴** | E3 运行时插件形态（维持反对）；E6 本体投入（仅平台 v2）；多轮/路由类全部（停投不变） | — |
