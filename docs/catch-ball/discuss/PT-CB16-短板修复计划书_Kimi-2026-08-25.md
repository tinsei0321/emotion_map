## 白话摘要

现在的系统像一辆能开但还没过磨合期的车。这份计划修五件事：①**家里电脑也能跑**——写一套「装机说明书」，到新机器按步骤 15 分钟装好（现在是 configs 都在办公室这台机器里，换机就抓瞎）；②**机器自己当质检员**——建一套自动检查，模拟真人问一遍问题、出一张图、核对结果对不对，以后不用你人肉去撞 bug；③**AI 会追问、会请示、会看事情大小**——你说「接着上次那个」它记得住；遇到岔路口它会问你选哪条而不是闷头狂奔；大问题多查、小问题快答；④**两台显示器不串台**——地图页开两个也不乱；⑤**资料更新自动提醒重建**——你改了资料，系统自己知道该「刷新记忆」了。简单的两件（装机说明书、自动提醒）派给 Codex，复杂的三件（自动质检、追问/请示/看大小、双屏不串）我来做。

## 二、简单类任务书（Codex·两件）

### S1 · 环境配方三步走（M1-M3）

- **背景**：全部 dsh/服务配置只在 office 单机（`~/.dsh`、启动脚本、依赖版本）。home 机无法复现，规则七判此类「只在单机生效且无配方」的任务未达完成定义。规格来源：`EMC-dsh工程预期与双环境同步核心思想_Codex-2026-08-21.md` 附录二（M1/M2/M3 三行表）+ 差异适配五条。
- **M1（0.5 天）**：`docs/dsh-environment/` 建仓——profile 配方模板（emc-analysis 白名单/guard 配置）、启动脚本模板、复刻清单（占位符 `{REPO}`/`{DSH_HOME}`·禁硬编码绝对路径与用户名）。只入库不生成。
- **M2（0.5 天）**：`manifest.yml` 环境清单——dsh/Node/Python/MCP client/EMC 分支/transformers+sentence-transformers 版本（**含 PT-CB15 K7 的 transformers 5.x 兼容注记**）/RAG 模型名与索引重建命令（`HF_HUB_OFFLINE=1 py tools/rag_index.py --rebuild`）。
- **M3（1 天）**：到岗体检脚本 `check.ps1`（或 .py）——分支版本/dsh profile 在位/8000 8080 存活/RAG 索引新鲜度（复用 check_server_freshness RAG 段）/inbox 无 pending 积压/标准快分析任务试跑（可选）。**验收：双机 pass；故意破坏一项能 fail 并给修复命令。**
- **验收**：home 机按配方到岗恢复 ≤15 分钟（下次到岗实测）。

### S2 · 索引重建半自动化

- **背景**：K8 已实现「索引陈旧告警」（check_server_freshness RAG 段），但重建仍需人肉记命令。08-25 事故证明：告警不在场=重建被遗忘。
- **做法**：①`tools/rag_index.py` 增 `--rebuild-if-stale` 选项——比对知识源最新 mtime vs 索引 mtime，陈旧才重建，新鲜直接报 OK（闭包判断·复用 check_server_freshness 的扫描逻辑，抽公共函数防双份）；②`rebuild_rag.bat` 一键入口（双击=检查+按需重建）；③口径注册表第七节「四载体同步检查表」补一行指向该入口。
- **验收**：陈旧态跑→重建且索引 mtime 今日化；新鲜态跑→报 OK 不重建；两条各实测一次。

## 三、复杂类任务书（Kimi·三件）

### C1 · E2E 自动化测试骨架

- **背景**：用户五连问题（色板/契约弱/选择/追问/规模）全是人肉复测撞出——用户在替团队做集成测试。R8 纪律：验证忌与实现同构，E2E 必须走真实 HTTP/浏览器层而非函数直调。
- **做法（分层·轻量优先）**：
  1. **HTTP 级链路测试**（pytest·无浏览器）：起测试服务 → 调 zonal_stats(layer_output=True) → 断言 render_dataset_id → 调 render_spec(dataset_id) → 断言 inbox spec 生成 → 模拟 watcher 消费 → 断言 dataset 端点可取数且字段过政策白名单。覆盖「分析→投递→取数」主链；
  2. **浏览器级一条**（playwright·对齐既有 tests/browser 先例）：开 8080 → 投 spec → 断言 [dsh] 图层出现且要素数正确 → 硬刷新 → 断言无图层复活（hello 协议验证）；
  3. 黄金问题集 5 条（含「12345 诉求最多 7 个社区」）——每条断言口径文本（193/无「两个方面」）+ 图层要素数 + 顶点保真率 100%（坐标子集比对·复用今日验证脚本思路）。
- **验收**：`pytest tests/e2e/ -q` 独立可跑；门禁纳入标准批；三条回归（刷新无复活/TOP7 顶点保真/口径文本）全过。

### C2 · 交互三机制（追问/选择/规模）

- **背景**：PT-CB10 测试问题 2/4/5 + 讨论批 D1 一直未排档。三机制共用一处地基：意图卡契约。
- **做法**：先发 D1 讨论定稿（规格评审），再实施：
  1. **追问接线**：契约工具输出带 `followup_cues`（rag_query 已有雏形· CB-22f）→ 会话续问按 cue 路由不重述背景；
  2. **选择时机**：三触发（不可逆分支/两解成本差大/口径分叉）+ 频率上限（单轮 ≤1 硬选择）+ ask_user_question 白名单放宽评估；
  3. **规模 scale**：意图卡 `scale` 枚举（brief/analysis/research）+ 出口核对「问的规模 vs 走的工具链」·双保险（入口档位+模型自填核验）。
- **验收**：两轮追问实测零重述；三触发各一例实测；黄金问题集 scale 判对率 ≥80%。

### C3 · SSE 多页面串台严谨化

- **背景**：T21 扇出广播=所有页面收所有 spec（「图亮在隔壁屏幕」）；watcher pidfile 锁+迟到 TTL 已治消费端，但「哪个页面该看哪张图」仍无规则。
- **做法**：页面加载时注册订阅身份（session 级 id）→ spec 可带目标订阅（缺省=广播·兼容现状）→ 前端只消费本订阅/广播 spec；多开页面各自的 [dsh] 图层自清不互相干扰。**宽松规则同 turn_ref 先例：无身份字段一律按现状广播处理（不破坏 dsh/脚本生产者）。**
- **验收**：双开两页投递定向 spec → 仅目标页上屏；广播 spec 两页同上；回归 T21 既有行为零退化。
