## 二、逐项评估

### ① 几何分流与 main.js 导入结构一致性

**结论：agree（结构完全一致）**

**一句话证据**：range-presets.js:88-121 与 main.js:135-155 同款——`detectColorMode(fc)` → polarity 拆三子层（l2-positive/l2-neutral/l2-negative·`parentId=group.id`·`srcName` 标记）+ group·confidence 单层（orange ramp）·needsAnalysis 灰点——`addGroup`/`addLayer` 同 API；collectSources（grid-tool:81-102）认 `group:` 合并 + `l2-*/confidence` 单点层 ✓——preset 点层进工具链打通。

### ② grid「综合」归并（多无时间源）

**结论：partial（P1 缺陷·需修）**

**一句话证据**：grid-tool:229-232 `const t = deriveTimeTag(s.fc) || '综合'; if (seen.has(t)) continue; seen.add(t);`——多无时间源（12345·体检小区点·其他非 T1-T3）**都归「综合」·seen 去重后只保留第一个**——第二个及以上无时间源在下拉不可选（用户验证只测了单源场景）。

**定稿建议**：
1. **seen 去重键改 `${t}|${s.value}`**（时间+源标识·多无时间源各自可选）；
2. **label 区分**：`t === '综合' ? '综合·' + (s.srcName || s.label) : TIME_LABEL[t] || t`——下拉显示「综合·12345」「综合·小区停车」；
3. 重测双无时间源场景（加载 12345 + 小区点 → grid 源两个「综合·xx」均可选）。

### ③ detectColorMode 对 preset 点层副作用

**结论：agree（副作用合理）**

**一句话证据**：detectColorMode（import.js:626-680）三分支——polarity 列 → L2 三子层 + score 补全（scoreKey/confKey/scoreFor·0~1）·confidence 列 → L1 orange（score 归一 0~1）·**无 polarity/confidence → needsAnalysis=true 灰点**（#4a4a4a·radius 4·不进 collectSources·保留原始属性）——控件层（小区点·标准地/存在问）为参考层合理；12345 层（polarity 5 级 + score 0~1）→ L2 三子层 + 权重 ✓。

**P2 观察**：控件层有 `_value` 缺口数值（role 不判 score/confidence·故灰点）——若未来要控件层做热力（缺口强度）·需显式 role 或手动标记·当前灰点正确（设计意图）。

### ④ 遗漏（其他工具数据源）

**结论：partial（rank 受益✓·heatmap/zonal P2 观察·线面合理）**

**一句话证据**：rank-tool collectPointSources（30-36）多源全列下拉（不去重）→ 受益 ✓；buffer-tool BUFFERABLE 点线面全支持 ✓；**heatmap-tool collectSources/resolveSource（428-445）按 level 取首个同 level 源**——多无时间源（同 L2）时热力图只用第一个（P2：heatmap 设计为 level 驱动·需源选择或标注「当前仅首个」）；zonal-tool 源列表未在本次核验范围（若复用 collectSources 只收情绪层·控件层 zonal 需走后端 API·P2 观察）；线/面层 preset 照旧（collectSources 只收 point·面层作 range 用途）✓。

**P2 建议**：
1. heatmap 多同 level 源时加源下拉（或标注「当前仅首个 L2 源」）；
2. zonal 工具源列表确认（控件层缺口值聚合是否需支持——若需·zonal 源放宽 kind 过滤）。
