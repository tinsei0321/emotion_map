## 二 方案（推荐 A）

### A · 本地色带编辑器（推荐）

settings.js 对 `paint.gridField` 层（覆盖**注入 choropleth + Toolbox zonal/area_stats/overlay 产物层**——同语义统一）：

1. **色带选择器**：复用 grid dialog 的 `hm-ramp-item` 渐变条按钮 + 分组结构（同 DOM/CSS 类=设计语言零分叉·零新 token）；
2. **反向 toggle**：与 grid dialog 同款交互；
3. **零值显隐 toggle**：就地翻转 zeroIsNoData（无数据格显/隐）；
4. 保留既有：面开关/线宽/线型/填充透明度；
5. **应用路径**：`normStops(key)`（导出复用）重算 gridStops → `setLayerPaint` + `renderLayer` → 图例自动跟随（B3-3 已挂 gridStops）——即时生效；
6. **契约更新**：§七-7 改「**色带/反向/透明度/线样式=本地可调**（数值已随层内嵌）；**数据/字段/归一化变更才需重投递**」。

**为什么不选 B（换色仍走重投递）**：dsh 每换一版色带要一次完整 MCP 调用+落盘+SSE 往返（秒级+多一跳），且 dsh 不在循环里时用户自己根本调不了——B 是「能力在服务端」，A 是「能力在手上」。

### 主手增值建议（用户邀·三条）

1. **样式偏好记忆**：用户手选的色带按层类型存 localStorage——下次同类型层默认沿用（「受管默认值」思想：调一次，以后不用想）。
2. **图例双入口**：点图例上的色带条也弹同一选择器（Kepler.gl 交互先例——图例即样式入口·手指到哪入口在哪）。
3. **MCP 偏好回写（v2·可不做）**：本地手选后，宿主下次投递的 ramp_hint 与用户偏好一致性——属锦上添花，不阻塞本轮。
