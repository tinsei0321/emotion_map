## 〇、通俗版摘要（给用户·三分钟）

1. **发生了什么**：最近三天的开发踩了两族坑——① 地图本身的（数据丢点、颜色方向反、悬停信息张冠李戴）；② 把情绪地图接进 dsh 工作台时的（插件被包管理器修剪、启动方式崩终端、画面投递抽风、就绪误判、跨机装环境三重受阻）。
2. **原来的问题**：这些坑散在十几份排查报告、交接卡、任务记录里。人换会话/换机器后要靠回忆找，同一个坑换个人还会再踩一遍。
3. **这次做了什么**：全部收进专门文件「全局调试记忆」，每条坑改写成**规则 + 案例 + 违反后果 + 交付前自查动作**四件套（现 R1-R19 共 19 条）；修掉了库里的编号撞号；补录了今天最新的 3 条坑；写明维护机制（什么情况必须记、记成什么样算合格、怎么防烂、怎么通知各组）；在全局工作方式里加了「调试资产化」习惯。
4. **业界的做法**：Google 的无责复盘、亚马逊的纠错报告、航空业的经验库——共同点是**不追责、只追根因、必须留下可执行动作**。我们等于把其中最有效的部分本土化了。
5. **各组要做什么**：阅读本报告 → 按四档（吸收 / 并入排期 / 暂缓 / 反对）给裁决 → 落回应文档。这是项目规矩，不回应不收敛。

## 三、归纳：六条元模式（Meta-pattern）

> 单个坑会过时，模式不会。以下六条是从 19 条规则里提炼的「坑的生成机制」，新坑出现时先对号入座再动手。

### M1 · 服务端绿 ≠ 客户端绿——验收到最终用户面

- **证据**：R13（服务 200、页面只剩「Failed to load plugins」）/ R14（bundle 200、DOM 是黑的）/ R15（服务端 200、按钮点击无感）。
- **机制**：寄生开发链路长（构建→登记→注入→浏览器），每一层都可能静默断，而服务端证据只覆盖最浅一层。
- **动作**：交付验收的最低标准 = **浏览器 DOM 实证**（无头快照或真人目验）；服务端日志全绿只算必要条件。

### M2 · 宿主隐式契约必须显式登记——寄生开发的税

- **证据**：R13（patch.yml 引用≠package.json 登记）/ R14（workspaceManifest 清单 / inject 服务声明 / build:web 产物）/ R15（openPath 被 monkey-patch）/ R16（控制台归属）。
- **机制**：宿主（dsh/cordis/pnpm/Windows）有自己的默认行为，寄生方不声明就踩雷；且报错被吞或极模糊。
- **动作**：动 dsh 侧任何东西前过「宿主契约自查段」（见 §六 T1）；新插件四查：登记了吗 / 导出 inject 了吗 / build 了吗 / 从哪种窗口起的。

### M3 · 静默失败是头号敌人——一切失败必须显式可见

- **证据**：R2（isin 空值静默丢行）/ R4（无字段静默兜底 0.5）/ R17（opaque 探测误判就绪）/ R15（console 静默 catch）。
- **机制**：静默失败不报错、不留下痕迹，下游统计/渲染/结论全错且无从归因——比崩溃更危险。
- **动作**：写过滤/兜底/探测时强制三问：空值去哪了？缺字段显示什么？这个「成功」真的验证了什么？

### M4 · 生命周期错配——状态挂错位置

- **证据**：R7（旧进程载旧码）/ R15（探测状态无自愈滞留禁用）/ R16（后台起的 web 被终端功能崩掉）/ R18（每次拉起重复加载模型）/ R12③（重启后 _seen 清零全量重放）。
- **机制**：「谁拥有这个状态/这份资产、活多久」没想清楚——进程级资产挂到请求级、会话级状态挂到模块级、控制台依赖挂到后台任务。
- **动作**：新增状态/资产时声明生命周期（进程级？会话级？一次性？）；「修了还错」先查进程重启了没；「偶发慢」先查冷热路径。

### M5 · 投递通道必须幂等——重放/积压/争用三连

- **证据**：R12（SSE 断线重放 backlog 无去重 / inbox 积压 15 个历史 spec / 单队列被一页独占——T21 扇出根治）。
- **机制**：长连接+重连+收件箱的组合天然会重放；不去重就「图层循环跳动」，不清箱就「历史僵尸复活」。
- **动作**：新投递通道设计三问（服务器线程模型？重连重放去重键？inbox 清理责任方与归档时机？）；演示前无头采样图层数恒定。

### M6 · 症状迁移与语义层根治——别在错误的层空转

- **证据**：R3（上层修复显影下层 bug）/ R10（入口×错误语义的乘积——修一个入口症状，主干还在）/ CB-23 加 reverse 开关没修语义反复发作。
- **机制**：每个症状=「入口 × 错误语义」的乘积；只修当前入口的症状，其他入口迟早复发。
- **动作**：修完必问「还有哪些入口/模式/字段组合走同一个错误语义」；复发 ≥2 次强制画入口×语义矩阵找主干（5 Whys 到机制层）。

## 四、业界一般怎么做（对照与本土化）

| 业界做法 | 核心思想 | 我们的对应 | 差距与动作 |
|---|---|---|---|
| **Google SRE 无责复盘**（blameless postmortem） | 事故后聚焦流程与系统不追个人，产出结构化复盘（影响/根因/触发/教训/行动项），且「写下来的事故才有价值」 | CB 排查三件套（发起/排查/定稿）+ debug-memory 规则 | 我们多了「规则蒸馏四件套」这一层（比 postmortem 更进一步：从事件到可执行规则）。保持 |
| **Amazon COE 纠错报告** + **Toyota 5 Whys / A3** | 连问五次为什么到机制层；纠错必须落到「什么流程让它发生、什么改变防它再发生」 | R10（修症状层没修语义层）+ R3（分层排查） | 已内化。复发 ≥2 强制走 5 Whys 到语义层，不停在表象 |
| **清单革命**（Gawande checklist）+ **pre-mortem**（Gary Klein） | 高危操作前用清单对抗遗忘；开工前先想象失败倒推预防 | 交付前 R1/R2/R8 自查；R12 演示前三问；§六 T1 宿主契约自查段 | 清单散在各规则里——T1 把 dsh 批次的合并成任务书固定段 |
| **Bug→回归测试**（"fix it twice"：修一次+防复发一次） | 修 bug 只完成一半，另一半是让它永远不能再悄悄回来 | buglog `_regression.md` 手动复验清单 + 门禁回归测试 | 诚实定位正确（语义预期不强行自动化=防虚假绿）；关键坑优先补可执行回归（如 T21 扇出测试先例） |
| **经验教训库**（NASA lessons learned / 航空 ASRS） | 结构化经验库+强制引用；最大风险是 knowledge decay（只进不出变垃圾场） | debug-memory 规则库 + 编号引用纪律（debug-memory R2） | 新增：维护协议 §6 除草（失效规则标 retired 留档）+ 编号守护（T4 脚本化） |
| **Runbook 化** | 易错的手工序列写成标准操作卡 | start.bat / start_silent.vbs / 「merge→pnpm install→build 三连」 | 收进任务书与交接卡的「标准动作」段，不靠口头传承 |
| **预演/混沌** | 演示前真实跑一遍故障面 | 演示前无头采样（图层数恒定）+ 冷启动预热确认 | 收进 T3「演示前 5 分钟 runbook」 |

**共同内核**（也是本报告的立场）：**不追责、只追根因、必须留下可执行动作、写进会被下一次开工读到的位置。** debug log 只有满足最后一条才算资产，否则是腐烂中的流水账。

## 五、持续更新机制（资产化飞轮）

> 已固化进 `docs/debug-memory.md` 文末「维护协议」，此处为摘要。三层载体分工：

```
事件发生 ──► cb-journal / EMC-dsh 台账（按轮流水·过程可溯）
              │
              ├─► tests/buglog/（按 bug 台账·AI-QA 功能 bug·索引脚本自动算·repro_count 触发趋势）
              │
              └─► docs/debug-memory.md（按规则蒸馏·含基建/环境/宿主坑·四件套质量门槛）
                        │
                        ├─► 新会话排查前必读（护栏前置）
                        ├─► 交付前对照自查（R1/R2/R8 + 专项）
                        └─► /garden 季度除草（retired 标记·防腐烂）
```

1. **强制蒸馏触发器**：修 ≥2 轮 / 症状迁移 / 同族复发 / 宿主契约坑 / 取证破案——任一命中，**当轮**新增规则。
2. **四件套门槛**：规则（动作语言）/ 案例（可溯编号）/ 违反后果 / 检查动作。缺一不成条。
3. **编号纪律**：R+ 连续唯一不跳号不撞号；引用带库名（debug-memory R2，区别于前端 R 系列规则）。
4. **通知**：新规则/沉淀报告 → `_cb-index.md` 登记 → 全组当轮四档回应（吸收/并入排期/暂缓/反对）。
5. **本次已同步落点**：全局用户级 AGENTS（跨项目「调试资产化」习惯第 6 条）/ 项目 AGENTS（知识源表+排查纪律更新到 R1-R19）/ context-map 登记 / 交接卡指针修正。
