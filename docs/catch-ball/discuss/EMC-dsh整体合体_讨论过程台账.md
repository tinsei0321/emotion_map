## R2（2026-08-17·用户↔zcode）拍板前澄清：方案B 对现状的提升与核心改变

**用户问题**：如果按方案B，对我目前有哪些提升，核心改变在哪？

**zcode 回答要点**（全文见当轮会话·此处为台账版）：

1. **三层提升**：
   - **工作流调用质量**（立即可感）：agent 调情绪地图能力从「读代码猜参数+bash 裸调+报错重试」变为「function calling+schema 前置校验+dataset_id 枚举」——CB 出图主线/数据治理任务往返减少；同时三类风险机制化（脱敏输出过滤/sim 白名单/路径沙箱）——注意现状里 agent bash 调用的 stdout 原样进 LLM 上下文，铁律 7 目前并不约束这条野生通道。
   - **真正的新能力**：rag_query（235 条索引首次进入任意 agent 会话·目前只服务 EMC 前端）/ outlet_card 对话级出口（与 G1 文件级呼应）/ kb_facts 权威事实源（CB-29 口径漂移类问题的部分解药）。

## R3（2026-08-17·用户↔zcode）讨论核心点纠偏：真痛点 = EMC 入口聪明度不足

**用户澄清**（讨论错位声明）：EMC 最大痛点 = 自然语言→分析方法+工具调用+结果产出的路径不够"聪明"——LLM 接入效果未充分发挥，靠提示词/字典驱动预制分析路径；稳定有了但 LLM 灵活性被大大弱化；核心=意图判断不够准/不够灵活→选不中正确方法+工具组合；困境持续很久，一直"拆东墙补西墙"修不完，没发挥 agent 优势。

**zcode 机理分析**（全文见当轮会话）：

1. **四层叠加机理**：① 开放问题空间 vs 封闭意图分类法（`paradigm.py` 尺度→方法映射 + `harness.js:57` 轻量预判词表 geo 动词/宜昌地名/宁落不误断）——结构性覆盖缺口，有限字典索引无限空间，修补数学上不收敛；② 单发诊断不可恢复——diagnose 一次 FC 定终身，失败全走降级（`harness.js:185` 起 degraded 出口串）不澄清不追问；③ 参数闭卷填空——CB-08 实测选型 12/12 全对、瓶颈在参数填充（buffer.center/overlay.layer_a,b），LLM 看不见数据资产清单；④ eval 失真（CB-01 C6 空 context）——补丁过当轮用例、长尾回归、下轮再补。
2. **精化用户诊断**：非"单次选型精度"问题（覆盖内 100%），是覆盖面+单发不可恢复+参数闭卷+eval 失真的叠加体感。
3. **核心 reframe**：痛不在内核错，在内核承诺的"Smart 入口"未兑现足额——入口只给 LLM 一发子弹（不能追问/不能看数据定参/不能产多步计划·CPD 空骨架）。**灵活性归还位置=入口端，非中间开放**（B001/B003 是中间变聪明的病）。三个机制：迭代诊断（1-2 轮澄清）/ 参数接地（数据图层清单实时喂诊断端）/ 计划生成（plans 契约·G9 delegated turn）+ G6 session log（eval 反 Whac-A-Mole）。
4. **诚实校准**：① "彻底解决"不存在——开放 loop 只是把路由错误换成过程漂移（B001 极端形态），dsh 也靠 guards 兜底；能收敛的是把结构缺失补成机制，不是换脑子；② 无需动架构骨架——四机制全长在内核允许位置。
5. **拍板语境更新**：用户真痛在 EMC 体内聪明度 → 方案A（换运行时）与方案B/G10（工作流侧门）都不治此痛（R2 边界①升为主矛盾）；**对症排序 = G6 → 参数接地 → 迭代诊断 → G9，G10 退居侧门**。
6. **建议（待用户指令）**：将「聪明路径」（入口端三机制+G6）作为新议题交三组讨论——比 A/B 裁决更接近真问题。

**状态**：讨论焦点已从"寄生方式"转向"入口聪明度"；D1-D4 拍板仍悬置（D1 结论更稳固，D2/G10 权重下降）；「聪明路径」议题开轮与否待用户指示。**R3 讨论稿已单独落盘**：`EMC-聪明路径_入口端灵活性_讨论稿_zcode-2026-08-17.md`（四机制 M1-M4+决策点 E1-E3·含红线兼容性分析——M2 走 schema 侧不走 prompt 侧）。

## R4（2026-08-17 晚·用户↔zcode）天然对照实验：通用 harness vs EMC 的空间操作能力

**用户问题**：用 claude/codex/zcode/dsh 喂线面数据做合并/剪裁等操作，不告诉剪裁逻辑、不做 GIS 工具调优，它们能迅速准确完成；EMC 调优多次仍常出错。同样是"用 GIS 工具"，差别在哪？为什么它们不用调优？

**zcode 分析**（全文见当轮会话）：

1. **核心答案：调优没有消失，而是发生了三次转移**——①**前移到预训练**：通用 agent 根本没用"GIS 工具"，用的是代码（通用底座）+ geopandas/shapely（公共库知识·训练分布内见过海量样本）；EMC 的 19 契约是**私有 API**，模型零先验，全靠 prompt/字典现场教——「你每调优一次 EMC 学到一条映射；通用 agent 的教材是整个 GitHub，这场词典竞赛 EMC 数学上赢不了」。②**内置到会话循环**：通用 agent 跑-看-改（读真实数据→写代码→执行→检查结果→修正），多次内部迭代，用户只看到最后一次成功——"不调优就完成"是错觉，**调优发生了，只是不可见**；EMC 单发闭卷，第一次尝试直接呈现给用户，试错责任外包给用户。③**外置给用户**：EMC 剩余不适配全落到用户身上（字典/映射/CB 轮）。
2. **三个结构差**：工具空间（无限=代码生成 vs 有限=19 契约分类选择）；反馈回路（执行后可自检自纠 vs 无执行反馈）；接地方式（先读真实数据列名/CRS/几何再操作 vs 闭卷填参）。
3. **公平性 caveat（诚实）**：用户测试任务（合并/剪裁）恰是通用范式最强的类型——明确、可客观验证、训练分布内；EMC 的叙事分析类任务（颗粒度/结论/行业对接）是私有域分布外。但 EMC 也必须服务空间操作类，故 caveat 不推翻结论。
4. **关键区分（对 B001/B003 的再认识）**：可验证操作（结果客观可查：面积/行数/几何有效性）vs 叙事分析（结论不可客观验证）。B001/B003 的病在叙事类的开放循环，不在可验证操作类。**"稳定 vs 灵活"的成熟形态不是一刀切 dumb 中间，而是按任务类路由**。
5. **对 R3 立场的修正（诚实声明）**：R3"灵活性归还入口端"不够——还需要第五机制候选 **M5 有界代码执行通道**：可验证空间操作类走「LLM 写 geopandas 片段→白名单数据集→沙箱执行→结果校验（几何有效性/面积/行数）→有界重试（2-3 次）→通过确定性渲染契约呈现」；叙事分析类仍走契约路径。这正是 G7 守卫管线+G6 日志的对口场景。风险与边界：沙箱安全/成本延迟/渲染确定性/迭代上限。
6. **与方案B 的对称性观察**：方案B（MCP）是把 EMC 能力导出到"能工作的范式"（通用循环）；M5 是把"能工作的范式"导入 EMC（限可验证操作类）——同一枚硬币的两面。

**状态**：R4=对 E1-E3 议程的重要输入——建议聪明路径机制清单从 M1-M4 扩为 M1-M5（下轮讨论稿更新时并入·本稿不改 R3 讨论稿以保持轮次清晰）；待用户拍板项新增：是否将 M5 纳入三组议题。

## R5（2026-08-17 晚·用户↔zcode）存在之问：dsh 比 EMC 做得好，那做 EMC 的意义是什么？
