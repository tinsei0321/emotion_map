## 0. 新会话任务框定

**一句话任务**：在“整体寄生已否决、形态3 平台化已达收敛预备、外挂大脑已收敛为实验保留”的基础上，进一步评估三条可行路线的真实落地条件、风险与证伪实验；只讨论与取证，不实施。

**必须守住的事实边界**：

1. **方案A（EMC 整体搬进 dsh）已被三组一致否决**，除非出现新的源码级事实，不重开。
2. **形态3（平台化）是当前主推荐**：EMC 沉淀数据/口径/知识/渲染/出口资产，通用 harness 经 MCP 消费；NL 路由层停止自研演进，冻结为参赛演示壳。
3. **外挂大脑链路是薄壳 B 变体**：不是产品主干，当前定位为实验保留；A 变体（单轮 FC 直连工具）先行。
4. **G8/G10 是主路前置**：没有契约派生与 EMC MCP 工具面，dsh 无 EMC 活可干。
5. **dsh 价值在协议消费与可遥控大脑，不在整体寄生**：dsh 原生支持 MCP；同时 preview/breaking 风险是核心约束。

## 2. R0-R9 讨论过程提取

### 前置：为什么会有这个专题

用户最初提出：让 EMC 也用 harness + LLM + plugin 形式运作，模仿 dsh 重构，是否会更聪明。zcode 底稿结论是：**EMC 已是领域定制 harness**，真正值得借鉴的是 G6-G9（session log、守卫管线、契约派生、条件性 CPD），不是换框架。

### R0：整体合体设想拆成 A/B

- 用户设想：把 EMC 整个项目（项目+数据+功能模块）作为扩展寄生进 dsh，直接使用 dsh 的开放对话、工作流、通用/GIS 工具调用。
- zcode 拆解：
  - **方案A = 运行时级寄生**：EMC 搬家，dsh loop 替换 EMC 编排。
  - **方案B = 协议级寄生**：EMC 不搬家，把稳定能力暴露成 MCP 工具面，任意 harness 消费。
- 关键洞察：用户想要的是“通用 harness 能力”，但已经拥有 zcode/Claude Code/Codex 三份；EMC 独有价值是领域栈，不是再造 harness。

### R1：三组一致否决 A、支持 B/G10

| 决策 | 三组结论 | 关键增量 |
|---|---|---|
| D1 方案A | 否决 | claude：红线载体湮灭、演示逻辑链断两环；Codex：CB 流程冻结、双运行时对冲；dsh组：breaking 周级实锤 |
| D2 方案B | 立项 + spike | 体外零耦合、可证伪；Codex 将量级修正为 G8 合流后 <1d |
| D3 载体 | MCP server 唯一解 | dsh 原生 MCP 客户端，工具命名与 Claude/Codex 同形 |
| D4 dsh组 | 回归本轮 | dsh 技术事实必须由母框架侧供给 |

**R1 工程要点**：

- v1 七工具：`rag_query`、`kb_facts`、`list_data`、`outlet_card`、`zonal_stats`、`buffer`、`rank`。
- `run_analysis` 降为 v2：长任务阻塞与攻击面尚需处理。
- 工具参数不收裸路径，只用 `dataset_id` 枚举。
- sim/gdb/PII/审批等纪律必须在 MCP server 侧做绝，不能依赖各宿主配置。
- `contracts_to_tools_schema()` 已存在，MCP schema 适配是“剥壳级”，不是重写。

### R2：方案B 提升的是可达性与安全性，不提升 EMC 智商

- 提升：function calling + schema 校验 + dataset_id 枚举；RAG/outlet card/KB 进入任意 agent 会话；四 harness 即插即用。
- 诚实边界：EMC 产品本身的四痛点（知识库薄、参数填充、假结论、多步链弱）不由 G10 解决。

### R3：用户纠偏，真痛点是入口聪明度

四层机理：

1. 开放问题空间 vs 封闭意图分类法；
2. 单发诊断不可恢复；
3. 参数闭卷填空；
4. eval 失真。

当时提出 M1-M4：迭代诊断、参数接地、计划生成、eval 重放。后续形态3 裁定后，M 系去向被重排：M2/M4 存活变身，M1/M3/体内 M5 停投。

### R4：通用 harness 为什么“不调优也会”

核心答案：调优没有消失，而是发生三次转移——前移到预训练、内置到会话循环、外置给用户。通用 harness 用代码 + geopandas 公共库知识，并有执行-检查-修正循环；EMC 是私有契约 + 闭卷单发。

关键区分：

- **可验证操作**：面积、行数、几何有效性可客观检查，适合通用 harness / 体外执行。
- **叙事分析**：口径、范式、行业结论不可仅靠代码验证，必须靠 EMC 平台资产与宪法约束。

### R5：EMC 的意义 = 沉淀资产，不是会话智能

EMC 四层拆解：

1. NL 路由壳：被通用范式支配，继续自研不划算；
2. 数据与口径资产：一次治理、长期复用；
3. 知识与范式资产：RAG、行业知识、尺度-方法映射；
4. 产品形态资产：地图、样式、演示逻辑链、视野-数据-结论同步。

dsh 会话智能用完蒸发；EMC 治理、trace、口径与资产可复利。

### R6：用户倾向形态3

用户判断：

- EMC 积累的地图、图例样式、专业知识库、宜昌基础信息、交互逻辑是长期财产；
- 深挖意图判断/agent-loop 是死路；
- “如何跑起来的路由”不是个人开发者应做的事；
- LLM/harness 用通用版本，在通用基础上搭自己的架子。

zcode 同意并给出五个实施含义：入口空窗、渲染 API、现行 CB 线转平台资产、正道好走、M 系沉没/变形。

### R7：落盘纪要并邀三组终审

明确“不急 plan、先讨论”。产出 R0-R6 纪要，并邀请 claude/Codex 联合评审，dsh 另发五问专项。

### R8：形态3 三组评审收敛

**E4 结论：形态3 成立，附三前置。**

1. **范式显式迁移（C11）**：工具 description 拆 `when/limits/output`；`caliber_ref` 可追溯；平台 eval 加范式回归。
2. **参赛演示用 QA 冻结壳**：冻结的是 QA 主链路新能力，不是仓库级 freeze；演示阻断 bug 可修。
3. **冻结≠放烂**：B002/B004 等 CRIT 修复优先级上升。

**七议题收敛**：

| 议题 | 结论 |
|---|---|
| E4 | 形态3 成立；形态2 被吸收，不是并行演进 |
| 渲染 API | render spec 三步：契约化 0.5d、前端 loader 1d、MCP 工具 0.5d；JS 保持令牌解析权威 |
| 产品入口 | 演示期 QA 冻结；赛后自建薄壳 A；长期入口可替换 |
| 工具面 | v1 七工具；`render_spec` 第二波；dataset_id 白名单由三源派生 |
| 迁移顺序 | CB-39 B/C 照旧；G8a 可即行；G8b 等 B1 `usage`；G10 随后 |
| 治理 | C1-C11 平台宪法 + “正道好走”五判据 |
| 沉没清单 | M1/M3/体内 M5 停投；M2 变身三消费端管道；G6 转平台 eval |

**平台宪法核心**：

- C8：MCP schema 一律从 `tool_contracts` 派生，禁手写第二份；
- C9：工具面版本化与 deprecation；
- C10：平台 eval CI 化；
- C11：范式编码义务，工具不得退化为裸函数；
- 数据敏感级 T0-T3：公开底座 / 治理产物 / 受控原始 / 演示模拟。

### R9：外挂大脑链路

朋友思路：Codex 经 MCP 遥控 dsh，dsh 作为薄壳的大脑；EMC 薄壳不造 loop。

三组修正后收敛：

- **D1 双定位成立**：用户工作流工具即刻可用；薄壳 B 变体实验保留。
- **B 变体转正五条件**：A 稳定、dsh 脱 preview 或 breaking 降频、自由任务需求实测出现、大脑端口契约完成、一次真实任务验收通过。
- **D2 剩一问**：朋友成品是否存在；存在则评审，不存在则 dsh组 以 ACP 为底新写 demo（1-2d 级）。
- **D3 独立小轮**：不搅动 E4 主拍板。

dsh 侧技术事实：

- ACP 提供 `session/new|prompt|cancel|update|request_permission`；
- headless 不挂 Host/HTTP/Web/浏览器，不开监听端口；
- API Gateway `@Remote` 面存在；
- ACP `session/new` 拒绝非空 `mcpServers`，EMC G10 工具须挂 dsh profile 全局 MCP 配置；
- ACP 自带 `request_permission`，审批策略可放 EMC 侧桥客户端；
- 会话复用需 `sessions.create(seed)` + `followup()` 自组，非从零重写。

**C12 控制面十条**：实例生命周期、send 全审计、模式白名单与确认令牌、插件最小权限人审、数据面必须走 G10、降级显式、密钥日志纪律、审批语义、溯源标注、数据回流对偶。

## 4. 可行性深挖议程（新会话主问题）

### A. 形态3 是否真能创造增量？

需要回答：

1. 同一真实 CB 任务下，MCP 工具调用是否显著优于 bash 考古？
2. 摩擦差如何量化：轮次、耗时、参数错误率、路径错误、上下文占用、结果口径可追溯性？
3. v1 七工具是否足以完成一条端到端任务？缺哪类工具会逼宿主绕回 bash？
4. 工具 description 的 `when/limits/output` 能否防止宿主误用范式与颗粒度？

建议实验：选一条近期真实出图/空间统计任务，分别做 bash 路径和假想 MCP 路径的纸面/接口级走查；记录每个卡点属于 schema、工具缺失、口径、审批还是渲染。

### B. G8/G10 契约链是否足够稳？

需要回答：

1. G8a 静态派生能否零风险即行？具体覆盖 prompts、GEO_TOOL_CATALOG、SKILL_DEFS 哪些面？
2. G8b 动态 enum 强依赖 B1 `usage` 字段，最小字段语义是否已明确？
3. dataset_id 白名单三源（geo_registry、presets、analysis 总账）如何合成单一视图？
4. MCP inputSchema/outputSchema 的最小公共词汇是否够用？

### C. 渲染 API 是否真能解锁地图资产？

需要回答：

1. 现有 layer 对象是否已经等价于 render spec，还是需要语义重命名？
2. “语义令牌 + 解析副本双载”如何避免 computeStyle 双源漂移？
3. `resolved_by` 标注能否支持无 JS 消费者降级？
4. v1 只管呈现、不进交互，边界是否会挡住真实演示任务？

建议实验：选热力、缓冲、分区统计三类代表图层，手工抽出 render spec，检验 JS 渲染器与外部消费者能否理解；先确认字段语义与缺失项，不写代码。

### D. 薄壳 A 是否能避免“重建 mini harness”？

需要回答：

1. 单轮 FC + 显式续问是否能覆盖规划师高频任务？
2. UI 上哪些任务应做成按钮/模板，哪些进入对话流？
3. “A 是按钮不是路由”是否可机器化检查？
4. 降级与失败回执如何设计，才不造成假成功？

### E. 外挂大脑 B 变体是否值得继续？

需要回答：

1. 朋友成品是否存在？若存在，代码、权限、审计、七守卫是否可审？
2. ACP 路线是否确实优于 Web Host 插件和 HTTP Gateway？
3. profile 全局 MCP 配置是否会带来工具泄漏/权限扩散？
4. `request_permission` 自动应答策略如何配置才符合 C12-⑩？
