## 白话摘要

两个 bug 查清楚了，一句话各概括：

**Bug 1（口径说错）**：AI 说「130 个社区、两个方面」，不是它记错了，是**家里的几本账没对上**——您今天在 DATA 整理里改了 RAG 知识库的口径，但另外两个 AI 必查的「账本」没同步改：一是 RAG 的索引文件还停在 8 月 20 日（您今天的整理根本没被索引进去）；二是图层注册表（list_data 数据说明书）里，130 社区那层还赫然写着「西陵+伍家岗（130社区）」，page7 三层的名字里直接写着「两方面合计」，两类点层（安全韧性/民生基础）也还在册。AI 查了旧账本，自然说旧话。**不是 RAG 没吸收，是同一个真相散在四个地方，只更新了一个。**

**Bug 2（边界像随手画的）**：先说一个好消息——**AI 没有瞎编坐标**。我把图纸上 7 个社区的所有顶点和权威源逐坐标比对，命中率 100%，每个顶点都是真坐标。坏消息是：源数据里这些社区有 66~1066 个顶点，图纸上只剩 4~19 个。原因像「让你把一整页乐谱听一遍后默写出来」——分析工具算出的精细边界（约 2000 多个坐标点、近百 KB）要先经过 AI 的「脑子」（上下文）再抄给出图工具，AI 抄不下那么多，就只挑了十几个有代表性的点抄。位置都对，形状就糙了。**这是链路设计缺陷：大宗几何数据不该让 AI 用脑子转运，应该像快递一样贴个单号直接取件。**

### 1.2 坐标级比对（Bug 2 定案）

spec 7 社区顶点 vs 权威源（`DATA/REGISTRY/presets/体检对象_西陵+伍家岗.geojson`·130 层·名称字段=`社区`）：

**三个推论**：
1. 顶点 100% 是源顶点子集 → **几何来自权威源，非模型编造**（排除了「幻觉出图」这个最坏假设）；
2. 抽稀率 1.2%~7.6%（源 66~1066 → 剩 4~19）→ 几何被严重有损压缩；
3. **不是服务端简化器干的**：`_layer_output_geojson`（`tools/mcp_server_emc.py:324-367`）只在序列化 >200KB 时才启动逐级 simplify；7 社区源顶点合计约 2297 个、序列化约 90-100KB，**低于触发线**，且该函数若跑过，输出会完整走 MCP 返回——而 spec 只有 5.4KB。压缩发生在**模型上下文转录环节**：模型收到近百 KB 的 layer_output 后，无法原样转录进 render_spec 的 geojson 参数，只挑抄了少量代表性顶点。

## 二、根因定性

### Bug 1 · 口径陈旧 = 「单一口径真相的多载体分裂」

> 同一个口径真相散落在四个载体：RAG 知识源文档 / RAG 索引 / manifest 注册表（label+note）/ 点层注册（geo_registry）。今天的 DATA 整理只更新了第一类，其余三类照旧。模型消费的是二三四（list_data 必读 + 旧索引），表现为「RAG 没有吸收」。

机制性缺口：
- **索引重建纪律未执行**：核心思想 v1.1 写明「RAG 源哈希变化时触发重建提示」——DATA 重组这么大的变动没有触发重建（索引仍 08-20）。无自动提醒机制；
- **注册表叙事无人认领**：manifest 的 label/note 是「模型可见的口径文本」，但没有纳入「口径更新」的同步清单——口径注册表改了，manifest label 没改；
- **边界选择无默认指引**：12345 社区级分析该用 193 还是 130，没有写进任何模型可读的契约（方法论契约/list_data 推荐位），模型凭旧知识选了 130。

### Bug 2 · 边界粗糙 = 「大宗几何经 LLM 上下文转录」的结构性缺陷

> render_spec 内联档要求几何数据穿过模型上下文两次（工具输出读入 → 工具参数写出）。LLM 对近百 KB 的坐标 JSON 必然做有损压缩——这不是模型犯错，是任何 LLM 的物理限制。**链路设计上就不该让几何过脑子。**

既有机制其实已经有答案：render-contract §三「③脚本+注册」档和 render_file 的临时 dataset 自动登记（TMP_RENDER_GROUP）都是「几何服务端直传、模型只传单号」——但 zonal_stats/rank 的 layer_output 仍把 geojson 塞进 MCP 返回值让模型手抄，相当于快递柜建好了，却还让客人手搬。

## 四、附带发现（登记不展开）

1. `_layer_output_geojson` docstring（顶点>100 才简化）与实现（>200KB 才简化）不符——文档漂移，随 R1-1 顺手修；
