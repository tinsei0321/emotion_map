## 二 逐焦点（F1-F5）

### F1 定位：双定位是否成立；B 变体是否进排期

**双定位成立**——①「用户工作流工具」今天就能用（零 EMC 改动·CB 出图主线即时增强）；②「薄壳 B 变体」消费 G10（无 G10 则空转·排期依附成立）。

**B 变体进排期=条件转正，附两个前提**：
- **前提一（架构）=「大脑端口」契约化**：EMC 侧定义自己的控制面协议（四动词+事件流+状态对象），dsh 插件是该协议的第一个**驱动/适配器**。收益：(a) dsh breaking 被隔离在适配器层（驱动可换——未来任何能暴露同等控制面的 harness/CLI 都可接入，朋友的「Codex 指挥各 CLI」实践恰好证明了这套动词对多大脑通用）；(b) 与「入口可替换」原则同构；(c) 成本≈0（契约本来就要定义，不比写死 dsh 贵）。**B 变体的依赖从「dsh 稳定」降为「协议稳定（我们自己的契约）」。**
- **前提二（时序）=A 先 B 后、B 骑在 A 上**：A 变体（2d 薄壳·单轮直连工具）是产品基线，B 是 A 之上的**可选增强**（断了不瘫——Codex 风险 1 对策的延伸）。转正条件=第 0 步证实 + A 稳定运行 + 一次真实任务验收（建议验收口径沿用 R1 的「同一任务 bash 考古 vs 工具调用」对比法的外挂版：同一自由任务·B 通道 vs 手开 dsh 对比）。

### F2 实现（dsh组 主答·zcode 补一个被忽略的第四前提）

- **插件由谁写**：优先序=①朋友成品拿来评审（若存在——最快且经实战）→ ②dsh组 新写+人工评审（**不建议「创造模式自写」作为交付路径**：AI 起草可以，但该插件是安全承重件——控制面入口，产物必须走代码评审+最小权限审查；朋友纪律第 6 条「创造模式只用于开发插件」说明朋友同样是「AI 起草+人把关」用法）。
- **三个技术前提（本地接口/无头启动/Session 复用）之外，补第四前提——审批语义透传**：dsh 的审批门（R1 dsh组 实锤：pre-execute waterfall 的 allow/deny/**ask**·ask 未答即拒）是为「坐在 dsh 前的人」设计的。被遥控（headless）时 ask 类调用怎么办？三选一须显式裁定：(a) EMC 薄壳把 ask 事件**转发给最终用户**确认（UX+协议设计·最干净但最贵）；(b) 遥控会话预配全 allow（**危险·等于拆审批门·应禁为默认**）；(c) 遥控模式仅允许**只读工具+白名单写操作**（推荐 v1——与 C4 三级审批对齐）。这是五跳链路里最容易被忽略的语义坑：**「无人值守的审批门」**——不裁它，安全条款（F4）就是漏的。
- **与 B 卷五问衔接**：B 卷问1（嵌入位置谱系）/问3（平台须暴露什么）正好覆盖本轮三个前提——建议 dsh组 **合并作答**（一次源码核查回答两轮·免二次开工；B 卷本就缺盘待补）。

### F3 薄壳双通道：交互与降级

- **通道选择不得变成新路由器（本轮最重要的设计红线）**：R3/R4 已证明封闭意图分类法是 Whac-A-Mole 的结构性根源——若薄壳要「判断这句话是固定任务还是自由任务」再选 A/B，就是给 19 契约路由器换马甲。设计原则：**显式选择 > 自动分类**——A 通道=快捷按钮/参数面板形态（已知固定任务一键直连·根本不出现在对话流里）；B 通道=对话框**默认且唯一**的语言入口（开放输入全走大脑）。一句话：**「A 是按钮不是路由」**。这样零意图分类、零新词表、零新降级树。
- **降级链**：B 不可用（dsh 离线/插件断/超时）→ 对话框显式提示 + 降 A（快捷任务照常）+ 可选「稍后重试」；B 半途失败（大脑任务中断）→ status 轮询 + Session 复用支持断点续问或显式失败回执（不静默吞）。
- **呈现**：B 的自由任务结果经渲染契约出图——与 Codex 议题2 裁定（v1 只管呈现·交互不进契约）正好衔接：大脑调 `render_spec` 工具→前端渲染，链路自然闭合。

### F4 安全（claude组 主答·zcode 补三条条款）

七条原纪律+Codex 补的⑧⑨全收。zcode 增补：
- **⑩ 审批语义条款**（F2 第四前提的条款化）：遥控会话的工具审批策略必须显式声明三档之一（仅只读/白名单写/ask 透传），**禁「全 allow」默认**；
- **⑪ 溯源标注**：B 通道产出的每个结果/图层带 `brain: dsh@session_id` 元数据（同 C7 usage 元数据模式）——评审质询时能区分「EMC 工具直出」vs「dsh 大脑综合」，演示与交付的口径边界不混淆；
- **⑫ 数据回流对偶**：⑨ 管住了「取」（大脑不得绕过 G10 取数），须对偶管「送」——EMC 经 send 送出大脑的内容先过脱敏（C1）才出进程；大脑侧回传的渲染请求同样必须走 render 契约（不得直写前端状态）。

### F5 排期

- 同意「G10 之后·不插队」；G1/渲染 API 顺序**不受影响**（本思路=入口层·它们=平台层·正交——Codex 初判正确）。
- 补一个排期技巧：**第 0 步不是排期项是调研项**——成品确认/技术前提证实（含第四前提）纯调研+评审、零代码，**现在就能做且与 G8a/G8b 并行**。这样 G10 落地之日 B 变体的前提已备齐，转正决策不用再等一轮证实，也不占任何工程窗口。
