## 件① BrainAdapter 实施首选：dsh headless 适配器（Qoder·~1.5d）

**目标**：EMC 对话框的问题经 BA 转发给 dsh（headless 子进程）·dsh 的输出转回 ACP 事件流在壳对话框渲染——**「EMC 窗口用 dsh 当引擎」首次端到端跑通**。

**规格**：
1. `frontend/js/ai_qa/brain-adapter-dsh.js`（或 backend 侧·按 acp-channel 架构择优）：
   - `open(question)` → 启动 dsh headless 子进程（`dsh --profile emc-test "<question>"`）
   - 监听 stdout/stderr → 解析 dsh 输出 → 转发 ACP 事件（msg.delta 近似·headless 无真流式→输出完成时一次性发 tool.end + msg.delta 批量）
   - `close()` → 进程清理
2. **降级形态声明**（brain-adapter.md 契约已定义）：headless 无真流式——BA 在等待期间发**进度桩事件**（`tool.begin: {query 摘要}` + 周期性 ping）·dsh 返回后发完整结果——用户看到的是「正在思考…→答案」而非逐字流（**如实告知·不伪装流式**）。
3. 引擎选择层：`ENGINE_MODE` 环境变量/URL 参数（`?engine=light|dsh|mock`·默认 light）——三引擎可切换。
4. E2E：`?engine=dsh` 模式下问一个真实问题（如「什么是留改拆」）→ 8080 对话框出答案+地图联动。
5. 红线：轻量引擎零退化（`?engine=light` 默认路径不变）·MCP 工具面零改动·ACP schema 兼容（过 S6 校验器）。
