# EMC 壳阶段架构草案 v0.9（zcode·2026-08-23·待 Qoder 对抗评审后合流 v1.0）

> 依据：用户架构裁定（EMC=交互壳子+Harness+RAG·大脑永远外置）+ ACP 契约 v1（`docs/acp-contract-v1.md`）+ 两阶段路线（测试期外置驾驶舱→壳吸收）。性质：**规划件·零实施**——阶段门（T1-T5 测稳）过前只出任务书。
> 章法：Q1-Q4 每题给「方案空间+主手倾向+理由」——Qoder 评审时逐题对抗·不同意给证据。

## Q1 大脑接口断点（最硬·先答）

**事实基座**：①壳要显示大脑思考流=消费 ACP 五族事件（msg.delta/tool.begin-end/...）②dsh 无公开会话事件接口（web 私有协议·宪法禁依赖；headless 无流式）③Codex Harness 有 app-server（官方「自建 UI」路径+Python/TS SDK）④用户裁定：暂 dsh·契约成熟后测 Codex。

**方案空间**：

| 方案 | 内容 | 优劣 |
|---|---|---|
| ①适配器族 | 壳侧建「大脑适配器」接口：`BrainAdapter`（ACP 事件流出·open/step/seal/close 入）——dsh 适配器走**降级形态**（headless 调用+壳侧进度桩事件模拟·无真流但有骨架）；Codex 适配器走 app-server 全量（契约成熟接入时启用） | 大脑可插拔=架构裁定本意；代价=dsh 适配器体验降级（无真流式） |
| ②轻量先行 | 壳先跑「EMC 自持轻循环」（现有 ai_qa 四阶段·ACP 事件已天然就位）·BrainAdapter 后插 | 最快见效；但自持循环=壳内大脑·**与「大脑永远外置」裁定的相容性需用户确认**（可辩护：轻循环只是过渡引擎·编排权仍在可插拔层） |
| ③双轨 | ①+②并行：壳对话框架按 ACP 建·引擎=可切换（轻循环/Harness 适配器） | 工程量最大但无浪费 |

**主手倾向：③双轨收敛为「②起步·①预留」**——壳对话框架按 ACP 事件模型建（前端只认事件不认引擎）·首引擎=自持轻循环（现有资产复活）·BrainAdapter 接口位预留（dsh 降级/Codex 全量两实现后插）。**理由**：不空等接口（dsh 无·Codex 未接入）·不锁死未来（事件模型统一）·复用 80% 现有资产（ai_qa 四阶段+渲染管线+followup_cue）。

## Q2 壳与现前端关系

**倾向：渐进升级**——8080 现有 ai_qa 对话框升级为「壳对话主面」（ACP 事件渲染改造）·不新建入口。理由：前端资产厚（四阶段 SSE/图层联动/复测刚验收的样式面板）·新建=重复建设+双入口违「入口统一」铁律。

## Q3 工具编排归属

**倾向：编排权=引擎层**（自持轻循环或 Harness·按 Q1 双轨）——壳只发 `open`（用户问题）+渲染事件·不直接调度 MCP 工具。理由：宪法「大脑外置」；壳直连 MCP 的「轻路径」不留（留了=编排双头·纪律破口）。

## Q4 ACP v1→v1.1（壳侧消费增补）

- `msg.delta` 增 `kind` 子类型（正文/思考链——EMC 已有 reason|content 两态·补进契约）；
- `tool.end` 载荷采纳 PT-CB11 已落地的四字段（count/dim_counts/top_dim/elapsed_ms）；
- followup_cue 渲染语义（cue→对话框「追问建议」chips 的交互契约）；
- 审批回路（approval.req）在轻循环引擎下的语义（默认全放行·只读工具面）。

## Q5 垂直域抽象层（08-23 用户愿景升维·新增）

**背景**：用户令——情绪地图也是壳子·终局=「城市规划大模型平台」·垂域 Agent 可插拔（垂域②候选=城市体检医生 Agent·「无体检不更新」）。**先两垂域后抽象**（从实例归纳契约·不先造空框架）。

**倾向**：Vertical Profile = 数据包+知识库（垂域语料）+口径注册表+身份卡/人设+工具预设 五件套——壳/工具/管线/渲染全平台层共享零改动。壳阶段建壳时**预留垂域切换位**（身份卡/语料地图/口径表的挂载点参数化）·不做完整多垂域实现（等垂域②试点归纳）。
