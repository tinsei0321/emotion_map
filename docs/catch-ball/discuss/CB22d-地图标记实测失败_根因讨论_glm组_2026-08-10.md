### 1.2 ★ 挂起根因精确定位（glm 修正 claude组）

claude组 说「while-loop 无限重试」。glm 代码定位发现**真正根因更精确**：

- **while-loop 有预算守卫**（[harness.js:1032](frontend/js/ai_qa/harness.js#L1032) `_deadline = Date.now() + 30000` + harness:1342 `if (Date.now() > _deadline) break`）——但守卫在 **while-loop 头部**，要等当前轮 `agentStep` 返回才能进下一轮检查。
- **`agentStep`（[stages.js:252](frontend/js/ai_qa/stages.js#L252)）的 `streamChat` 调用无单轮超时**——只传 `ctx.signal`（用户取消）·无 12s/30s timer。对比 `fcDiagnoseStep`（stages.js:302）有明确 `_timer = setTimeout(() => _ac.abort(), 12000)`。
- **后端 LLM client `timeout=60s`**（llm.py:58 httpx）——但流式调用 token 间隔到来不触发连接超时。模型持续吐 reasoning token（用户铁证「反复权衡不终止」）→ **前端无超时·后端流式不超时·单轮无限挂·deadline 守卫够不着**。

→ **挂起 = 单轮 agentStep 的 streamChat 流式 LLM 调用无超时 + 模型 reasoning 不收敛**。while-loop 循环次数（MAX_ROUNDS_GIS=10）和 deadline（30s）都没问题——**问题是单轮 LLM 调用本身不返回，守卫根本执行不到**。

**这是 claude组 方向 B 需要对症的点**：B2（轮数上限）/B3（循环识别）**治不了这个**（单轮就挂了·轮数没增加）。真正的解药是 **B1（全未命中快速降级·不进第二轮 LLM）+ 补「agentStep 单轮超时」**（仿 fcDiagnoseStep 的 12s timer 模式）。
