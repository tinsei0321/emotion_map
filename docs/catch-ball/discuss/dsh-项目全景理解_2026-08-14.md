### 4.2 编码与术语铁律

- 代码禁 emoji（仅 ASCII 标记 `[OK]/[WARN]/[LOAD]/[ERR]`）；print 走 `_safe_print`；禁劫持 builtins.print。
- 术语「**街办**」非「街道」（街道=行政单元，admin_street 非路网线）；「社区 ≠ 小区」（社区=行政区划·小区=居住形态单元·社区 ⊃ n 小区）。
- 追踪编号连续不跳号：新增 ID 先 grep 全仓取现有最大 +1，经 `register_track_id()` 注册。
- 入口统一 `run_analysis_task()`；导出命名 `{name}_{L1..L4}_result_csv.csv`；结果脱敏。
- 两板块/片区 = 结论（分析过程不消费 board、不预设片区）；分析数据源 = 中转站真实数据、sim 禁入、gdb 只读。

### 4.3 承重红线（不可协商）

决策追踪编号连续性；diagnose prompt 永不动（两度豁免均有 3 条件 + 回滚条款）；四态出口契约；L0 购买途径策略；EMC 委托主 Toolbox 不自造 geo 端点；aggregate 别名静默零。（KNOWLEDGE §1）

### 4.4 图数表出图隐规则（当前主线）

- 风险主题命名一律「XX 安全」后缀（房屋/管网/消防安全），禁设施清单式旧名。
- 每页重构 = 重构 + 数据审计（点文件/矩阵/77 项/问题清单全对账，不一致以实测为准修正）。
- 结构化主体：概况 → 问题内容（"主要为……"式举例）→ 集中区域；详细数字全放表格。
- 用户定稿的类名/说明是最高权威，md/Excel 不得自拟命名替代。
- 「以及」仅用于分隔城市社区与行政村；纯城市社区口径不用「以及」。
- 排行表一律 top10：列满前 10；**0 值行不列、不足不硬凑**（曾犯「用户说 top10 硬塞 0 值村凑 9 个」——错）。
- 沟通：逻辑框架 + 条目化 + 总结；专业词后跟「(=通俗解释)」；交付物全中文；结论先行、不谄媚、不附和。

不附和用户、不为满足字面要求硬做明知是错的事；用户要求与事实冲突时主动指出并说明原因；发现问题当场说。（`session-handoff.md:99`）

### 5.3 问题清单（按优先级）

**P0（结论可辩护性）**

1. **丢弃 EB 收缩 + 丢弃低置信标记 = 小社区噪声回归，是对 CB-33 已共识防线的倒退**。密度口径下，8 栋楼的临江溪（热线民生 31 件 → 387.5 件/百栋，zcode v2 预览排强度 13 名）会天然霸榜「主观高」；CB-33 Codex 焦点 2 明确同意 `bldg_n<20` 标注低置信「列而不进结论」。裸密度没有任何收缩/标记。**最低要求**：恢复低置信标记列（低置信社区不进结论句/不进「重点片区」依据）；更好：分层判定对低楼栋社区降档或恢复 EB 收缩（算法现成，zcode 预览脚本在 `DATA/analysis/page7小结/preview_intensity_rank_v2.py`）。
2. **「双高」术语三代漂移，图/数/表一致性风险**：v1 合并双高 → CB-32 v2 分轨（16/32/3）→ zcode 合并双高 26 → 现行密度分层双高——四份文档同一词指向四个不同集合。zcode 已渲染的双变量主图（`page7_双高社区_双变量主图.png`，合并口径 26 双高）与现行 md 的分层口径不一致。若沿用 zcode 图而不重渲，page7 图与表将互相矛盾。**必须指定单一权威口径**，其余产物显式标注废弃或重渲。
3. **阈值三选一未定，且三选项语义差异巨大**：p75 与 CB-32 分位框架一致且稳健（推荐）；「全市平均 2 倍」受重尾支配（朝阳路热线民 638 件/百栋会显著拉高均值，2×平均可能只切中极少数社区），且「平均」算法未写死（社区级均值的均值 vs 全局率=总量/总栋，可差数倍）；「前 N 名」N 随意且恰是小社区噪声最敏感的口径。
