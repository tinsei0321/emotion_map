# PT-CB15 · 渲染链路治本复核意见（Kimi·2026-08-25）

> **性质**：CB 组员独立复核——对 Codex 根因报告（`PT-CB15-EMC渲染残留与后台幽灵图层根因报告_Codex-2026-08-25.md`）的逐题独立意见 + 分歧点 + 最终建议。复核范围：`api/render_routes.py` / `frontend/js/render_client.js` / `tools/mcp_server_emc.py`（render_spec）/ `frontend/js/time-source.js` / `core/render_policy.py` / inbox 实况。零实施。

## 白话摘要

刷新后旧图复活这个病，Codex 已经把最大的出血点（连接时重放旧图）止住了，我的复核确认这刀切对了。但「后台慢半拍的回答把旧图突然推回来」这个根子还在：目前图层图纸（spec）上**没有写「这是哪一轮回答产的、什么时候产的」**，谁递图纸地图页就画谁。我的主张和 Codex 略有不同——不给每张图纸绑「轮次身份证」（要做这个得新修一条宿主到地图页的反向通道，贵且脆），而是给图纸加「保质期」：落盘超过几分钟的图纸直接归档不推送，页面只画「我打开之后新产出」的图。两刀都是闭包规则（查时间戳），符合零思考壳子纪律，半天能落地。TOP7 变 TOP10 的问题，病根是模型偷懒抓了现成的「TOP10 预设图层」而不是用自己刚算出来的结果出图——这个不能靠把预设层禁掉（演示还要用），正确做法是让工具在引用预设层时回显一句「你引的层有 10 个要素，和你的答案对得上吗」，让模型自检。时间轴 manifest 404 是早就知道的窟窿（代码注释写明生成权限留给用户），建议前端安静降级，别每次开页都在控制台报错吓人。

## 一、复核确认（Codex 说对的）

1. **backlog 重放=幽灵图层主根因，止血正确**。`render_routes.py:243` 连接时重放已移除（注释记 2026-08-25 用户令）。我额外确认：inbox 当前零积压、applied/ 归档 31 件、watcher pidfile 竞争锁（P2-9）在位——重放链路已无残余出口。
2. **TOP7 变 TOP10 是数据源选择问题，不是渲染问题**。`render_spec` 对 dataset_id 只做「是否在 manifest 注册」校验（`mcp_server_emc.py:1474-1478`），`page7_12345_top10` 是合法注册层——守卫没有立场拒绝它，因为**它本身不是非法输入，只是与本轮答案语义不符**。这层判断 Codex 报告准确。
3. **_time_manifest.json 404 是已知数据缺口**。`time-source.js:21` 注释明写「DATA/performance/ 当前无 _time_manifest.json，再生成属数据红线（留用户）」——404 是刻意留白，不是 bug。

## 二、逐题独立意见

### 题 1 · spec 绑定 turn_id？——目标同意，机制反对，换更便宜的刀

**结论：不做 turn_id 绑定；用「服务端 TTL + 前端连接水位线」双闭包校验达到同等根治效果。**

turn_id 方案的结构性困难（Codex 未展开的代价）：
- **地图页是「显示屏」，没有 turn 上下文**。8080 页面与 dsh 窗口是不同进程，「当前轮次」这个状态在地图页一侧**没有权威来源**——要绑定就得新建一条反向通道（宿主→地图页声明「现在轮到谁」），这恰好是核心思想红线警惕的「宿主侧状态渗入 EMC」；
- MCP server 逐调用无状态，turn_id 只能由宿主当参数传入——宿主不传/传错时行为如何定义？又一个受管默认值坑（我 08-21 设计书 §1.2 已预警此类）；
- ai_qa 面板与地图同页时 turn 概念存在，但 dsh/Codex Harness 是主要生产者，跨进程 turn 关联成本远大于收益。

替代方案（两刀都是查时间戳的闭包规则，零思考合规）：

| 刀 | 位置 | 规则 | 治什么 |
|---|---|---|---|
| 服务端 TTL | watcher 扫描时 | spec 文件落盘超过 **N 秒**（建议 300s）首次被扫到 → 直接归档不推送（stderr 留痕一行） | 现象②「后台延迟完成把旧图层推回」——迟到图纸永不上屏 |
| 前端水位线 | render_client `_connect()` | 连接建立时记 `connectTs`；spec_id 前缀本来就是毫秒时间戳（`mcp_server_emc.py:1567`），**ts < connectTs − 60s 宽限的 spec 拒收**（console.warn 留痕） | 一切「页面打开前产生的图」复活路径——即使将来有人又误开 backlog 重放，前端这刀也挡得住（防御纵深） |

**一个必须明示的语义代价**：页面未连接期间产出的图将不再出现（「先出图后开页」流）。这与用户 08-25 止血令的语义一致（连接不重放），入口插件的就绪门流程（先探测 8080→开页→模型再出图）天然规避；60s 宽限覆盖「页面加载中模型刚好出图」的竞态。若验收时发现该流有真实需求，再单独裁决——不预先兼容。

### 题 2 · 出图数据源收敛？——三分：契约纪律 + 软校验自检 + 临时层生命周期；反对硬白名单

**结论：不把 dataset_id 约束死；用三件套让模型「选错时自己看得见」。**

反对硬白名单的理由：`page7_*_top10` 是合法演示资产，`tmp_render_*` 是 render_file 的合法产物（T18 核心链路）。服务端枚举禁止 = 把「语义是否匹配本轮答案」这个不可枚举判断伪装成查表——违背零思考操作性定义（CB3 终收敛 v2），且误伤演示流。

三件套：

1. **契约纪律（双写·零代码）**：render-contract §七增补一条 + render_spec docstring 同步——「分析问答的出图，数据源必须来自本轮分析工具（zonal_stats/rank/grid_aggregate 等）`layer_output=True` 的内联 geojson；dataset_id 仅用于①用户点名显示某已注册层 ②render_file 自动登记」。这正是方法论契约双写纪律（D-c）的标准用法；
2. **软校验回显（提示级·不阻断·守软校验红线）**：render_spec 收 dataset_id 且命中 `tmp_render_*` / `page7_*_top\d+` 模式时，返回 ok 但 `caliber_lite.note` 追加：「引用预注册层（实际要素 N 个·usage=X）而非本轮计算结果——若答案指定了 Top-N 请核对」+ **回显该 dataset 实际要素数**。模型拿到「我答 7 个社区、图层 10 个要素」的对账信息，自纠发生在当轮（大脑自纠行为有 CB6 先例）；前端同步把该 note 打进图层名后缀或 tip，用户也可肉眼对账；
3. **tmp_render_ 生命周期**：render-contract §五已有「用毕清理」纪律文字——落实为 applied/ 同款 TTL（7 天）或会话归档，防临时层在 manifest 里永久累积成「图与答案对不上」的候选池。（待核实：当前是否已有清理机制；若无，随本批补。）

### 题 3 · _time_manifest.json——优雅降级先行，生成单列裁决

**结论：前端静默降级（本批可做·零数据决策）；是否生成最小 manifest 属数据资产裁决，单列给用户。**

- 现状：`loadManifest()` 失败路径是 `console.error` + rethrow（`time-source.js:37`），每开页必炸一次控制台；时间轴模块对「manifest 不存在」没有一等状态。
- 修法（纯前端·轻量）：404/拉取失败 → 置 `_manifest = {datasets: []}` 空态而非抛错；`isManifestReady()` 语义不变；time-bar 检测空态**隐藏时间轴控件**；控制台降为一次性 `console.info('[time-source] 无时间片数据·时间轴已隐藏（manifest 待数据侧生成）')`。错误只在「manifest 存在但解析失败」时报（那才是真异常）。
- 生成 manifest：代码注释已定「属数据红线留用户」——本组不越权生成；建议列入数据资产登记（沉淀四要素），由用户裁决是否补一份最小 manifest（单数据集单片也算合法起点）。

### 题 4 · 启动到结束统一自检？——同意，但挂既有载体，不新建框架

**结论：做，但收敛为「到岗体检三项新增 + /version 三端比对」，不造独立自检系统。**

- 三服务口径（待主手确认）：8000 API + 8080 静态 + MCP（8600·见 _tmp_mcp8600 日志）。
- 落地建议：
  1. `/version`（8000·已存在）扩展返回 `repo_root`；8080 serve.py 加同名轻端点返回服务根路径——**两端 repo_root 一致**即「路径一致性」自检通过（闭包字符串比对）；
  2. M3 到岗体检脚本新增三项：端口存活 + 双端 commit/路径一致 + **inbox 无 pending 积压**（`render_inbox/*.json` 顶层应为 0，非 0 即上次异常残留）；
  3. 「连接不重放」不需要运行时自检——它是代码行为，应变成**一条 pytest**（断言 `_sse_stream` 首产出不来自 `_BACKLOG`），防回潮比运行时探测便宜得多。同理 watcher TTL 与前端水位线各配一条测试。
- 反对面：不建议做启动期「全链路试渲染自验」之类的重自检——R8（验证忌与实现同构）+ 启动路径加重，收益不成比例。
