## 一 议题1（主答）：E4 正式裁定 + 三支柱在平台形态下的存废变形

### 1.1 先做任务书点名的反证：「形态3 是否只是逃避可解问题」

对 R3 诊断的入口聪明度四层机理逐层检验（不附和·真反证）：

| 机理 | 形态2 解法 | 形态3 处置 | 反证结果 |
|---|---|---|---|
| ② 参数闭卷填空 | M2 参数接地（list_data+dataset_id 枚举） | **M2 变身存活**（schema 接地服务 MCP 工具面——纪要含义⑤） | 未逃避——本来就要做且平台更需要 |
| ④ eval 失真 | M4 eval 重放（G6） | G6 降权为**平台 eval**（本回应 C10） | 未逃避——变形保留 |
| ① 封闭分类法 vs 开放空间 | M1 迭代诊断（多轮 FC 循环） | 交给通用 harness 的 agent loop | **未逃避——M1 要造的东西（多轮工具循环+失败恢复+澄清）就是通用 harness 的本体**。自研 M1=造一个 mini harness=与巨头竞赛（R4 三次转移论证：预训练教材是整个 GitHub·私有词典竞赛数学上不收敛） |
| ③ 单发不可恢复 | M3 计划生成（G9 CPD） | 宿主 plan-execute 天然承担 | 同上——正确解法外包给最擅长它的东西 |

**反证失败，形态3 不是逃避，是正确的解包**：把"让入口变聪明"从自研义务转交给通用能力供给方，把私有能力（口径/知识/渲染）做厚。用户论断「如何跑起来的路由不是个人开发者该做的事」经此检验成立——这不是放弃可解问题，是承认该问题的解属于商品化竞赛层。

### 1.2 三支柱的存废变形（本议题最重的裁定）

三支柱（CB-22 铁律：知识库完备度+EMC 架构+LLM 综合·缺一不可）在平台形态下**不存废、重新分工**：

| 支柱 | 平台形态下的变形 | 载体 |
|---|---|---|
| ① 知识库完备度 | **不变且强化**——升格为平台核心资产（C 线沉淀正是它） | RAG/outlet_kb/industry_kb |
| ② EMC 架构（分类→范式映射） | **变形而非消失**：范式知识（尺度→方法→输出颗粒度）从代码路由（paradigm.py）**迁移进工具面设计**——工具 description 编码尺度适用性、参数枚举编码数据资产、输出 schema 编码回答范式 | MCP 工具的 schema/description 质量 |
| ③ LLM 综合 | 由宿主 harness 承担（每家都有） | 通用 harness |

**承重判断（claude组 核心增量）**：支柱②的迁移不是自动发生的——**如果工具面只是裸暴露函数（名字+参数），蒸发掉的不是路由代码，而是范式知识的载体**——十年领域积累（尺度纪律/颗粒度匹配/口径标注）将无处栖身。故设**前置条件三**：工具面设计必须显式继承范式知识（落为宪法 C11·见议题6）。三支柱从"每答必过的产品保证"变为"消费者依赖的平台质量属性"——**CB-22 铁律在平台形态下的正确表述：砍任何一根支柱，平台产出的可信度崩塌**。

### 1.3 三项前置条件（E4 成立的附加条款）

1. **范式知识显式迁移**（→C11）：工具面=范式知识的新载体·设计评审过不了"裸函数"关不放行。
2. **参赛演示仍用现有 QA 壳**：演示逻辑链三环中"引导点击→交互分析"两环在形态3 下部分让渡给宿主对话——**现场演示质量变得依赖宿主发挥（不稳定）**。参赛期（可控性最优先）现有 QA=演示级冻结态保演示主力；形态3 是赛后主线。此条直接决定议题3 时序。
3. **冻结的精确定义**：路由层"停止自研投入"≠删除≠放烂——diagnose prompt 永不动（红线本来就写）/编排器冻结期维持/**B002/B004 等 CRIT bug 仍须修完**（演示可信度·CB-39 D1 批不因形态3 取消）；冻结=不投新能力（M1/M3 停）+修 bug 保稳。

### 1.4 形态2 与形态3 的关系（E4 第二问）

**不是渐进也不是并行，是吸收**：形态2 的 M2/M4 本来就是平台需要的基础设施（无论哪种终局形态都要参数接地和 eval）；M1/M3/M5(体内) 是重造 harness 的子集（砍）。所以"形态2 先做再演进到形态3"的路径**不存在独立价值**——直接按形态3 走，M2/M4 自然包含在内。

## 二 议题3（主答）：产品入口空窗的过渡策略

三阶段时序裁定：

| 阶段 | 策略 | 理由 |
|---|---|---|
| **现在~参赛**（演示期） | 现有 QA 面板**冻结为演示级**（E4 前置条件2）：稳定冻结+B002/B004/D 线 bug 修完+零新能力 | 参赛演示对象=业内同行+评审（非住建局实地交付）——空窗不痛；演示可控性>入口先进性 |
| **参赛后~立项接触**（中期） | **薄入口自建为主**：前端 chat 组件 + MCP client（经后端薄代理·复用现有 ai_qa router 架子）——量级小（估 2-4d）·完全可控·天然消费平台工具面；**dsh Web 场景 S 作观察项不依赖**（其产品化节奏不可控） | 立项客户（规划师/住建局·非开发者）需要"打开就能问"的入口；自建薄壳=通用 FC over MCP（任务书原话）的最小实现 |
| **长期** | 薄入口迭代·或被更好的通用消费形态替代（harness 消费级化/场景 S 成熟） | 平台心态：入口可替换·资产不绑定入口 |

## 三 议题6（主答）：平台宪法与"正道好走"标准

### 3.1 C1-C7 补全为 C1-C11 平台宪法

| 增补 | 条款 | 依据 |
|---|---|---|
| **C8** | 契约单一源延伸：MCP schema 一律从 `tool_contracts` 派生（G8）·**禁手写第二份 schema** | 契约单一源红线在平台形态的自然延伸；CB-04 H1（自带默认另搞一套）的教训在工具面重演预防 |
| **C9** | 工具面版本化：对外工具=对外 API 承诺——语义版本+破坏性变更须 deprecation 期（参考 dsh 组 R1 breaking 定量：周级变更节奏的教训） | 平台消费者（四 harness+未来薄入口）需要稳定性承诺 |
| **C10** | 平台 eval：G6 降权后的归宿——工具面调用质量回归（每工具可调用性/schema 稳定性/黄金问题平台版），CI 化 | 三支柱③让渡给宿主后·平台自己可控的质量面收窄到工具面——这是新的防线位置 |
| **C11** | **范式编码义务**：工具 description 必须含尺度适用性/前置条件/输出范式说明；工具面不得退化为裸函数清单——设计评审关 | 三支柱②迁移的落点（1.2 承重判断）；防领域知识蒸发 |

C1-C7（PII 过滤/sim 白名单+demo 参数/gdb 不进 MVP/三级审批/路径沙箱/key 不透传/铁律7 元数据）维持原文并入宪法。

### 3.2 「把正道修得比野路好走」的可操作判据

每个 MCP 工具须答赢"**为什么不用 bash 裸调脚本**"，五判据：

1. **结构化输出**：JSON schema 保证（vs 解析 stdout）
2. **口径内建**：返回值自带口径标签/来源（裸调要自己翻文档·口径注册表的知识进工具返回）
3. **脱敏/沙箱自动**：C1/C5 内建（用户不用记纪律）
4. **错误语义化**：可编程处理的错误码（vs traceback）
5. **组合性**：dataset_id 枚举让工具间可链式（bash 裸调无类型链）

验收形式：工具面评审时逐工具一行答辩；**答不赢的删或改**——R4 已实证通用 harness 会写代码绕过不好用的工具，与其被绕过不如不做。
