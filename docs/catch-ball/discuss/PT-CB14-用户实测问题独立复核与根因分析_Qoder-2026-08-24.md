## 白话摘要

把您测出的四个问题挨个重查了一遍，结论像三种不同的"故障"凑到了一起：**第一种是"库房有货但货架没上架"**——停车位问题的空间点位数据其实躺在仓库里，但没有登记到"可分析货架"上，分析工具拿不到（这解释了"无法出图"的一半）；**第二种是"一次性问答没人把关"**——套壳里的 AI 是单人单轮干活，有时答得又快又好（我复测三问全成，其中一问还成功画了图），有时会钻牛角尖超时，而且它有时会反问"要不要画图？"但单轮模式下没人能回答它（这解释了"无法出图"的另一半）；**第三种是"两个客服混接了电话"**——您看到的"需要补充边界资料"报错和"暂时无法直接回答"，其实来自 EMC 自家的轻量问答管线，不是 dsh 引擎——两条管线的报错混在一起，容易误判是同一个病。另外要向您认领一件事：**图上那个 top5 社区图层，是我之前做工具测试时投进去的样张**，您打开地图时恰好被显示出来，不是系统乱出图。RAG 知识库里体检/停车/12345 的积累**都能用**（我逐一检索核实），但它们只是"知识卡片"，不含地图几何——画图仍要走数据货架。

## 二、用户四问题逐条根因（按证据定性）

### 问题 1/2「停车位点位显示 / 停车位不足小区 → 无法出图」——三因叠加

| 因 | 性质 | 证据 |
|---|---|---|
| **① 数据消费面缺口（确定性）** | qty_* 体检点层 15 层（含「量化-民生-停车设施」274 点）**在仓、在 manifest、在 list_data presets，但未注册进 `_POINT_LAYERS`** | 实测 `geo_registry._POINT_LAYERS` 仅 12 层（情绪 6+治理 3+12345 3），`any('qty' in k)=False`。后果：zonal/rank/hotspot 等分析工具**无法以它为 layer**——"哪些小区缺车位"这类空间归位问题在分析面走不通 |
| **② 单轮反问形态（非确定性）** | dsh 引擎答完文字后反问「需要的话我可以上图」——单轮一次性形态下无人应答，图就停在了嘴边 | 复现回执原文（`_tmp/ptcb14_repro.json` Q1 末尾） |
| **③ RAG 无几何（设计使然）** | RAG 沉淀=知识卡片+文档片段，**不含图层几何**——"从 RAG 直接出图"在架构上就不成立；出图必走 list_data 消费面 | RAG 盘点回执（§三） |

> 与 zcode 报告差异一处：其称「dsh 看不到这层数据」——复核修正为：**presets 可见**（复现答案中原话引用「图层『量化-民生-停车设施』已在数据目录中注册」），不可见的是**点层分析面**。后果相同（无法空间分析出图），但修复面更准：注册点层即可，非数据缺失。

### 问题 3「12345 top10 → 边界报错 + top5 混现」——两个独立成因

- **报错文案归属 = EMC light 引擎，非 dsh 引擎**：「需要您补充数据…标准边界资料（行政区划/更新单元 Shapefile/GeoJSON·EPSG:4326）…该区边界为法定功能区/非预置范围·EMC 不硬猜不可信范围（CB-14）」逐字出自 [harness.js#L1851-L1852](../../frontend/js/ai_qa/harness.js#L1851-L1852)（light 管线 data_plan.gap 出口）。dsh 引擎的输出是 stdout 全文直显，不产此造型。**该轮走的是 8080 默认 light 引擎**——light 管线的模型把「社区」误构进边界参数，触发 CB-14 防线（防线本身是正确行为，错在参数构造，与 zcode 判定一致）。
- **图上 top5 社区 = 我（Qoder）L2 测试投递件，非模型产物**：L2 C16 用例投递的「12345×174 TOP5」spec（`1787540931818-7981`）留在 render_inbox，用户打开 8080 地图页时被 SSE 消费显示（applied/ 归档可查）。**更正 zcode 报告 R5「模型发散半成品残留」的定性**——那是测试样张污染，责任在测试流程（见缺陷 D-6）。
- top10 本身在 dsh 引擎侧**可成功**（复现 184.7s 出图）；用户当轮失败属 light 管线参数构造问题 + dsh 侧概率性发散（zcode 实证 1/3 超时）的叠加窗口。

### 问题 4「纯问答思考链正确 → 最终『这个问题我暂时无法直接回答』」——light 引擎 exit=gap

文案逐字出自 [harness.js#L401](../../frontend/js/ai_qa/harness.js#L401)：「诊断成功但执行未开始（暂无法回答）」分支（零工具失败尝试·`exit:'gap'`）。即：**该轮同样走 light 引擎**——diagnose 成功（所以思考链看着正确）但工具执行未启动/全部失败，落 gap 出口。思考内容没传给答案是因为 light 管线的 gap 出口用确定性文案兜底，不继承中间推理。精确定位需当轮 session 日志（diagnose 卡/template/执行痕迹），建议用户提供时间点后取 trace。

### 「思考链内调用工具依然是 _qa，没有 GIS 工具」

`_qa` 系 light 引擎知识问答通道（`knowledge_qa` 意图）的显示名——**当轮根本没进 dsh 引擎**。8080 引擎由地址栏 `?engine=` 决定（缺省 = light·见 [brain-adapter-dsh.js#L14-L24](../../frontend/js/ai_qa/brain-adapter-dsh.js#L14-L24)）：不带参数或参数丢失 → 走 light。dsh 引擎的思考链显示的是「dsh_brain」桩事件。

## 三、回答用户的三个直接问题

**Q：是因为我没有上传图层吗？**
不是。数据在仓（qty 停车 274 点、12345 全量、社区 174 边界等均已注册）。卡点是**消费面注册缺口**（qty 点层未进分析面）+ **单轮形态**，与上传无关。

**Q：目前是否能调用 RAG 中的城市体检数据积累？沉淀了哪些？**
**知识层可用（已实证）**：复现第 3 问全程基于 RAG 体检积累作答。盘点结果（每类均 hits≥3·dense_score 0.56-0.70）：

| 检索词 | 命中素材（Top 源） | 维度 |
|---|---|---|
| 停车位不足 | CHK-I05 体检指标卡 / URP-I03 / URP-I07 | 小区·城区 |
| 停车设施 | URP-I07 / CHK-P03 / CHK-I05 | 城区·项目库·小区 |
| 城市体检 住房 | URP-M05 / URP-P09 / CHK-P01 | 方法论·片区·项目库 |
| 12345 热线 社区 | URP-C06 / 03-10 全覆盖口径笔记 / B2 主观落位 | 城区·小区·社区 |
| 更新单元 划定 | URP-L01 / URP-L03 / URP-A01 | 方法论·片区 |

沉淀主体=`ai_qa/outlet_kb/urban_renewal_knowledge.py` 事实卡（CHK-/URP- 系列）+ `docs/urban-renewal-plan/` 笔记文档。**红线提醒：RAG 只含知识不含几何**——「显示点位」类诉求必须由数据消费面承载（当前缺口见问题 1/2①）。

**Q：是 dsh_engine 端点的 spawn 环境出问题了吗？**
**实测不是**：双 profile 的 MCP 接线一致（同为 8600 streamable-http），spawn 链路（npm shim→bin.js 解析、编码、超时、输出截取）3/3 复现成功。真差异在**会话形态**：3080=多轮+交互+工作区上下文兜底；emc-test headless=单轮一次性、无思维管控、无人设引导——发散概率高（zcode 实证 1/3 超时，我复现 3/3 成，说明是**概率性**非确定性坏）。

**Q：为什么你（Qoder）自测时都没发现？**
如实回答，三层盲区：
1. **L1.5 只测了「hi」**——问候不需要工具链，验的是通道不是行为（与 zcode 自审同源教训）；
2. **L2 全部直调 MCP 工具**——按设计隔离了模型编排层（任务书明确要求），测得出工具好坏、测不出"模型会不会用、会不会发散"；
3. **light 引擎 QA 管线的行为层从未进测试矩阵**——问题 3/4 恰发生在该管线，而任务书四层体系未覆盖它。
教训已明：**通道测试≠行为测试；凡经模型编排的链路，验收必含真实复杂问题且至少跑 3 次看稳定性**。
