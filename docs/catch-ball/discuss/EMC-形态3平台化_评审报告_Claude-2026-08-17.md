## 一 议题1（主答）：E4 正式裁定

### 1.1 反证检验：「形态3 是否只是逃避可解问题」（任务书点名要求的反证）

评审的诚实性要求先做反证：如果 R3 诊断的入口聪明度问题是**可解且解法在自有能力圈内**的，那么形态3 就是逃避。逐层检验 R3 的四层机理：

**机理②参数闭卷填空（CB-08 实证：FC 选型 12/12 全对·瓶颈在参数）**

形态2 解法是 M2 参数接地——让 LLM 看见数据资产清单（list_data 工具+dataset_id 枚举）。检验：这个机制**与入口形态无关**——无论 NL 入口是自研 QA 还是通用 harness，工具消费方都需要知道"有哪些数据可查"。M2 在形态3 下不仅保留，而且升格：它变成 MCP 工具面的 schema 接地服务（工具参数的 enum 直接来自数据资产清单），是平台本体的组成部分。**未逃避——本来就要做，平台更需要。**

**机理④eval 失真（CB-01 C6：手工空 context 不反映运行时）**

形态2 解法是 M4 eval 重放（G6 session log）。检验：eval 的价值在于回归防护——这在平台形态下**收窄但不消失**：自研路由死了，路由 eval 随之降权；但工具面本身需要质量回归（工具可调用性/schema 稳定性/黄金问题平台版）。G6 降权为**平台 eval**（本报告 C10）是正确归宿而非丢弃。**未逃避——变形保留于 C10。**

**机理①开放问题空间 vs 封闭意图分类法（预判词表+尺度映射=有限字典索引无限空间·修补数学上不收敛）**

这是最核心的一层。形态2 解法是 M1 迭代诊断（多轮 FC 循环+失败恢复+澄清追问）。检验的关键在于：**M1 要构建的东西是什么？**——多轮工具调用循环、执行反馈吸收、失败重试、澄清追问。这四样东西**恰恰就是通用 agent harness 的定义性能力**（dsh/claude code/codex 的本体）。自研 M1 = 在自己项目里重造一个 mini harness = 与 DeepSeek/Anthropic/OpenAI 的商品化竞赛正面对撞。R4 的三次转移论证已经实证了这个竞赛的不对称性：通用 agent 的工具知识来自预训练（教材=整个 GitHub 的 geopandas/shapely 用法），EMC 的 19 契约是私有 API（模型零先验·每调优一条映射都是一次性的）；"词典竞赛赢不了"。**未逃避——该问题的解存在，但解就是通用 harness；把它交给通用层是正确解包，不是放弃。**

**机理③单发诊断不可恢复**

形态2 解法是 M3 计划生成（G9 CPD 复活·受控多步链）。检验：多步任务分解与执行的宿主能力=通用 harness 的 plan-execute 范式（三家 harness 均原生）。自研受控多步（G9）是为绕开开放 loop 病史（B001/B003）而设计的折衷——在宿主承担入口后，折衷的必要性消失（宿主的 loop 自带护栏与迭代）。**未逃避——外包给最擅长它的东西。**

**反证总结论：四层机理中两层（②④）的解法在形态3 下完整保留且升格，两层（①③）的解法本体就是通用 harness。形态3 不是逃避可解问题，是把"让入口变聪明"从自研义务正确地转交给商品化能力供给方，把私有投入集中于比较优势区（口径/知识/渲染资产）。用户论断「如何跑起来的路由不是个人开发者该做的事，在通用的基础上搭架子」经此检验成立。**

### 1.2 三支柱在平台形态下的存废变形（本报告最重的裁定）

CB-22 顶层铁律：纯回答稳定性 = ①本地知识库完备度 + ②EMC 架构（分类→范式映射）+ ③LLM 归纳总结，三者缺一不可。形态3 把 ② 的载体（diagnose→19 契约路由）停掉——支柱②是否随之消失？

**裁定：不消失，载体迁移。** 逐柱分析：

**支柱①（知识库完备度）**：不变且强化。C 线沉淀（体检域 fact/口径注册表/图层卡片）正是这一支柱的建设——形态3 让它从"产品的三支柱之一"升格为"平台的核心商品"。任何宿主 harness 消费 EMC 工具时，回答质量的下限仍由知识库厚度决定。

**支柱②（EMC 架构·分类→范式映射）**：这是唯一真正面临"存废之问"的支柱。范式知识——什么尺度的问题用什么方法、什么数据、出什么颗粒度的结论（尺度-方法-范式映射·paradigm.py 的决策树+尺度表+MEMORY 里沉淀的归因哲学）——**不随路由代码停投而蒸发，但也不会自动搬家**。它的迁移路径是唯一确定的：**编码进 MCP 工具面的设计**——
- 工具 `description` 编码尺度适用性（"本工具适用宏观面域问题·微观精确归因禁用"这类范式约束进描述文本）
- 参数 `enum` 编码数据资产（dataset_id 枚举=参数接地的平台化）
- 输出 schema 编码回答范式（返回值结构强制带口径标签/来源/结论性质元数据）

**承重判断（本报告核心增量）**：如果工具面只是裸暴露函数（名字+参数+返回值），那么蒸发掉的就**不是路由代码（那只是实现），而是范式知识的载体（那是十年领域积累）**——尺度纪律、颗粒度匹配、口径标注、铁律7（片区=结论）这些知识将无处栖身，平台退化为"一组 GIS 函数的 MCP 包装"，与直接用 geopandas 无异。故设**前置条件一=宪法 C11（范式编码义务）**：工具面设计评审必须过"裸函数"关——每个工具的 schema 里找不到范式知识的，不放行。

**支柱③（LLM 综合）**：让渡给宿主 harness——每家宿主都有自己的 LLM 与综合风格。这是三支柱中唯一"完全离开自有控制"的——其质量保证方式从"自建 finalStep+降级链"变为"平台输出质量高到宿主综合不会跑偏"（工具返回自带结构化结论素材·宿主只需组织）。**三支柱的平台形态表述：砍任何一根支柱，平台产出的可信度崩塌——①靠 C 线做厚、②靠 C11 编码、③靠返回值结构化设计兜底。铁律变形不失效。**

### 1.3 E4 成立的三项前置条件

1. **范式知识显式迁移（→C11）**：如上。这是形态3 从"正确的战略"落地为"正确的工程"的分水岭。
2. **参赛演示仍用现有 QA 壳（演示级冻结态）**：演示逻辑链（张力图面→引导点击→交互分析）三环中，"引导点击→交互分析"两环在形态3 下部分让渡给宿主对话——**现场演示质量从此依赖宿主发挥**（agent 当场怎么说是概率性的）。参赛评审场景对可控性的要求是绝对的：演示现场翻车不可接受。故参赛期现有 QA 面板=演示级冻结态（稳定冻结+bug 修完+零新能力）保演示主力；形态3 的薄入口/宿主消费是**赛后**主线。此条同时决定议题3 的时序。
3. **冻结的精确定义**：路由层"停止自研投入"≠删除≠放烂——①diagnose prompt 永不动（红线原文·冻结期自然满足）；②编排器确定性冻结期维持（纪律原文）；③**B002/B004 等 CRIT bug 仍须修完**（CB-39 D1 批不因形态3 取消——演示可信度在冻结期更重要·因为壳不再进化就只能靠"不撒谎"立信）；④冻结=不投新能力（M1/M3 停）+保稳修 bug。

### 1.4 形态2 与形态3 的关系

**不是渐进（先 2 后 3）、不是并行（两条都做），是吸收（3 包含 2 的有效子集）**：

- M2 参数接地 → 平台必需（工具面 schema 接地）→ **保留**
- M4 eval 重放 → 变形为 C10 平台 eval → **保留**
- M1 迭代诊断 → 解法=宿主 agent loop → **停**
- M3 计划生成（G9） → 解法=宿主 plan-execute → **停**
- M5 体内代码通道 → 宿主原生代码能力承担·但受宪法约束（见 1.5）→ **体内停·体外由宿主承担**

"先做形态2 再演进形态3"的路径不存在独立价值：M2/M4 无论哪种终局都要做（直接按形态3 做即可包含），M1/M3 无论哪种终局都不该自研。二分法消解。

### 1.5 M5 的特殊性（补充）

M5（有界代码执行通道）在形态3 下有个值得单列的治理问题：**通用 harness 写 geopandas 代码操作 EMC 数据 = 天然绕过工具面的全部内建约束**（脱敏/口径/审批/沙箱）。这正是议题6"正道好走"标准的存在理由——工具面必须好用到 agent **自愿选择工具而非裸写代码**（结构化输出/口径内建/免记纪律/错误语义化/可链式）。同时 C2/C5 的防线要意识到其边界：白名单挡得住工具参数，挡不住宿主直接读文件——**数据的敏感级分层（哪些数据裸读无害/哪些必须过工具）应作为宪法附录讨论项留给 Codex 工程评审**。

## 二 议题3（主答）：产品入口空窗的过渡策略

### 2.1 空窗的性质先认清

形态3 下非开发者（规划师/住建局）失去唯一入口（QA 面板冻结为演示级、不再进化）——但空窗的**实际痛感是分阶段的**：

- **现在~参赛**：演示对象=业内同行+评审（CLAUDE.md 画像·当前 demo 定位）——不是住建局实地交付。空窗零痛感。
- **参赛后~立项接触**：画像二（事企业单位）开始需要"打开就能问"——空窗开始有痛感。
- **长期**：城市运营单位（画像三）需要持续监测界面——薄入口或专用形态。

### 2.2 三阶段时序裁定

| 阶段 | 策略 | 细节与理由 |
|---|---|---|
| **现在~参赛** | QA 冻结壳（E4 前置条件2） | B002/B004/D 线 bug 修完；零新能力；演示脚本与 QA 壳锁定版本 |
| **参赛后~立项** | **自建薄壳为主**：前端 chat 组件 + MCP client（经后端薄代理·复用 ai_qa router 的 SSE 架子） | 量级估 2-4d；完全可控（不依赖 dsh 产品化节奏）；天然消费平台工具面（吃自己的狗粮=平台质量的最真实回归）；**"通用 FC over MCP"的最小实现**——一个聊天框+宿主级 FC 循环（或最简直连 MCP）即可。**dsh Web 场景 S 只作观察项**：其形态/节奏均不可控，立项接触不能押注第三方 roadmap |
| **长期** | 薄入口迭代·或被更好的通用消费形态替代 | 平台心态：入口是可替换的消费者·资产（数据/口径/知识/渲染契约）不绑定任何单一入口 |

### 2.3 配套登记

goal-status.md（CB-40 建立的每轮必更机制）增记"产品入口"维度：当前=QA 演示级冻结；规划=中期薄壳。空窗是**战略选择的已知代价**，如实记录而非回避。

## 三 议题6（主答）：平台宪法与"正道好走"标准

### 3.1 C1-C7 → C1-C11 平台宪法

R1 时 claude组 提的七条工具面硬约束（C1 PII 输出过滤 / C2 sim 白名单+demo=true 显式参数 / C3 gdb 不进 MVP / C4 三级审批（只读免审→产物写走宿主审批→删除类永不暴露）/ C5 路径沙箱前缀校验 / C6 key 不透传 / C7 铁律7 元数据随结果）直接升格入宪。形态3 下补四条：

**C8 契约单一源延伸**：MCP schema 一律从 `tool_contracts`（`contracts_to_tools_schema()`·:473 实存）派生·禁手写第二份 schema。依据：契约单一源红线在平台形态的自然延伸；CB-04 H1 教训（ForAI 自带默认绕过 computeStyle→彩虹图）的教训在工具面重演预防——手写 schema 就是下一代的"自带默认"。G8（契约派生自动化）是其工程实现。

**C9 工具面版本化**：工具面=对外 API 承诺。语义版本+破坏性变更须 deprecation 期（工具返回 `deprecated: true`+迁移提示·宽限期后移除）。依据：dsh组 R1 的 breaking 定量实锤（近 600 commit 内 16 个 `!:`·周级节奏）证明生态侧变更频率高——平台自己必须反例：变更慢、承诺稳，消费者才敢绑定。四 harness+薄入口都是消费者。

**C10 平台 eval**：G6 降权后的归宿。内容：每工具可调用性回归（schema 解析/参数校验/执行成功）+黄金问题平台版（5 个体检域问题经工具面跑通）+ schema 稳定性断言（C8 派生产物与 contracts diff=0）。CI 化。依据：三支柱③让渡给宿主后，平台自己可控的质量面收窄到工具面——防线从"每答必检"移到"每版工具必检"。

**C11 范式编码义务**（E4 前置条件一的落点）：工具 description 必须含尺度适用性/前置条件/输出范式说明；输出 schema 必须带口径标签（caliber）/来源（source）/结论性质（usage·铁律7）元数据；**工具面不得退化为裸函数清单**——设计评审逐工具检查 schema 里的范式知识含量，找不到的不放行。依据：1.2 承重判断——这是领域知识在平台形态下的唯一新载体。

### 3.2 「把正道修得比野路好走」的可操作判据

治理逻辑从"限制入口"（旧·防用户走歪路）转为"让正道成为最好走的路"（新·工具比野路强到没人想绕）。可操作化为五判据，每个 MCP 工具须答赢"**为什么不用 bash 裸调脚本**"：

1. **结构化输出**：JSON schema 保证的字段（vs bash 裸调解析 stdout——agent 解析文本是错误源）
2. **口径内建**：返回值自带口径标签/来源/作废状态（裸调要 agent 自己翻文档·口径注册表的知识随工具返回）
3. **脱敏/沙箱自动**：C1/C5 进程内强制（用户与 agent 都不用记纪律——纪律从条款变机制）
4. **错误语义化**：结构化错误码+建议动作（vs Python traceback——agent 可编程恢复 vs 只能重试或放弃）
5. **组合性**：dataset_id 枚举贯穿全部工具（A 工具输出=B 工具输入·类型安全链式；bash 裸调无类型链）

验收形式：工具面评审逐工具一行答辩（"用 bash 怎么做/用工具怎么做/差在哪"）；**答不赢的删或改**。R4 已实证：通用 harness 会写代码绕过不好用的工具——与其被绕过（且绕过时失去全部内建约束），不如不做或改好。

## 四 其他议题补充质证（Codex 主答·claude组 补充）

**议题2（渲染 API）**：zcode 的一般化教训（"资产没有稳定对外接口就会被锁死在当时的入口形态里"——19 契约锁死路由的前车之鉴）成立且是形态3 最大新工程的定性。补充三点：①最小可行形态=`render_layer` 工具——把 `computeStyle`/`terrainRampOf`/色带常量（grid-palette-tuning 记忆资产）+ generate\*ForAI 的"图层描述→MapLibre 样式"能力包成契约（输入=dataset_id+样式预设名·输出=样式 JSON/渲染指令）·**先契约后消费者**（契约先立·消费者可以是薄壳也可以是任何 harness 的浏览器联动）；②B012/B013（悬停归属/tooltip 显图层名）的教训提示：**渲染交互（hover/click/视野-数据-结论同步）在共享呈现层下的归属**（谁监听、谁派发、状态在哪）必须进 spike 验证项——这是比样式更深的耦合面；③样式预设名要成为受管词表（C8 派生）·防自由字符串漂移。
