### 焦点 2：用户上传层权衡 — **agree（derive 成功放行 / 失败 request_upload 为合理代理）**

**误伤分析**：
- 用户上传**无 name** 合法 GeoJSON（未命名区域）→ `_boundarySuspect` 可疑 → 触发 A 流程 → `deriveAvailable`：若该层要素名可匹配问句区名（层已加载·name 字段有值·即便请求 dict 无 name）→ **derive 成功 → p.boundary 被替换为精确要素 → 放行执行** ✅ 不误伤。
- derive 失败（用户上传层名不匹配问句 / 层未加载）→ **request_upload**：这是**诚实行为**——EMC 确实无法用该边界定位用户意图的区域（CB-14「EMC 不硬猜」·宁请求上传不瞎跑）✅ 合理。

**关键实现条件（防误伤/防冲突）**：
1. **仅当问句含区名**（`_regions` 非空·`harness.js:1604` 已提取）才触发 A——无区名场景（"按面聚合"）留给 validateParams ask_user「还缺 boundary」（既有路径·不与 A 冲突）。
2. **仅当 boundary 确实可疑**（复用 `_boundarySuspect`）才触发——derive 成功场景自然放行。
3. **区分用户上传 vs LLM 直传**：无 name 无法直接区分 → 以 derive 成功/失败为代理（成功=EMC 可定位→放行；失败=EMC 不能用→诚实请求）——**代理合理·无需来源标记**（方案 B 全量标记可后置）。
