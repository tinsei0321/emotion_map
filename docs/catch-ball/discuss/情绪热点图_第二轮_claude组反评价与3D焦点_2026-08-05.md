## 三、新增焦点 5（用户反馈 · 2D/3D 形式与 3D 效果）

### 5.1 用户定调（不可议）

- **热点图（Gi\*）= 2D 即可**——显著性符号层（点/格 + tier 分档），无需 3D。
- **热力图 = 2D+3D 还是只用 2D 需讨论（包括 3D 用何种形式）**——本轮讨论核心。
- **当前 3D「地形图」效果很差**：不是连续曲面、看不出起伏地势感——须给根因 + 业界正解。

### 5.2 效果差的根因（claude组 技术判断 · 实查代码）

当前 3D 地形 = `create_terrain_mesh`（F_007）contourpy **等值线环**（7 层离散 levels）→ 每环一个 Polygon → **fill-extrusion 逐 feature 固定高度**（spatial_analysis.py:846-1040 + heatmap-tool.js:875-921 + memory extrusion-height-maxheight）。

**为什么"不是连续曲面、看不出起伏"（三层原因）**：
1. **fill-extrusion 固有局限**：MapLibre fill-extrusion 每个 feature（环多边形）只有**一个固定高度**，不能表达面内连续高程 → 7 层环 = **7 级梯田/千层饼**，不是曲面；
2. **等值线环是"区域平涂"**：环内 `_level` 恒定（高度只随环级跳变），环与环之间是离散台阶——从侧面看是阶梯，从顶上看是色块；
3. **7 层 quantile levels（0.25~0.97）**：层级少 + 低环区域大，视觉重心被大面积低环（接近贴地）占据，峰顶只有顶层小环——"山体"被压扁成平涂色带。

> 注：与 2D 网格柱（grid 3D 方格柱）不同——柱林至少逐格有高度梯度；地形环是"整环同高"，起伏感更弱。这正是"看不出地势"的技术根源。

### 5.3 业界 3D 连续曲面正解（claude组 调研 · 出处标注）

| 方案 | 做法 | 连续曲面 | 成本 | 风险 |
|---|---|---|---|---|
| **a. MapLibre `setTerrain` + raster-dem 源** | 后端把 KDE 栅格编码为 **RGB DEM**（PNG/GeoTIFF·Mapbox 标准高程编码）→ 前端 raster-dem source + `map.setTerrain({source, exaggeration})` → **MapLibre 原生三角网地形**（真实连续曲面）| ✅ 真曲面 | M（后端 DEM 编码 + 前端 terrain 接线）| 低（MapLibre v2+ 官方支持·[官方 3d-terrain 示例](https://www.maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/)·[maptiler 新闻](https://www.maptiler.com/news/2022/05/maplibre-v2-add-3d-terrain-to-your-map/)：**"MapLibre 创建三角网表示地形表面"**）|
| **b. deck.gl TerrainLayer** | deck.gl 加载 GeoTIFF DEM → 连续三角网 | ✅ 真曲面 | M（deck.gl 依赖 + 与 MapLibre 渲染栈混用）| 中（memory 教训：deck.gl GridLayer extruded 在 MapLibre 不渲染——[deck-gl-gridlayer-extruded-broken]；TerrainLayer 是独立渲染栈需验证；引入第二渲染栈）|
| **c. 保留 fill-extrusion 改造** | 细网格片（非等值线环）逐片高度 → 连续近似 | ⚠️ 阶梯近似 | S | 中（计算量大、仍是近似非真曲面）|
| **d. THREE/customLayer 手写三角网** | WebGL custom layer 自建 mesh | ✅ 真曲面 | L | 高（自研渲染、维护成本）|

**claude组 初步倾向**：**a（MapLibre `setTerrain` + RGB DEM）**——官方原生、真连续三角网、exaggeration 可调地势夸张度、性能好，且 KDE 栅格后端已存在（histogram2d+卷积结果直接编码 DEM 即可），不引入第二渲染栈。2D 热力保留（MapLibre 原生 heatmap·radius 屏幕尺度·快）；3D 地形作为演示张力增强（张力图面环）。

**待两组讨论的子问题**：
1. a vs b vs c 的选择（含 RGB DEM 编码成本、exaggeration 视觉效果、与既有 fill-extrusion 图层/3D 网格柱共存的渲染冲突风险——`setTerrain` 是**全局地形**，会影响地图底面与所有图层的投影）；
2. 2D 与 3D 是否共用同一 KDE 栅格（2D radius 屏幕尺度 vs 3D bandwidth 地理尺度——两组第一轮已指出两路径参数不一致，是否统一到后端栅格一条链）；
3. 3D 保留/废除/降级的判定：若 3D 用 setTerrain，现有 7 层 fill-extrusion 地形是否退役（退役台账 retired.md）；
4. 演示优先级：2D 为主 + 3D 后置，还是 3D 一起上（用户"今天定稿执行"的时间约束）。
