## 一、0b · EMC RAG vs 官方窗口价值定位 — **agree（工作台 vs 问答机·聚焦非劣势）**

**claude 定位**：官方"全量塞上下文"vs EMC"检索 Top-K+出处+工具"·工作台 vs 问答机。

**glm 判定**：**agree——价值定位准确·聚焦本地化是 EMC 核心优势（产品定位·KNOWLEDGE :49）。**

**glm 深化（3 维对比）**：

| 维度 | 官方窗口 | EMC RAG |
|---|---|---|
| **上下文策略** | 全量塞（1M·泛领域） | 检索 Top-K（聚焦宜昌专题） |
| **知识来源** | 互联网（泛·浅） | 本地知识库（专题·深·权威源） |
| **工具** | 通用（搜索/代码/写作） | 专业（GIS 空间分析 + 情绪归因 + 体检指标） |
| **定位** | **工作台**（泛领域助手） | **问答机**（聚焦专业蒸馏） |
| **核心价值** | 广度（什么都能答） | **深度+本地化+聚焦+可追溯**（KNOWLEDGE :49 产品定位） |

**glm 关键**：
- EMC **不是"弱版官方窗口"**——是**不同定位**（聚焦专业蒸馏 vs 泛领域工作台）。
- "检索 Top-K+出处"vs"全量塞"不是降级——是**设计选择**（聚焦反而更准·专题深度 > 泛领域广度）。
- 用户类比"EMC = 迷你版 AI 平台"——glm 修正为"EMC ≠ 弱版平台·EMC = **聚焦专业蒸馏工具**"（产品定位差异·非能力高下）。

**glm 价值确认**：
- EMC 核心优势 = **本地化（宜昌专属）+ 聚焦（更新/体检专题）+ 专业（权威源/政策/指标）+ 可追溯（来源引用）**。
- 官方窗口做不了这 4 点（无本地知识库/无专题聚焦/无权威源/无出处标注）。
- **EMC 不需要追平官方**——聚焦定位反而更准（用户原话"EMC 不需要平台那么强·聚焦反而更准"）。

## 二、0c · 性能差距根因（4 因素·glm 逐条验证）

### 因素 ① 模型 tier—— **agree 成立（EMC 全链路强制 flash）**

**claude 假设**：EMC 默认 flash·diagnose 硬编码 flash·官方可能 pro。

**glm 核实（铁证）**：

| 组件 | 现状 | 证据 |
|---|---|---|
| 后端 DEFAULT_MODEL | MODEL_PRO（`deepseek-v4-pro`） | llm.py:24 `DEFAULT_MODEL = MODEL_PRO` |
| **前端默认** | **强制 flash** | panel.js:27-29 `_thinkMode = 'flash'`（CB-12 拍板"flash 足够·强制 flash·pro 停用"） |
| **diagnose 阶段** | **硬编码 flash** | stages.js:278 `model: 'flash'`（不可配·始终 flash） |
| **finalStep 阶段** | **强制 flash** | stages.js:471 `pro 停用·最终守卫强制 flash` |
| optimize 阶段 | 硬编码 flash | stages.js:458 `model: 'flash'` |

**glm 定案**：
- EMC **全链路强制 flash**（diagnose/finalStep/optimize 均 flash）——虽然后端默认 Pro·但前端 CB-12 用户拍板强制 flash 覆盖。
- 官方窗口可能用 **pro**（旗舰推理·1M 上下文）——能力基线高一档。
- **flash vs pro 差距**：flash 快但浅（推理/理解/综合能力弱一档）·pro 慢但深。
- **即因素 ① 成立**——EMC 全 flash vs 官方可能 pro·能力基线差一档。

**但 glm 关键背景（CB-12 用户主动选择）**：
- CB-12（2026-08-08 前后）用户拍板"flash 足够·pro 停用"——是**超时优化决策**（pro 慢·1M 上下文 + 深度推理 → 延迟大·用户感知 60s+）。
- **即 flash 强制是用户为速度主动选的**·非 claude 技术失误。
- **如果性能差距是 flash vs pro·用户当初的"flash 足够"判断需重新审视**——知识问答（需 LLM 综合）可能需 pro（推理/综合更深）。

**glm 建议（重新评估 CB-12 flash 决策）**：
- CB-12 时"flash 足够"针对的是**分析类**（zonal/rank → 图层·flash 够）。
- 知识问答（RAG → LLM 综合·归纳素材+引用）**可能需 pro**（综合/归纳/表述深度 > 分析工具执行）。
- **建议**：知识问答通道（knowledge_qa）**可选 pro**（diagnose 判 knowledge_qa → finalStep 用 pro·非强制 flash）——**这是缩小性能差距的直接手段**。

### 因素 ② 中介层限制型—— **agree 成立（限制型 harness 防错优先 vs 增强型放权 LLM）**

**claude 假设**：规则短路/JSON 卡/FC 选型/图层模板 = 限制型（削弱 LLM）。

**glm 核实**：

| 限制型机制 | 位置 | 效果 |
|---|---|---|
| _quickIntent 规则短路 | harness.js:60-82（127 条 if/return 规则） | 抢判断（在 LLM 之前）·限制 LLM 自由 |
| JSON 诊断卡约束 | prompts.py:198-214（严格 JSON·禁自然语言） | 约束 LLM 输出格式（防自由发挥） |
| FC 工具选型 | router.py（14 工具·LLM 从预选选·非自由） | 限制 LLM 工具空间 |
| FINAL_TEMPLATE 图层导向 | prompts.py:134（图层主出口·严禁只给文字） | 约束 LLM 回答范式 |

**glm 判定**：**因素 ② 成立**——EMC harness 是**限制型**（防错优先·多层约束）vs 官方**增强型**（放权 LLM·少约束）。
- **限制型优点**：防幻觉/防越维/防编造（EMC 诚实铁律）。
- **限制型缺点**：削弱 LLM 自由（判断/创造/综合受限）。
- **本次失败正因此**——限制型 _quickIntent 词表脆弱 + diagnose 无知识问答分类 = 知识问答被限制层拦死。

**glm 关键（限制型 vs 增强型取舍）**：
- 限制型是 EMC **设计哲学**（AI·Copilot 内核：Dumb 中间稳定 + Smart 两端）——非 bug。
- 但**知识问答需增强型**（LLM 综合是核心·三支柱③）——限制太强则 LLM 无法综合。
- **修复方向**："限制型→增强型"不是全盘放权·是**精准松绑**：
  - 意图判断归 LLM（diagnose 判 knowledge_qa·非规则短路）= 松绑。
  - 知识问答走 LLM 综合（非零 LLM 拼列表）= 松绑。
  - 但防幻觉/防越维/引用来源保留（三支柱质量底线不松）。

### 因素 ③ 上下文降级—— **partial（设计选择 vs 降级）**

**claude 假设**：EMC 注入小上下文+截断 vs 官方全量 1M。

**glm 核实**：
- EMC ctx.context 注入：RAG Top-5 × 1000B = ~5000B + 指令 ~500B = ~5500B（glm 上轮 B2 已核实）。
- vs 官方 1M 上下文——**量级差距巨大**。
- 但 EMC 的"小上下文"是**检索 Top-K**（精准注入相关素材）·非"降级"——是**设计选择**。

**glm 判定**：**partial**——
- **量级差距客观存在**（5500B vs 1M）——EMC 上下文远小于官方。
- 但**非"降级"**——EMC "检索 Top-K+出处"是**精准注入**（只给相关素材·vs 官方全量塞可能含噪声）。
- 聚焦场景下·5500B 精准素材可能**比 1M 全量更好**（信噪比高·LLM 不被噪声干扰）。
- **差距在"上下文不够时"（复杂跨文档综合）**——EMC Top-5 可能漏相关素材·官方 1M 不漏。

**glm 建议**：
- EMC 上下文策略是**设计选择**（聚焦精准）·非需改。
- 但可**提升 Top-K**（5→10？或动态·复杂问句 K=10·简单 K=5）——覆盖更多素材·缩小"漏检"差距。

### 因素 ④ 官方底层闭源—— **agree 成立（客观差距·不可追平）**

**claude 假设**：harness/mcp/微调/后处理闭源·API 拿不到。

**glm 判定**：**agree——客观事实·不可追平。**

**glm 分析**：
- 官方窗口底层：定制 harness + MCP 工具 + 微调模型 + 后处理 pipeline——**闭源·API 用户拿不到**。
- EMC 用公开 API（DeepSeek V4 flash/pro）——无定制 harness/微调/后处理。
- **这是结构性差距**——API 用户 vs 平台方·能力不对等（平台方有微调+后处理加持）。
- **不可追平**——除非 DeepSeek 开放微调/后处理 API（短期不可能）。

**glm 诚实**：因素 ④ 是**不可消除的差距**——EMC 能做的是"缩小"（因素 ①②③ 可改善）·非"追平"（因素 ④ 不可改）。

## 三、修复方向评估（限制型→增强型·glm 逐条）

**claude 方向**：EMC harness 从"限制型"转"增强型"（理解归 LLM + 检索补强 + 工具三通道 + 提示词增强·诚实边界 = 追不平但大幅缩小差距）。

**glm 判定**：**agree 方向对——但精准松绑（非全盘放权）·守三支柱质量底线。**

**glm 修复优先级（4 层·按因素对应）**：

| 因素 | 修复 | 优先级 | 可缩小差距？ |
|---|---|---|---|
| ① 模型 tier | **知识问答通道可选 pro**（diagnose 判 knowledge_qa → finalStep 用 pro·非强制 flash） | P0 | ✅ **直接缩小**（pro 综合能力 > flash） |
| ② 限制型 harness | **意图判断归 LLM**（diagnose 判 knowledge_qa·_quickIntent 降级加速器） | P0 | ✅ **直接缩小**（LLM 判断 > 规则词表） |
| ③ 上下文 | **Top-K 动态**（复杂问句 K=10·简单 K=5·或按 recall 调） | P1 | ✅ 部分（覆盖更多素材） |
| ④ 闭源 | — | — | ❌ **不可改**（诚实标注） |

**glm 关键（因素 ① 是最直接的缩小手段）**：
- CB-12 强制 flash 是为**分析类**速度（zonal/rank flash 够）。
- **知识问答需综合/归纳**——flash 能力弱一档·pro 显著更强。
- **建议**：knowledge_qa 通道**默认 pro**（或可选）——用户为知识问答质量接受稍慢（pro ~10-20s vs flash ~5s·质量差值得）。
- **vs 分析类**：分析类保持 flash（工具执行 flash 够·速度优先）。

**即 EMC 分 tier**：
- 知识问答（knowledge_qa）→ **pro**（综合深度优先）。
- 分析类（gis/emotion）→ **flash**（速度优先·flash 够）。
- 概念问（general）→ flash（简单定义·flash 够）。

## 六、结论

### 0c 性能差距根因：4 因素成立度

### 修复方向"限制型→增强型"：**agree**（精准松绑·守三支柱·缩小但不追平）

**glm 核心立场**：
- EMC **不需要追平官方**（聚焦定位·产品优势）·但**聚焦也要做到最好**。
- 性能差距 4 因素：①②③ 可改善（须做）·④ 不可改（诚实标注）。
