## 2 · rag_query 范式 — **两级（不是二选一）：确定性组装（高置信主路径）+ 注入指令（开放语义兜底）**

| 层 | 条件 | 范式 | LLM |
|---|---|---|---|
| **L2 确定性组装** | Top-K **全 fact 类型** + min score ≥ 阈值（如 0.6） | 条目式事实卡拼接 + 来源 + 维度声明（**复用 EXIT_CONCEPT 卡机制**·零 LLM） | ❌ 根治 |
| **L3 注入指令 + finalStep** | 开放语义/需跨文档综合 | "知识问答排版"指令（仿 quick-general `:963`·禁图层/禁 4×5）·LLM 综合 | ✅ 治标但必要 |

**理由**：事实卡直命中 = 结构化数据·确定性可拼（零幻觉·根治）；开放语义问（"哪些城市用片区统筹"）需跨文档综合·LLM 必要——**两级按检索结果类型分流**（同 B 的 L1/L2/L3 分级思想）。

**顺序建议**：先 L3 注入指令（**立即修复本次失败**·1 行）→ 确定性组装（L2）随 B 路径落地（**复用 query_knowledge_base 组装器·不重复实现**）——rag_query 的确定性分支与 knowledge_query 共用同一组装函数。

## 3 · knowledge_query 与 rag_query 关系 — **同一"知识问答范式"的两级·非并列**

```
知识问答范式（分类 = knowledge_query 优先 → rag_query 兜底）：
  L1 knowledge_query 确定性 WHERE 命中        → 直答（零 LLM·B 路径）
  L2 rag_search 全 fact 高置信                 → 确定性组装（零 LLM·复用 L1 组装器）
  L3 rag_search 开放语义                       → 注入指令 + finalStep（LLM 综合·禁图层）
  L4 全失败                                   → EXIT_CONCEPT 诚实兜底
```

- B 落地后 RAG 触发词收窄（只留开放语义）·**knowledge_query 承担 L1**·rag_query 承担 L2/L3——**两级同源同组装器·不双建**
- 事实卡扩量（CB-22b 已建议）→ L1/L2 命中率提升 → 确定性路径占比↑·LLM 路径占比↓（正反馈）

## 4 · 映射落地方式 — **推荐"集中映射表 + 分支执行"（不新建编排层）**

| 方案 | 判定 |

| 新建编排层（统一 dispatch） | ❌ 过度设计·承重（现有分支已工作·重组风险大） |
| **集中映射表 + 分支执行** | ✅ **推荐**：`emc-patterns.js` 加 `PARADIGM_MAP = {general:'text_qa', rag_query:'knowledge_qa', knowledge_query:'knowledge_qa', gis_operation:'layer', emotion_analysis:'layer'}`·各分支读取（显式·可测·可审计）·**执行仍在各自分支**（最小改动） |
| 纯分支内隐式 | ⚠️ 现状（映射不显式·缺陷来源） |

**测试**：`PARADIGM_MAP` 完整性单测（5 分类都有范式·e2e-seam 可测）·分支行为 e2e（rag 指令断言）。
