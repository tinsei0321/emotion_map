## 一、逐焦点评估

### 焦点 1：P1-1 需求强度分级阈值 — **disagree（阻断级·值域双轨未处理）**

**计划**：分级 高(≤-1) / 中(-1~-0.15) / 低(>-0.15)·对齐 valenceOf（state.js:329-338）±0.15/±1。

**glm组 发现阻断级问题：polarity_index 值域双轨制·计划未处理。**

**证据（glm组 独立核实 core/spatial_analysis.py）**：
- **L1 路径（3 级极性·:267）**：`polarity_index = (n_positive - n_negative) / denom` → **值域 -1~1**
- **L2 路径（5 级极性·:277-282）**：`polarity_index = (very_pos*2 + pos*1 + neg*-1 + very_neg*-2) / point_count` → **值域 -2~2**
- docstring（:216）称"polarity_index: 综合情绪指数（-1~1）"——**但这是 L1 的注释·L2 实际可达 ±2**（实测：全 very_negative → -2.0）

**后果（计划分级在 L2 失效）**：
| polarity_index 值 | 计划分级 | valenceOf（state.js:329） | L1/L2 语义 |
|---|---|---|---|
| -2.0（L2 全非常消极） | 高（≤-1） | 非常消极 | L2 真实"非常消极" ✅ |
| -1.5（L2 偏非常消极） | 高（≤-1） | 非常消极 | L2 真实"非常消极"·**但 -1.5 与 -2 同档·粒度丢** |
| -1.0（L1 全消极 / L2 边界） | 高（≤-1） | 非常消极 | L1 = 全消极已是极端 ✅ / L2 = 仅"消极偏强" |
| -0.5（消极） | 中（-1~-0.15） | 偏消极 | ✅ 一致 |
| 0.0（中性） | 低（>-0.15） | 中性 | ⚠️ 语义问题（焦点 1 第二问）|

**核心问题**：L2 的 -2~-1 区间（"非常消极"到"消极偏强"）在计划分级里**全判"高需求"**·无法区分——这丢失了 L2 五级极性的粒度优势（L2 比 L1 多"非常"档）。

**glm组 建议（2 选 1·P1-1 须先解）**：

**方案 A（推荐·归一化值域）**：
```python
def grade_demand_intensity(polarity_index, level='L2'):
    """需求强度分级（P1-1）。L2 值域 -2~2 归一化到 -1~1 再分级·L1 直接用。"""
    pi = float(polarity_index) if polarity_index is not None else 0
    if level == 'L2':
        pi = max(-1, min(1, pi / 2))   # -2~2 → -1~1 归一化
    if pi <= -0.5: return ('高', '极性 <=-0.5（非常消极）·需求强烈')
    if pi <= -0.15: return ('中', '极性 -0.5~-0.15（消极）·有需求')
    return ('低', '极性 >-0.15（中性/积极）·无明显负面需求')
```
- 阈值用 -0.5（归一化后）区分"非常消极/消极"·保留 L2 粒度。
- L1 直接用原值（-1~1）·-0.5 阈值区分全消极/偏消极。

**方案 B（双轨阈值）**：L1 用 ±0.15/±1·L2 用 ±0.3/±1.5（按 -2~2 值域缩放）。**不推荐**——双阈值维护复杂·易漂移。

**"低"档语义问题（计划焦点 1 第二问）**：
- 计划"低"档 `pi > -0.15` 含中性 + 积极——**"需求强度低"语义不准确**：
  - 中性（pi≈0）= 无明显情绪倾向 → 应是"**无显著需求**"而非"低需求"
  - 积极（pi>0.15）= 满意 → 应是"**无负面需求**"（不该排在"需求强度"体系里）
- **glm组 建议**：分四档更诚实——`高 / 中 / 低 / 无显著`（pi>0.15 = 无显著负面需求）·或"低"档文案改"无明显需求（中性/积极）"·明示非"低需求"。

### 焦点 2：P1-2 复合优先级权重（0.5/0.3/0.2）— **partial（方向对·覆盖度归一有坑）**

**计划**：`priority = 强度×0.5 + 覆盖度×0.3 + 主题契合×0.2`·覆盖度 point_count/全域 max（缺省 0.5）·主题契合 1/0.5。

**glm组 判断：方向对（升级单一 polarity 降序合理）·3 个边界须明确。**

**① 权重分配合理性**：
- 强度 0.5（主）+ 覆盖度 0.3（规模权重）+ 主题契合 0.2（相关性）——**比例合理**·对齐"需求 = 强度为主·规模与相关性辅助"的行业直觉。
- 但**权重是经验值·非数据校准**——建议 P1 文档标"权重为启发式初值·待真实数据回归校准"（诚实标注·非定论）。

**② 覆盖度归一（point_count/全域 max）的坑**：
- "全域 max"——**全域指什么？**当前 zonal_stats 的所有单元的 max point_count？还是 L2 全数据集的 max？
  - 若是"当前 zonal 的所有单元 max"——则归一化是**相对的**（同一次分析内可比·跨分析不可比）。
  - 若是"L2 全数据集 max"——则需要传全局参数·build_outlet_schema 当前只收 `result`（单次产物）·**拿不到全域 max**。
- **glm组 建议**：明确"全域 max = 当前 result.rows 的 max point_count"（相对归一·同次分析内可比）·缺省 0.5（无 point_count 时）。**禁用跨分析绝对归一**（拿不到全局·且不同区域 point_count 基线不同）。

**③ 主题契合 1/0.5 粗糙性**：
- 有 domain_top/element_top 值 = 1·空 = 0.5——**粗糙但可接受**（P1 初版）。
- 更细可分"domain 命中 +0.5 / element 命中 +0.5 / 都空 0.5"——但 P1 初版用 1/0.5 够。
- **glm组 建议**：主题契合**只在问句含 domain/element 意图时才参与**（如问"设施类需求排序"才用 element 契合）·否则所有单元主题契合都=1（无判别力）·浪费 0.2 权重。**建议**：问句无主题意图时·主题契合项权重转给强度项（0.7/0.3/0）。
