## 白话摘要

上一批（S3）把家里所有收音机都改成了标准插座；这一批（S4）把「电台」本身升级——以前电台（引擎）播节目用的是内部暗号，靠家里一个翻译员（emitter）转成标准信号；现在电台直接播标准信号，翻译员退休。

而且新信号自带「质检合格证」：每条节目按官方格式表（JSON Schema）的要求逐字段填写——节目编号（toolcall_id）、节目名（verb）、播出序号（seq）一样不缺，将来跨机器传输时接收方拿格式表一验就知道合不合格。家里的收音机完全没换（播放内容一个字没变，验收时新旧信号逐字段对过），墙上也没多打一个洞——引擎的循环逻辑零改动，只换了「往外播」的那一小块，总共 4 行。

验收四层：①单测从 35 项扩到 56 项全过（含「信号必须带合格证」「节目编号首尾配对」等严检）；②浏览器全链路三场景复验全绿（走的就是新发射器路径）；③隔壁组留下的冒烟测试（S7）三场景也全绿；④评分锚点文件依旧一字未动。

小插曲：按隔壁组测试文件里留的开关指引，试着把「mock 电台」切到「真电台」，结果本机没有外网、真电台的信号源（DeepSeek）够不着——按预案切回 mock 并在开关上写清楚「联网机器再开」，两边机器互不耽误。

## 二 wire 造型纪律（S6 schema 对齐·关键决策）

1. **四族严格**：msg_delta（kind/delta/session_id/turn_id/seq）/ tool_begin（toolcall_id/verb/session_id/turn_id/params_summary）/ tool_end（同 id 配对+result_summary 摘要）/ error（code/message/session_id）——键集白名单（additionalProperties:false 纪律）。
2. **followup_cues 不入 wire**：tool_end schema 尚无此字段（S2 增补在途）——bus 载荷照带（S5 链路活）·wire 不带（防 schema 违例）。S2 增补后随载荷结构模式入。
3. **turn/render 族不带 wire**：wire schema 未定稿——bus 直发（与 S3 逐字兼容）。
4. **诚实性边界**：空 token 不造型 wire（minLength:1）但 bus 照发（渲染不断流）；孤立 observation（无前置 call 可配对）不造型 wire·载荷照发；session_id 用稳定占位 `emc-shell`（session 语义 v1 不建·S3 决策 2 延续·BrainAdapter 阶段补真实 session 对象）。
5. **toolcall 配对**：onAction 发 toolcall_id/verb → onObservation 回填同 id 同 verb → 一次配对一对。
