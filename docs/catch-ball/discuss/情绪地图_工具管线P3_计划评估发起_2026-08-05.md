## 〇、P3 执行计划全文（claude组 起草 · 待两组评估）

### 背景：现状管线

| 路径 | 执行方式 | 工具间关系 |
|---|---|---|
| `runTemplatePath` | 单技能（1 工具）| 无依赖 |
| `runChainPath` | CHAIN_REGISTRY 2 条链（extract_overlay / clip_density）·串行 | `$n` 前序产物引用·**有依赖·必须串行** |
| `runAllToolCalls` | multi skill（LLM 产多 tool_calls）·**顺序执行** | 现状未判依赖·**全部串行**（可并行但未并行）|

### P3 目标

**工具间协作 = 线性（依赖串行）+ 并行（独立并行）编排**——让"无依赖的独立分析"并行执行（墙钟提速·对齐编排器确定性·不交 LLM 判依赖）。

### P3-1 依赖图判定（纯函数·确定性·不调 LLM）

- 落点：`frontend/js/ai_qa/harness.js`（或新 `dep-graph.js`）
- 逻辑：对 `tcs[]`（multi 工具调用列表）判依赖关系：
  ```
  依赖判据（两工具 A→B）：
    ① A 的产物被 B 引用（$n 引用 / layerId 传入 B.params）
    ② B.params 含 A 的 layerId / 前序产物引用
    ③ 同源数据链（A 聚合 → B 在其结果上分析）
  无依赖（可并行）：不同数据源 / 不同维度的独立分析（多极性 density / 多域 zonal）
  ```
- 输出：依赖图（DAG）→ 拓扑排序 → 并行组（同层可并行·层间串行）
- **对齐 AI·Copilot 内核**：依赖图由编排器代码判定·不交 LLM（铁律 4"编排器确定性"）

### P3-2 并行执行（Promise.all 同层）

- 落点：`runAllToolCalls` 改造——按依赖图分层 → 同层 `Promise.all` 并行执行
- 约束：
  - **无 `$n` 依赖 / 独立数据源才并行**（Codex 上轮共识）
  - 结果合并：同层成功后按原 tcs 顺序写入 toolHistory（保顺序确定性）
  - 失败处理：并行组内一步失败不阻塞其他（各自 failedSteps 记录）
- **墙钟收益**：多极性 density（3 个独立）3 并行 → 1 次耗时（~3×→1×）

### P3-3 编排器稳定性保护（红线区 SOP）

- **先扩 eval 再动**：新增 `tests/browser/` 或 test-cases.js 并发用例（依赖图判定纯函数单测 + 并行执行 E2E）
- **一次一处**：P3 改动独立 commit·不与 P0/P1/P2 混
- 回退路径：并行开关（`PARALLEL_ENABLED` 常量·默认开·回归异常可一键关）

### P3-4 地点联动（用户方向 C·工具出口联动地点）

- 现状：CB-15 已落地（place_name 双源 + poi_names + place_name_source）·P0 结论段已按尺度取地点·P2 出口卡已 scale 标注
- P3 补：**工具出口统一地点字段**——各工具返回结果统一带 `place_name`（若含空间落点）·供 EMC/出口消费（确定性·非新分析）
