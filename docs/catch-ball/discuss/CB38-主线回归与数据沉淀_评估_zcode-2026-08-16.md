### F2 RAG 数据层级设计 —— 单库 + domain 字段，反对目录分库

**主张：物理单索引不变，meta.jsonl 加 `domain` 字段（建议枚举 `checkup` / `renewal` / `base`），检索默认全域、后续可选域加权。**

理由（按承重排序）：

1. **体检/更新是交叉问题域，不是互斥分区**。产品出口抽象层要求 EMC 答案同时对接体检（找问题）与更新（项目对接）——典型问法「西陵区停车缺口对应哪些更新项目」天然跨双域。目录分库会把交叉问题变成「先选库再检索」的路由问题，新增 domain 误路由这一失败模式；单库 + 标签则保底全域检索永远可用。
2. **域信号在 fact 层已存在，只差规范化**。实测 67 条 fact = 52 URP-\* + 15 CHK-\*（前缀即域），topic 字段已有「城市体检」×11/「城市更新项目库」×4。加 domain 字段是把已有信号统一，不是新造概念（符合术语纪律）。
3. **规模不支持分库的理由**。295 条 → 沉淀后预计仍 <1000 条量级，numpy 暴力余弦检索毫秒级，分库无性能收益纯增复杂度。
4. **工程增量最小**。`rag_index.py` 四个 `_load_*` 各加一行 domain 赋值 + meta 落盘 + search 透传，老索引 `--build` 重建即迁移，无 schema 破坏。

**四类型够用，不造第五类型**：体检沉淀映射——77 项率值/占比矩阵/宏观率值 17 项 → fact（指标/口径卡）；`汇总/page*.md` → note（成文切段）；方法论/边界认知 → concept；他城做法 → case。现有四类语义完整覆盖，符合「禁概念创造」。

**「宜昌市基础数据」域（base）：支持，但严格限定为口径卡**——只收 22 街办/174 城市社区/1562 小区/26426 楼栋、去村口径、坐标系、来源这类**跨域共用口径 fact**；POI 明细/空间数据不进（那是图层体系的事，见 F3）。域数 3 个封顶，防域爆炸。

**zcode 独立发现——存量分域债（发起文档漏项）**：现有 214 条 note 全部来自 `docs/urban-renewal-plan/`，其中 `00-宜昌专项/03-05~03-08`（葛洲坝体检报告/2024 国土空间体检/2025 体检全维度/2025 体检报告摘要）是**体检域**笔记，`00-01~00-06` 是**更新域**笔记，`_笔记/12345治理方法论` 属体检主观轨方法论。目录规则可推断大半（03- 指标体系类目录混有标准指南需人工过），**存量回溯标注 + 抽检是分域工程的隐藏工作量，实施计划必须列入**，否则「分域」只对新数据生效、旧检索结果仍混域。

**事实修正**：发起文档「295 条（08-11 口径·体检 fact 67）」表述错误——67 是 fact **总量**，其中体检域 CHK-\* 仅 **15 条**。此数直接影响「体检域现有底子多薄」的判断（15 条 vs 67 条，差 4.5 倍），收敛稿须改。

### F3 大文件边界 —— 同意确认，并补两条硬边界 + 一个可校验契约

同意：geojson/xlsx 一律不进 RAG。实测大文件 Top：小区面 16M / 住宅点 6.6M / 楼栋质心 6.2M / 12345 有坐标点 5.7M（18,130 要素）——向量化这些既无意义也违背「RAG=本地化聚焦的专业知识蒸馏·非空间数据库」定位。

## 四 任务③：时间轴重构——zcode 边界意见（一句边界 + 支撑）

**边界一句话：重构范围=「数据源与时间语义全替换、manifest 发现机制保留」，波及面必须从「前端三件」扩为「前端三件 + geo_registry 点层注册 + DATA/performance 布局 + manifest 生成红线 + 飞轮测试基建」五处；真实时间点与 T1~T3 演示数据严禁同轴混挂。**

支撑三点（对应发起方留给下周的三问）：

1. **数据源时间字段规范**：manifest dataset 声明 `time_field + time_format`，**时间不再编码进文件名**（现 `yichang_L2_T1_L2_result_csv.csv` 把时间刻度焊死在名字里，正是三段式耦合的根源）。年度体检/12345 分年度数据按真实时间戳入 manifest。
2. **UI 离散 vs 连续**：真实时间点天然离散且稀疏（2024 体检/2025 体检/12345 分年度≈2-4 个点），**离散节点式刻度**（chip/步进）是唯一合理形态——连续 slider 在两个时间点下不可用。好消息是现有 T1-T3 三节点交互形态本就同构，改动主力在数据语义不在交互范式。
3. **并存 or 替代**：**数据替代、机制保留、分域挂轴**。time-source 的 manifest「发现」机制（注释自称「不写死 T1/T2/T3」）本就是为自由时间点设计的，T1~T3 只是当前数据 occupant。演示数据（performance 的 yichang/ermawu）若保留演示用途，应与体检真实时间轴**分 manifest**——真实时间点轴上出现 sim/演示数据 = sim 禁入红线的时间轴版本，一票否决。

排期建议：下周「时间轴工程」与「E3 修 404」合并为一个 CB 任务（同一地基）；E1/E4 浏览器复测可作为其附属验收场。**开工前 Codex 先出 T1~T3 全仓引用清单**（zcode 粗测 12 个文件含相关模式，含 test-cases.js/test-assets.js 飞轮基建），清单先行防漏改。
