## 〇、执行摘要（结论先行）

**核心命题**：情绪地图·EMC 的"出口"指的是——**在情绪地图完成意图判断与空间分析之后，把分析结果作为"资源"进行再理解、再整理，最终格式化对接到行业明确接口的过程**。这是"成果范式 agent"的职责，是意图 agent 与结果 agent 之后的**第三段**。

**底层逻辑（铁律）**：**情绪地图·EMC 去找市场接口，而非让市场来反向对接情绪地图·EMC**。情绪地图的每一个答案，必须对应某个具体的项目/指标/任务/编制板块——有明确的、具体的指向性，具备实操价值，不能泛泛而谈。

**当前缺口（立项风险点）**：情绪地图已具备成熟的**入向链路**（用户问句 → 诊断卡 → 工具执行 → 前端产物），但**出向链路（分析结果 → 行业格式化产物 → 编制/体检流程）= 0**。现有"出口"只指前端交互对象（图层/卡片/胶囊），**不是**对接行业系统的 output port。这是情绪地图能否成功立项的**最关键缺口**。

**本文交付**：
1. 厘清"意图 agent + 结果 agent + 成果范式 agent"三段式线性架构（避免一竿子插到底）；
2. 梳理城市更新/城市体检的**明确行业接口清单**（八项任务 × 8大领域指标 × 三级体系 × 四维度）；
3. 建立 **EMC 4×5 归因矩阵 ↔ 体检指标 ↔ 更新任务**的"对口映射"；
4. 定义成果范式 agent 的产出形态（定性+定量+地理信息联动，按尺度分类）；
5. 给出以城市更新/体检为核心演示场景的**实操接口对接清单**。

## 一、底层逻辑：为什么"出口"是情绪地图立项成败的关键

### 1.1 用户意图锚点（原文转述 + 提炼）

> "情绪地图的答案要对应某个具体的项目/指标/任务……要有'对口'的关系，是情绪地图去找这个市场接口（行业接口），而不是让市场来反向去对接情绪地图的答案 → 这是底层逻辑！"

> "意图+结果两个 agent 是互相配合的线性关系 → 避免任何问题得到的答案都是'一竿子插到底'。"

> "图、数、观点要耦合意图 agent 判断分析尺度，避免任何问题都'一竿子插到底'……图、数、观点要与地理信息形成联动，并结合分析尺度的不同，对地理信息类型的选取进行分类。"

> "定性+定量内容能够清晰、明确的对接市场接口/行业接口 → 这是整个情绪地图项目的最最最底层逻辑。"

### 1.2 三条铁律（贯穿全文，后续设计必须遵守）

| # | 铁律 | 含义 | 违反后果 |
|---|------|------|----------|
| **铁律 A** | **情绪地图·EMC 找市场，非市场找情绪地图·EMC** | 情绪地图主动对接行业既有板块（更新需求分析/片区划定/体检指标），而非自造一套让行业来适配 | 立项失败——产品无落点 |
| **铁律 B** | **三段式线性，禁一竿子插到底** | 意图 agent（判尺度/方法）→ 结果 agent（出图数观点）→ 成果范式 agent（对接行业接口）三段承接，任何问题不得跳过中间环节直接给"终极答案" | 结论错位——宏观问给微观答，或反之 |
| **铁律 C** | **定性+定量+地理信息，按尺度分类** | 图/数/观点必须耦合分析尺度，地理信息类型按尺度选取（宏观=面域/中观=单元/微观=点-网格），不夸大结论、不越界 | 结论失真——用微观证据答宏观问题，或用宏观判断指点具体地点 |

### 1.3 为什么这是"最最最底层逻辑"

情绪地图的学术价值（海量评论聚合 + 空间情绪建模）已经成立。但**学术价值 ≠ 立项成功**。立项成功的充要条件是：

> **情绪地图·EMC 能回答一个具体的问题：「你的分析结果，能填进哪个行业/哪个编制流程的哪张表、哪个指标、哪个任务板块？」**

如果答不出这个问题，情绪地图就是一个"自娱自乐"的工具——技术再精巧，规划院/更新办/住建局不会采购。**"出口"抽象层，就是把"情绪地图的分析结果"翻译成"行业听得懂、用得上、接得进的语言"的那一层。** 这是情绪地图从"技术 demo"走向"可立项产品"的临门一脚。

### 2.2 缺失的能力（出向链路 = 0，立项风险点）

| 缺口 | 影响 | 证据 |
|------|------|------|
| **行业接口对接层（出向）** | 情绪地图无法把分析结果按"更新需求分析卡/体检指标对接表/片区划定建议/时序排序表"格式输出——所有"出口"只到前端图层/卡片为止 | 全仓库搜索"行业接口/对接规划/对接体检/专项规划/片区策划"→ 仅命中 1 行无关描述；0 个 IndustryAdapter/OutletAdapter 类 |
| **DOMAIN_OUTLETS 无实现** | `DOMAIN_OUTLETS`（`paradigm.py:70-107`）虽列了 4 领域×3 出口范式名（如"更新时序排序/微更新点位识别"），但**仅启发 LLM 选型，无序列化/导出/对接实现** | dict 纯数据，无 render/export 函数 |
| **export.py 无行业格式** | `core/export.py` 仅通用 CSV/GeoJSON，不含任何规划编制/体检指标格式 | 9.6KB 通用导出 |
| **诊断卡 `outlet` 字段是引导词非契约** | `outlet` 枚举（生成图层/地图定位/指标排序/报告结论/建议清单/预警/执行操作）只给 LLM 选 prompt 引导词，不是对接外部系统的接口契约 | `paradigm.py:462` |

### 2.3 关键洞察

> 情绪地图的"行业"能力，目前**全部是入向的**（给 LLM 注入权威知识，让它用专业话语作答）；**出向的对接能力为零**（不会把结果按行业格式吐给外部系统/编制流程）。
>
> **`DOMAIN_OUTLETS` + 诊断卡 `outlet` 字段是出向链路最自然的挂载点**——已有"领域×出口"二维雏形，目前只用作 LLM 选型启发，未做序列化/对接实现。**抽象层要做的事 = 把这个二维雏形从"启发词"升级为"接口契约 + 渲染器"。**

| 8 | 保护传承历史文化 | 文物普查+专家评估 | "烟火气"难量化 | 历史街区"烟火气/记忆"情绪指标 |

|------|----------|----------|------------------|

| 层级 | 编制内容 | **情绪地图能填的"料"** |
|------|----------|-------------------|
| **专项规划** | 城市体检 + 规划目标 + 重点任务 + 片区指引 + 项目库 | 宏观诊断信号（哪类空间系统性落后）+ 更新优先级排序（片区级） |
| **片区策划** | 片区体检 + 功能业态 + 更新项目 + 设计引导 | 片区情绪诊断 + 需求类型归因（中观单元 4×5）+ 微更新点位 |
| **项目实施方案** | 基础条件 + 实施方案 + 保障措施 | 项目级情绪落点（微观网格/POI 归因）+ 改造前后效果评估 |

### 3.3 行业痛点总结（情绪地图要解决的"缺什么"）

| 行业现状（传统做法） | 痛点 | **情绪地图的替代价值** |
|---------------------|------|-------------------|
| **问卷调查**（空间分层抽样） | 主观性强、覆盖人群有限、样本代表性不足、**时滞性**（年度一次）、数字鸿沟（老年/低收入群体） | 海量真实评论 → **大样本、实时、空间精准、归因可溯** |
| **实地调研**（小量数据） | 人力成本高、覆盖窄、难以常态化 | 评论聚合 → **低成本、全城覆盖、可持续监测** |
| **第三方体检**（客观定量） | 偏"客观指标"（遥感/普查等硬数据），缺"市民真实主观感受" | 主客观互补 → 情绪地图是"主观感受"的**海量数据源**（替代小样本问卷） |
| **12345 热线**（投诉数据） | 偏"已发生问题"，缺"潜在需求/满意度" | 评论含正向/中性/负向全谱 → **补全"满意度+需求"维度** |

> **一句话定位**：情绪地图 = **城市体检"社会满意度调查"板块（"三位一体"中公众参与最主要的方式）的海量化、实时化、空间化升级**。它不替代客观指标（遥感/CIM），而是**填补"主观感受"这一维度的数据真空**——从"年度小样本问卷"升级为"持续海量真实情绪流"。

## 四、抽象层设计：意图 → 结果 → 成果范式（三段式）

### 4.1 三段式线性架构（铁律 B 的落地）

```
┌─────────────────────────────────────────────────────────────────┐
│  第一段：意图判断 agent                                          │
│  （已有雏形：诊断卡 intent/scale/domain_lens/decision_type）      │
│                                                                   │
│  职责：判断"这是什么类型的问题" → 决定分析尺度、方法、路径         │
│  产出：诊断卡（scale=macro/meso/micro + domain_lens + template）  │
│  关键：决定宏观还是中微观 → 选对分析工具（铁律 C 的尺度耦合起点）  │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  第二段：结果 agent                                              │
│  （已有雏形：工具执行 → 图层数据 + 归因字段）                     │
│                                                                   │
│  职责：执行空间分析，产出"图+数+观点"的原始产物                   │
│  产出：标准分析产物（网格/热力图/zonal/缓冲）带定量+定性字段       │
│  关键：产物按尺度差异化（macro=体系/meso=单元/micro=落点）        │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  第三段：成果范式 agent  ←  本文核心！目前缺失！                  │
│                                                                   │
│  职责：把分析结果作为"资源"再理解、再整理，格式化对接行业接口     │
│  产出：行业接口对接产物（体检指标对接卡/更新需求分析卡/            │
│        片区划定建议/时序排序表/任务清单/项目库条目...）            │
│  关键：情绪地图找市场接口（铁律 A）→ 对接到具体编制板块               │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 三段的边界与配合（避免一竿子插到底）

| 段 | 回答的问题 | 不回答的问题 |
|----|-----------|-------------|
| **意图** | "这是什么问题？该用什么尺度/方法？" | 不直接给结论（那是结果的事） |
| **结果** | "分析显示什么？"（图/数/观点） | 不决定结论怎么用（那是成果范式的事） |
| **成果范式** | "这个结果对接到行业的哪个接口？" | 不重新做分析（那是结果的事） |

**违反铁律 B 的典型错误**（必须避免）：
- ❌ 用户问"中心城区整体如何"（宏观）→ 直接给"某公园某点最差"（跳过尺度判断，微观答宏观问）
- ❌ 用户问"这个小区哪里差"（微观）→ 给"全市老旧小区普遍问题"（跳过落点，宏观答微观问）
- ✅ 正确：意图判 macro → 结果出宏观聚合 → 成果范式对接"专项规划·重点片区诊断"

### 4.3 成果范式 agent 的设计原则

1. **接口驱动，非方法驱动**：先列行业明确要的接口（第三节），再设计情绪地图怎么填——不是先有情绪地图能力再找用处。
2. **尺度耦合**（铁律 C）：成果范式的产出形态必须匹配意图 agent 判定的尺度——macro 出"重点片区诊断报告"，meso 出"单元需求分析卡"，micro 出"点位归因+建议清单"。
3. **定性+定量+地理信息三位一体**：每个对接产物必须有图（地理可视化）+ 数（量化指标）+ 观点（归因结论），且地理信息类型按尺度分类。
4. **可序列化、可导出**：成果范式产物必须能导出为行业可消费的格式（报告卡/指标表/项目库条目），而非只在前端展示。

### 5.3 具体接口对接示例（以用户举例的"更新需求分析"为例）

**行业现状（传统）**：更新需求分析靠问卷调查 + 实地调研 → 小样本、时滞性、覆盖窄。

**情绪地图对接逻辑（成果范式 agent 产出）**：

```
意图 agent：判 "某老旧小区更新需求" → meso/micro 尺度 → domain_lens=urban_renewal
    ↓
结果 agent：执行 zonal_stats（社区单元）+ 精细网格聚合 → 产出：
    - 定量：polarity_index=-0.3（偏消极）、n_negative=180、设施类归因占比 45%
    - 定性：domain_top=urban_renewal、element_top=设施、issue_label=电梯老旧/停车难
    - 地理：网格落点（xx 栋周边网格消极聚集）+ POI（xx 小区电梯/xx 路停车）
    ↓
成果范式 agent（本文新增）：对接"更新需求分析"接口 → 产出：
    ┌─────────────────────────────────────────────┐
    │  更新需求分析卡（对接片区策划·需求分析板块） │
    ├─────────────────────────────────────────────┤
    │ 【需求类型】设施类（电梯/停车）为主，占 45%  │
    │ 【需求强度】polarity_index=-0.3，负面聚集   │
    │ 【需求位置】xx 小区 3-5 栋周边 / xx 路沿线  │
    │ 【归因】电梯老旧（xx 栋）+ 停车难（xx 路）  │
    │ 【对接任务】老旧小区整治（②）+ 基础设施（⑥）│
    │ 【建议优先级】电梯 > 停车（按情绪强度排序） │
    │ 【数据基础】N=xxx 条真实评论（YYYY-MM-DD）  │
    └─────────────────────────────────────────────┘
```

> **这就是"情绪地图找市场接口"的样子**：分析结果不是泛泛的"这里情绪不好"，而是精确填进"更新需求分析"这张行业已有的表——需求类型、需求强度、需求位置、归因、对接任务、优先级、数据基础，每一项都对应编制流程里要填的字段。

## 五之补充：结构化体系化梳理（更新+体检双主线 · 能/不能双栏）

> **本节是"情绪地图找市场接口"的系统化展开**——从顶层政策任务逐层拆解到核心指标，标注情绪地图的**能力边界**（能/不能双栏），并提取典型场景做**一一对应对标对表**。

### 5.4 从大到小的层级梳理（四层）

#### 第一层：顶层设计（政策任务·抽象）

| 主线 | 顶层文件 | 顶层任务（抽象） | 核心机制 |
|---|---|---|---|
| **城市更新** | 《关于持续推进城市更新行动的意见》(2025.5) + 《城市更新"十五五"规划》(2026.5) | **八项重点任务**（既有建筑改造/老旧小区整治/完整社区/老旧街区/城市功能/基础设施/生态修复/历史文化） | 「先体检后更新、无体检不更新」·三级编制体系（专项规划—片区策划—实施方案）|
| **城市体检** | 2026 城市体检工作部署 + 《城市体检可复制经验清单》(2025.10) | **四维度**（住房→小区→街区→城区）·**8 大领域指标** | 体检发现问题 → 更新解决问题 → 评估效果 → 巩固提升 |

> ⚠️ **注意**：八项任务是中央出台的**相对抽象的顶层设计**，不是具体任务。须往下拆到**可操作的业务板块**。

#### 第二层：业务板块（可操作·每主线的核心工作环节）

**城市更新主线**（从专项规划到实施的全过程）：
1. **更新对象识别**（哪些地方需要更新）
2. **更新需求摸排**（这些地方具体需要什么——旧改/停车/电梯/绿化）
3. **更新单元划分**（怎么划定更新片区/单元）
4. **更新时序排序**（先更新哪些、后更新哪些）
5. **更新内容确定**（每个单元更新什么——留改拆建）
6. **更新项目生成**（从需求到项目库条目）

**城市体检主线**（四维度的诊断业务环节）：
1. **住房维度诊断**（建筑安全/居住品质）
2. **小区维度诊断**（设施/服务/环境）
3. **街区维度诊断**（功能/活力/风貌）
4. **城区维度诊断**（整体发展质量）
5. **社会满意度调查**（市民主观感受）

#### 第三层：指标体系（每板块官方指标 + 能/不能双栏）

> 每个板块下，列官方指标体系，**标注情绪地图能做什么/不能做什么**——明确能力边界，不夸大。

**示例：更新需求摸排（板块2）**

| 官方指标 | 情绪地图「能」 | 情绪地图「不能」 | 边界说明 |
|---|---|---|---|
| 设施缺口（停车/电梯/养老） | ✅ 评论归因→设施缺口热点（海量真实评估）| ❌ 不能测实际设施数量（需普查数据）| 情绪=感知维度，客观数据=结构维度，互补 |
| 需求强度 | ✅ polarity_index + 负面占比（空间精准）| ❌ 不能替代工程检测（如电梯结构安全）| 情绪识别"哪里呼声高"，检测确认"是否真危险" |
| 需求位置 | ✅ place_name + 网格/POI 落点 | ❌ 不能测精确产权/面积 | 情绪给空间落点，详规给地块数据 |

**示例：社会满意度调查（体检板块5）**

| 官方指标 | 情绪地图「能」 | 情绪地图「不能」 | 边界说明 |

##### 占比统计（官方三类·标注为估算）

| 类别 | 占比 | 获取方式 | 特点 |
|---|---|---|---|
| **可量化** | **~55-65%** | 统计/普查/遥感/空间大数据 | 客观可靠·**但不含市民声音** |
| **可感知** | **~15-20%** | 居民抽样问卷 | 含民意·**但采集不可靠** |
| **可评价** | **~15-25%** | 多源融合 | 复合评估·**融合感知维度** |
| **地方特色** | 各城自定 | 地方自主 | 补地方关切·以可量化为主·少量可感知 |

> **核心论证（凸出结构性缺失）**：61 项基础指标中 **可量化指标约 55-65%**——客观可靠但数据本身不含市民声音；**可感知指标约 15-20%**（10 项·全罗列）——含民意但采集不可靠（样本小/时滞/难定位）；**可评价指标约 15-25%**（多源融合·含感知成分）——复合评估同样依赖主观感知输入。**合计约 30-45% 的指标涉及市民感知维度**（可感知 + 可评价）——正是情绪地图要填补的"主观指标可信性缺口"。

> **关键洞察（不是"少"，是"覆盖广但采集弱"）**：可感知指标占比不高（~15-20%·10 项），加上可评价指标（~15-25%·多源融合）**合计约 30-45% 的指标涉及市民感知**——承载的感知面极广：宜居感知、活力烟火气、满意度、停车便利、物业管理、公共服务便利……几乎每个维度都有"市民感受"的一面（住建部要求指标"可感知"）。然而这海量感知面，却只靠**小样本问卷**采集（广州 6.5 万/上海 4.5 万·抽样 0.6‰~1.5‰）：
> - **代表性差**：样本偏差（配合政府/关心事务的居民更可能参与）·数字鸿沟（老年人不熟悉手机）·外来务工被排除（电话调查）·高学历偏多
> - **成本高/时滞**：问卷设计（30-50 题）→发放→回收→统计数月·年度一次·缺乏延续性（问卷每年调整·难以多年对比）
> - **难空间定位**：综合分（93.60 分）难拆解到具体空间/主题
> - **难追踪验收**：满意度复查等下次问卷·闭环以年计
>
> **结论**：可感知/可评价指标"覆盖广（感知面遍布各维度）但采集弱（问卷承载不了）"——这正是**结构性缺失的真正痛点**：不是缺"感知指标"，而是缺**一个能承载海量感知面、又统计可靠、可空间定位的采集手段**——情绪地图（全量评论）正是要填补这个采集空缺。

> **承上启下（A→B）**：——这就是体检的"表"：**约 55-65% 可量化指标**靠遥感普查（可靠但读不出民意）+ **约 15-20% 可感知问卷满意度**（有民意但 0.2% 样本·不可靠）+ **约 15-25% 可评价多源融合**（复合评估·融合感知）+ **地方特色**（因地制宜·基础指标之上增加·非第三类并列）。问题来了：**这样的表，中间缺了什么？**（见 B）

##### B. 结构性缺失：主观指标可信性缺口（soft-indicator credibility gap·业界俗称"软指标缺口"）

> 城市体检指标存在**"主观指标可信性缺口"（soft-indicator credibility gap·业界俗称"软指标缺口"）**：客观指标（业界俗称"硬指标"·可靠·但数据本身不含市民声音）与主观指标（感知/满意度指标·业界俗称"软指标"·问卷·含民意·但采集不可靠）之间，缺乏一个**"既承载市民民意、又具备统计可靠性"**的主观指标层。
> - 客观指标太硬：可靠但不含民意（遥感测得出绿地率·读不出市民觉得好不好）
> - 主观指标太飘：含民意但不可靠（问卷样本小·时滞·难定位·难统计）
> - **缺口** = 一个既反映市民声音、又统计可靠、可空间定位的主观指标——这正是情绪地图要填补的。

> **观点补充（政策锚点）**：住建部要求城市体检指标须**"可量化、可感知、可评价"**——其中**"可感知"正是主观指标**（感知/满意度类），官方已认定"市民感受"是不可或缺的体检维度；但官方采集手段仍靠问卷，**缺可靠采集**——这进一步印证 B 的缺口不是"主观指标少"，而是"主观指标无可靠采集手段"。

> **承上启下（B→C）**：——缺的这层"**可靠软指标**"，正是**传统方式做不好的地方**。为什么做不好？看 C 的四条硬伤。

##### C. 传统数据"不靠谱"论证（不靠谱 ≠ 主观·是数量/时效/质量）

> **"不靠谱"不在于"主观"**（情绪地图也是主观数据），而在于"量不够、太慢、不牢"。体检里"满意度/活力/烟火气/宜居感知/停车便利度"这类**主观/感知类指标**全靠问卷/座谈拿数据——恰恰是"不靠谱"短板所在：

1. **数量不足**：抽样（广州 6.5 万 / 上海 4.5 万·0.6‰~1.5‰·最低 1500 份）vs 全量评论——覆盖有限·数字鸿沟（老年/低收入缺位）
2. **时效滞后**：年度一次·问卷设计→发放→回收→统计数月·无法持续追踪·捕捉不到动态（事件/舆情）
3. **质量不稳**：问卷自评主观（"满不满意"综合分如上海 93.60 分难定位）·预设题目（只问已知·难发现新痛点）·开放建议人工归纳费力（上海 2431 条）·**样本偏差**（配合政府/关心事务的居民更可能参与）·**数字鸿沟**（老年人不熟悉手机）·**外来务工被排除**（电话调查）·高学历偏多
4. **难以闭环**：体检→问题清单→整治建议（限时/尽力/长期谋划）→项目库→实施；验收 = 整改完成率 + **满意度复查（等下次问卷·慢）**——发现到验收以年计·无法实时追踪·**问卷缺乏延续性**（问卷每年调整·难以多年对比）

> **承上启下（C→D）**：——传统方式四条硬伤（**数量/时效/质量/闭环**）叠加，体检结论"**难以闭环**"：发现问题靠年度问卷·**验收还靠下次问卷**。情绪地图怎么破？看 D。

##### D. 情绪地图+AI 赋能价值（更客观/更有说服力/更科学）

| 维度 | 传统方式 | 情绪地图+AI |
|---|---|---|
| 覆盖 | 抽样（0.6‰~1.5‰·≥1500 份）| 全量评论·不遗漏沉默多数·无数字鸿沟 |
| 时效 | 年度一次·数月周期 | 实时·持续流式·任意时间窗 |
| 空间分辨率 | 问卷难定位（区/街办级）| 网格/POI 级·精准到栋/路 |
| 可归因 | 综合分难拆解 | 4×5 归因·政策→情绪→项目 |
| 可追踪/验收 | 靠下次问卷回访 | 持续极性对比·改造前后效果·可实时验收 |

> **核心观点**：情绪地图带来**更客观（全量非抽样）、更有说服力（真实评论）、更科学（空间+主题+极性三维·可追踪可验收）**的评级方式，作为城市体检/更新的支撑（之一）——它填的正是 B 里那道"主观指标可信性缺口"。

> **观点补充（主客观交叉耦合分析）**：情绪地图不只替代主观问卷，还能与客观指标**交叉耦合**——**匹配**（客观设施达标 + 主观满意度高 = 建设有效）·**失配**（客观达标但主观不满 = "城市病"——设施有了但不好用/不方便/不舒适，如车位够但停车难）·失配处即**发现城市病、生成更新项目**的富矿。

> **承上启下（C→D）**：传统数据"不靠谱"（数量/时效/质量）+ 难闭环 → 情绪地图 + AI 恰好补上这个**采集空缺**（全量/实时/空间精准/可归因/可追踪）——从 B 的"缺口诊断"到 D 的"填补方案"完成闭环。

> **承上启下**：——情绪地图以全量评论填补"**主观指标可信性缺口**"：**更客观**（全量非抽样）、**更有说服力**（真实评论）、**更科学**（可定位可追踪）。下面四个真实城市案例检验这套逻辑——每个传统环节的"不靠谱"点，情绪地图用哪种图/数/表/观点去填（每个案例的「直接指向的指标体系」块即检验结果）。

#### 案例 1：湖北宜昌 · 望洲岗 10 号楼"原拆原建"（本地示范工程 · 成效展示）

> **定位**：望洲岗是宜昌市**示范工程**（湖北首个"原拆原建"·央视报道）。本案例的情绪地图分析目标是**展示积极面**——用图/数/表/观点**证明望洲岗做得好、好在哪里**，为"原拆原建"模式的可复制可推广提供数据支撑。

## 六、成果范式 agent 的产出形态（定性+定量+地理信息，按尺度分类）

### 6.1 三类产出形态（对应三类行业接口）

| 产出形态 | 对接接口 | 内容构成（铁律 C） | 适用尺度 |
|----------|----------|-------------------|----------|
| **诊断卡类** | 体检指标对接 / 需求分析 | 图（极性面/热力图）+ 数（polarity_index/指标值）+ 观点（归因+短板识别） | macro/meso |
| **排序表类** | 更新时序 / 优先级 | 图（排序地图）+ 数（排名/分值）+ 观点（排序依据） | macro/meso |
| **落点清单类** | 微更新点位 / 项目库条目 | 图（网格/POI 落点）+ 数（聚集强度）+ 观点（具体地点归因+建议） | micro |

### 6.2 地理信息类型选取（按尺度分类——铁律 C 的地理联动）

| 尺度 | 地理信息类型 | 禁止 | 依据 |
|------|-------------|------|------|
| **macro** | 行政区/片区**面域**（极性面、排序地图） | 禁落单点/单一网格 | 用微观结论答宏观问 = 尺度错位 |
| **meso** | 街办/社区**单元面**（zonal 归因面、单元排序） | 不混单点、不泛整城 | 单元级结论，颗粒度匹配 |
| **micro** | 网格/POI**点**（50-100m 网格、Gi* 热点、POI 标注） | 禁泛泛而谈 | 必须可飞到地图的具体落点 |

> **耦合关系**：图（地理信息类型）由尺度决定 → 数（统计粒度）匹配图 → 观点（归因颗粒度）匹配尺度。三者**强耦合**，成果范式 agent 不得越界（如 macro 卡片里塞 micro 落点）。

### 6.3 产出的"接口契约"要素（每个对接产物必含）

为对接行业编制流程，成果范式 agent 产出的每个卡片/表格必须含：

| 要素 | 说明 | 示例 |
|------|------|------|
| **接口标识** | 对接的行业板块（哪个编制层、哪个任务、哪个指标） | "片区策划·需求分析" / "体检·健康舒适·设施完善度" |
| **数据基础** | 数据来源、样本量、时间范围 | "N=xxx 条评论，YYYY-MM-DD，来源：L1/L2 聚合" |
| **定量指标** | 可填入行业表格的数值 | polarity_index、n_negative、占比、排名 |
| **定性归因** | 4×5 归因落点 | domain_top/element_top/issue_label |
| **地理定位** | 可在地图定位的空间对象 | 片区名/街办名/网格 ID/POI 名 |
| **对接建议** | 对应的更新任务/指标/措施 | "对接任务②老旧小区整治·电梯加装" |
| **局限标注** | 数据口径与边界（不夸大） | "仅覆盖评论人群，老年群体可能 under-represented" |

## 八、待两组讨论的焦点问题

### 焦点 1（最高优先）：成果范式 agent 的架构位置

成果范式 agent 应该放在情绪地图架构的哪一层？三个候选：

| 方案 | 位置 | 优点 | 缺点 |
|------|------|------|------|
| **A. 后端层** | `core/` 新增 `outlet_adapter.py`（类似 export.py） | 纯函数、可测、不碰承重 prompt | LLM 不可见，无法用自然语言组织"对接建议" |
| **B. prompt 层** | `ai_qa/prompts.py` 新增 `build_outlet_prompt`（类似 build_final_prompt） | LLM 可组织自然语言对接建议 | 撞 final prompt 极瘦红线（D019），需谨慎 |
| **C. 分层** | 后端出结构化数据（outlet_schema）+ prompt 层渲染自然语言（build_outlet_prompt 消费 schema） | 空间数据在后端、语言组织在 LLM，职责清晰 | 实现复杂度最高 |

**初步倾向**：方案 C（分层）——符合 CB-15 共识"后端空间查询 + 前端联动工具分层"模式。后端 `core/outlet_adapter.py` 产 outlet_schema（结构化对接卡数据），`ai_qa/prompts.py` 新增轻量 `build_outlet_prompt` 渲染自然语言（不撞 final 红线，因这是 final **之后**的独立渲染阶段）。

### 焦点 2：DOMAIN_OUTLETS 从"启发词"升级为"接口契约"

现有 `DOMAIN_OUTLETS`（`paradigm.py:70-107`）只有 4 领域×3 出口范式名。升级为接口契约需要：

1. 每个 outlet 补全：**对接的行业接口标识**（如"片区策划·需求分析"）+ **产出 schema**（第六节 6.3 的 7 要素）+ **适用尺度** + **所需产物字段**（从 result agent 的图层数据取哪些字段）。
2. 诊断卡 `outlet` 字段从 7 值枚举（生成图层/...）升级为指向 DOMAIN_OUTLETS 的具体接口。
3. 是否新增 `core/industry_kb/` 的出向镜像？（入向已有 `ai_qa/industry_kb/`，出向或需 `core/outlet_kb/` 定义接口契约）

### 焦点 3：尺度耦合的强制执行

铁律 C 要求"图数观点耦合尺度"。现有 `SCALE_PARADIGM` + 前端 `_outletLine`（harness.js）已硬约束。成果范式 agent 是否需要**额外**的尺度校验层（防止 outlet_schema 里 macro 卡片混入 micro 落点）？

### 焦点 4：与 CB-15 数据认知重构的协同

CB-15 在做"格↔POI sjoin + place_name 双源融合"（让网格归因能落到具体地点）。本文的成果范式 agent **依赖** CB-15 的产出——micro 尺度的"落点清单类"产物，必须有 CB-15 的归因↔地点联动才能填"地理定位"要素。两者实施顺序：**CB-15 先行（P0 下钻链闭环）→ 本文成果范式 agent 依其产出构建**。

#### 一、《关于持续推进城市更新行动的意见》

**发布单位**：中共中央办公厅、国务院办公厅

**发布时间**：2025年5月2日

**公开时间**：2025年5月15日向社会公开发布

**文件性质**：党中央、国务院对城市更新工作作出的顶层设计部署，是指导全国实施城市更新行动的纲领性文件。

##### （一）出台背景

党中央、国务院高度重视城市更新工作。习近平总书记作出重要指示批示，强调要积极实施城市更新行动，推动城市业态、功能、品质不断提升。党的二十大提出实施城市更新行动，打造宜居、韧性、智慧城市。党的二十届三中全会进一步明确建立可持续的城市更新模式和政策法规。2021年以来，每年《政府工作报告》均对城市更新行动作出部署。

截至2024年底，我国常住人口城镇化率达到67%，9.4亿人生活在城镇。当前，我国城市发展从大规模增量建设转向存量提质改造和增量结构调整并重，进入了城市更新的重要时期，人民群众的需要从"有没有"转向"好不好"。

##### （二）总体要求

**指导思想**：坚持以习近平新时代中国特色社会主义思想为指导，深入贯彻党的二十大和二十届二中、三中全会精神，全面贯彻习近平总书记关于城市工作的重要论述，坚持稳中求进工作总基调，转变城市开发建设方式，建立可持续的城市更新模式和政策法规，大力实施城市更新，促进城市结构优化、功能完善、文脉赓续、品质提升，打造宜居、韧性、智慧城市。

**工作原则**（六项）：

1. **坚持以人民为中心**，全面践行人民城市理念，建设好房子、好小区、好社区、好城区；
2. **坚持系统观念**，尊重城市发展规律，树立全周期管理意识，不断增强城市的系统性、整体性、协调性；
3. **坚持规划引领**，发挥发展规划战略导向作用，强化国土空间规划基础作用，增强专项规划实施支撑作用；
4. **坚持统筹发展和安全**，防范应对城市运行中的风险挑战，全面提高城市韧性；
5. **坚持保护第一、应保尽保、以用促保**，在城市更新全过程、各环节加强城市文化遗产保护；
6. **坚持实事求是、因地制宜**，尽力而为、量力而行，不搞劳民伤财的"面子工程""形象工程"。

**1. 加强既有建筑改造利用。** 稳妥推进危险住房改造，加快拆除改造D级危险住房，通过加固、改建、重建等多种方式，积极稳妥实施国有土地上C级危险住房和国有企事业单位非成套住房改造。分类分批对存在抗震安全隐患且具备加固价值的城镇房屋进行抗震加固。涉及不可移动文物、历史建筑等保护对象的，按照相关法律法规予以维护和使用，"一屋一策"提出改造方案，严禁以危险住房名义违法违规拆除改造历史文化街区、传统村落、文物、历史建筑。持续推进既有居住建筑和公共建筑节能改造。加强老旧厂房、低效楼宇、传统商业设施等存量房屋改造利用，推动建筑功能转换和混合利用。

**2. 推进城镇老旧小区整治改造。** 更新改造小区燃气等老化管线管道，整治楼栋内人行走道、排风烟道、通风井道等，全力消除安全隐患，支持有条件的楼栋加装电梯。整治小区及周边环境，完善小区停车、充电、消防、通信等配套基础设施，增设助餐、家政等公共服务设施。加强老旧小区改造质量安全监管。结合改造同步完善小区长效管理机制，注重引导居民参与和监督。

**3. 开展完整社区建设。** 完善社区基本公共服务设施、便民商业服务设施、公共活动场地等，建设安全健康、设施完善、管理有序的完整社区，构建城市一刻钟便民生活圈。开展城市社区嵌入式服务设施建设，因地制宜补齐公共服务设施短板。引导居民、规划师、设计师等参与社区建设。

**7. 修复城市生态系统。**（原文后续内容略）

##### （二）主要目标

- **到2030年**：城市更新行动取得重要进展；
- **到2035年**：城市更新体制机制更加完善，城市结构优化、动能转换、品质提升、绿色转型、文脉赓续、治理增效取得显著成效，创新、宜居、美丽、韧性、文明、智慧的现代化人民城市基本建成。

##### （四）城市体检相关要求

规划明确要求全面开展城市体检，坚持 **"先体检后更新、无体检不更新"**。根据体检结果，科学编制城市更新专项规划，建立城市更新项目库，完善"专项规划—片区策划—项目实施方案"的规划实施体系。

城市更新规划是一定时期内统筹城镇开发边界内城市更新活动，谋划实施城市更新项目，推动城市结构优化、功能完善、文脉赓续、品质提升的规划。它是编制和调整详细规划，配置资金和要素，完善相关配套政策的重要依据。

1. 坚持以人民为中心；
2. 坚持系统观念；

4. 坚持守正创新。

导则要求坚持 **"先体检后更新、无体检不更新"**，将城市体检发现的问题作为城市更新工作重点，建立 **"体检发现问题、更新解决问题、评估更新效果、推动巩固提升"** 的闭环工作机制。

专项规划期限一般为5年，与国民经济与社会发展规划期限保持一致。

##### （七）专项规划主要内容

1. **城市体检**——查找群众急难愁盼问题和影响城市竞争力、承载力、可持续发展的短板弱项；
2. **规划目标**——确定五年期总体目标和年度工作目标；
3. **重点任务**——涵盖既有建筑改造、老旧小区整治、完整社区建设等八方面；

**住房城乡建设部党组成员、副部长秦海翔**出席会议并讲话。

##### （一）2025年工作成效回顾

各地城市体检组织实施扎实有序、广度深度大幅拓展、结果应用更加充分。**全国297个地级及以上城市和152个县级市**开展了城市体检工作，查找并推动解决了一批群众身边急难愁盼问题，为高质量开展城市更新提供有力支撑。

##### （二）2026年工作部署

**核心要求**：

1. **设市城市全面开展城市体检工作**，加快实现住房、小区（社区）、街区、城区（城市）**四个维度体检全覆盖**；
2. **一体化推进城市体检与城市更新**，坚持 **"先体检后更新、无体检不更新"**；
3. 加强城市体检结果应用与**城市更新规划实施体系衔接**；
4. 结合城市更新重点任务**因地制宜开展专项体检**；
5. 健全 **"发现问题、解决问题、评估效果、巩固提升"** 的工作机制。

##### （三）"四个维度"体检全覆盖的含义

四个维度体检是指：

| 维度 | 说明 |
|------|------|
| **住房维度** | 从微观层面评估建筑安全、居住品质等 |
| **小区（社区）维度** | 评估社区设施、服务、环境等 |
| **街区维度** | 评估街区功能、活力、风貌等 |
| **城区（城市）维度** | 从宏观层面评估城市整体发展质量 |

这一体系打破了传统城市评估偏重宏观层面的局限，构建了从微观到宏观、从个体到整体的全链条诊断框架。

##### （四）秦海翔副部长讲话要点

秦海翔指出，2026年是"十五五"开局之年，各地要充分借鉴先进省市经验，结合相关工作，一体化推进城市体检和城市更新：一方面，要提高城市体检工作质效，坚持 **"无体检不更新"**。

**经验交流**：吉林、江苏、广州、呼和浩特、武夷山等5个省市代表介绍了经验做法。

### 第五章 经验推广文件

#### 《城市体检可复制经验做法清单（第一批）》

**发布单位**：住房城乡建设部办公厅

**发文字号**：建办科函〔2025〕280号

**发布时间**：2025年10月16日

**文件性质**：系统总结各地在推进城市体检领域的创新实践，供各地学习借鉴的指导性文件。

**文件背景**：为贯彻落实中央城市工作会议精神和《中共中央办公厅、国务院办公厅关于持续推进城市更新行动的意见》，住房城乡建设部总结各地在建立健全城市体检工作组织机制、创新城市体检工作方法、建立一体化推进城市体检与城市更新工作机制、加强城市体检工作保障等方面的经验做法，形成本清单。

##### （一）四大方面经验

**1. 建立健全城市体检工作组织机制**（4项举措）：

- 建立城市体检工作机制；
- 优化城市体检工作组织方式；
- 建立监测评价机制；
- 完善公众参与方式。

**典型做法**：广东省建立"统一领导，高位推动"的工作机制，成立城镇人居环境提升工作领导小组，由省长任组长，统筹推进全省城市体检工作，编制《城市体检工作指南》，明确指标计算方法、统计口径、责任主体及填报标准。各市建立市长或副市长任组长的城市体检工作领导小组。

**2. 创新城市体检工作方法**（4项举措）：

- 完善城市体检指标体系（采取 **"基础指标+特色指标"** 模式，**基础指标涵盖8大领域35项核心内容**，保障全国体检标准统一，地方结合实际增设特色指标，兼顾共性与个性）；
- 创新数据采集方法；
- 优化问题诊断分析方法；
- 探索专项体检方法。

**3. 建立一体化推进城市体检与城市更新工作机制**（4项举措）：

- 体检问题立行立改、限时解决；
- **依据城市体检生成城市更新项目库**；
- 依据城市体检制定城市更新专项规划；
- 持续跟踪问题解决情况。

**4. 加强城市体检工作保障**（3项举措）：

- 制定城市体检法规和标准；
- 建立城市体检信息平台；
- 加强人员保障。

#### 二、核心机制：城市体检与城市更新一体化推进

城市体检与城市更新一体化推进是贯穿上述所有政策文件的核心机制，其基本逻辑为：

**"先体检后更新、无体检不更新"** ——体检结果直接指导专项规划编制，形成完整闭环：

```
城市体检（发现问题） → 城市更新（解决问题） → 评估（评估效果） → 巩固提升（推动巩固提升）
```

具体体现为：

1. **城市体检是前提**：坚持城市体检先行，将城市体检作为城市更新的前提；
2. **体检结果是依据**：把城市体检发现的问题短板作为城市更新的重点；
3. **规划是统筹**：发挥城市更新规划统筹作用，依据城市体检结果编制专项规划；
4. **项目是载体**：依据城市体检生成城市更新项目库。

#### 三、中央城市工作会议精神

2025年7月召开的中央城市工作会议要求，以推进城市更新为重要抓手，建设**创新、宜居、美丽、韧性、文明、智慧的现代化人民城市**。
