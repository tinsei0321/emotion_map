## 一 议题1（主答）：E4 正式裁定 + 三支柱在平台形态下的存废变形

### 1.1 先做任务书点名的反证：「形态3 是否只是逃避可解问题」

对 R3 诊断的入口聪明度四层机理逐层检验（不附和·真反证）：

| 机理 | 形态2 解法 | 形态3 处置 | 反证结果 |
|---|---|---|---|
| ② 参数闭卷填空 | M2 参数接地（list_data+dataset_id 枚举） | **M2 变身存活**（schema 接地服务 MCP 工具面——纪要含义⑤） | 未逃避——本来就要做且平台更需要 |
| ④ eval 失真 | M4 eval 重放（G6） | G6 降权为**平台 eval**（本回应 C10） | 未逃避——变形保留 |
| ① 封闭分类法 vs 开放空间 | M1 迭代诊断（多轮 FC 循环） | 交给通用 harness 的 agent loop | **未逃避——M1 要造的东西（多轮工具循环+失败恢复+澄清）就是通用 harness 的本体**。自研 M1=造一个 mini harness=与巨头竞赛（R4 三次转移论证：预训练教材是整个 GitHub·私有词典竞赛数学上不收敛） |
| ③ 单发不可恢复 | M3 计划生成（G9 CPD） | 宿主 plan-execute 天然承担 | 同上——正确解法外包给最擅长它的东西 |

**反证失败，形态3 不是逃避，是正确的解包**：把"让入口变聪明"从自研义务转交给通用能力供给方，把私有能力（口径/知识/渲染）做厚。用户论断「如何跑起来的路由不是个人开发者该做的事」经此检验成立——这不是放弃可解问题，是承认该问题的解属于商品化竞赛层。

### 1.2 三支柱的存废变形（本议题最重的裁定）

三支柱（CB-22 铁律：知识库完备度+EMC 架构+LLM 综合·缺一不可）在平台形态下**不存废、重新分工**：

| 支柱 | 平台形态下的变形 | 载体 |
|---|---|---|
| ① 知识库完备度 | **不变且强化**——升格为平台核心资产（C 线沉淀正是它） | RAG/outlet_kb/industry_kb |
| ② EMC 架构（分类→范式映射） | **变形而非消失**：范式知识（尺度→方法→输出颗粒度）从代码路由（paradigm.py）**迁移进工具面设计**——工具 description 编码尺度适用性、参数枚举编码数据资产、输出 schema 编码回答范式 | MCP 工具的 schema/description 质量 |
| ③ LLM 综合 | 由宿主 harness 承担（每家都有） | 通用 harness |

**承重判断（claude组 核心增量）**：支柱②的迁移不是自动发生的——**如果工具面只是裸暴露函数（名字+参数），蒸发掉的不是路由代码，而是范式知识的载体**——十年领域积累（尺度纪律/颗粒度匹配/口径标注）将无处栖身。故设**前置条件三**：工具面设计必须显式继承范式知识（落为宪法 C11·见议题6）。三支柱从"每答必过的产品保证"变为"消费者依赖的平台质量属性"——**CB-22 铁律在平台形态下的正确表述：砍任何一根支柱，平台产出的可信度崩塌**。

### 1.3 三项前置条件（E4 成立的附加条款）

1. **范式知识显式迁移**（→C11）：工具面=范式知识的新载体·设计评审过不了"裸函数"关不放行。
2. **参赛演示仍用现有 QA 壳**：演示逻辑链三环中"引导点击→交互分析"两环在形态3 下部分让渡给宿主对话——**现场演示质量变得依赖宿主发挥（不稳定）**。参赛期（可控性最优先）现有 QA=演示级冻结态保演示主力；形态3 是赛后主线。此条直接决定议题3 时序。
3. **冻结的精确定义**：路由层"停止自研投入"≠删除≠放烂——diagnose prompt 永不动（红线本来就写）/编排器冻结期维持/**B002/B004 等 CRIT bug 仍须修完**（演示可信度·CB-39 D1 批不因形态3 取消）；冻结=不投新能力（M1/M3 停）+修 bug 保稳。

### 1.4 形态2 与形态3 的关系（E4 第二问）

**不是渐进也不是并行，是吸收**：形态2 的 M2/M4 本来就是平台需要的基础设施（无论哪种终局形态都要参数接地和 eval）；M1/M3/M5(体内) 是重造 harness 的子集（砍）。所以"形态2 先做再演进到形态3"的路径**不存在独立价值**——直接按形态3 走，M2/M4 自然包含在内。

1. **结构化输出**：JSON schema 保证（vs 解析 stdout）
2. **口径内建**：返回值自带口径标签/来源（裸调要自己翻文档·口径注册表的知识进工具返回）

4. **错误语义化**：可编程处理的错误码（vs traceback）
5. **组合性**：dataset_id 枚举让工具间可链式（bash 裸调无类型链）

## 一 议题1（主答）：E4 正式裁定

### 1.1 反证检验：「形态3 是否只是逃避可解问题」（任务书点名要求的反证）

评审的诚实性要求先做反证：如果 R3 诊断的入口聪明度问题是**可解且解法在自有能力圈内**的，那么形态3 就是逃避。逐层检验 R3 的四层机理：

**机理②参数闭卷填空（CB-08 实证：FC 选型 12/12 全对·瓶颈在参数）**

形态2 解法是 M2 参数接地——让 LLM 看见数据资产清单（list_data 工具+dataset_id 枚举）。检验：这个机制**与入口形态无关**——无论 NL 入口是自研 QA 还是通用 harness，工具消费方都需要知道"有哪些数据可查"。M2 在形态3 下不仅保留，而且升格：它变成 MCP 工具面的 schema 接地服务（工具参数的 enum 直接来自数据资产清单），是平台本体的组成部分。**未逃避——本来就要做，平台更需要。**

**机理④eval 失真（CB-01 C6：手工空 context 不反映运行时）**

形态2 解法是 M4 eval 重放（G6 session log）。检验：eval 的价值在于回归防护——这在平台形态下**收窄但不消失**：自研路由死了，路由 eval 随之降权；但工具面本身需要质量回归（工具可调用性/schema 稳定性/黄金问题平台版）。G6 降权为**平台 eval**（本报告 C10）是正确归宿而非丢弃。**未逃避——变形保留于 C10。**

**机理①开放问题空间 vs 封闭意图分类法（预判词表+尺度映射=有限字典索引无限空间·修补数学上不收敛）**

这是最核心的一层。形态2 解法是 M1 迭代诊断（多轮 FC 循环+失败恢复+澄清追问）。检验的关键在于：**M1 要构建的东西是什么？**——多轮工具调用循环、执行反馈吸收、失败重试、澄清追问。这四样东西**恰恰就是通用 agent harness 的定义性能力**（dsh/claude code/codex 的本体）。自研 M1 = 在自己项目里重造一个 mini harness = 与 DeepSeek/Anthropic/OpenAI 的商品化竞赛正面对撞。R4 的三次转移论证已经实证了这个竞赛的不对称性：通用 agent 的工具知识来自预训练（教材=整个 GitHub 的 geopandas/shapely 用法），EMC 的 19 契约是私有 API（模型零先验·每调优一条映射都是一次性的）；"词典竞赛赢不了"。**未逃避——该问题的解存在，但解就是通用 harness；把它交给通用层是正确解包，不是放弃。**

**机理③单发诊断不可恢复**

形态2 解法是 M3 计划生成（G9 CPD 复活·受控多步链）。检验：多步任务分解与执行的宿主能力=通用 harness 的 plan-execute 范式（三家 harness 均原生）。自研受控多步（G9）是为绕开开放 loop 病史（B001/B003）而设计的折衷——在宿主承担入口后，折衷的必要性消失（宿主的 loop 自带护栏与迭代）。**未逃避——外包给最擅长它的东西。**

**反证总结论：四层机理中两层（②④）的解法在形态3 下完整保留且升格，两层（①③）的解法本体就是通用 harness。形态3 不是逃避可解问题，是把"让入口变聪明"从自研义务正确地转交给商品化能力供给方，把私有投入集中于比较优势区（口径/知识/渲染资产）。用户论断「如何跑起来的路由不是个人开发者该做的事，在通用的基础上搭架子」经此检验成立。**

### 1.2 三支柱在平台形态下的存废变形（本报告最重的裁定）

CB-22 顶层铁律：纯回答稳定性 = ①本地知识库完备度 + ②EMC 架构（分类→范式映射）+ ③LLM 归纳总结，三者缺一不可。形态3 把 ② 的载体（diagnose→19 契约路由）停掉——支柱②是否随之消失？

**裁定：不消失，载体迁移。** 逐柱分析：

**支柱①（知识库完备度）**：不变且强化。C 线沉淀（体检域 fact/口径注册表/图层卡片）正是这一支柱的建设——形态3 让它从"产品的三支柱之一"升格为"平台的核心商品"。任何宿主 harness 消费 EMC 工具时，回答质量的下限仍由知识库厚度决定。

**支柱②（EMC 架构·分类→范式映射）**：这是唯一真正面临"存废之问"的支柱。范式知识——什么尺度的问题用什么方法、什么数据、出什么颗粒度的结论（尺度-方法-范式映射·paradigm.py 的决策树+尺度表+MEMORY 里沉淀的归因哲学）——**不随路由代码停投而蒸发，但也不会自动搬家**。它的迁移路径是唯一确定的：**编码进 MCP 工具面的设计**——
- 工具 `description` 编码尺度适用性（"本工具适用宏观面域问题·微观精确归因禁用"这类范式约束进描述文本）
- 参数 `enum` 编码数据资产（dataset_id 枚举=参数接地的平台化）
- 输出 schema 编码回答范式（返回值结构强制带口径标签/来源/结论性质元数据）

**承重判断（本报告核心增量）**：如果工具面只是裸暴露函数（名字+参数+返回值），那么蒸发掉的就**不是路由代码（那只是实现），而是范式知识的载体（那是十年领域积累）**——尺度纪律、颗粒度匹配、口径标注、铁律7（片区=结论）这些知识将无处栖身，平台退化为"一组 GIS 函数的 MCP 包装"，与直接用 geopandas 无异。故设**前置条件一=宪法 C11（范式编码义务）**：工具面设计评审必须过"裸函数"关——每个工具的 schema 里找不到范式知识的，不放行。

**支柱③（LLM 综合）**：让渡给宿主 harness——每家宿主都有自己的 LLM 与综合风格。这是三支柱中唯一"完全离开自有控制"的——其质量保证方式从"自建 finalStep+降级链"变为"平台输出质量高到宿主综合不会跑偏"（工具返回自带结构化结论素材·宿主只需组织）。**三支柱的平台形态表述：砍任何一根支柱，平台产出的可信度崩塌——①靠 C 线做厚、②靠 C11 编码、③靠返回值结构化设计兜底。铁律变形不失效。**

### 1.3 E4 成立的三项前置条件

1. **范式知识显式迁移（→C11）**：如上。这是形态3 从"正确的战略"落地为"正确的工程"的分水岭。
2. **参赛演示仍用现有 QA 壳（演示级冻结态）**：演示逻辑链（张力图面→引导点击→交互分析）三环中，"引导点击→交互分析"两环在形态3 下部分让渡给宿主对话——**现场演示质量从此依赖宿主发挥**（agent 当场怎么说是概率性的）。参赛评审场景对可控性的要求是绝对的：演示现场翻车不可接受。故参赛期现有 QA 面板=演示级冻结态（稳定冻结+bug 修完+零新能力）保演示主力；形态3 的薄入口/宿主消费是**赛后**主线。此条同时决定议题3 的时序。
3. **冻结的精确定义**：路由层"停止自研投入"≠删除≠放烂——①diagnose prompt 永不动（红线原文·冻结期自然满足）；②编排器确定性冻结期维持（纪律原文）；③**B002/B004 等 CRIT bug 仍须修完**（CB-39 D1 批不因形态3 取消——演示可信度在冻结期更重要·因为壳不再进化就只能靠"不撒谎"立信）；④冻结=不投新能力（M1/M3 停）+保稳修 bug。

### 1.4 形态2 与形态3 的关系

**不是渐进（先 2 后 3）、不是并行（两条都做），是吸收（3 包含 2 的有效子集）**：

- M2 参数接地 → 平台必需（工具面 schema 接地）→ **保留**
- M4 eval 重放 → 变形为 C10 平台 eval → **保留**
- M1 迭代诊断 → 解法=宿主 agent loop → **停**
- M3 计划生成（G9） → 解法=宿主 plan-execute → **停**
- M5 体内代码通道 → 宿主原生代码能力承担·但受宪法约束（见 1.5）→ **体内停·体外由宿主承担**

"先做形态2 再演进形态3"的路径不存在独立价值：M2/M4 无论哪种终局都要做（直接按形态3 做即可包含），M1/M3 无论哪种终局都不该自研。二分法消解。

### 1.5 M5 的特殊性（补充）

## 三 议题6（主答）：平台宪法与"正道好走"标准

### 3.1 C1-C7 → C1-C11 平台宪法

R1 时 claude组 提的七条工具面硬约束（C1 PII 输出过滤 / C2 sim 白名单+demo=true 显式参数 / C3 gdb 不进 MVP / C4 三级审批（只读免审→产物写走宿主审批→删除类永不暴露）/ C5 路径沙箱前缀校验 / C6 key 不透传 / C7 铁律7 元数据随结果）直接升格入宪。形态3 下补四条：

**C8 契约单一源延伸**：MCP schema 一律从 `tool_contracts`（`contracts_to_tools_schema()`·:473 实存）派生·禁手写第二份 schema。依据：契约单一源红线在平台形态的自然延伸；CB-04 H1 教训（ForAI 自带默认绕过 computeStyle→彩虹图）的教训在工具面重演预防——手写 schema 就是下一代的"自带默认"。G8（契约派生自动化）是其工程实现。

**C9 工具面版本化**：工具面=对外 API 承诺。语义版本+破坏性变更须 deprecation 期（工具返回 `deprecated: true`+迁移提示·宽限期后移除）。依据：dsh组 R1 的 breaking 定量实锤（近 600 commit 内 16 个 `!:`·周级节奏）证明生态侧变更频率高——平台自己必须反例：变更慢、承诺稳，消费者才敢绑定。四 harness+薄入口都是消费者。

**C10 平台 eval**：G6 降权后的归宿。内容：每工具可调用性回归（schema 解析/参数校验/执行成功）+黄金问题平台版（5 个体检域问题经工具面跑通）+ schema 稳定性断言（C8 派生产物与 contracts diff=0）。CI 化。依据：三支柱③让渡给宿主后，平台自己可控的质量面收窄到工具面——防线从"每答必检"移到"每版工具必检"。

**C11 范式编码义务**（E4 前置条件一的落点）：工具 description 必须含尺度适用性/前置条件/输出范式说明；输出 schema 必须带口径标签（caliber）/来源（source）/结论性质（usage·铁律7）元数据；**工具面不得退化为裸函数清单**——设计评审逐工具检查 schema 里的范式知识含量，找不到的不放行。依据：1.2 承重判断——这是领域知识在平台形态下的唯一新载体。

### 3.2 「把正道修得比野路好走」的可操作判据

治理逻辑从"限制入口"（旧·防用户走歪路）转为"让正道成为最好走的路"（新·工具比野路强到没人想绕）。可操作化为五判据，每个 MCP 工具须答赢"**为什么不用 bash 裸调脚本**"：

1. **结构化输出**：JSON schema 保证的字段（vs bash 裸调解析 stdout——agent 解析文本是错误源）
2. **口径内建**：返回值自带口径标签/来源/作废状态（裸调要 agent 自己翻文档·口径注册表的知识随工具返回）
3. **脱敏/沙箱自动**：C1/C5 进程内强制（用户与 agent 都不用记纪律——纪律从条款变机制）
4. **错误语义化**：结构化错误码+建议动作（vs Python traceback——agent 可编程恢复 vs 只能重试或放弃）
5. **组合性**：dataset_id 枚举贯穿全部工具（A 工具输出=B 工具输入·类型安全链式；bash 裸调无类型链）

验收形式：工具面评审逐工具一行答辩（"用 bash 怎么做/用工具怎么做/差在哪"）；**答不赢的删或改**。R4 已实证：通用 harness 会写代码绕过不好用的工具——与其被绕过（且绕过时失去全部内建约束），不如不做或改好。

## 二 议题2 渲染 API（主答）

### 2.1 代码事实（重测校准，比「最大新工程」的预期乐观）

- 16 个 `generate*ForAI` 在位（heatmap/terrain/terrain3D/grid/buffer + toolbox 11 件），全部走「collectSources→computeStyle→addLayer→renderLayer」路径；
- **layer 对象 = 事实上的 render spec**：`generateHeatmapForAI`（`heatmap-tool.js:838`）产出的 layer（`:864-869`）＝ `{name, kind:'heatmap', colorMode, fc, paint:{unit,radius,opacity,intensity,weightField,weightCurve,rampKey,rampStops,intensityMin,_ui:{tool,analysisKey,dim,level,polarity,rampKey}}}`——渲染所需全部语义已在位，缺的是**契约化**（版本化 schema + dataset_id 数据引用 + spec-loader）；
- **style registry 雏形已在**：`computeStyle`（:105）= analysis→rampKey 语义令牌路由；`HEATMAP_RAMPS`（:5）= 色板注册表；`terrainRampOf`（:88）= 地形 ramp 同构。style registry 不是新建，是把这三件从 JS 函数**提升为登记契约**。

### 2.2 技术路径（三步 + 一个关键设计裁定）

| 步 | 内容 | 量级 |
|---|---|---|
| ① spec 契约化 | layer 对象 → 版本化 JSON schema：`{spec_version, kind, data:{dataset_id\|inline_fc}, style:{语义令牌(analysis/polarity/mode/ramp_key)+解析副本(ramp_stops)}, ui:{初始视角提示}}` | 0.5d（字段已存在·只做序列化契约） |
| ② 前端 spec-loader | 逆向入口：吃 spec JSON → 走既有 addLayer/renderLayer 同款路径（复用不重写） | 1d |
| ③ MCP render 工具 | 服务端产 spec：数据取 geo_registry/presets（dataset_id 解析）·样式令牌按登记契约解析 | 0.5d（G10 之后顺势） |

**关键设计裁定（防双源）**：**令牌解析权威留在渲染器（JS）**，spec 双载「语义令牌 + 解析副本」——渲染器优先用令牌走本地 `computeStyle`（单一源不破），解析副本仅供无 JS 侧消费者（场景 S）降级使用并标注 `resolved_by: frontend@version`。把解析搬进 Python = 第二份 computeStyle = 重蹈 CB-04 H1 rainbow 分裂。

**claude 补充的 `render_layer` 最小形态确认**：`dataset_id + 样式预设名 → 样式 JSON` 与三步①是同一件事的两种表述（①的 spec 输出即 render_layer 的契约体）；「先契约后消费者」正确——契约立在①，消费者（前端 loader/薄壳/宿主浏览器联动）后接。

### 2.3 渲染交互归属（新增·工程裁定）

- **v1 契约只管呈现，交互不进契约**。hover/click/视野-数据-结论同步是渲染端本地行为：状态持有=共享呈现层（现有 map.js 体系），谁监听谁派发=渲染端内部。协议化它没有消费者——宿主 harness 没有 MapLibre 实例，收不到交互事件；硬塞进 spec 只会造一个无人调用的死接口。
- **场景 S 的跨进程联动才需要 spike**，方向裁定：**前端持事件源唯一权威**（hover/click/sticky 状态 → SSE/频道推宿主），宿主反向指令=渲染指令（v2，一条 `focus_layer`/`set_view` HTTP 或 WS 指令）。spike 验证项三条：① B012/B013 教训下的 hover 归属不变（queryRenderedFeatures 取要素名）；② 订阅频道延迟与断线重连；③ sticky 状态跨进程同步语义（谁先到谁权威）。
- 图例文案/色带名=spec（呈现的一部分）；**联动逻辑=非 spec**——这条线写进契约文档。

### 2.4 边界（诚实）

- v1 只承诺呈现契约，不承诺交互 API（过度前置 = 死接口）；
- 大 fc 不内联：数万点一律 `dataset_id` 引用，`inline_fc` 仅限小边界层调试；
- 样式预设名=受管词表（C8 派生·防自由字符串漂移）——同 claude。

## 六 对 claude 报告的四点质证（重点）

### 6.1 C11 范式编码义务的可操作性——方向必须收，执行机制必须改

**质证点**：claude 的表述是「设计评审逐工具检查 schema 里的范式知识含量，找不到的不放行」——「找不找得到」是人判，**流于主观**；且「description 里提到尺度」≠「有范式知识」，纯文本检查会诱导文案堆砌（把「适用宏观面域」抄一遍就过关）。C11 若不改造，将变成无法执行的宣誓条款。

**工程改造：三层可操作化，把「含量」从文笔分变成可验证结构**：

1. **结构义务（机器可判）**：工具 schema 的 description 拆结构化子字段——`when`（适用尺度/前置条件）、`limits`（禁用条件/颗粒度边界）、`output`（输出范式与口径标注说明）。三字段必填非空 + 长度下限，CI lint 判定「有/没有」；设计评审只判「对不对」（内容质量），不判「有没有」（机器已兜底）。
2. **出处指针（机器可验）**：范式性约束必须带 `caliber_ref` 指针（`paradigm.py#id` / `outlet_kb#id` / 口径注册 id），CI 检查指针可解析。「含量」的操作定义=**可追溯知识条目数**，不是评审的主观印象。这同时呼应 C8（单一源）：范式知识从 paradigm.py/kb 派生进 schema，禁手写转述。
3. **行为回归（行为级）**：C10 平台 eval 加「范式回归用例」——同一问题经工具面 vs bash 裸调，结论口径/尺度/usage 标注一致才算过。这是对「含量」的终极检验：不是文案说了什么，是行为做对了什么。

**结论**：C11 的承重判断（裸函数清单=领域知识蒸发，与 R4 词典竞赛同源）我完全同意；但执行必须是「结构义务+出处指针+行为回归」三层，纯评审判含量=把红线交给主观。

### 6.2 G8 提前并轨是否与 B/C 线资源冲突——文件零交集，真依赖在数据字段

**文件域核对**（实测）：B 线 = `DATA/boundaries/presets/manifest.json` + `_总账.md` + usage 字段（DATA 层）；C 线 = `ai_qa/outlet_kb` + `industry_kb` + RAG 素材；G8 = `ai_qa/tool_contracts.py` + SKILL_DEFS/GEO_TOOL_CATALOG/prompts 派生 + （M2）白名单生成器。**三方文件零交集**——唯一交叉是 C3/C4 图层卡片 fact 的 source 指向 manifest，只读引用、无写冲突。

**真依赖在数据不在代码**：G8b 动态 enum 消费的是 **B1 的 `usage` 字段**。若 G8 整块提前到 B1 之前，生成器只能读无 usage 字段的 manifest → enum 会把 `analysis_output`（结论层）当输入暴露，撞铁律7。所以「提前并轨」的准确形态是**拆批**（§4 修订表）：G8a 静态派生现在就能并行（零风险），G8b 挂 B1 完成后。

**资源结论**：确认 claude「G8 提前并轨」——附拆批条件。单线程 Codex 下「并行」=交错排程，总工期不变，收益=G10 不被 G8 整体阻塞。

### 6.3 数据敏感级分层——工程初判（M5 绕过问题的宪法附录）

| 层 | 数据 | 宿主裸读 | 工具面 |
|---|---|---|---|
| **T0 公开底座** | boundaries/presets 几何、geo_registry 点层（治理后）、口径注册、知识库 | 无害 | list_data 全列 |
| **T1 已治理分析产物** | DATA/processed、DATA/analysis 大部分、出口卡 CSV（已脱敏） | 基本无害 | list_data 列 + 脱敏断言 |
| **T2 受控原始层** | DATA/raw 原始评论、12345 原文、中转站 PII 层（CB-38：PII 只引用不复制·派生剥离） | **必须过工具** | 工具内脱敏、server 侧路径白名单、禁裸读 |
| **T3 演示模拟** | DATA/performance sim、T1-T3 | 平台不暴露 | sim 禁入红线：不入工具面，白名单标 `demo=true`（C2） |

- **机械化**：manifest/总账加 `sensitivity` 字段（public/derived/restricted/demo），list_data 按 sensitivity 过滤、白名单生成器按字段自动分类——分层不靠人记。
- **诚实边界（必须写进宪法附录）**：分层防「误用」不防「恶意」——宿主有 bash+文件读，C2/C5 挡不住宿主直接 cat 文件；分层+工具面的作用=把正道修得比野路好走（五判据的工程意义），物理隔离（restricted 数据不进宿主工作目录/授权挂载）超出 v1 范围。**M5 绕过的残余风险=宿主写代码时敏感层纪律全靠宿主自觉——这正是「工具必须好用到自愿不绕」的工程理由。**

### 6.4 薄壳 2-4d 量级——复用度实测比 claude 假设更高，2d 端有三个前提

**实测复用面（比 claude 假设乐观）**：`api.js:220-235` `streamChat` = `POST /api/v1/chat` → `text/event-stream`，且**已带 `phase='plan'|'answer'` 端到端两段编排**（前端编排器逐步执行+结果回喂）——SSE 管道+编排骨架现成，不是从零；`llm.py` 适配层 provider-agnostic；`serve.py` 自起 uvicorn；前端 Design Token 体系现成。

**新做清单**：① MCP client（Python mcp 库 stdio 子进程——G10 产出 server）；② 薄 FC 编排（v0=单轮 FC+工具执行+结果回喂，参考现有 plan/answer 编排）；③ 极简 chat 组件（复用 tokens/既有组件）；④ 后端薄代理端点（`/api/v1/platform-chat` 同管道）。

**量级判定**：**2d 可达**，三个前提——G10 已产出 server、坚持单轮 FC（v0 不做多轮自主 loop）、Windows stdio spawn 无坑（vision_bridge 已证明 stdio MCP 本机可跑）。多轮自主 loop +1-2d → 3-4d。claude 的 2-4d 区间成立，但区间两端对应不同承诺：2d=消费型薄入口，4d=薄壳开始自带 mini loop。

**边界警告**：薄壳若做多轮自主 loop，就是在自研 mini harness——踩 M1/M3 停投的边界。v0 必须坚持「单轮+显式续问」，把 loop 留给真正的宿主。

### 6.5 附：对「正道好走」五判据的工程化验收补一条（沿用旧稿）

**同一任务 bash 裸调 vs MCP 调用的摩擦差可量化**——bash 路径「读代码猜参数+报错重试次数+N 次工具调用」vs MCP 路径「一次 schema 校验通过」——spike 验收时实测两组数字入档，作为「正道好走」的第一份基线证据（而非口号）。
