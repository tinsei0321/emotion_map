### 对齐 1：颗粒度原则（结论=数据来源维度）— **agree（理解一致 + 历史框架已活代码化）**

**用户原则**：数据来自哪个维度+颗粒度 → 只能得到哪个维度+颗粒度的答案·不臆造越维。

**glm组 理解确认**：**完全一致**——

**层级关系（glm 确认与原则文档一致）**：
```
城区（宏观）
  └── 街区（中观·由若干社区组成）
        └── 社区（行政单元·调研最小单元·党群中心）
              ├── 小区 A/B/...（居住单元·社区子集）
              ├── 零散非小区住房
              └── 城中村（专门调研对象）
                    └── 住房/栋（最细·若数据源支持）
```

**关键：社区 ≠ 小区（glm 理解）**：
- **社区** = 行政区划（官方管理·设党群中心·调研最小单元·**机制决定**）—— 体检按社区采集。
- **小区** = 居住形态单元（社区的子集·**社区 ⊃ n 小区 + 零散住房 + 城中村**）。
- 两者**维度不同·不混**：社区是行政维度·小区是居住维度。

## 二、对出口契约影响（glm组 建议）

**原则**：cannot 按维度声明（"本数据源为社区维度·无法到栋"）。

**glm组 建议（cannot 维度化模板）**：

现有 outlet 契约 cannot 是静态能力边界（如"不能测客观达标·需遥感"）——**升级为按数据源维度声明**：

```python
# urban_renewal_outlets.py 契约 cannot 升级
'renewal_demand': {
    ...
    'cannot': '不能测客观达标（需遥感）',  # 现状（静态能力）
    # 升级（维度动态·运行时填）
    'cannot_dimensional': '本数据源为 {data_dimension} 维度·无法到 {target_dimension}',  
}
```

**运行时填值（build_outlet_schema）**：
```python
# build_outlet_schema 组装时·按 result 数据源维度填 cannot
data_dim = result.get('data_dimension', '社区')  # 从分析产物取
target_dim = '栋' if data_dim in ('社区', '街区') else '小区'
card['limitations'].append(f'本数据源为 {data_dim} 维度·无法到 {target_dim}')
```

**glm组 落实（评估时）**：
- 检验出口卡 limitations 是否含维度声明。
- 检验是否按数据源动态填（非静态模板）。
- 检验"无法到 X"是否诚实（非臆造到 X）。
