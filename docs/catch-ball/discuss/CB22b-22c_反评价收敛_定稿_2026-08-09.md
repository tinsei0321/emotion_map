## 二、CB-22c（RAG 向量化）· 定稿

### 关键纠正（glm 实测·采纳）

1. **方案 A 概念混淆**：火山 multimodal embedding = **图片** embedding（2048 维图文匹配）·**非文本**——RAG 需文本 embedding·禁方案 A 原型
2. **CB-14 硬阻塞仍在**：.env 仅 AMAP + DEEPSEEK·智谱 key 未配·DeepSeek embedding 仍 proposal → **Phase 0 必须独立闭环**
3. **本末倒置修正**：2-7 步全依赖 embedding·须 Phase 0 通过后才启动 Phase 1

### 采纳（两组合并）

| 焦点 | 采纳 |
|---|---|
| embedding 选型 | **先验证智谱 embedding-3（文本·智谱优先）→ 本地 BGE（Py3.14 实测）→ 火山文本 embedding（查 endpoint）**·禁 multimodal |
| 向量库 | Codex **自建 numpy+sqlite**（零新依赖·规模够）vs glm **sqlite-vss**（兼容稳）——**Phase 0 实测**（chroma wheel 先试·失败降级）·倾向零依赖 |
| 颗粒度 | 文档/段落/条目/字段四层·**字段级数值走确定性（B 路径）禁 RAG** |
| rag vs query | B 先（精确）→ B 空降级 RAG（召回兜底）·不双建 |
| 后期维护 | 增量重向量化 + **embed_hash 指纹** + 与 validate_kb_drift 合并 `validate_kb_consistency.py` |
| 测试 | **分 Phase**：Phase 0（embedding 可用 + 向量库兼容）→ Phase 1（检索 e2e + **召回率 ≥80%** + 体积 <3000B） |
| 检索质量 | **黄金集**（10-20 query·Recall@5）·`tools/rag_eval.py`·选型有量化依据 |

### RAG 严格分阶段

```
Phase 0（P0 阻塞·不通过则后续全悬）：
  ① 验证 embedding：智谱 embedding-3 → 本地 BGE → 火山文本（配 key 是实际阻塞点）
  ② 验证向量库：chroma/sqlite-vss/numpy+sqlite 在 Py3.14 跑通
  ③ 闭环判定：任一 embedding + 任一向量库可用 → Phase 0 通过

Phase 1（Phase 0 通过后）：
  建向量库 + rag_search + 接入复杂语义 + 增量重向量化 + 召回率 e2e
```
