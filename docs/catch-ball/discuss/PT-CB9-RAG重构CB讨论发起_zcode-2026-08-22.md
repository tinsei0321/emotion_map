## 一 项目背景（为什么现在重构 RAG）

### 1.1 EMC 的平台化定位与 RAG 的角色

EMC（情绪地图）已完成为期两个月的平台化转型（形态3）：**EMC=平台**（数据/口径/知识/工具面/渲染契约自持）·**通用 Harness=可换的外置大脑**（现 dsh·未来或 Codex）·**唯一接触面=MCP 协议**（18 件工具·F_021-F_040）。两阶段路线：测试期外置驾驶舱验证 → 稳定期 EMC 壳吸收测试链路（自持对话框·ACP 事件流已定 v1 契约）。

RAG 在其中的角色=**平台的知识服务**：①MCP `rag_query`/`kb_facts` 面向外脑（dsh 实测已消费）②自持对话框 ai_qa 的 diagnose 阶段面向壳阶段。**换脑零知识损失**是平台承诺的一部分。

### 1.2 现状与问题（R52 审计链结论）

- 资产：蒸馏笔记 282 段（39 份 md 上游·**同源冗余**）+fact/concept/case 知识库 ≈ **<1k chunk 小语料**·中文·本地 BGE（预热 15s）。
- 已知问题：黄金集仅 14 条且旧断言弱（validate_rag_material·9 用例）·索引漂移无门禁·无同义词处理·无混合检索（纯稠密）·口径时效性（「未作废但已过时」）未治理·rag_query 返回无追问引导。
- 治理链已走完：Qoder 审计 → zcode 研判 → claude 双机回应 → **v1.1 定稿候选**（P0 基线→泳道①内容/②检索/③工程·含验收与门禁设计）——待用户确认生效。

## 二 主手报告·业界对照评估（详摘·全文见②）

### 2.1 业界 2026 标准管线（已检索核实·证据带源）

```
入库治理（元数据/谱系/去重/上下文前注）
   → 路由（Adaptive RAG：按问题类型分流）
   → 一阶段混合检索（BM25+稠密·RRF 融合·overfetch）
   → 二阶段重排（cross-encoder·top100→top5）
   → 评测门禁（黄金集 Recall@k·CI 化）
```

关键单项：**Contextual Retrieval**（[Anthropic 实证检索失败率 -49%](https://www.anthropic.com/engineering/contextual-retrieval)·叠加重排 -67%）——小语料一次性成本可负担·对 EMC 高适用。

### 2.2 EMC 形态适配判断

| 判断 | 依据 |
|---|---|
| **治理优先于暴力检索** | 小语料 <1k chunk·口径卡体系是独有强元数据资产 |
| **明确不采用**：GraphRAG/ColBERT/late-chunking/agentic 多跳 | 大语料/复杂推理专用·引入=纯复杂度 |
| 中文 BM25 用 jieba（已锁版）·稠密维持本地 BGE 系 | 本地纪律+现状延续 |

### 2.3 对 v1.1 的评审结论

**骨架不动**（P0→①②③泳道/混合检索/门禁/谱系去重均已对齐业界）·**增补六项**：

| # | 增补 | 一句话 | 量级 |
|---|---|---|---|
| A1 | 上下文化前注 | 入库时 DeepSeek 离线为每 chunk 生成 1-2 句定位前注（文档名+小节+口径状态）·embedding/BM25 同吃 | +0.5d |
| A2 | 显式路由契约 | 工具契约写明：精确口径→kb_facts 直查·叙述→rag_query；rag_query 命中口径类附「精确值以 kb_facts 为准」 | +0.2d |
| A3 | 可选重排档 | `rerank` 参数位（默认 False）·本地 bge-reranker·黄金集 A/B 实证后定默认 | +0.5d |
| H1 | **followup_cue 契约化** | rag_query 返回 `followup_cues:[2-3 条]`（确定性派生：维度相邻/口径关联/小节邻接·零 LLM）——**EMC 出知识地图·宿主决定走哪条边** | +0.3d |
| H2 | ACP 事件载荷 | rag_query 挂 ACP `tool.begin/end`（命中数/口径 refs）——壳阶段对话框显示「查知识库·命中 3 条·口径 K-C1」 | +0.1d |
| H3 | 双入口防漂移断言 | MCP 面与 ai_qa 面同一检索核心·两入口返回 diff=0 进门禁 | +0.1d |
