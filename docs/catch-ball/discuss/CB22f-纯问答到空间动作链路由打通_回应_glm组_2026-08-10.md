## 一、北极星对齐

**用户北极星**：「纯问答不只是生成答案文本为结束·EMC 优势在于空间落图的追问——文本中的地理/归因信息能识别+消费·通过追问实现 plan+execute 形成完整动作链。」

**glm 判定**：**完全 agree——这是 EMC 的核心差异化·护城河级定位。**

**glm 对齐理解（3 层）**：

| 层 | 含义 | 对标 |
|---|---|---|
| **纯问答** | 文本答案（55 项目/分片区/指标数值/政策要点） | 其他平台也有（DeepSeek 等能答文本） |
| **空间追问** | 文本答案→追问→衔接工具→空间图层 | **其他平台做不到**（无 GIS 工具/无本地知识库/无坐标解析） |
| **动作链** | 文本→标记→分析→对比→图层+结论（plan+execute 多步） | **EMC 独有**（EMC = 文本→空间动作的平台） |

**glm 对动作链边界的理解**：

| 追问类型 | 应衔接工具？ | 示例 |
|---|---|---|
| **标记/地图/点位** | ✅ 衔接 generate_point_layer | "能在地图上标记吗"（已实现 CB-22d） |
| **分析/密度/分布/热力** | ✅ 衔接 density/zonal/hotspot | "分析葛洲坝片区"→density/zonal |
| **对比/比较** | ✅ 衔接 compare_regions | "对比伍家岗和西陵"→compare |
| **归因/为什么/4×5** | ✅ 衔接 zonal（4×5 归因） | "为什么消极"→zonal |
| **概念解释/政策含义** | ❌ 纯文本（无空间操作） | "什么是城市体检"→general |
| **更多数据/清单** | ❌ 纯文本（再检索） | "还有哪些指标"→knowledge_qa |

**动作链深度建议（glm）**：
- **Phase 1（本轮）**：1 步衔接（文本→标记 / 文本→分析）——打通"识别+消费+工具衔接"。
- **Phase 2（后续）**：2 步链（文本→标记→分析 / 文本→分析→对比）。
- **Phase 3（远期）**：3+ 步链（文本→标记→分析→对比→归因）。
- **理由**：先 1 步再多步——避免一步到位架构风险（多步链编排复杂·1 步没通就做多步 = 空中楼阁）。

```python
# ai_qa/outlet_kb/urban_renewal_knowledge.py 新增
def query_knowledge_base(city, topic, keyword=None):
    """B 路径：确定性查询事实卡（精确 WHERE·非向量）。
    L1 city+topic → L2 keyword contains → L3 兜底"""
    facts = all_facts()  # 已有 :193
    results = [f for f in facts if f.get('city') == city and f.get('topic') == topic]
    if keyword:
        results = [f for f in results if keyword in f.get('detail', '') or keyword in f.get('name', '')]
    return results[:5]  # Top-5
```

## 五、glm 交叉挑战

### 挑战 claude（1 条）

**挑战：Plan B.5 识别层从"LLM 答案文本提取"改为"RAG 检索结果 source 溯源"——why？**

- claude Plan B.5："_assembleKnowledgeQA 出答案时·同步提取**文本中的**地理实体清单"——从 **LLM 生成的答案文本**提取实体。
- **glm 挑战**：LLM 答案文本是概率性产物——LLM 可能编造/漏掉/扭曲地名（如答案说"葛洲坝"但检索结果没葛洲坝）。
- **glm 替代**：从 **RAG 检索结果 source** 溯源（检索结果每条有 source/data_dim/type）——**确定性·不依赖 LLM 产物质量**。
- **理由**：ctx.extracted 是动作链消费的基础——**确定性优先**（对齐 AI·Copilot 内核 Dumb 中间）·LLM 答案文本仅作辅助（Phase 2）。
- **挑战 claude**：从 LLM 文本提取 vs 从 RAG source 溯源——哪个更稳？

**glm 倾向**：RAG source 溯源（Phase 1 确定性）——LLM 文本提取后置（Phase 2 补充精度）。

### 自我挑战（1 条）

**glm 动作链"先 1 步再多步"是否过度保守？**

- 用户北极星是"完整动作链"（文本→标记→分析→对比）——glm 建议先 1 步。
- **自我挑战**：用户可能期望一次看到完整链（非分阶段）—— 1 步是否不够"震撼"？
- **glm 诚实**：1 步是工程稳健（先通后优）——用户"打通路由"是**先通**（1 步通 = 路由打通 = 本轮目标）·完整链是**后优**（Phase 2）。本轮"打通"足够。
