### 焦点 2：query_knowledge_base 设计 — **partial（city+topic 确定性对·但需补"分级查询"）**

**方案**：city+topic 确定性 WHERE·Top-N ≤5·复杂语义 CB-22c RAG 后置。

**glm组 判断：partial——确定性 WHERE 对·但需补"分级查询"避免精确匹配漏命中。**

**精确匹配的问题**：
- 用户"宜昌有哪些更新项目" → city='宜昌' topic='project' → ✅ 命中 PROJECTS。
- 但用户"葛洲坝有什么项目" → city='葛洲坝'？——葛洲坝是宜昌片区·非城市。若 city 枚举只有"宜昌/伍家岗/葛洲坝"·需精确匹配"葛洲坝"。
- 用户"伍家岗停车项目" → city='伍家岗' topic='project' + 关键词'停车'——**精确 WHERE 查不到**（需 name/detail 含"停车"过滤）。

**glm组 建议（分级查询·3 层）**：

```python
def query_knowledge_base(city, topic, keyword=None):
    # L1 精确：city + topic（方案原设计）
    results = [r for r in KB if r['city'] == city and r['topic'] == topic]
    # L2 关键词：若 keyword 提供·在 L1 基础上 name/detail 模糊匹配
    if keyword:
        results = [r for r in results if keyword in r['name'] or keyword in r['detail']]
    # L3 兜底：若 L1/L2 空·降级 topic-only（同 topic 跨城市·标注"未找到 {city} 专属·以下是其他城市参考"）
    if not results:
        results = [r for r in KB if r['topic'] == topic][:3]
        return {'results': results, 'fallback': True, 'note': f'未找到 {city} 专属·以下是其他城市参考'}
    return {'results': results[:5], 'fallback': False}
```

- **L1 精确**（city+topic）：主路径·确定性。
- **L2 关键词**（name/detail 含 keyword）：细化查询（如"伍家岗停车"）。
- **L3 兜底**（topic-only + 诚实标注）：防空答·标注"非本城"。

**禁关键词模糊匹配的"过宽"风险**：
- 不用全文模糊（如 rapidfuzz）——L1.5 事实卡 detail ≤40 字·精确 contains 够·模糊反而误命中。
- RAG（CB-22c）处理复杂语义·L1.5 只做精确/contains。

### 焦点 3：接入点（general 短路 + 新端点）— **agree（复用 _quickIntent 模式·独立端点）**

**方案**：harness _quickIntent 加"知识数据查询词"短路 → /aiqa/knowledge_query 端点 → query_knowledge_base。

**glm组 判断：agree——复用 _quickIntent 短路模式正确·但独立端点（勿混 buildContext）。**

**现状核实**：
- `_quickIntent`（harness.js:60-77）已有 general 短路：CONCEPT_KW（概念）+ INVENTORY_KW（数据清单）+ GREETING_KW（问候）。
- INVENTORY_KW（emc-patterns.js:30）：`['上传了哪些', '有哪些数据', '数据列表', ...]`——**查的是已加载图层**（buildContext 直列）。

**B 路径与 INVENTORY_KW 的本质区别（glm 关键提醒）**：
| 维度 | INVENTORY_KW（现有） | B 路径（新增） |
|---|---|---|
| 问句 | "上传了哪些数据" | "宜昌有哪些更新项目" |
| 数据源 | **已加载图层**（buildContext 可列） | **知识库**（未加载·需查询） |
| 答法 | finalStep 直列清单（buildContext 已有数据） | **调 query_knowledge_base 查知识库** |
| 短路 | general（不调工具·buildContext 直答） | **general 但需调查询工具** |

**glm组 建议（接入设计）**：
- **复用 _quickIntent 短路模式**（加 KNOWLEDGE_QUERY_KW：'有哪些更新项目'/'体检问题'/'更新政策'...）→ short-circuit 到 general。
- **但 general 短路后不直答**——需调 `/aiqa/knowledge_query` 取数据·再注入 finalStep。
- 即：B 路径 = general 短路（省 FC 螺旋）+ **工具调用（取知识库数据）** + finalStep 注入。
- **vs INVENTORY_KW**：INVENTORY 是"buildContext 已有·直答"·B 是"知识库未有·需查"——**短路后分支不同**。

**实现建议（harness _quickIntent 扩展）**：
```javascript
// harness.js _quickIntent 加知识查询识别
const KNOWLEDGE_QUERY_KW = ['有哪些更新项目', '更新项目', '体检问题', '更新政策', '体检指标'];
if (KNOWLEDGE_QUERY_KW.some(w => s.includes(w))) return 'knowledge_query';  // 新短路值
// harness 主循环：if (qi === 'knowledge_query') → 调 /knowledge_query → 注入 finalStep
```
- 注意：`_quickIntent` 现返 `'general'`/`null`——B 路径需新返 `'knowledge_query'`（或 general 子类）·harness 主循环据此走查询分支。
