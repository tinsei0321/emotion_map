## 〇、一句话结论

**同意文档的核心命题——用户要的「情绪热点图」在 GIS 正名上就是 KDE 热力面（连续密度曲面），与 Gi\* 显著性检验是两个物种；但文档对「热力图=地形=同一端点」「Toolbox 无用户热力入口」的实查有误，且遗漏了两处关键事实（dormant deck.gl「热点图」第 4 轨、L1 数据字段 `spatial_hotspot` 实为 POI 地名而非 Gi\* 分类），推荐按「定名 KDE 热力面为主图 + Gi\* 网格化后作为显著聚集辅助层」的路线执行，先做命名定标与 3D 地形用户入口（P0），再做 Gi\* 网格化与双图层演示（P1）。**

## 一、逐焦点回应

### 焦点 1（最高优先）：「情绪热点图」的最终定位

**判定：agree（对"用户诉求 = KDE 热力面"的诊断） + partial（对三方案与初步倾向的收敛）**

证据：
- 用户诉求「舆情热度 + 高程/地势感」与现有 KDE 产物的属性完全对应：`create_terrain_mesh` 即加权 KDE 等值面，高度=`_level`（密度×强度）、颜色=`_norm`（区域极性），见 core/spatial_analysis.py:846-1050（F_007，带宽 250m/栅格 60m 默认，:849-850）；`/spatial/terrain` 端点接线 api/routes.py:309-340。方向正确，不应推翻。
- Gi\* 是推断性检验（hot/cold/ns 按 z 分数 ±1.96 分级，core/spatial_analysis.py:31-111），与"连续地势感"确实不同物种——文档 1.1/1.2 的概念基座论述客观、无争议。
- 演示逻辑链（CLAUDE.md:47-61）：张力图面（密度对比/色带/高低柱体）→ 引导点击 → 宏观诊断信号（定位关注区+主题倾向+排序优先级）。**KDE 热力面承担"张力图面"，Gi\* 承担"关注区显著性验证"，二者不是替代关系而是链条上下游**——这正是文档方案 C 与业界 KDE+Gi\* 双图层惯例成立的原因。

建议：
1. **定名即定标**：「情绪热点图」= KDE 连续密度面（2D 热力 + 3D 地形统一命名族）；Gi\* 更名为「显著聚集检验」（冷热点检验），不再叫"情绪热点图"。命名决定应先于实现（否则文档焦点 4 的契约同步无处落锚）。
2. 实现路线：**A（KDE 主图）先行、B（Gi\*）叠加为辅助层**——即文档方案 C 的 MVP 化。理由：A 改动最小（现有地形/热力管线已就绪，缺的只是 UI 入口与命名），能最快让演示看到"对的效果"；B 在输入粒度未修（逐点）前上主图只会重复"效果不太对"。
3. **不建议**把逐点 Gi\* 直接升为"情绪热点图"主图（方案 B 现形态）；也不建议双图层在未定名时并行开发（会放大焦点 4 的混乱）。

### 焦点 2：Gi\* 的输入粒度（若保留）

**判定：agree（逐点是主因候选成立） + partial（具体复用对象与粒度建议需修正）**

证据：
- 当前 `hot_spot_analysis` 强制 Point geometry、KNN k=min(8, n-1) 逐点计算（core/spatial_analysis.py:63-77），`/geo/hotspot` 直接把点层喂入（api/geo_routes.py:657-666）。逐点 Gi\* 对点密度/噪声敏感是统计常识，文档归因合理；但属"高可信推断"，本次未做运行时对照验证。
- **修正 1**：文档建议"复用 `/geo/grid_pois`"不准确——`/geo/grid_pois` 返回的是格内 POI 归属清单（api/geo_routes.py:415-473），不是聚合统计值。应复用 **`/spatial/grid` → `create_square_grid`（F_006）**：已输出每格 `point_count / score_mean / polarity_index / n_*`（core/spatial_analysis.py:725-827；测试断言 tests/test_spatial_analysis.py:26-37），拿格质心 + 每格一个值做 Gi\* 是现成数据链路，改动小。
- **修正 2**：粒度建议 500m（对齐尺度表"区=500m"，tool_contracts density mode=3d 默认 cell_size=600 偏大、社区档 250m 偏细易空格）。宜昌城区演示建议 **500m 起步**，`point_count >= 3` 的格才参与（空格无数值会破坏 Gi\* 的 n 与邻接语义）；KNN k=8 保留（防岛屿，代码注释 rationale 正确，core/spatial_analysis.py:73-75），若格数上千可考虑 k=10~16 更稳，属可调参数非必须。
- 输出建议补 `Gi_Z/Gi_P/tier`（90/95/99% 分档），替换现在固定 ±1.96 二值分级（core/spatial_analysis.py:104-111），让"关注区"有置信度梯度可讲。

### 焦点 3：Gi\* 的 hot/cold → 极性色映射是否成立

**判定：partial（语义链逻辑自洽，但把两维信息压成一维色，且丢弃置信度）**

证据：
- `invert=true` 链条本身成立：score 为 0~1（SnowNLP，docs/spec.md:33），`values = 1.0 - values` 后 Gi\* 的 hot = 显著"高(1-score)聚集" = 显著负面聚集（core/spatial_analysis.py:88-89；HotspotRequest invert=True 默认，api/geo_routes.py:660-661）。前端重映射 `hot=Very Negative / cold=Very Positive / ns=Neutral`（frontend/js/toolbox/hotspot-tool.js:24-29）与后端语义一致。
- **问题在于信息损失**：(a) Gi\* 检验的是"高/低值聚集的显著性"，不编码聚集区极性强度——一个显著负面聚集区的平均极性可能只是"轻微负面"；(b) 分类只用 ±1.96 一个阈值，丢弃 z 幅值与 90/95/99% 三档（core/spatial_analysis.py:104-111）；(c) 前端重映射后 `Gi_Z/Gi_P` 虽有保留（hotspot-tool.js:23 拷贝 props），但渲染只用 3 色，图例文案"显著热点/显著冷点"（api/geo_routes.py:674）未说明"热点=负面聚集"。
- 双图层分工（若走 C）：KDE 层已用 terrain-9 红绿发散编码极性（frontend/js/state.js:526-534 `terrain-9`；`_norm` 由 `_pi_to_norm` 映射，core/spatial_analysis.py:1023-1035），Gi\* 层若再全色重涂会产生"红绿双主色"语义冲突。

建议：
1. 保留点位/网格 hot/cold 时，图例文案改为「显著负面聚集 / 显著正面聚集 / 不显著」（语义等价但诚实，不冒充强度色）。
2. 双图层模式下：KDE 层承担极性色，Gi\* 层用**显著性视觉通道**（透明度/描边/符号尺寸按 90/95/99% 分档，可单色系），避免双色带打架。
3. Gi\* 输出补 tier 字段（z > 1.65/1.96/2.58），演示"关注区置信度"是宏观诊断信号的加分项。

### 2.2 误诊 / 不准确

1. **「热力图 = heatmap-tool.js 实际委托 runTerrain（与地形同款 KDE mesh）」「热力=地形=同一端点」——误诊**。
   - 2D 热力图（`generateHeatmapForAI`，frontend/js/heatmap-tool.js:830-871）**无后端调用**，直接创建 `kind:'heatmap'` 图层（:855-862），由 MapLibre 原生 heatmap 渲染（map.js:678-741 `addHeatmapPaint`，注释明言 "native MapLibre `type:'heatmap'` = Gaussian KDE"）。
   - 只有 3D 地形（`generateTerrainForAI`，heatmap-tool.js:879-921）才调 `runTerrain` → `/spatial/terrain`（:894）。
   - EMC density 路由是三出口（tools.js:1304-1340）：mode 2d → generateHeatmapForAI；mode 3d → generateGridForAI；mode terrain → generateTerrainForAI。**文档自引的 :826-877 恰是"不调 runTerrain"的函数区间，自相矛盾**。
   - 对结论的影响：文档 2.2-1 的依据被削弱，但"2D 热力与 3D 地形同属 KDE 族、与 Gi\* 不同物种"的核心结论不受影响。
2. **「Toolbox 里没有面向用户的 KDE 热力入口」——不准确**。
   - 实际有用户入口："HeatMap · 核密度分析" 工具行（frontend/index.html:144-149）+ 完整 dialog（#heatmap-dialog，index.html:417+），`generateHeatmap` 可产出 2D 热力图（heatmap-tool.js:677-820）。
   - 准确的说法是：**用户入口只有 2D 热力（且主卡名叫"情绪地形"却只出 2D 彩虹）；3D KDE 地形（真正"地势感"）被 dialog 拦截**——`if (isDev || dim === '3d') { toast.info('该表达（3D / 网格聚合）待后续批次开发，UI 已就位'); return; }`（heatmap-tool.js:689-691），computeStyle 对 terrain 也只给 2D 按钮（:106-111）；Gi\* 则确无 UI。
3. **次要：带宽"250m"是后端默认**，前端 `generateTerrainForAI` 实际按点数自适应 350/250/180m（frontend/js/heatmap-tool.js:897）——文档 2.1 表"高斯带宽 250m"作为实现要点描述不全。
4. **次要：焦点 2 的复用对象 `/geo/grid_pois` 不准确**（见焦点 2 修正 1）。

### 2.3 遗漏

1. **第 4 轨：dormant deck.gl「热点图」**（frontend/js/map.js:742-784 `addHotpointLayer`，ScreenGridLayer 屏幕方格聚合；:794 标注"搁置，独立功能"；全仓无调用）。文档"三轨"漏掉它——若重做"情绪热点图"时未清理，易被误当现成方案或产生第 3 个"热点图"实现。
