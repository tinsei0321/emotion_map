### 2.2 为什么 60s httpx 超时没触发（R2 核心·代码实锤）

- `llm.py:345` `cli = LLMClient(base_url=..., model=..., api_key=...)`——**未传 timeout → 默认 60.0**（:58）；`:96` `httpx.Client(timeout=self.timeout)`。
- **关键机制**：httpx `timeout=60.0` 是「每次 read 的超时」而非「整个流的总时长」——若 DeepSeek 慢速 trickle（reasoning token 每 <60s 一帧）或 office 网络中继半开（Windows recv 不超时），读超时不会触发；流式挂起 = **无异常** → `_is_retryable`/retry/fallback（llm.py:354-366）全部不生效（它们只处理已抛出的 LLMError）。
- 结论：缺**墙钟总 deadline**（每 chunk 检查 monotonic）；这解释了「挂 5.5 分钟无任何日志」。

## 三、逐焦点

### 焦点 1：DeepSeek 流式挂起机制 — **partial（挂起事实 agree·机制 = 无总 deadline + 读超时失效）**

- 本机 curl 10/10 全 200（见一）——当前无法复现挂起；claude 的 office 17:0x 失败（401/net/mid）属间歇性/时段性环境。
- trace 无 D_* 日志 = 非「已抛错→重试」路径，而是「无异常挂起」：httpx 60s 读超时未触发（慢 trickle/半开连接可绕过 per-read 超时）。
- 修复：墙钟总 deadline（每 chunk 检查）→ 抛 LLMError → 现有 SSE error 帧 + retry/fallback 接管。

### 焦点 2：后端 LLM 无服务端超时 — **agree（修正：timeout=60 已设·但非总时长）**

- 证据：llm.py:58/96 timeout=60.0 已设；但 5.5 分钟无 exit 证明其未生效（per-read 语义 + 半开/慢流）。
- 修复：`chat_with_fallback` 加 `deadline = time.monotonic() + LLM_TOTAL_TIMEOUT_S`（flash 60 / pro 90）·每 chunk 检查·超时 `raise LLMError('LLM 流式总超时(Ns)')` → router.py:167-168 已有 catch 并 yield `{"error":...}`（链路已通·只欠 timeout 触发）→ 前端 `stages.finalStep` onError 抛 → 降级。
- 附带：httpx timeout 显式三元组（connect=15/read=60/write=30/pool=15·`httpx.Timeout`）防 connect 阶段无限等。

### 焦点 3：前端 abort 后降级链路 — **partial（runTemplatePath 已覆盖·quick-rag 未覆盖）**

- 45s abort → finalStep reject → runTemplatePath/runChainPath catch → `_composeDegradedConclusion` ✓（用户本应 ~46s 看到降级）。
- **quick-rag 路径 `_assembleKnowledgeQA:214` 无 catch** → `[请求失败]`（非降级）·且 onFinalDone 未调用时 UI 转圈不停——本会话正是 quick-rag（无 FC）。
- 后端 zombie 线程：前端 abort 后后端生成器仍阻塞·后续请求排队——用户「一直转圈」的另一来源。
- 修复：:214 包 try/catch（复用 `_composeDegradedConclusion` 或诚实文本·必须调 onFinalDone 收尾）+ 服务端 deadline（释放线程）。

### 焦点 4：rag_search BGE 冷加载 15.9s — **agree（真实·warmup 已接但不可观测）**

- 15.9s 与 claude 描述一致（F_015 exit 15899.8ms）；warmup（api/main.py:71-86）已存在但静默失败/未完成。
- 修复：warmup 完成标志（模块级 + 启动日志 `[OK]/[WARN] RAG warmup`）·首问前未就绪时 rag_search 返回明确 ok:False 或保持阻塞但可观测——不新造机制。
