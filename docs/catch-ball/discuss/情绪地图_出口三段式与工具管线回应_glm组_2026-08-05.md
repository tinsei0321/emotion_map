### 焦点 2（观点 vs 结论区分）：agree —— 关键是 prompt 指令 + 前端视觉分层

**glm组 判断：agree —— 观点/结论区分是对的，落地靠两层：prompt 指令分工 + 前端视觉层级。**

**证据**：
- 现状 FINAL_TEMPLATE 三句骨架（:129）= ①动作 ②产出 ③交互——**没有"观点"位置**。结论与观点混在"简短结论"里（manifesto:57）。
- router.py:114 finalStep 传 `context`（req.context·含 grounding 图层摘要）+ `question`（用户原问句）——**问句已可达 finalStep**（prompts.py:168 FINAL_TEMPLATE 里 context 含问句上下文）。

**glm组 建议（两层落地）**：

**① prompt 指令分工（finalStep 软扩·D019 边界）**：
在 FINAL_TEMPLATE 加一句指令（~50 字）：
```
**观点先行**：第一句给基于用户提问的明确观点（回答"所以呢/这说明了什么"）·
再给描述性结论（基于图数的客观论述）。观点答用户·结论述结果·两者不重复。
```
这让 LLM 区分"观点（转化回答）"vs"结论（描述论述）"。

**② 前端视觉分层（harness/panel·非 prompt）**：
- 观点 = 强调卡（醒目色块/大字·如蓝色 callout）
- 结论 = 学术段落（常规 markdown）
- 用 markdown 语法约定区分：如观点用 `> **观点**：...`（引用块+加粗）·结论用 `### 结论` 小标题——前端按语法渲染不同视觉层级。

**防重复/矛盾**：prompt 指令"两者不重复"是软约束·真正防矛盾靠**前端呈现分层**（视觉层级不同·用户自然区分）+ applyQualityDefense 可加规则（观点与结论文本相似度>0.8 标 warning）。
