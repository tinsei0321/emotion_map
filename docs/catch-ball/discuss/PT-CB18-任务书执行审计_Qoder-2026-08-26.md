## 白话摘要

像施工队开工前对图纸：六件活五件能干、一件要先改图纸（「待用户拍板的清单」一栏没有现成材料来源，照原样干会越干越歪）；三处验收是「拿尺子量不了」的虚条款，已各给替代判法；工期 2.25 天偏乐观，按我方手速重估 2.75~3.25 天；Kimi 的 7 条修改全数接受。另发现图纸本身一处笔误——写着「七字段」实际列了 8 项。

## 二、验收审计（逐条可判真伪 / 虚）

- **虚①** W1-1「骨架与 git 实测一致」：靠人眼比对不可复验。替代：交 `check_state.py` 或 pytest 用例，断言「重生成 diff=0 且分支/最近提交与 `git` 输出一致」（progress 契约门禁已有同构先例）。
- **虚②** W1-1「交接段七字段齐全」：**名实不符，实列 8 项**（当前目标/已完成/技术决策/核心文件/测试结果/已知问题/失败方案/下一步）。修法：正名为八字段或删并一项，否则验收数数都有歧义。
- **虚③** W1-2「同一要求全仓只出现一次」：需附 Kimi③ 映射表 + 全仓 grep 校验程序，否则纯主观。
- **虚④** W1-3「覆盖主要编号」：「主要」不可判，改覆盖率 + 未覆盖清单（§一）。
- **虚⑤** W2-1「本批产出 ≤2 文件」：Kimi 已指出（流程天然 2 份必过），同意改下批试用。
- **虚⑥** W2-2「下一批强制带档位字段」与 W2-3「本批实际使用」：本批窗口内均不可判，按 §一 改判据。
- 其余（行数达标/模板成文/档位成文）可判，无异议。

## 五、改造者悖论自证方案（四条可检查判据）

- **判据 A（信息未丢）**：去重清单逐条四列——原分布文件 / 删后唯一落点 / 哪些 harness 读该落点 / 校验命令（全仓 `grep -r` 关键词确认旧位置零命中或仅剩指针行）。清单随交付落盘，任何一条可复核。
- **判据 B（纪律未静默失效）**：四条全局纪律（沟通纪律/白话摘要硬条款/学习报告必回应/双环境同步）做全仓关键词校验——新落点命中、旧位置零命中，校验脚本输出作为交付附件。
- **判据 C（行为未退化）**：瘦身后开一个全新 Qoder 会话，只注入新手册，令其当场回答「四条纪律是什么 + 当前分支」，答案正确即通过（异构验证，忌与实现同构·R8）。
- **判据 D（机制未断裂）**：`py tools/gen_progress.py` 重生成 diff=0 + 全量门禁零失败——指针化不得打断任何被测试保护的路径。
