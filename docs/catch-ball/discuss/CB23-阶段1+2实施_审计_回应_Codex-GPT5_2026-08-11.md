### 焦点 2 · A3 hotspot 守卫（std=0 / NaN>0.5）

**结论：agree（阈值合理·invert 正确）+ 补 P1：NaN 残留传播**

**一句话证据**：守卫在原始值上执行——常数序列 std=0 在 invert 变换（1.0-v）后仍为 0·负数序列 std>0 通过（invert 不改变方差）·逻辑正确；NaN>50% 阈值合理（多数缺失=不可用）。

**定稿建议（P1）**：
1. **NaN ≤50% 的残留问题**：守卫后 `values = gdf[value_col].values.astype(float)` 仍含 NaN → `G_Local` 对 NaN 传播 → 部分点 Gi_Z=NaN 静默 ns（与「防静默退化」目标部分冲突）。建议守卫通过后 `dropna()` 行 + `trace_log` 记录 n_dropped（或更严：任一 NaN 即报错——checkup 适配器已保证 value 无 NaN，此分支只影响上传层）。
2. 阈值维持 0.5（可调参数化更好，但非必需）。

### 焦点 3 · A4 {col}_sum 影响面

**结论：agree（无消费方冲突）+ 补 P1：zonal_stats 响应裁剪丢 sum 值**

**一句话证据**：`_props_df(gdf, cols)` 只返请求列（geo_routes.py:156-158）——prop_cols 不含 `{c}_sum` → **排序用了 sum 但 rows 输出不含 sum 值**；现有消费方（frontend zonal-tool.js 读 rows[0]/sort_by·rank 直读 gdf.columns·panel.js 读图层 feature.properties）均不受影响。

**定稿建议（P1）**：
1. `zonal_stats` 在 `agg_cols` 非空时动态扩展 prop_cols（追加存在的 `{c}_sum`）——阶段 3' 统计表/观点卡（harness `_lastToolRows` → 出口卡）需要总量数值·否则 AI 只能看到排序看不到值。
2. 聚合列冲突：agg_stats 为新建 DataFrame·与 polygon 属性 merge 时若输入面层含同名 `X_sum` 列可能覆盖（低概率·上传层场景）——可加列名冲突检查或注释说明，非阻断。
