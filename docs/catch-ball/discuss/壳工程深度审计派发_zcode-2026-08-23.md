## Qoder 审计重点（架构/安全/性能）

1. **C1 事件通道**：向后兼容是否真兼容（legacy 签名零破坏·载荷逐字段核对）；事件序列化/反序列化的内存泄漏面（长会话 listener 清理）；键白名单是否有绕过面。
2. **C2 BA 适配器**：dsh 子进程生命周期（启动→超时→杀→清理·有无僵尸进程风险）；错误传播链（dsh 崩溃/网络断/API key 失效时用户看到什么）；安全面（subprocess 注入风险·输入是否消毒）。
3. **C3 服务端端点**：并发安全（多用户同时 dsh 调用·端口/进程竞争）；超时 300s 的合理性（vs FastAPI/uvicorn 默认）；响应体积控制。
4. **C4 前端分发**：三引擎切换的竞态（快速切换 engine 参数时·旧引擎事件是否泄漏到新引擎会话）。
5. **横切**：五文件间的依赖闭环有无死锁/循环引用风险。

## claude 审计重点（正确性/测试/集成）

1. **C1 事件契约合规**：实现的四族事件是否与 `docs/acp-contract-v1.md` + `tests/acp_schema/` 的 schema **逐字段吻合**（有无私自加字段/漏字段/类型不匹配）。
2. **C3 API 设计**：端点的错误响应格式是否语义化（ok:False+hint 惯例）；HTTP 状态码正确性；与 aiqa_routes 既有端点风格一致性。
3. **C5 测试覆盖缺口**：schema 校验器 30 用例+冒烟三场景——**漏测什么**？边界（空事件/超大载荷/并发事件/malformed JSON）覆盖吗？S5 chips 三态降级有无独立测试？
