# CB42 · dsh 思维链成本诊断 · 「契约约束思维发散」与业界方案（Qoder 评估讨论发起 · 2026-08-21）

> 发起方：Qoder（独立分析组）。触发：用户实测反馈「简单 GIS 操作也要思考 2~3 分钟，太夸张」——在 12345 热线 800m 方格聚合任务（56 step / 9m29s / deepseek-v4-flash / reasoning=max）过程数据上做一次根因诊断。
> 数据源：`DATA/exports/12345_800m方格/session_parse.json`（逐 step usage/thinking/工具）+ `任务过程与成本报告.md`。本文所有数字均可从上述两件复核。
> 性质：诊断 + 方案评议，零实施。

---

## 〇 一句话结论

**慢的主因不是「想太多」而是「步太多 × 每步固定思考税」**：单步 thinking 其实很短（简单步骤仅 5-100 字符），但 `reasoning_effort=max` 让每个 step——包括改一个变量名——都支付推理模型的固定延迟（2~34s），56 步累计 9m29s。「契约约束思维发散」方向正确，但业界证明有效的不是"禁止思考"式 prompt 契约，而是**effort 分档、预算封顶、路由分级、工具粗粒度化、模板固化**五种机制——EMC 的 ai_qa harness 阶段化设计恰好是其中"阶段化 effort"的现成载体。

---

## 一 为什么这么慢（数据钉死，三层根因）

### 1.1 配置层：max 推理是全局常驻税

会话配置（主报告 §0）：`deepseek-v4-flash` + **Reasoning Effort = max** + Max Tokens 256000。

- 推理模型的固定成本结构：每步 = prefill（重读全上下文）+ reasoning 生成 + 首 token 延迟 + output。effort=max 意味着**每一步都按最高档推理**，不区分"规划一步"还是"改个列名一步"。
- 实测每步耗时分布（session_parse step start/end）：**最小 2.0s（step 35，thinking 仅 17 字符）→ 最大 34.1s（step 20 写脚本）；56 步中位数 ≈ 10s**。
- 关键反直觉证据：**慢 ≠ 思考长**。step 34（2.6s）thinking 81 字符、step 41（2.5s）thinking 95 字符——都是"修 count_cols 加两个字段"级别的琐碎推理，但每步仍付 2.5s 起步价。真正的思考大户是 step 20（4546 字符，写 235 行脚本）与 step 33（2915 字符），它们慢得有道理；**多数步骤慢得没道理**。

### 1.2 循环层：一步一调用的串行循环把步数放大 2-3 倍

- 56 step 中 **50 个是单工具步**（仅 step 1/6/7/8/9/10/11/18 有并行调用）——dsh loop 默认串行，没有把独立的探查/编辑批量下发。
- 三个可压缩的步数黑洞：
  1. **微调循环**（step 39-42：四次连续 str_replace_editor，每次 2.5-4.1s）——4 个小补丁本可一次 edit 完成；
  2. **重复验证**（step 29/36/43 三次 pwsh 参数长 109、结果长 1598，完全同形命令）——"跑一遍看看"反复执行；
  3. **先写后补**（step 20 写脚本时未含 count_cols/summary 区域字段，step 23/28/33/38/39-42/48 共 8+ 步补写）——方案阶段（step 14-20 读 grid_export/既有脚本）没把输出 schema 一次定全。

### 1.3 上下文层：cacheRead 线性膨胀（成本而非时间主因）

- cacheRead 从 step 1 的 256 涨到 step 56 的 104,192，**平均每步 +1,860 token**，Turn 1 累计 3.87M。DeepSeek cacheRead 单价低所以账单不吓人，但①每步 prefill 随上下文变长（时间税）②若换按 cacheRead 正常计价的供应商，同样循环成本放大 10-50 倍。

### 1.4 对用户「2~3 分钟」的诚实校准

单步没有 2-3 分钟（最大 34s）。用户体感的 2-3 分钟对应两种真实情况：①**一个语义操作**（如"把区域统计从质心改成点级"）在 loop 里摊成 4-8 个 step（探查→改→跑→验），累计 40s-2min；②整个任务 9m29s 的总等待。两种都是真的，且**同根**：步数 × 每步固定税。

## 二 「契约约束思维发散」可行吗——可行，但不是那种契约

### 2.1 先否决一种做法

「在 system prompt 里写"简单操作不要思考/少思考"」**无效甚至反效**：推理模型的 reasoning 是采样行为，prompt 压不住 effort 档位的预算；且"判断这步简不简单"本身又要花思考。业界（Anthropic/OpenAI 文档口径一致）：**思考深度由参数控制，不由劝说控制**。

### 2.2 有效的"契约"长什么样（五种机制，按 EMC 适配度排序）

| # | 机制 | 业界出处 | EMC 适配 |
|---|---|---|---|
| ① | **阶段化 effort 契约**：规划/总结步 high，执行/调试步 low/none | OpenAI reasoning_effort（minimal/low/medium/high）；Anthropic extended thinking 可按请求关；Google Gemini thinking_level | **EMC 已有现成载体**：ai_qa 四阶段 harness（THINK/EXECUTE/ANSWER/REVIEW，`docs/ai-qa-design.md` 第 3 章）——Stage 2 EXECUTE 的工具步天然该 low/none，Stage 1/4 才给 high |
| ② | **预算契约**：每步 reasoning budget 封顶 + 全任务总预算，超即降级/截断 | Anthropic `budget_tokens`（硬预算）；学术 STILL-2 / Quiet-STaR（自适应截断冗余思维） | EMC 三态出口契约旁加一条「思考预算契约」：harness 代码强制（与"由 harness 强制非靠模型自觉"同哲学） |
| ③ | **路由契约**：轻模型先判任务复杂度，再决定大模型 effort | OpenAI model routing（gpt-5-mini 路由）；各家 cascade | EMC 已有 router.py / candidate_selector.py 基础；短任务直连工具（A 通道）根本不过大脑循环——与「A 是按钮不是路由」决议同构 |
| ④ | **工具粒度契约**：提供粗粒度复合工具，一次调用替代 N 步微调 | Anthropic tool use 最佳实践「batch & 粗粒度工具」；CARTO 地理 agent 教训「结构失败多源于工具过细」 | **本次最大的单点收益**：G10 插座已经是粗粒度（zonal_stats 一步完成聚合+统计）；本任务 agent 没用 G10 而是手写 235 行脚本——因为场景在 dsh_test 仓自由模式。若走 EMC 插座，「800m 方格聚合」=1 次 MCP 调用 ≈ 10s 冷启动，**9m29s → 约 1-2 分钟** |
| ⑤ | **模板/playbook 契约**：已验证路径固化，同类任务跳过侦察-方案-编码 | Claude Code skills；OpenAI AgentKit workflows；Codex skills | EMC 已有 SCRIPT/gen_* 脚本资产族；把「网格聚合」做成参数化模板（grid_size/数据源/区域口径三参数），第二次同类任务零思考直跑 |

### 2.3 给 EMC 的具体建议（按收益排序）

1. **④+⑤ 合并（收益最大，约 80% 提速）**：把本次手写脚本沉淀为 G10 第 9 插座「grid_aggregate（cell_size, source, region_caliber）」或至少参数化模板。同类任务从 56 step 变 1-3 step——**约束思维发散最好的办法是让不需要思维的任务不进思维循环**。
2. **①（架构内最干净）**：EMC harness 阶段表加一列 `effort`（THINK=high / EXECUTE=low / ANSWER=medium / REVIEW=low），LLM 调用层按阶段传参。改动面 = llm.py 一处 + 阶段表配置。
3. **②**：设全任务 reasoning 总预算（如 50k token），harness 超预算即降档续跑并告知用户——防止未来某个任务跑成 30 分钟。
4. **dsh 自由模式侧**（本次任务的真实场景）：给数据分析类会话配 medium 档而非 max；max 仅留给"复盘/方案设计"类显式请求。dsh 的 router-standard 预设可加 effort 分级（若其支持 per-session effort）。

### 2.4 预期收益量化

| 场景 | 现状 | 目标 | 手段 |
|---|---|---|---|
| 同类 GIS 聚合任务（第二次起） | 9m29s / 56 step | **30-90s / 1-3 step** | 机制⑤模板直跑 |
| 首次自由探索任务 | 9m29s / 56 step | 3-4min / 20-25 step | ①effort 分档 + ④粗工具 + 并行下发 |
| 每步固定税 | 中位 10s | 2-4s | effort max→medium/low（执行步） |
