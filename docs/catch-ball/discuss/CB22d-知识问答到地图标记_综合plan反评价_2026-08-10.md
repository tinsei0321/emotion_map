### 1.2 claude组 对用户判断的客观评估

**认可的核心（根因比「意图路由落空」深一层）**：

> 根因 = **Smart（意图/计划）与 Dumb（工具/执行）之间能力接口断裂**。deepseek 能计划「项目名→匹配地点→生成点图层」，但：① 意图枚举仅 4 值无此值（LLM 只能硬塞 gis_operation）② FC 14 工具无 names→点图层 ③ 编排器无此路由 → **计划与执行脱节** → C2 闸门 request_upload 兜底。官方模型计划=执行=同一模型天然不脱节（代价=幻觉）；EMC 拆开二者就必须补承接，承接缺失即根因。

**修正的两点（客观立场·用户要求说错必指）**：

| 用户说法 | claude组 修正 | 证据 |
|---|---|---|
| EMC 的 deepseek 没通过意图判断 | **不准确**——diagnose **必做**意图判断（编排器强制流程），问题是**判断目标集里无此值**（4 值枚举），非没判断 | [prompts.py:200](ai_qa/prompts.py#L200) intent 四值 |
| 官方真匹配了地点信息 | **不准确**——官方是**幻觉**（预训练猜测·无真实地理数据可查），「匹配」只是模型**以为**匹配了；EMC 不能复刻（铁律拒幻觉·数据溯源） | 官方窗口无地理数据源·EMC 有 C2 数据闸门守数据真实性 |

### 1.3 根因精确表述（供三组对齐）

> **EMC 的 Smart 与 Dumb 之间能力接口断裂**：LLM 能计划「项目→地点→图层」，但意图枚举无此值 + 工具集无此工具 + 编排器无此路由 → 计划与执行脱节 → C2 request_upload。官方不脱节（同模型·幻觉兜底）；EMC 拆开须补承接。**用户判断二成立·两处表述修正**。

### 2.3 claude组 分歧仲裁（glm 独立新意图 vs Codex 归 gis_operation）

**裁决：采纳 Codex 方案「归 gis_operation + 新技能 generate_point_layer，不新增 intent 枚举」**。技术取证：

1. **intent 是 LLM 从枚举字符串输出**（[prompts.py:200](ai_qa/prompts.py#L200) 四值）·「选择要点·铁律」硬编码 gis_operation 可选技能（[prompts.py:267](ai_qa/prompts.py#L267)）·技能目录由 `tool_contracts.py` 派生（prompts.py:88 D026 单一源）——**归 gis_operation + 新技能改动面最小·最贴合既有架构**
2. **不新增 intent → 不碰枚举四值注意力 + PARADIGM_MAP + 静态断言**（Codex 论证）·规避 glm「改 prompts.py:200 + 4 值注意力稀释」风险
3. **glm 合理内核全采纳**：独立于 knowledge_qa（不开内部分支·守 CB-22 铁律）+ 不动 `_isResumeCue` 正则（Codex 挑战 A 证实）
4. **Codex 挑战 2 全采纳**（defaultPaint point 样式 / 并发策略 / 未命中来源标注）

**分歧本质**：两者都能实现，但 Codex 方案改动面更小、更贴合既有架构（intent 枚举是 LLM 自由输出的 4 值·新增值改 prompts.py:200 + 注意力稀释风险）。glm 的「独立新意图」架构更清晰，但增量更大。**取 Codex 骨架 + glm 内核**。
