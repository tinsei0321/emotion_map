## 二 真正的四个悬置点（研判主体·按重要性排序）

### 悬置 1（最大）：A1 前注的价值主战场——Codex 挑战成立吗？

- **Codex 的挑战**：Anthropic -49% 是英文大语料+通用检索场景；EMC 黄金集主痛点=精确名词类（胜负手在元数据路由+BM25 精确匹配），**前注/重排主要改善叙述类**——若黄金集 60 条中名词类占大头，A1 整体增量被稀释。建议分类增量呈现·<2pp 降级「口径类专用」。
- **Kimi 的反面**：A1 全票支持（小语料最大单项收益）——但 Kimi 的支持基于业界证据·未直接回应 Codex 的分类稀释论。
- **我的研判**：**Codex 论点在逻辑上成立且可检验——但它恰恰指出 P0-1 黄金集的构成比例是 A1 命运的判决数据**。P0-1 原设计只要求「口径/名词/体检域各 ≥8」（下限），没规定总占比——比例不同结论完全不同（名词类 70% → A1 价值塌缩；均衡 40/30/30 → A1 主战场成立）。**这不是立场之争·是数据之争**。
- **处置预案**：P0-1 完成后先看分类占比再定 A1 作用域（全量 vs 口径/叙述类专用）——把 Codex 的「<2pp 降级」判据前移为「黄金集构成即预判」。

### 悬置 2：A1 前注的资产归属——两组条件表面冲突·实际可合

- **Codex 条件**：前注进 build_id 派生物（content_hash 覆盖正文+前注·强制一致性）+重建命令一体化+质量门禁 1 条。
- **Kimi 条件**：前注=**权威资产进 git**（chunk_id→ctx_prefix 映射表版本化）·索引重建不重生成前注（防双机/跨时模型版本漂移→不同前注→索引漂移复发 R52 旧病）。
- **我的研判**：**不冲突·是互补的两半**——Kimi 管「前注从哪来」（git 权威源·确定性），Codex 管「前注与正文的一致性」（hash 绑定·防失配）+ schema 落地（ctx_prefix/ctx_prefix_model/ctx_prefix_hash 三字段·None 态保泳道先行）。**合流方案**：前注文本进 git（Kimi）→ 三字段 schema（Codex 6a）→ content_hash 含前注（Codex 护栏 1）→ 增量生成仅 chunk 变更时（Kimi）→ 质量门禁 1 条（Codex 护栏 3）。五件合一是完整护栏——**无需二轮·直接合流**。

### 悬置 3：A3 重排——两组都往「降权」方向推·那还要不要立项？

- Codex：替代方案（ONNX int8 优先·原生权重备选）+资源账（无 CUDA/torch CPU 百 ms 级/1GB 权重离线分发/双机锁版矩阵）——「参数位免费·权重有价」。
- Kimi：用户价值最虚的一件·排末位+判据写死（<5% → False 归档不重开·防沉没成本心理）。
- **我的研判**：两组叠加后的诚实结论=**A3 在小语料上大概率「测不出显著差异→默认 False 收场」**（Kimi 自己都预判了）。那么连 ONNX 选型评估（Codex 的替代方案）现在做都是「给业界标配交税」——选型研究应在 A/B 判定「值得开」之后再做·不是之前。**处置预案：A3 从「六增补」降为「P0 数据门控的观察项」**——P0 基线出来后若叙述类检索质量已达标（如 Recall@5 ≥ 目标），A3 直接不开；只有数据喊痛才立项（届时再议 ONNX）。比两组立场都再轻一档。

### 悬置 4：A2 结构化字段的必要性边界（小悬置）

- Kimi 的 caliber_ref 结构化设计好·但它服务于「宿主误调」场景——主防线（工具描述）生效后误调率有多高未知。**预案**：v1.2 按 Kimi 版实现（成本极低）·但加一条 rag_query 返回统计（caliber_ref 出现率）作为观察项——若两周内出现率≈0·下版删除该字段（契约演进惯例：缺省省略·删除无破坏）。

## 三 研判得出的结构性洞察（本轮最大产出）

**P0 的角色应从「基线」升级为「基线+判决门」**：

```
原 v1.1 顺序：P0 基线 → 泳道①②③（六增补并入任务书）
研判后顺序：P0 基线+黄金集构成分析 → 【数据判决点】
             ├─ 黄金集名词类占比高 → A1 缩为口径/叙述类专用·A3 不立项
             ├─ 均衡/叙述类占高 → A1 全量（五合一护栏）·A3 观察（质量喊痛才开）
             └─ 判决依据落档 → v1.2 细则定稿 → 泳道开工
```

这一步不增加工期（P0 本来就先做）·但把两组的深层分歧从「立场辩论」转为「数据判决」——正是不急定稿的最好用法。
