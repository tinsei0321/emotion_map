### F3 G2 补法路径 —— **partial disagree（顺序：先 e2e 后单测·vitest 现在只记录选型不落地）**

三条路要按「投入产出时序」排，不是并列三选一：

1. **先 e2e（已在 CB-39 内）**：e2e-seam + tests/browser 35 件基建已存在，P1-5 的 CI browser job 直接激活存量；审计 P2 的 10-15 条冒烟补齐=「网」的主体。**这条最便宜且立刻护住演示链路**。
2. **vitest 单测：选型可定·落地推迟到拆楼前夜**。两个 repo 现实约束（发起文档未提）：
   - **package.json 被 .gitignore:54 拒绝**（参赛文件·含个人信息）——vitest 需要独立工程文件（如 `frontend/package.json` 或 `tests/frontend/`）并明确 ignore 例外，基建成本 ≈1 天起（工程文件+依赖锁定+CI node job）；
   - **可测面窄**：52 个 JS 中大量 DOM/MapLibre 强耦合（map.js/panel.js/state.js 巨石），纯模块可测清单实际很短（stages.js 契约逻辑——且已被 P0-2 跨语言守卫覆盖·边际价值降；harness 纯函数；field_dictionary 镜像）。**为巨石写单测=负资产**，拆楼后纯化的函数才值得测。
3. **组合结论**：`e2e 网（CB-39 内）→ 拆楼获批 → vitest 基建 + 为拆出物补单测`。本轮只产出一行决策记录（选 vitest·理由：Vite 生态原生/浏览器模式可后续升组件测），不建工程。
