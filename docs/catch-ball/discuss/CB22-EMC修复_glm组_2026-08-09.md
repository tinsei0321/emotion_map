## 一、6 焦点确认（glm组）

### 焦点 1：R1 serve 启动预热 — **agree（实现简单 + 失败降级建议）**

**计划**：serve.py 启动后台预热 rag_index.warmup()（异步·不阻塞）。

**glm组 确认**：**agree——_get_model 单例已有·预热只须主动触发·实现简单。**

**glm 实现建议（异步预热·不阻塞 serve）**：
```python
# serve.py main()·httpd 启动后
import threading
def _warmup_rag():
    try:
        import sys; sys.path.insert(0, repo_root)
        from tools.rag_index import _get_model
        _get_model()  # 触发首次加载 + 缓存
        print('[OK] RAG 模型预热完成')
    except Exception as e:
        print(f'[WARN] RAG 预热失败（非阻塞）: {e}')

# httpd 启动后·异步预热（不阻塞 serve_forever）
threading.Thread(target=_warmup_rag, daemon=True).start()
```

**关键**：
- **异步线程 + daemon**——不阻塞 serve_forever·预热期间 serve 已可用（首检仍可能冷加载·但用户不等 serve 启动）。
- **失败降级**：预热失败（如模型未下载）打 WARN·不阻塞 serve·RAG 首检仍冷加载（回到现状·非更差）。
- **预热窗口**：serve 启动到用户首检通常 >5s（用户打开浏览器 + 输入问句）·预热 18.6s 可能在用户首检前完成。

**glm 提醒（预热 vs 首检竞态）**：
- 若用户在预热完成前首检（serve 启动 <18.6s 内问）→ 仍冷加载。
- **R4（AbortController 30s）是预热的必要补充**——预热治本·30s 容预热未完成的窗口。

### 焦点 2：R2 catch 兜底诚实标注 — **agree + 措辞中性化建议**

**计划**：超时/失败 → ctx.context 注入"【知识库检索超时·本次未引用 RAG·可能不完整】"。

**glm组 确认**：**agree——glm 上轮诊断 W1 建议采纳。措辞建议中性化。**

**glm 措辞建议（防误导）**：

| 方案 | 措辞 | glm 评估 |
|---|---|---|
| 计划原案 | "知识库检索**超时**·本次未引用 RAG·可能不完整" | ⚠️ "超时"可能误导（用户以为系统故障） |
| **glm 建议** | "知识库检索**未就绪**·本次回答基于通用知识·未引用项目库·建议稍后重试" | ✅ 中性（"未就绪"非故障·"建议重试"给出路） |

**glm 理由**：
- "超时"= 技术故障词·用户可能判"系统坏了"。
- "未就绪"= 中性（冷加载/预热中·稍后好）。
- "建议稍后重试"= 给用户出路（预热完成后重试即正常）。
- "基于通用知识"= 诚实说明 finalStep 用的是 LLM 通用知识（非知识库）。

**实现**（harness:1003 catch）：
```javascript
catch(_e) {
  ctx.context = '【知识库检索未就绪·本次回答基于通用知识·未引用项目库·建议稍后重试】\n\n' + (ctx.context || '');
}
```

### 焦点 3：R3 防幻觉约束 — **disagree（不应"约束 LLM"·应直接 EXIT_CONCEPT 确定性兜底）**

**计划**：RAG 不可用时约束行"不要编造项目/数据/分析结论·如实说明"。

**glm组 判断：disagree——LLM 弱 context + "不要编"约束仍可能产情绪分析式幻觉（LLM 不听话）。应直接 EXIT_CONCEPT 确定性兜底·禁走 finalStep 让 LLM 编。**

**glm 理由**：
- 现状 rag_query 短路（:1004）走 `stages.finalStep`——即使 RAG 不可用（catch 分支）·仍走 finalStep·LLM 用弱 context（grounding/情绪分析背景）生成。
- **"不要编造"约束是软约束**——LLM 可能不听（尤其弱 context 时·LLM 倾向用训练知识"编"情绪分析式内容）。
- 本次失败正是此情况——finalStep 弱 context → LLM 编了"西陵老城居住带/二马路/伍家岗"情绪分析式（非知识库·非编造具体数据但偏题）。

**glm 替代方案（RAG 不可用 → EXIT_CONCEPT 确定性兜底）**：

```javascript
// harness:1003 catch 分支·不走 finalStep·直接确定性兜底
catch(_e) {
  // RAG 不可用 → EXIT_CONCEPT 确定性直答（禁 LLM 编）
  const _gap = `## 知识库检索未就绪\n\n`
    + `本次提问「${ctx.question}」需引用知识库（城市更新项目库/体检指标）·`
    + `但知识库检索暂未就绪（模型加载中）。\n\n`
    + `**建议**：稍后重试（约 20 秒后模型预热完成）·或换问"宜昌情绪分布"等分析类问题。`;
  if (hooks.onFinalDone) hooks.onFinalDone(_gap);
  return { ok: true, rounds: 0, final: _gap, degraded: true,
           diagnose: { degraded: true, intent: 'general', quick: true, rag: false },
           defense: { degraded: true, fixes: [], skipped: 'rag-timeout-exit-concept' } };
}
```

**glm 方案优势**：
- **确定性兜底**——不走 finalStep/LLM·直接模板文字·零幻觉风险。
- **诚实 + 出路**——告知"模型加载中"+ "稍后重试/换问"。
- **对齐 EXIT_CONCEPT**——纯问答诚实直答（非 EXIT_RESULT 图层/分析）。
- **防情绪分析式幻觉**——根本不让 LLM 编·杜绝本次失败模式。

**vs 计划 R3（约束 LLM）**：
| 方案 | 机制 | 幻觉风险 |
|---|---|---|
| 计划 R3 | finalStep + "不要编"约束 | 🟡 中（LLM 可能不听） |
| **glm 方案** | 直接 EXIT_CONCEPT 确定性兜底 | 🟢 零（不走 LLM） |

**glm 强烈建议 R3 改为"直接 EXIT_CONCEPT 确定性兜底"**——禁走 finalStep 让 LLM 弱 context 编。
