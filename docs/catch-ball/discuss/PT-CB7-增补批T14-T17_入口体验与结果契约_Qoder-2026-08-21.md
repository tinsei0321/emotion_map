## 二 用户追加思路的专业评估

| 用户想法 | 评估 | 落地方式 |
|---|---|---|
| ① 不弹终端窗口，在 dsh 内置终端跑进程+对话窗口显化进度 | **目标对，路径需修正**：better-sidebar 终端是交互式 shell 标签，service API **无外部命令注入能力**（service.d.ts 实证：仅 registerTab/openTab 族）；且终端输出转发进对话窗需再造一层桥。**正解 = 隐藏式启动（.vbs 无窗运行 start.bat）+ 对话窗口进度卡**（启动中→预热中→就绪三态，由现成双端点探测驱动：index.html 送达=前端就绪、/api/v1/health 送达=后端 RAG 就绪） | T15 |
| ①' 欢迎卡做到对话窗口（交流感） | 对——欢迎卡本就在会话视图（conversation.input.dock·composer 上方）；T15 再把**进度卡**也放进来，形成"卡片式对话感"；不注入 session 消息（会污染会话历史，且无公开 API） | T15 |
| ② 进度提示+就绪后再自动开页，且用默认浏览器 Edge 不内嵌 | **完全正确**，且与 T3 已建的就绪 gate 完全合拍——只需把开门目标从内嵌 tab 改回 `window.open`（用户手势段留 popup 句柄防拦截）。内嵌 tab 保留为可选（注册不自动开）。**口径覆盖链记录**：CB6 外部 Edge → T3 内嵌（任务书裁定）→ 本次回外部 Edge（用户新偏好·用户优先） | T15 |
| ③ 测试页残留历史结果图层 | **根因已查实**：`api/render_routes.py` 的 `_SEEN` 是内存态——start.bat 每次杀旧起新 serve → seen 清零 → watcher 首轮把 render_inbox 存量 spec 全量入 backlog → 新 SSE 连接补推（最多 20 条）→ 历史层复活。T8 自清只管本脚本产物，管不到全部来源。**修法**：spec 推送成功后移入 `render_inbox/applied/` 归档（glob 只扫一级 *.json·重启不再重放·留痕可查） | T16 |

**入口 UX 整体优化建议**（定位认同：临时测试工具·即点即用）：
1. **一键即走**：点击 → 进度卡三态 → 就绪自动开 Edge 主页，全程零终端零手动刷新；
2. **测试页快捷键**：进度卡就绪态带「打开测试页」按钮（`/frontend/index.html?test=1`），测试动线一步直达；
3. **失败可见**：40s 未就绪 → 进度卡转错误态+手动指引（不静默）；
4. **不做的事**：不注入会话消息、不做意图判断、不自动内嵌——入口保持"哑按钮+状态卡"，符合「A 是按钮不是路由」。
