## 〇、用户顶层原则（最高指引）

1. **NL 意图判断必须通过 LLM**（「是不是知识问答」是 NL 意图判断·归 Smart 端）——规则词表不得承担判断主体（仅可做明显命中直通省调用）
2. **意图判断 agent 的位置在计划执行之前**（规划层/实施层之前·诊断阶段）——用户对架构的理解
3. **「语义判断」= 用户输入自然语言的意图判断（NL→intent）**·非数据文件字段语义

## 一、EMC 三层架构（用户提出）

```
数据层（3 库）         实施层（LLM+Toolbox）         表达层（出口）
概念库 ← →        计划执行流水线                三段式（1+1+1）
城市情绪数据库    （Smart Agent·Dumb Tool）    → 1 明确观点
本地基础数据库      工具集 14（gis）+1（Q&A）     → 1 方法+分级数据+分级结果
                                              → 1 对标对表（行业接口）
```

## 二、RAG-意图判断-回答 三通道路由（用户类比映射）

**用户类比**：像 AI 工作平台——资料（各种格式）丢进资料库 → 平台向量化（RAG）→ 提问 → 平台综合（检索+理解+工具+生成）出答案/工作结果。EMC = 迷你版。

**三者关系（claude 映射·待两组验证）**：
- **意图判断 agent = 总调度**——读 NL 意图 → 路由三通道之一：
  - 知识问答（判 knowledge_qa）→ RAG 检索 → LLM 综合（表达层三段式）
  - GIS 工具调用（判 gis_operation）→ 14 工具执行 → 图层（表达层）
  - 城市情绪分析（判 emotion_analysis）→ 情绪分析 → 图层/报告（表达层）
- **数据层三库 = 弹药库**（概念/情绪/基础）·意图判断 agent 决定通道 + 弹药
- **表达层 = 统一出口**（三段式·不分通道）

**用户期望「知识问答 + GIS 工具调用 + 城市情绪分析」基本工作 = 完全可能**——EMC 已具备大部分骨架：GIS + 情绪分析已通·**唯一断的是知识问答通道**（意图判断未覆盖 + RAG 素材窄）。补上两块 = 三层架构完整 = 本次优化目标。

**「没平台强」的本质差距**：平台 = 泛领域通用 + 全格式自动入库；EMC = 本地化聚焦（宜昌专题·产品定位优势）+ 人工提炼素材——EMC 不需要平台那么强·聚焦反而更准·打通三通道即可。
