## 一 Q1-Q5 逐题对抗

### Q1 大脑接口断点 —— **agree（相容性成立，但论证要换地基）**

**主手辩护**是「轻循环只是过渡引擎·编排权仍在可插拔层」。这个辩护有一个更硬的版本，建议任务书 v1.0 直接换用：

**「既有资产复活」辩护**：ai_qa 四阶段（diagnose/agent_step/answer/optimize）是 EMC 从 QA 主链路时代就在跑的**既有管线**（`ai_qa/prompts.py:1-11`），不是壳阶段新建的编排引擎。「大脑永远外置」裁定（EMC=交互壳子+Harness+RAG）的适用对象是**测试期外置驾驶舱路线下的「新做大脑」**——它禁止的是「为对话能力新建自持编排引擎」（EMC-Harness 选型收口已裁：自持编排方向不评估不排期），不追溯既有 QA 管线。方案②的准确表述应为「**既有 QA 管线作为首个引擎**」而非「自持轻循环作为过渡引擎」——前者是事实陈述无需辩护，后者是新生事物需要辩护。**换用此地基后，Q1 与裁定的相容性从「可辩护」升级为「不构成争议」。**

**但真正的对抗点在别处——双轨并行期的「双头大脑」问题**（主手未列）：

测试期 dsh 外置大脑（主驾·3080）与壳阶段引擎①（8080 对话框）将同时存活。两个会话入口的答案质量、口径纪律、渲染行为是否一致？**若壳对话框表现差，打击「壳吸收」路线信心；若更好，打击「大脑外置」的必要性论证——这是一个政治-技术双重敏感的对照面，不能无意发生，必须有意管理。**

**建议任务书 v1.0 加一条「双轨对照口径」**：轻循环引擎上线验收时，做一次同题对照（同 10 题 × 两引擎·覆盖纯问答/GIS 操作/情绪分析/知识问四类）——既是 S 系列验收件，也是「壳吸收测试链路」两阶段路线的**架构证据**（对照结果进 CB 归档，未来「稳定期 EMC 壳吸收」决策的依据就在这里积累）。

**降级形态的诚实性补丁**：BrainAdapter 的 dsh 降级形态（headless 调用+壳侧进度桩事件模拟）有一个用户认知风险——壳显示的「思考流」是桩不是真流，用户会误以为 dsh 在真流式思考。**建议 ACP v1.1 给 msg.delta 补 `provenance: real|synthesized` 字段**（契约层面解决·前端对 synthesized 事件渲染为「步进进度」而非「思考流」样式）——一个字段，防一个长期误导。

### Q2 壳与现前端 —— **agree（渐进升级方向对，但有一个隐藏重构坑必须先侦察）**

渐进升级（8080 现有 ai_qa 对话框升级·不新建入口）正确——前端资产厚、双入口违「入口统一」铁律、复测刚验收的样式面板（C3）零接触。

**隐藏坑：ACP 五族事件是「过程可见性」契约，不是「内容渲染」契约**。现前端的四阶段直连消费里混着两层语义：
- **过程语义**（diagnose 卡出现/某工具开始/某工具结束/流式 token）——可映射到 ACP 事件；
- **内容语义**（`{{show}}/{{focus}}/{{chart}}` 内联模板、追问胶囊、出口卡四态、[ref:] chip）——**这些是 EMC 特有的渲染语义，不在 ACP v1 事件集里，也不该在**。

若 S3 改造时不做显式分层，两种走法都有坑：把渲染语义塞进 ACP（契约膨胀·违「宿主无关语义层」红线）或全留在 content 字符串里（现状·前端仍需解析 markdown 内嵌指令——耦合没真正解开）。

**建议**：任务书 S3 验收口径加一条「**过程/内容分层检查**：ACP 事件只承载过程可见性；内容渲染语义走既有 markdown+内联模板通道，两通道在代码层有显式边界（不同模块/不同解析器）」。且 S3 动工前先出「耦合面清单」（现前端解析四阶段 SSE 的全部触点·0.2d 前置侦察并入 S3）——防「2d 预估撞上比预期大的耦合面」（debug-memory R1：多入口逐入口验证的前车之鉴）。

### Q3 工具编排归属 —— **agree（补一条防误伤边界）**

编排权=引擎层、壳只发 `open`+渲染事件、不留壳直连 MCP 轻路径——与 ACP 契约角色分工（工具面归 MCP·会话机制归 ACP）和「大脑外置」裁定一致，无异议。

**防误伤补丁**：Q3 禁的是「**壳代码自动调度 MCP 工具**」，不禁「**用户点 Toolbox 按钮手动跑工具**」（六件手动工具走 addToolboxLayer·用户操作不是编排）也不禁「壳消费 tool.end 载荷渲染追问 chips」（消费不是调度）。任务书把这条边界写明，防 S3 执行时误伤 Toolbox 既有交互。

### Q5 垂直域抽象层 —— **partial agree（方向对·「先两垂域后抽象」纪律对·五件套有两漏件+一契约缺口）**

**同意的部分**：壳阶段只预留切换位不做多垂域实现；从实例归纳契约不先造空框架（R26 架子先行纪律的垂域版·正确）；自洽核账三条（平台层资产垂域无关/垂域层资产可打包/概念同源）均经核证属实（MCP 工具 18 件确为垂域无关·`build_server()` 注册清单核证；口径卡/身份卡/preset 确按宜昌专项目录组织）。

**漏件①：渲染预设（建议五件套→六件套）**。五件套不含渲染样式——情绪地图的极性色板（polarityStops/HEATMAP_RAMPS 受管词表）是垂域特有语义；城市体检医生垂域可能要「体检达标率色带」。渲染契约当前把词表硬编码在平台层，垂域②来了要么平台扩词表要么垂域自带——**必须显式归位**。建议：五件套扩为「数据包+知识库+口径注册表+身份卡/人设+工具预设+**渲染预设**（受管色带词表的垂域子集+垂域 scheme）」——与「图层同源」红线一致（样式权威在 EMC·垂域配置走词表注册·禁自带色值，render-contract §九已有此纪律）。

**漏件②：范式库槽位**。`ai_qa/paradigm.py`（尺度-方法-范式矩阵）与 `manifesto.py`（领域宪法）是情绪地图垂域的结构化知识——城市体检医生有自己的范式（检查→诊断→策划）。五件套的「知识库」若只指 RAG 语料，则范式库无处安放；若泛指则两形态（向量语料 vs prompt 组装用结构化文本）混为一谈。**建议「身份卡/人设」件扩为「身份卡/人设+范式库」**，或在知识库件内显式分两槽（语料槽+范式槽）——两案留给主手在 v1.0 定，但必须定。

**契约缺口：垂域间共享不变量清单未显式化**。评审范围明示此问（「垂域间共享什么」）。愿景登记 §一自洽核账已有素材（平台层=工具/检索管线/治理管线/渲染契约/ACP），但那是「现状描述」不是「契约承诺」。**建议 Vertical Profile 契约显式列「共享不变量清单」**：换垂域时必须不变的——①ACP 事件语义 ②MCP 工具签名 ③渲染契约结构（spec 七段）④治理字段 schema（status/lineage/X-01）⑤四态出口契约。**这份清单是垂域②试点的核心观察项**（试点要验证的就是「这些不变量在第二个垂域上真的不用改」——有一个要改就说明抽象层划线错了，早发现早便宜）。

**拆解脱节（须修）**：Q5 说「壳阶段预留切换位」，但 v0.9 的 S1-S8 **没有任何垂域相关任务件**——规划与拆解脱节。**补 S9**（见 §二拆解表）。
