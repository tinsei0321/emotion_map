### T7 失败根因（逐行代码级）

**根因**：`469bf32` 在 `frontend/js/ai_qa/boundary-resolve.js` 新增：

```js
const _ADMIN_BLOCKLIST = ['小溪塔', '龙泉', '白洋', '生物产业园', '东部产业新区', '绿心'];
function _rejectNonAdminBoundary(b) {
  if (b == null || typeof b !== 'object') return null;      // 只拦 GeoJSON dict
  const feats = b.features;
  if (!Array.isArray(feats) || !feats.length) return null;
  const p = feats[0].properties || {};
  const nm = String(p.name || p.MC || p.NAME || '').trim();
  const hit = _ADMIN_BLOCKLIST.find((d) => nm.includes(d) || d.includes(nm));
  if (hit) return new Error(`「${nm}」为法定功能区…`);
}
export async function resolveBoundaryInput(b) {
  const _rej = _rejectNonAdminBoundary(b);
  if (_rej) throw _rej;
  ...
}
```

**误伤链**：
1. 演示行政区层 `DATA/boundaries/行政区.geojson` 含 **9 要素·其中 5 个命中黑名单**（实测要素序：`[0]龙泉 [1]猇亭区 [2]点军区 [3]小溪塔 [4]白洋 [5]西陵区 [6]龙泉绿心 [7]伍家岗区 [8]生物产业园`）——演示数据把法定功能区也作为聚合单元（L2 演示语义）。
2. 多步链「把西陵区裁出来」→ extract_feature 的 layer/range 解析 → 经 `resolveBoundaryInput` 收到**从行政区层解析的 GeoJSON dict**（`feats[0].properties.name='龙泉'`——层首要素）→ `_rejectNonAdminBoundary` 命中黑名单「龙泉」→ 抛错 → 整个链第一步失败。
3. `_rejectNonAdminBoundary` **不区分「LLM 直传的原始 boundary 参数」与「从已加载图层/索引解析出的合法要素」**——只要 dict 首要素名含黑名单词即拦 → 合法图层操作被误伤。
4. B3 单步 zonal 用例未暴露（zonal 的 boundary 是 derive 的**精确单要素** name=西陵区·不命中）；extract/clip/链的 layer 解析路径走整层/首要素 → 暴露。

**影响面**：任何从行政区层解析要素的 extract/clip/overlay 链操作（演示数据层含黑名单词）·`multi` 路径的 `clip 图层类型不匹配` 疑同源（链状态被黑名单抛错破坏·需修复后复测确认）。

**阻断依据**：判据「任何新增 fail（不在 {PRM-03/04}）→ 阻断」。多步链（extract_overlay）是演示逻辑链核心路径（RST 系·三路径观点卡验收项），现被 469bf32 修复误伤 → 必须修复 + 复测。

**修复建议（供 claude 决策·不越权实施）**：
- `_rejectNonAdminBoundary` 仅拦 **LLM 直传的原始 boundary 参数**（如参数带 `_source:'llm'` 标记或未打标的 dict），不拦**从已加载图层/索引解析出的要素**（打标 `_source:'layer'/'preset'`）；或
- 校验前置条件收紧：黑名单命中时**先排除"该要素来自已加载面层"**（`getLayers()` 含同名要素 → 放行·用户已加载可信）；或
- 最小改动：黑名单判定仅对**完整等于**黑名单词的 name 生效（`nm === d`）·去掉包含匹配（`nm.includes(d)` 把「龙泉绿心」也拦了·且合法图层名含「龙泉」时误伤）——但仍需处理"层首要素恰为黑名单词"的整层解析场景（上两条之一）。
- 复测：修复后重跑 `test_insight_cards_3path.py`（多步链必须 PASS）+ `verify_prm57_fix.py`（小溪塔仍拒识）+ 浏览器「西陵区裁出」3 次。
