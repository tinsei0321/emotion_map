## 一、逐焦点回应

### 焦点 1（定位）：「情绪热点图」= KDE / Gi\* / 双图层 —— **partial agree**

**判定**：同意"用户诉求 = KDE 连续地势感"，同意"双图层是学术业界通行做法"，但**不同意 claude组 的"初步倾向 C（双图层）作为目标、A 作为 MVP"的排序**。我的排序反过来：**A（KDE 正名）即终态主图，B（Gi\* 修正）作为可选叠加，C（双图层）不作为独立目标**。

**证据**：

1. 用户诉求"舆情热度 + 高程/地势感"在 GIS 里**只有 KDE 一个答案**（`core/spatial_analysis.py:855` 的 docstring 自己也写："高度=核密度（此处加权 emotion_intensity），颜色=区域内极性均值"）。Gi* 输出的是**离散点 + z 分数**（`spatial_analysis.py:91-93` `gdf['Gi_Z']/['Gi_P']/['hotspot']`），本质是点层标注，**不产生曲面**——它无论如何重做都给不出"地势感"。所以"情绪热点图"这个词在用户语义里 = KDE，没有歧义。

2. claude组 现状三轨里"情绪地形"已经就是 KDE（`create_terrain_mesh` F_007，`spatial_analysis.py:846-1040`，加权 histogram2d + 可分离高斯卷积 = 标准 KDE）。换言之 **KDE 主图已存在且方向正确**，重做的核心动作是**改名 + 厘清边界**，不是重新实现。这与 claude组 2.3"已排除：地形方向对"一致，但我把它提为**首要结论**而非"已排除项"。

3. "双图层（C）"听起来全，但对**演示场景**是负担：演示逻辑链是"张力图面→引导点击→宏观诊断信号"，KDE 热力面已经承担了"张力图面"，Gi\* 叠上去如果还是 hot/cold 红绿点（`hotspot-tool.js:16` `_CLS_POL`），会和 KDE 的极性色（terrain-9 发散，`heatmap-tool.js:89`）**视觉打架**——除非 Gi\* 层改用纯显著性符号（见焦点 3）。所以 C 的"双全"是有代价的，不应作为默认目标。

**可操作建议**：
- **第一步（A，必做）**：把"情绪热点图"这个用户可见词**绑定到 KDE**。Toolbox 里已经有「情绪地形」（`heatmap-tool.js:52` ANALYSIS_PRESETS.terrain），演示口径统一叫"情绪热力图（KDE）"，"地形"作为渲染模式（3D fill-extrusion）的别名保留。
- **第二步（B，可选，看演示反馈）**：Gi\* 作为"显著性验证"独立工具，**默认不叠在 KDE 上**，只在用户问"哪里是统计上显著的聚集"时单独出图。这对应 claude组 焦点 4 里"Gi\* 降级为 EMC 专用"的方向，我同意。
- **C（双图层叠加）不单列**：它只是"A 主图 + B 显著性"在用户主动叠图时的自然结果，不值得作为独立方案立项。

### 焦点 2（输入粒度）：逐点 vs 网格聚合 Gi\* —— **agree（但根因表述需修正）**

**判定**：同意"应改网格聚合"，但 claude组 把根因说成"逐点 Gi\* 对点密度敏感 / 噪声大"**不够准确**。真正的技术问题是**空间权重矩阵的尺度一致性**。

**证据与修正**：

1. claude组 2.2.2 说"逐点 Gi\* 对点密度敏感（点少的区域 z 波动大）"。但看代码 `spatial_analysis.py:75-78`：`k = min(8, len(gdf) - 1)`，权重是 **KNN k=8**（k 最近邻），**不是距离带**。KNN 权重下，每个点的"邻居"都是它最近的 8 个点——**无论该区域点稀疏还是密集，邻居数恒为 8**。所以"点少则 z 波动大"在 KNN 下不成立（KNN 的设计初衷就是抗密度不均）。claude组 的表述把"距离带权重的问题"安到了"KNN 实现"上，**诊断错位**。

2. 真正的根因有两个：
   - **(a) 单元语义缺失**：Gi\* 的 `value_col='score'`（`geo_routes.py:653, 665`）是**每条评论**的得分。一条评论 = 一个样本，它的 score 是个体噪声，不是"该地点的情绪"。业界做网格聚合 Gi\*（如 POI 研究）是因为**先聚合才有稳定的单元均值**。逐点 Gi\* 等于"用单条评论的噪声值做显著性检验"，显著性结论会被单条强情绪评论主导。这才是"效果不对"的主因——不是密度敏感，是**样本单元不对**。
   - **(b) KNN 尺度漂移**：k=8 在密集区（商圈）可能只覆盖 50m，在稀疏区（郊区）可能覆盖 2km——**同一个"邻居"概念在不同区域尺度差 40 倍**。Gi\* 的 z 分数跨区域不可比：商圈的"显著热点"是 50m 尺度的聚集，郊区的"显著热点"是 2km 尺度的聚集，画在同一张图上会误导。这跟 claude组 说的"波动"是两回事。

3. claude组 焦点 2 问"KNN k=8 vs ArcGIS 距离带权重差异风险（注释已注明 KNN 防岛屿）"。看 `spatial_analysis.py:74` 注释："DistanceBand threshold=0 会让几乎所有的点无邻居致 Gi\* 退化"——这个注释**有问题**：DistanceBand 的 threshold 应该是一个正的距离值（如 500m），不是 0；threshold=0 当然退化，但这不构成"放弃距离带、选 KNN"的理由。正确对比是：**距离带（固定尺度，跨区可比，但稀疏区会有岛屿） vs KNN（无岛屿，但尺度漂移）**。两者各有代价，不是 KNN 单方面更优。

**可操作建议**（按优先级）：
- **P1：改输入为网格聚合**。复用已有的 `create_square_grid`（`spatial_analysis.py:724`，F_006，EPSG:4546 米制 snap-to-grid），每格的 `score_mean`（`:790`）或 `polarity_index`（`:798-804`）作为 Gi\* 的 value_col。这样每个 Gi\* 要素 = 一个稳定单元，且天然带边界（可在前端画面）。网格粒度建议 **200–400m**（与 `create_square_grid` 默认 `cell_size=200` 和 `tool_contracts.py:46` density cell_size=600 对齐，取演示主城尺度）。
- **P2：权重改距离带 + 阈值 = 网格对角线×N**。若用 200m 格，对角线≈283m，阈值取 500m（约 1.8 倍）能覆盖相邻格 + 部分次相邻，尺度统一且可比。岛屿问题用 `transform='R'`（行标准化，`spatial_analysis.py:87` 已在用）+ 落到无邻居格直接判 ns 兜底。
- **P3：保留 KNN 作为 fallback**，仅当点数极少（<30，无法建网格）时退逐点 + KNN。这对应 claude组 焦点 2 的"防岛屿"，但作为降级路径而非主路径。

### 焦点 3（色彩语义）：Gi\* hot/cold → 极性色映射 —— **disagree（当前映射不成立，但 claude组 的理由给错了）**

**判定**：当前 `hot=Very Negative 红 / cold=Very Positive 绿 / ns=灰`（`hotspot-tool.js:16`）**应当废弃**，但**不是因为 claude组 说的"语义链隔着 score"**（这条链其实是通的），而是因为它**把"显著性"偷换成了"极性"，让 Gi\* 层在视觉上重复了 KDE 层的极性信息**。

**证据**：

1. claude组 2.2.3 担心"把 hot 解释为负面热点需 score=负向得分（invert=true），这个语义链是否站得住"。我实查了 score 语义：`SCRIPT/emotion_analysis_v1.py:114` 注释明写 `"score: 综合情绪得分 0~1（0=极端负面, 1=极端正面）"`，且 `spatial_analysis.py:84-85` `invert=True → values = 1.0 - values`。所以：score 低（负面）→ invert 后值高 → Gi\* Z 高 → hot。**这条链在数学和语义上都成立**，hot 确实=负面显著聚集。claude组 的担忧在这里是多余的（措辞"score=负向得分"还把方向说反了——score 是高=正面，invert 才翻转）。

2. 真正的问题在**两层视觉语义冲突**（这是 claude组 焦点 3 第二问"双图层视觉分工"的核心，但 claude组 没给出结论）：
   - KDE 地形层：`_norm` = polarity_index → terrain-9 发散色（红=负/绿=正，`heatmap-tool.js:89` `terrain-9`，`spatial_analysis.py:1023-1032` `_pi_to_norm`）。
   - Gi\* 层：hot=红 / cold=绿（`hotspot-tool.js:16`）。
   - **两层都用红绿表达"负/正"**。若叠图（方案 C），用户无法分辨"这片红是密度高的负面区（KDE）还是统计显著的负面聚集（Gi\*）"。Gi\* 层复用离散 5 色极性色带（`hotspot-tool.js:4-5` 注释"复用离散 5 色极性色带零 map.js 改动"），是为了**零改动偷懒**，不是为了语义正确。

3. 业界惯例（claude组 1.3 引的经济地理 2018 论文）：KDE 表达密度强度（连续面），Gi\* 表达显著性（分级符号/晕邈）。**两层视觉编码维度不同**（密度 vs 显著性），才能叠加互补。

**可操作建议**：
- **Gi\* 层改用纯显著性符号，不复用极性色**：hot/cold/ns 三类用**单一颜色 + 符号大小/描边**区分（如 hot=实心圆红描边、cold=实心圆蓝描边、ns=小灰点不强调），颜色深浅 = Gi\* Z 值绝对值（置信度 90/95/99% 分级）。
- **保留 invert 语义但在 legend 明示**：legend 写"hot = 负面显著聚集（score 经 invert）"，不要让用户自己猜。当前 `geo_routes.py:675` legend 只有 `'hot': '显著热点'`，没说"负面"，这确实是 claude组 担心的"语义隔着 score"的落点——但解法是**说清楚**，不是弃用 invert。
- **若焦点 1 走 A（KDE 为主）**：Gi\* 默认不叠，这个色彩问题降级为"Gi\* 单独出图时的图例清晰度"，优先级 P3。

### 2.2 已确认问题 —— **4 条里 2 条需修正**

1. **命名/语义错位** —— ✅ 同意。补充：用户可见层最混乱的是"热力图（2D）"和"情绪地形（3D）"都是 KDE，却用了两个词；而"情绪热点（Gi*）"完全不是 KDE 却占用了"热点"这个词。

### 2.3 已排除项 —— ✅ 同意

"情绪地形（KDE mesh）方向对，重做不是推翻地形"——同意，且我提为**首要结论**。KDE 主图已存在（`create_terrain_mesh`），重做的核心是改名 + 厘清边界，不是重新实现。"EMC density 委托链正确"——同意。

### 遗漏（claude组 未提及）

- **2D 热力 vs 3D 地形的渲染路径分叉**：`generateHeatmapForAI`（MapLibre 原生 heatmap，半径驱动）和 `generateTerrainForAI`（后端 KDE mesh，带宽驱动）用的是**不同的 KDE 近似**——前者是 GPU 屏幕空间核函数（radius=`heatmap-tool.js:23` DEFAULTS.radiusM=300），后者是 CPU 栅格高斯卷积（bandwidth=`spatial_analysis.py:851` 250m）。两者参数（radius vs bandwidth）和尺度单位（像素 vs 米）不同，**同一份点数据可能画出不一致的"热度中心"**。这是潜在的"效果不对"隐患，claude组 完全没提。建议在命名统一时同步明确：2D 用 radius（屏幕尺度，快），3D 用 bandwidth（地理尺度，准），两者各自独立调参，不互相承诺一致。

## 三、推荐方案与优先级表

### 推荐立场

**以 A（KDE 正名）为终态主图，Gi\* 修正（焦点 2 的网格聚合）作为可选第二工具，C（双图层叠加）不独立立项。** 与 claude组 "C 为目标、A 为 MVP" 的排序相反——理由见焦点 1：演示场景下双图层视觉打架的成本 > 显著性叠加的收益；Gi\* 的价值在"单独回答显著性问题"，不在"叠在 KDE 上"。

### 优先级表
