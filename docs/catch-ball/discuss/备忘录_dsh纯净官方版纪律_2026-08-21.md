# 备忘录 · dsh 纯净官方版纪律（用户裁定·2026-08-21·长期生效）

> 级别：项目宪法条款（与「A 是按钮不是路由」「让不需要思维的任务不进思维循环」并列）。

## 条款

1. **只用官方原版 dsh**：安装=官方 origin 最新版（github.com/deepseek-ai/deepseek-harness）。双环境（home/office）统一。
2. **只用官方自带插件**：dsh 安装时默认附带的插件保留，**其他一切第三方/自建插件全部退役**——包括但不限于：dsh-emc-entry（入口）/ emc-analysis-guard（守卫）/ dsh-better-sidebar / dsh-synapse / dsh-subprocess-win32 等。
3. **EMC×dsh 的唯一接触面=MCP 协议**：EMC 侧=tools/mcp_server_emc.py（十件标准插座）；dsh 侧=一个 profile 注册 mcp-emc（stdio·四行配置）。**除此之外零定制**。
4. **双环境适配=只配官方原版**：M1-M3 环境配方简化为「安装官方 dsh + 四行 profile 配置 + 验证 10 工具」——不再配方 guard/entry/双模/synapse 等。
5. **禁止清单**：不自建 dsh 插件·不修改 dsh 源码·不维护 dsh fork·不依赖 dsh 私有 API（IConversation/host.openPath 等）·不在 dsh 内嵌 EMC UI。
6. **重装时旧文件全部清除**：避免多版本共存造成混乱——清理 ~/.dsh/ + D:/Github/dsh/ + D:/Github/dsh-emc-entry/ + 全局 npm 包 + junctions。

## 原理

EMC 的资产（数据/契约/知识/渲染/工具面）完全自持·dsh 只是"大脑+驾驶舱"的消费者。拔掉 dsh 换 claude/codex/zcode 当大脑，EMC 不改一行代码。**保持接触面最小=维护成本最小=热拔插能力最强**。

guard 等纪律逻辑**在 EMC 的 MCP server 侧实现**（服务端代码强制·不依赖宿主自觉）——这本来就是「纪律在 server 侧」设计哲学的应有之义。

## 违反判定

任何提案如果要求「写一个 dsh 插件」「修改 dsh 配置文件」「依赖 dsh 私有 API」→ 触犯本条款·须用户显式豁免才可立项。
