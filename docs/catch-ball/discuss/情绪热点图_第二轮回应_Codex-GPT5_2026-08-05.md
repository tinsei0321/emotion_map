## 一、焦点 5 定案：3D 热力形式

### 1.1 四维评估

| 维度 | a. MapLibre setTerrain + RGB DEM | b. deck.gl TerrainLayer | c. fill-extrusion 改造 |
|---|---|---|---|
| 连续曲面真实性 | ✅ MapLibre 原生三角网地形（raster-dem → 连续 mesh，官方 3d-terrain 能力；v2 起支持，本项目 CDN 为 maplibre-gl@5.2.0，frontend/index.html:11-12） | ✅ 真 mesh（TerrainLayer 从 heightmap 生成三角网） | ⚠️ 本质仍是"逐 feature 恒定高度"——只有无限细分才逼近曲面，成本高且仍是近似（现实现 7 层环 = 千层饼，map.js:636 `fill-extrusion-height` 按 `_level` 单值插值，每环同高） |
| RGB DEM 编码成本 | M：后端 KDE 栅格（create_terrain_mesh 内 `Hs`，core/spatial_analysis.py:930-957）→ Mapbox RGB 编码 → PNG 瓦片 + tilejson；**requirements.txt 无 Pillow/rasterio/GDAL**，需加 Pillow（轻量）或纯 Python zlib PNG 编码器；宜昌范围约 830x670 格，单幅/金字塔均可 | M：同一 DEM 编码 + **需新增 @deck.gl/geo-layers@9.1.0 CDN**（index.html:15-17 只载 core + aggregation-layers + mapbox） | S：无需编码，但需新后端细分网格生成 + 前端多 feature 渲染，计算量向数据面转移 |
| setTerrain 全局地形冲突风险 | 中且可枚举：raster 底图被铺上曲面（天地图影像→张力增强，map.js:10-31 底图为 raster 源）；fill-extrusion 层会被置于其质心处地形高度上（网格柱叠在 DEM 上，需与 grid-3D 互斥——现有 enforceMutualExclusion 已部分覆盖）；compare 卷帘双 map 需同步开/关（map.js:120-164）；**项目无 sky 层**（rg 无命中），地平线露容器底（项目已有露底刺眼先例并修过，docs/revision-log.md 06-30）；2D heatmap 在 terrain 下的拖放行为需 Playwright 验证（演示 2D 视图不开 terrain，风险低） | 高：TerrainLayer 经 MapboxOverlay 叠在 MapLibre 上，**MapLibre 底图不铺在 deck 曲面上（曲面浮空于平底图）**；仓库前科：deck.gl GridLayer extruded 在 MapLibre+MapboxOverlay 不渲染、ColumnLayer 效果不及 kepler、用户弃用回自创（map.js:790-794 + revision-log 06-28 "差太远"）；TerrainLayer 自身有缺瓦/性能已知问题（deck.gl issue #8976） | 低（不引入全局地形），但产品目标是"连续曲面"——风险为零也无意义 |

### 1.2 选择与理由

**选择 a（MapLibre setTerrain + RGB DEM）。** 理由：
1. 唯一同时满足"真连续曲面 + 官方原生 + 不引第二渲染栈 + 底图随地形起伏"的方案；b 的 mesh 再真，浮空底图与双栈前科使其演示风险最高；c 在原理上就治不了"非连续"的病根（用户反馈的核心）。
2. 与既有架构契合：后端已算 KDE 栅格（F_007 的 histogram2d + 高斯卷积），DEM 只是把同一栅格换一种输出（RGB PNG），不是新算法；前端已有 raster 底图管线（天地图 raster 源，map.js:10-31），setTerrain 对 raster 源天然支持。
3. 冲突风险可枚举、可验证、可兜底：互斥（grid-3D）、compare 同步、sky 层、heatmap 行为——均列 1.3 落地清单，不阻塞。

### 1.3 落地条件与风险清单（定案 a 的附加项）

1. **后端**：重构 `create_terrain_mesh` 暴露 KDE 栅格（Hs + extent + 分辨率），新增 `/spatial/dem` 返回 tilejson + mapbox 编码 RGB PNG 瓦片；`/spatial/terrain` 的 GeoJSON 环仅保留给 2D 等值线用途或随旧地形退役。
2. **依赖**：requirements.txt 增 Pillow（或纯 Python PNG 编码器）；**不引 rasterio/GDAL**（重依赖，无必要）；按 AGENTS.md Ops 角色同步环境。
3. **前端**：raster-dem source + `map.setTerrain({source, exaggeration})`；补 sky 层 + 地平线背景（防露底，先例 revision-log 06-30）；exaggeration 与 `maxHeight` 语义对齐（DEM 高度 0~1 归一 × exaggeration 或直接米值，二选一并在 UI 明示）。
4. **互斥与并存**：terrain 开启时隐藏 grid-3D fill-extrusion 柱（现有 enforceMutualExclusion 已覆盖 grid/terrain，需验证边界）；terrain 关闭时恢复原 2D/3D 网格层。
5. **compare 卷帘**：mapA/mapB 双 map 同步 setTerrain/removeTerrain（map.js:120-164 `_enterCompare`/`_exitCompare`），否则卷帘两侧地形不一致。
6. **退役**：7 层 fill-extrusion 地形（F_007 环 mesh + generateTerrainForAI 的 fill-extrusion 渲染路径）在 setTerrain 验证通过后登记 `docs/catch-ball/retired.md`；F_007 的 KDE 栅格计算保留（成为 DEM 源头），不改算法。
7. **验收**：Playwright 加载无错 + 肉眼确认"连续曲面、起伏张力"；A/B 与现状 fill-extrusion 对比；2D 视图不开 terrain（默认状态无行为变化）。

### 1.4 四个子问题回应

1. **a vs b vs c**：a（见 1.1-1.2）。
2. **2D/3D 是否共用同一 KDE 栅格**：**不统一**。2D 保留 MapLibre 原生 heatmap（GPU 屏幕空间核、radius 米制，map.js:678-741），3D 用后端 KDE 栅格（bandwidth 地理尺度）。两者参数（radius vs bandwidth）独立调参、UI 文案明示"不承诺一致"（采纳 glm 第一轮遗漏补充；统一到后端栅格一条链会牺牲 2D 的交互性能，收益低）。
3. **3D 保留/退役/降级**：定 a 后，fill-extrusion 地形退役（retired.md 台账），**KDE 栅格管线不退役**（升级为 DEM 源头）；若 setTerrain 验收不过，降级路径 = 保留 2D 热力 + 2D 等值线，3D 后置（不退回 c）。
4. **演示优先级**：**2D 为主、3D 后置**——P0/P1（命名 + Gi\* 网格化）先行今天定稿；setTerrain 3D 作为独立 P1.5 张力增强（2-3 人天）单独验收，不阻塞主链路。

## 二、焦点 2 收敛：Gi\* 网格粒度与权重

### 2.1 粒度：500m 默认 + 有效格过少自动降档

- **最终建议 = claude组 收敛的 500m 起步，但补自动降档护栏**：500m 格 → `point_count>=3` 过滤后有效格 < 30（Gi\* 最小样本护栏）→ 自动降档 300m 重算。演示逻辑链要的是"定位关注区（宏观）"，500m 对齐尺度表"区=500m"与宏观诊断信号；200-400m 更细、更适合社区级分析，保留为可选参数（200/300/400m），默认 500m。
- **顺带修一处现状不一致**：同一条链上存在三个默认粒度——backend `create_square_grid` 默认 200（core/spatial_analysis.py:728）、前端 grid DEFAULTS cellSize 400（grid-tool.js:20）、契约 density cell_size 默认 600（ai_qa/tool_contracts.py:46）。P1 落地时统一到一张尺度表（社区 250 / 区 500 / 主城 1000），默认 500。
- value_col 建议 **`score_mean` 为主**（连续、符合 Gi\* 假设），`polarity_index` 备选；invert 语义保留（score_mean 低=负面→hot=显著负面聚集），legend 明示（api/geo_routes.py:674 现 legend 只说"显著热点"，补"负面"）。

### 2.2 权重：P1 KNN k=8 默认，P2 距离带实测

- **同意 claude组 收敛（KNN 默认 + 距离带 P2 实验）**。补充两点：
  1. 网格聚合后，glm 担心的 KNN 尺度漂移被**大幅削弱**（规则格局部邻居尺度一致，原始点密度不均的 50m vs 2km 漂移主要发生在逐点场景）；但**边缘格**的 KNN 邻居会跨研究区边界，距离带在"跨区可比"上仍更优——这构成 P2 实验的动机。
  2. 距离带参数建议 threshold = 格对角线 × 1.5~2（500m 格对角 ≈ 707m → 阈值 1000~1400m），`transform='R'` 保留（core/spatial_analysis.py:87 已在用），无邻居格直接判 `ns` 兜底（替代现注释里"DistanceBand threshold=0 退化"的粗糙论证，core/spatial_analysis.py:73-75 的注释理由不构成放弃距离带的充分依据，但 KNN 作为默认仍是稳妥选择）。
- **护栏**：min cells >= 30；`point_count>=3` 过滤；A/B（逐点 vs 500m 网格）出图对比显著格数量/空间形态后再定权重终稿。
