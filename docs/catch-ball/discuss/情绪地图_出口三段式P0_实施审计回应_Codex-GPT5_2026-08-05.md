### 焦点 2：glm B2（结论段独立聚合）落实 + 学术化够不够

**判定：agree（B2 落实）+ partial（学术化素材不足）**

证据：
1. **B2 落实**：`buildResultStruct` 的 `_conclusionOf` 纯从 `{question, toolHistory, toolHistoryText, registryText, scale}` 组装，**无 draft 入参、不解析 finalStep markdown**（frontend/js/ai_qa/result-struct.js:35-51，docstring :4-6 明言"结论段独立聚合·LLM markdown 解析脆弱·finalStep 正文只进观点段"）——glm B2 阻断项解除。
2. **学术化 partial**：现句式偏"系统日志"——"本分析为宏观（面域分布）研究。共执行 N 步空间分析。产出图层：…。观察摘要：…"（result-struct.js:42-50）。用户要"基于图/数/表的描述性论述"，现状缺**数值与地名**（registryText 是图层名列表、toolHistoryText 是 raw 观察摘要），无 polarity_index/point_count/Top 区域等"数"与"表"素材；`toolHistoryText.slice(0,200)` 还含工具名/参数等技术噪音。
3. 建议（P1 深化，非 P0 缺陷）：从 result rows/features **确定性取 Top 数值+地名**（缺失降级"暂无数据"），填学术句式模板（"数据显示 X 区极性指数 -0.6（N 条样本），为全域最差；归因集中于 A×B"）；观察摘要改过滤或弃用。P0 验收 = 结构到位即可。

### 焦点 3：Codex R2（观点提取兜底）落实 + 首段首句误取风险

**判定：partial（三档落实，但首段首句兜底有真实误取风险——建议改保守）**

证据：
1. 三档落实：`_extractInsight` = 标记正则 `/^>\s*\*\*观点：\*\*(.*)$/m` → 首段首句（strip `*#>`）→ null 不显卡（frontend/js/ai_qa/result-struct.js:15-21）。
2. **误取风险真实存在**：FINAL_TEMPLATE 三句骨架①是"动作（做了什么）"（ai_qa/prompts.py:136）——LLM 若未写标记，首段首句**大概率是"我裁出西陵区情绪点 → 按极性染色 → 落到地图"这类动作句**，会被当"观点"显示在观点强调卡——语义错误比无卡更糟（用户最在意"观点=干货"，动作句稀释核心价值）。
3. **建议（警告级·P0 内一行级快修）**：无标记 → **null 不显卡**（删首段首句档），或给首段首句加启发式过滤（排除含工具动词/`→`/`分析`/`生成` 的句子；要求含结论性信号词：最/显著/优先/需/应/问题在于）。模板软扩后标记出现率应高，兜底档实际命中率低，保守化代价极小。
4. 细节：正则 `(.*)$` 只取**同行**内容；若 LLM 写 `> **观点：**\n> 内容`（多行引用块），m[1] 为空 → 落入首段兜底 → strip 后残留"观点："字眼。建议正则捕获整个引用块（如 `/^>\s*\*\*观点：\*\*\s*([\s\S]*?)(?=\n\n|\n>|$)/m`）。

### 焦点 4：双保险（软扩 + ctx 注入）+ 遗漏渲染路径

**判定：agree（双保险落实）+ 警告（onResultStruct 覆盖路径不全，但比审计怀疑的轻）**

证据：
1. 双保险落实：prompt 软扩（主，prompts.py:133）+ harness ctx.context 注入【观点先行】提示行（兜底，frontend/js/ai_qa/harness.js:679-680，与 G6a 同通道）——按设计（软扩=正式指令、ctx=兜底）落地。
2. **审计核心疑问澄清**：`onResultStruct` 派发只在 `runTemplatePath` 单技能路径（harness.js:704-713）；但 **runCapsule 实际已接**——它委托 `runTemplatePath`（harness.js:758 `return await runTemplatePath(ctx, hooks, synthDiagnose)`），故胶囊路径有观点卡。审计文档"runCapsule 路径有没有接"的答案：**接了（经委托）**。
3. **未接的路径**：`runChainPath`（多步链 extract_overlay/clip_density，finalStep :803、onFinalDone :811，无 onResultStruct）· agent-loop（:1097/:1370）· merge 直执行（:1884）· deliberate（:1943）。影响：这些 EXIT_RESULT 的 `> **观点：**` 行以**引用块**留在正文（内容不丢、样式降级），4 要点卡缺失。
4. **判定**：警告级非阻断——多步链/agent-loop 是进阶交互，P0 主路径（单技能+胶囊）已覆盖；建议 P1 内把 onResultStruct 派发抽成共享 helper（`_dispatchResultStruct(ctx, hooks, {draft, diagnose, toolHistory, toolHistoryText})`），在 runChainPath/agent-loop 收尾调用——低风险增量、不碰红线。GAP/PARTIAL/降级结论路径无卡是**正确**的（无 LLM 观点）。

### 焦点 5：前端渲染 + 条件段

**判定：agree（渲染落地正确）+ 两个细节**

证据：
1. 渲染顺序正确：onResultStruct 先于 onFinalDone 派发（harness.js:704-713），panel `_pendingStruct` 暂存 → onFinalDone 统一渲染"观点卡置顶 + 正文 + 4 要点卡底部"（frontend/js/ai_qa/panel.js:1507-1529）。
2. 观点行移除正则 `/^>\s*\*\*观点：\*\*[^\n]*\n?/m`（panel.js:1524）与提取正则同构、正常路径一致；**多行引用块场景会残留第二行**（与 F3 同一根因，建议一并改成"删整个引用块"）。
3. 4 要点映射合理：method（diagnose.method/template）· data（data_plan.available）· result（registryText+步数）· conclusion（确定性组装）（result-struct.js:23-51）；result 缺数值属素材限制（F2 已述，P1 深化）。
4. 条件段：outlet_card 复用既有 onOutletCard/renderOutletCard（panel.js:278-322），D2 保持 resolve_outlet_id 评分制（build_outlet_schema.py:24-35）未动——符合定稿，无问题。
5. 建议级：`_pendingStruct` 只在 onFinalDone 内清（panel.js:1528），send() 起始未重置（:1609）——若用户在 onResultStruct 与 onFinalDone 之间中断（stop）后发新问，新答可能短暂渲染旧观点卡；建议 send() 起始 `_pendingStruct = null`（一行防御）。

### 焦点 6：新问题/遗漏

**判定：3 项新发现（1 警告 + 2 建议）**

1. **前端验证缺口（警告级）**：283 passed 是后端 pytest，覆盖不了前端 JS 运行时；node 不可用、python 括号平衡验证有漏检风险（语法合法≠行为正确）；浏览器肉眼验收未做。**P1 开工前建议补最小验收**：浏览器加载无 console 错 + 单技能问答 1 例（观点卡/4 要点卡/正文无重复行）。
2. **结论段素材缺数值/地名（警告级，P1 深化）**：registryText 仅图层名列表，无法支撑"基于图数表的描述性论述"（用户对第二段的明确要求）——P1 从 result rows/features 确定性取 Top 数值+地名（缺失降级），禁止 LLM 补数。
3. **体积预算 23B 余量（警告级）**：P1 起 FINAL_TEMPLATE 冻结加字（学术化走前端），门禁注释写明。
4. 建议级：三锚点补"指令位置"断言；观点行无卡时也可移除（防引用块重复语义）；`_pendingStruct` send 重置。
