## 一、已查证事实（claude 实测）

### 事实 1 · 问句应命中 RAG 短路（但回答是情绪分析式）
- 「宜昌有哪些更新项目」→ `RAG_QUERY_KW` 命中（有哪些项目）+ `RAG_KNOWLEDGE_RE` 命中（项目）→ `_quickIntent` 应返 `'rag_query'`
- **但用户回答是「网格聚合+极性热力」情绪分析式**·非「知识库检索引用」式 → **短路疑似未生效**（或注入被覆盖）

### 事实 2 · trace 日志（用户测试 session sess-31860）
```
16:45:27 MOD_RANGE.F_013（范围处理·纯问答不该触发范围）
16:45:38 MOD_AIQA.F_015（rag_search）enter → 16:45:57 exit 18630.9ms（RAG 跑了·18.6s 冷加载）
16:45:57 MOD_AIQA.F_003（finalStep）enter → exit 0.0ms（立即返回？）
16:45:57 MOD_LLM.F_002 / F_001（LLM 调用）
```
- **F_005（diagnose）未出现** → 走了短路（非 diagnose 路径）
- **F_015 18.6s** = serve 重启后首次检索·模型冷加载（缓存是进程内·重启后清空）
- **F_003 0ms** = 可疑·finalStep 不应 0ms（或 trace 记录粒度问题）

### 事实 3 · serve 前端加载问题
- serve 16:45 启动·磁盘 harness.js 含 rag_query（新版）
- 但 `curl serve 返回的 harness.js` 含 0 次 rag_query → **serve 未注入最新前端**？（或 curl 未走 ?v= 注入）
- serve.py 注释明确「改子 module 后 F5 仍跑旧版·Chrome 复用 module graph」→ **浏览器可能缓存旧模块图**

### 事实 4 · 耗时根因（用户疑问 1）
- serve 重启后首次 rag_search → 模型冷加载 18.6s（`_get_model` 缓存进程内·重启清空）
- **RAG 模型应在 serve 启动时预热**（Codex/glm 提过「启动预热可选」·未实施）

### 事实 5 · 问题分类（用户疑问 1·4 类机制）
- intent 三值（general/gis_operation/emotion_analysis）+ 四态出口（EXIT_CONCEPT/RESULT/GAP/PARTIAL）
- 「宜昌有哪些更新项目」= 纯问答（无数据/无范围/无分析）→ 应判 **general → EXIT_CONCEPT 直答**
- **但 trace 显示走了 MOD_RANGE + rag_search**（非 general 直答）→ **分类机制疑似未正确运作**

## 二、待两组深挖的根因假设

### H1 · 前端跑旧代码（最可能）
- serve 未正确加载新 harness.js（浏览器缓存 module graph）→ rag_query 短路不存在 → 问句落 diagnose → 判 emotion_analysis → 情绪分析式回答
- **证据支持**：serve 返回 harness.js 无 rag_query·回答情绪分析式
- **矛盾**：F_015 跑了（RAG 真调用了）·且 F_005 未出现（应走了短路）

### H2 · rag_query 短路生效但注入被覆盖
- 短路触发 → rag_search（F_015 18.6s）→ 注入 ctx.context → finalStep
- **但 ctx.context 被后续逻辑覆盖**（如 MOD_RANGE 或情绪分析上下文）→ 回答用情绪背景而非 RAG 结果
- **证据支持**：MOD_RANGE.F_013 出现·回答情绪分析式

### H3 · finalStep 0ms + 截断
- F_003 0ms 退出·回答截断 → finalStep 流式中断？或 applyQualityDefense 截断？
- 需查 harness 短路分支的完整执行（是否 await 完整 finalStep）

### H4 · 问题分类机制缺陷
- 「宜昌有哪些更新项目」含地名（宜昌）+ 实据词（更新/项目）→ `_quickIntent` 可能走 REGION_KW 分支（实据词→general·但这里是"更新项目"非"政策"）
- 需核对：纯问答问句是否正确走 EXIT_CONCEPT 直答·而非触发范围/分析

## 三、用户三疑问的初步答案（待两组确认）

| 疑问 | 初步判断 |
|---|---|
| ① 耗时太长·分类没运作 | **RAG 模型冷加载 18.6s**（serve 重启后首检·未预热）·分类疑似走错（含地名→范围/分析） |
| ② 没引用知识库 | **RAG 跑了**（F_015）·但**回答没用 RAG 结果**（情绪分析式）——注入被覆盖或短路未生效 |
| ③ embedding/RAG 跑起来了吗 | **跑了**（F_015·索引 225 条·检索正常）·但**模型加载慢 + 结果未被回答引用** |

## 四、待两组验证/深挖焦点

1. **H1 vs H2**：前端是否跑旧代码（浏览器缓存）？rag_query 短路是否真生效？
