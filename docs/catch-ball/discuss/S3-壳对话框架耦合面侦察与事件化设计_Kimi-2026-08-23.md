## 二 隐藏重构坑（侦察发现的四个坑·设计已规避）

1. **闭包状态深耦合**：buildHooks 内 9 个状态变量（reasonSegs/streamAcc/RAF×2/读秒器×3/_reasonCopyWired）被 14 个 hooks 共享——**不可把 hooks 体搬出 buildHooks 作用域**。设计规避：事件订阅注册仍在 buildHooks 闭包内完成（`bus.on` 与状态同作用域），只把「hooks 对象字面量」换成「bus 订阅 + emitter 返回」。
2. **onRound 是 no-op 但 harness 调 8 次**：保留事件（turn round.tick）但订阅侧空实现——防未来消费者需要节拍。
3. **onDiagnose 在 quick-rag 路径不触发**（panel.js:1715-1717 靠 orchestrate 返回值补写 _curTrace.diagnose）——事件化不能假设每轮都有 diagnose 事件，send 尾部补写逻辑原样保留。
4. **onAskUser 有副作用序**（cancelStream→stopThinking→读 usage→渲染胶囊）：事件订阅内严格保持原语句序，只换触发方式。

## 三 事件化改造设计（S3 主体）

**形态**：新增 `frontend/js/ai_qa/acp-channel.js`（事件通道模块），buildHooks 内部接线改为：

```
harness (零改动·仍调 14 个 legacy hooks 签名)
   ▼
emitter（acp-channel 提供·hooks 签名 → ACP 事件翻译）
   ▼
ACP bus（family 路由·turn_id 贯穿）
   ├─ process lane：msg.delta / tool.begin / tool.end / turn / error（ACP v1.1 五族）
   └─ content lane：render 族（ask_user/result.struct/outlet.card/defense·非 ACP·分层红线）
   ▼
panel 渲染订阅器（原 14 个 hooks 回调体·逐事件搬迁·闭包共享）
```

**设计决策三条**：
1. **harness 零改动**——eval-anchor 红线下引擎一行不动；事件化全部发生在壳侧（emitter 保持 legacy hooks 签名，harness 无感知）。这也是「渐进升级」的应有之义：S4 再把引擎发射层换成原生 ACP（那时 emitter 退役，bus 直连引擎）。
2. **turn_id 每 send 一枚**（buildHooks 每轮 send 调用一次）——事件贯穿同一轮次；session 语义 v1 不建（panel 历史已是事实会话层，ACP session 对象留 S4/BrainAdapter 阶段补）。
3. **bus 暴露于 shell**（`shell._acp`）——S7 E2E 与 BrainAdapter 的注入点预留：远端引擎未来可直接向同一 bus 注入事件，壳渲染零改动。

**事件 envelope**：`{family, lane, turn_id, ts, ...payload}`；`provenance:'real'`（轻循环直发·v1.1 §5-1——降级形态由未来 BrainAdapter 标 synthesized）。
