## 要点2：grid「综合」归并对多无时间源的影响

**结论：agree ✅（综合归并合理·seen去重正确）**

### 2.1 实现验证（grid-tool.js L226-230）
```javascript
const seen = new Set();
// ...
const t = deriveTimeTag(s.fc) || '综合';  // 无time_label→'综合'
```

- **deriveTimeTag 返回 null/falsy → fallback '综合'**——12345 无 time_label（2024年单年数据）→ 归入"综合"分类 ✅

## 要点3：detectColorMode 对 preset 点层的副作用

**结论：agree ✅（score填充/极性规范化合理·needsAnalysis灰点合理）**

### 3.1 score/emotion_intensity 填充逻辑（import.js L635-648）
```javascript
// L2 polarity: score优先scoreKey→confKey→scoreFor(polarity)兜底
p.score = Number(p[_sk]);           // 有原始值用原始
if (p.score == null) p.score = scoreFor(p.polarity);  // 无值用极性映射分
```

- **12345 点层**：有 polarity/score → detectColorMode 填充 score（热力图权重）✅
- **体检点层（如小区点）**：可能无 polarity → detectColorMode 走 confidence 或 needsAnalysis 路径
- **score 范围**：0-1（scoreFor 映射极性→分值）· 热力图 KDE 权重正确 ✅

### 3.2 needsAnalysis 灰点（控件层）
- **体检控件层**（如小区点/住房隐患面质心）：无 polarity 无 confidence → `colorMode='needsAnalysis'` → 灰点 `#4a4a4a`
- **是否合理**：✅ **合理**——控件层是"问题点位参考层"（非情绪数据），灰色表示"客观存在但无情绪评分"，不进热力图/grid（collectSources 过滤 needsAnalysis）但在地图上可见
- **用户语义**：灰点="这里有体检问题·但无市民情绪数据"· 红蓝点="这里有市民情绪"· 两者地图上可区分

### 3.3 detectColorMode 的潜在副作用检查
- **score 被填充到原始属性**：detectColorMode 会给 feature.properties 写入 score/polarity——如果用户后续导出该层·导出数据会含填充值。**这是合理行为**（填充值是规范化结果·非篡改原始数据·用户可区分原始列vs填充列）
- **confidence 路径**：L1 confidence 点层也会被 collectSources 认（`l.colorMode === 'confidence'`）→ 进工具 ✅
