## 一、原则 1 · 颗粒度 = 数据来源维度（结论细粒度对齐数据源颗粒度）

### 用户原话（两轮澄清·修正）
> ① 虽然最小调研单元是社区，但是**可以精确到"栋"的**——这要看**数据来源的颗粒度**。我的意思是**结论的细粒度要对齐数据来源的颗粒度**。
> ② 城市体检/城市更新就是**"四个维度"：城区、街区、小区、住房**。一个社区包含**若干个小区以及一些零散住房**（包括城中村）·若干个社区组成**街区**·街区组成**城区**。要明白这个**层级关系和组成/包含关系**。**数据来源是哪个维度+颗粒度·就只能得到哪个维度+颗粒度的答案**。

### 四维度层级与组成关系（核心）

```
城区（宏观）
  └── 街区（中观·由若干社区组成）
        └── 社区（调研最小单元·但非最细）
              ├── 小区 A
              ├── 小区 B
              └── 零散住房/城中村
                    └── 住房/栋（最细·若数据源支持）
```

**关键**：层级 = **包含关系**（社区 ⊃ 小区+零散住房）·不是「社区最细」。**颗粒度取决于数据来源**——数据若来自"栋"（如 GIS 危旧房图层·MultiPolygon 到栋），结论就能精确到栋。

### 数据来源维度 → 可达结论颗粒度（实测映射）

| 数据来源维度 | 实例数据（已核实） | 可达结论颗粒度 |
|---|---|---|
| **住房/栋** | GIS：50 年建筑 380 栋/250 栋危旧房/结构隐患 42 栋（MultiPolygon 到栋） | **精确到栋**（"xx 小区 x 栋有结构隐患"） |
| **小区** | GIS：停车泊位缺口 140 小区/充电桩 84 小区（Point）·附件1 小区维度 | **精确到小区** |
| **社区** | 体检报告社区级结论·葛洲坝 33 社区 | **精确到社区** |
| **街区** | 街区维度体检（步行道 24/乱停 5） | **精确到街区** |
| **城区** | 综合体检城区维度·宏观诊断 | **精确到城区** |

### 原则落地
**EMC 回答颗粒度 = 数据来源维度**·**结论细粒度严格对齐数据源颗粒度**·不越维、不硬答、不编造。

1. **回答只达数据源维度**：数据来自"栋"→ 可答到栋；数据只到"社区"→ 只答到社区（**不得臆造到栋**）
2. **空间落位 = 数据落位**：数据有栋的坐标 → 可落位到栋；数据只到社区 → 只落位到社区/片区集中度
3. **层级关系内置**：回答社区问题可上溯街区/城区（包含关系）·但**不得下探到无数据的更细维度**
4. **出口契约 cannot 强化**：现有 cannot（不能测 X 需 Y）升级为**按维度声明**（"本数据源为小区维度·无法到栋"）

### 对 RAG/检索的影响
- **元数据标注数据维度**（住房/小区/社区/街区/城区·来自数据源）+ 颗粒度
- 检索返回带维度标注·RAG 回答**不得超出检索数据的维度推断**
- 黄金集含「越维度问题」验证（数据到社区·问精确到栋 → 诚实降级声明）

## 二、原则 2 · 案例 = 方法论参考（不引用具体数据）

### 用户原话
> 关于各个城市的案例，**最主要的功能是作为实施策略、做法、路径、机制、指标体系等方法论内容的参考**，**避免去引用、参考具体数据**（城市规模不同，各项指标的参考意义不大），**尤其注意不要张冠李戴**。

### 原则落地
**案例库/他城资料 = 方法论参考**·不引用具体数据·防张冠李戴。

| 案例用途 | ✅ 方法论参考 | ❌ 具体数据引用 |
|---|---|---|
| 上海考察 | 片区化实施路径/历史街区活化模式/REITs 资金机制 | 上海某片区投资额/指标值 |
| 杭州专项 | 95 片区划分逻辑/六大更新对象分类/无体检不更新机制 | 杭州 86 项指标具体值 |
| 广州/成都 | 微改造模式/公园城市理念 | 广州某项目面积/投资 |

**实现机制**：
1. **案例引用 = 提炼做法/路径/机制**·不引用他城具体数值
2. **防张冠李戴**：任何他城数据**不得**用于宜昌回答（城市规模不同·指标无可比性）
3. 出口契约/知识库引用案例时**只取方法论 point**·不取他城数据 detail

### 对 RAG 的影响
- 案例类向量化 = 提炼「做法/路径/机制」·**剔除具体数据**
- 检索「宜昌停车」→ 不得返回「南京案例数据」作为宜昌答案（glm 已发现此问题）——案例只作方法论参考
