## 〇 一句话结论

**思路成立、定位要摆对**：它不是「EMC 调用 dsh」，而是「**给哑入口外挂一个 dsh 大脑**」——与形态3 正交互补（形态3 主路=任意 harness 主动消费 EMC 插座；本思路=我们自己的薄入口把 dsh 当可编程大脑来驱动），**不替代 G10、消费 G10**；朋友方案自带的守卫纪律（仅关自启实例/不擅重启/精简状态回传/模式分级）专业且应全盘采纳；主要风险=dsh 处于 preview 期（R1 实锤：近 600 commit 内 16 次 breaking·集中在插件承重层）+ 双 MCP 跳链路的长鞭效应；建议定位为「用户工作流工具 + 薄壳可选 B 变体」，排 G10 之后，前置第 0 步=确认 Host 插件与本地接口是否已真实存在。

## 一 思路还原（忠实转述·七要点）

1. 不重造 DSH：先让 DSH Web（Pro+max+创造模式）**给自己写一个正式 Cordis Host 插件**；
2. 插件运行在现有 Web Host 内，**复用原生 Workspace/Session/模型/工具/Skills/权限/日志**，对外提供 start/send/status/stop 本地接口；
3. Codex 侧写一个**薄 stdio MCP**（dsh_start/dsh_send/dsh_status/dsh_stop/dsh_shutdown）转发到插件；
4. DSH 离线时仅 start/send 可按需后台启动；不开机自启、不自动开浏览器；
5. MCP 只回**精简状态**，完整过程与日志留在 DSH Web UI；
6. 普通调用固定 anchored-standard·Flash/Pro 均 max；**创造模式只用于开发 DSH 插件**；
7. shutdown 只能关 MCP 自己启动的 DSH；**未经用户同意不重启 DSH**。

用户补充语境：朋友实践=Codex 指挥其他 CLI 与局域网 CLI；dsh 精简模式下 Flash 表现好、Pro 管文档、Flash 三次失败派 sol 升级解决（=模型分级调度已在实战运行）。

## 二 专业评估（Codex 主开发视角）

### 2.1 本质判定：这是 harness-of-harness 编排，不是平台能力

链路解剖：`调用方 → stdio MCP(dsh_*) → Cordis Host 插件 → dsh Web Host（大脑）→ dsh 内部再调 EMC MCP 工具（若接 G10）`。
- 它解决的问题是「**可编程地驱动 dsh**」——把 dsh 从「人手开的网页」变成「任何程序都能遥控的员工」；
- 对形态3 而言，主路方向是反的（dsh 主动来消费 EMC）；但**两条链在「薄入口」上汇合**：薄壳自己不造大脑（M1/M3 停投），把对话转给 dsh——loop 发生在 dsh 体内，薄壳保持哑转发，**合规于停投边界**（这是本思路最妙的契合点：薄壳=遥控器，dsh=机芯）。

### 2.2 与形态3 各构件的关系

| 构件 | 关系 |
|---|---|
| G10（EMC MCP 七工具） | **前置且不可替代**——dsh 当大脑后干 EMC 的活仍需插 EMC 插座；本思路不改变 G8a/G8b/G10 排期 |
| 薄壳 v0（2d·单轮 FC） | 本思路=薄壳的 **B 变体**：A 变体=直连 EMC 工具做固定任务（无大脑）；B 变体=经 dsh_* 做自由任务（外挂大脑）。两通道服务不同任务类型，可并存 |
| 场景 S（dsh Web 原生展示） | 互补而非竞争：场景 S=人在 dsh 里看；本链路=人在我们入口里用、dsh 在后台想 |
| T0-T3 数据分层 / 五判据 | 照常适用——dsh 经 G10 取数同样过工具面约束 |

### 2.3 三条真价值

1. **产品入口的最便宜「聪明」**：不自研路由（已裁定死路）也不逼用户开 dsh 网页——一个窗口、背后是 dsh 的完整智能（含其会话循环/自检自纠= R4 三次转移论的能力）；
2. **用户工作流即时增强**：朋友模式（Codex 指挥各 CLI·Flash/Pro/sol 分级）今天就能用于 CB 出图主线——零 EMC 改动；
3. **会话复用**：插件复用 dsh 原生 Workspace/Session——跨轮对话上下文由 dsh 专业管理，我们不用造。

### 2.4 五条风险（按重量排序）

1. **dsh preview 供应链**：R1 实锤 breaking 集中在 cli/config/profile=插件承重层——自写 Host 插件+自写桥 = **自定义集成面裸露在 dsh 最不稳定的一层**；每次 dsh 破坏性变更都要跟着修。对策：插件面最小化（四接口）、锁版本、把该链路定位为「可选增强」而非产品主干（断了不瘫）；
2. **链路长度**：五跳（UI→薄后端→MCP→插件→dsh→再出 EMC MCP）——每跳=延迟/失败面/状态同步。对策：MCP 只回精简状态（方案已含）+ 超时与降级路径（dsh 不可达时薄壳回落 A 变体直连工具）；
3. **安全半径**：start/send 驱动的是一个有 bash/文件能力的代理——等于给它开程序化入口。对策：沿用方案守卫（只关自启实例/不擅重启）+ 补两条：send 内容审计入 trace、创造模式调用须显式二次确认；
4. **AI 写插件的供应链**：让 dsh 自己写自己的插件——务实但产物须走代码评审（朋友方案未提）；插件权限按最小化审查；
5. **产品化卫生**：dsh Session 的上下文卫生/口径一致性——靠 EMC 工具返回自带口径标签（T 分层+C11）兜底，不靠 dsh 自觉。

### 2.5 护栏（朋友方案纪律全收 + Codex 补两条）

采纳原七条（尤其 4/5/6/7 守卫款）；补：⑧ send 载荷与返回摘要入后端 trace（可观测）；⑨ 该链路任何调用不得绕过 G10 工具面直取数据（正道好走纪律的延伸）。

### 2.6 合规性判定

- **M1/M3 停投边界：合规**——薄壳单轮哑转发，多轮循环在 dsh 体内（我们把 loop 外包而非自研）；
- **契约单一源：合规**——dsh_* 四接口是「控制面」契约（启动/发送/状态/停止），与分析工具「数据面」契约（G10）分属两域不冲突；
- **四承重红线：零接触**——不碰 diagnose prompt/编排器/EMC 内核。

### 2.7 排期定位与第 0 步

**排 G10 之后**（无 G10 则 dsh 无 EMC 活可干·本链路空转）。**第 0 步（先于一切）**：确认朋友方案的插件+MCP **是否已真实可跑**——转述文本是「实施计划」而非「交付物」；若未实现，则首个问题归 **dsh组 B 卷**（其五问中「嵌入工程位置谱系」正是此题）：Host 插件能否开本地接口、dsh 能否无头后台启动、Session 复用 API 形态——三个技术前提全部待 dsh 侧证实。若已实现（朋友处有成品），则第 0 步改为**拿来评审**（代码+守卫核验）。
