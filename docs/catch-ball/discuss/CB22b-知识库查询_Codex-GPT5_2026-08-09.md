## 焦点 1 · L1.5 事实卡 schema — partial（字段补 4 项·覆盖范围扩 3 类）

**现有字段**（id/city/name/detail/source）够用，**建议补 4 项**：

| 补字段 | 为什么 |
|---|---|
| `region`（区/片区） | "葛洲坝体检有什么问题""伍家岗停车项目"需要片区级过滤（10 片区/23 片区/葛洲坝/西坝）——只有 city 会命中到市域卡 |
| `topic`（类目枚举） | 查询路由主键：`项目/指标/体检问题/片区/案例/政策/指标体系`——确定性 WHERE 的依据 |
| `keywords`（同义词/直名） | "汉宜村安置房""51.33 亿""原拆原建"直名/数值子串兜底（焦点 2 第三层） |
| `year`（适用年度） | 防过期误用（2025 体检数值 vs 2027 行动方案·版本状态已在 _INDEX·事实卡带年度防张冠李戴） |

**覆盖范围建议**（方案仅 3 类 → 扩到 6 类）：

```python
PROJECTS        # 项目库（55 个 51.33 亿 / 危旧房 16.4 亿 / 汉宜村 18.06 亿…）
INDICATORS      # 指标数值卡（结构隐患 42 栋 / 泊车比 1.11 / 中学覆盖 56.10%…）
CHECKUP_ISSUES  # 体检问题清单（附件3 四维度问题）
PANELS          # 片区卡（10 重点更新片区划分表 / 23 更新片区四大分类）
CASES           # 案例卡（上海 5 启示 / 杭州 95 片区 / 成都公园城市 / 宜昌葛洲坝示范）
POLICIES        # 政策卡（国家 7 / 湖北 4 / 宜昌 1·gist 级摘要）
METRICS_SYSTEM  # 指标体系卡（伍家岗 40 项 / 葛洲坝 20 项 / 附件1 78 行·框架与数值分离）
```

**粒度纪律**：每条 ≤80 字 + source 指针（`_INDEX` 编号 + G 盘相对路径）——从三组提炼笔记确定性提取·**非 LLM 编造**（延续 CB-22 L1.5 结论）。

## 焦点 4 · B vs A 边界 — agree（路由判据=分析动词 vs 查询动词·单源数据不重复）

| 维度 | B（知识查询） | A（出口卡引用） |
|---|---|---|
| 问句特征 | 查询词：有哪些/多少/是什么/清单 | 分析词：分析/评价/感受/趋势/排序/为什么 |
| 意图 | general（数据类） | emotion_analysis |
| 出口形态 | 直答文本（事实卡 + 来源）·**不产 outlet_card** | 出口卡（build_outlet_schema + kb_reference） |
| 数据源 | L1.5 事实卡（L0 提炼） | EMC 分析产物 + case_library/L0 引用 |
| 实现 | query_knowledge_base（新） | _maybeBuildOutletCard（既有·`harness.js:1426`）+ `_attach_kb_reference` |

**防重叠三规则**：
1. **路由单一**：意图词表判据唯一（查询词→B·分析词→A）——不双走
2. **混合问叠加不冲突**："葛洲坝有哪些更新项目，居民感受如何" → 先 B 事实卡 + 再 A 情绪卡（含分析意图则 A 为主 B 补充）
3. **数据同源不重复**：L1.5 事实卡 = A 的 kb_reference 与 B 查询的**共同数据源**——A 引用案例/项目（增强出口卡）·B 查询事实（直答）·不建两套
