## 2 · 先建事实卡再重 build — agree（schema 确认）

**顺序确认**：事实卡（含 dimension）+ case point 补齐 → **再** `rag_index.py --rebuild`——一次到位（与用户裁决一致·与我 CB-22c Phase 1 评估"先建事实卡"建议一致）。

**事实卡 schema**（6+1 类·`ai_qa/outlet_kb/urban_renewal_knowledge.py`）：

```python
{id, city, region, topic, name, detail(≤80字),
 dimension,   # 住房/小区/社区/街区/城区/片区/城中村专项（颗粒度原则·落位维度）
 year, keywords, source}   # source = _INDEX 编号/G 盘相对路径
```

- 类目：PROJECTS / INDICATORS / CHECKUP_ISSUES / PANELS / CASES / POLICIES / METRICS_SYSTEM
- **CASES 卡与 case_library 同源不重复**：CASES 事实卡 = point 方法论（source 指向 `case_library.py#key`）·由 point 派生
- **dimension 落位规则**（分歧 4 共识）：看数据落位·非采集机制——42 栋=住房维度·140 小区=小区维度·33 社区=社区维度

## 3 · cannot 静态+动态合并 — agree（实现确认）

| 层 | 实现 |
|---|---|
| **静态**（契约声明） | field_mapping 行业槽加 `[dim=xxx]`（仿 CB-16 `[scale=xxx]` 先例·`urban_renewal_outlets.py` 既有语法） |
| **动态**（运行时填） | `build_outlet_schema` 按数据源维度渲染 cannot："本数据源为 {dim} 维度·无法到 {更细维度}"——维度从 result/知识数据元数据读 |
| **合并逻辑** | 数据源维度 < 契约声明维度 → cannot 降级声明；≥ → 可答（不降级） |

**实现建议**：`_render_dimension_cannot(contract, result_dim)` 纯函数（可单测）·契约 schema 补可选 `dimension` 字段 + `test_outlet_kb` 守护。

## 5 · 黄金集 3 类合并 — agree（设计确认 + 1 点细化）

| 类 | 用例 | 门槛 | 断言层 |
|---|---|---|---|
| ① 正确召回 | "葛洲坝有哪些更新项目" | Recall@5 ≥80% | 检索层（Top-5 含期望 source） |
| ② 越维降级 | 数据到社区·问精确到栋 | **100%** | **回答层**（检索可返回相关片段·LLM/出口组装**不得越维使用**·须声明"数据维度=社区·无法到栋"） |
| ③ 案例不引数据 | 检索"宜昌停车"不得返回南京数值作为答案 | **100%** | **回答层**（案例只作方法论参考·他城数据不得出现） |

**1 点细化**：②③ 是**行为断言（回答层）**而非仅检索层——检索本身可以返回相关片段（含数据·供 LLM 判断），关键在**回答/出口组装不得越维使用**——黄金集断言应覆盖"回答文本不含越维数值"（e2e 层·`tools/rag_eval.py` 输出三类分项通过率）。
