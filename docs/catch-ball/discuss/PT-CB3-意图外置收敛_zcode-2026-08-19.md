## 一、四问研判（claude 组 §五）

### 问 1：范式体系（尺-方法-结论）在外置场景如何保住

**答：范式映射下沉为契约的一部分，不随 Agent 外移（模式 B）。**

- 外置大脑只做它真正擅长的事：**自然语言 → 结构化意图卡的转译**；
- 范式规则（`ai_qa/paradigm.py` 的尺度→工具→结论颗粒度路由）**留在 EMC 侧**，从"被内部 Agent 消费的库"升级为"契约的执行体"——职责不变，消费方变；
- 理由：范式是领域知识资产不是实现细节。外置到宿主侧=每个宿主重学一遍、无法统一升级、跑偏难约束——违背单一权威源纪律。Cordis 的 Service 思想同构：范式路由是 EMC 的内部服务，外置大脑是 Consumer，**消费服务不拿走服务**。

### 问 2：需求契约的粒度与形态

**答：两级契约，tool_contracts 升级 + 新增轻量意图契约层，不推翻现有。**

| 层 | 内容 | EMC 现状 |
|---|---|---|
| 工具契约（参数级·已有） | 工具参数/默认值/别名/输出 schema | `tool_contracts.py` 单一权威源 ✅ |
| **意图契约（新增·轻量）** | ①意图卡 schema（输入：尺度/主题/时点/区域/期望结论形态）②范式路由表（EMC 侧确定性执行）③**结论口径声明（输出验证：结论必带 caliber/usage 标签）** | 意图卡待设计；路由表=paradigm.py 已有；输出验证=**PT-CB2 T2 守卫管线的天然第二道闸位** |

业界四条做法的取舍：**输出边界验证层**（论文思想）是 EMC 最缺且最该先做的——意图卡校验 + 结论口径校验；MCP 工具契约已有；ADR 契约文档化与约束即契约头作为格式参考。Python 栈落地：pydantic 意图卡 schema + 现有路由表 + 守卫管线挂输出验证。

### 问 3：与 MCP v1 的关系

**答：并入 MCP v1 设计输入，不独立专项。** 意图外置（Smart 端外移）与工具面（Dumb Tool 对外开面）是同一个对外服务面的**入口与出口**，分立专项=两套对外契约重复建设。时序同 MCP v1（B/C 线治理后），静态演示已解除"演示驱动提前开面"的压力。

### 问 4：演示静态化对排期影响

**答：零影响，反而减压。** 治理线（PT-CB2/PT-CB4）与演示本就解耦；静态演示=前端已有图层与结论展示，不依赖 AI 问答链路改造。**但关键澄清**：静态化是"不投入新演示功能"，**不是"可拆现有链路"**——过渡策略见下。

## 三、收敛结论（四档裁决）

### 立即吸收（生效即执行）

- **N1 意图外置方向确认**（用户拍板）：EMC 终态 = Dumb Tools + 确定性编排器 + 范式契约 + 审查；Smart 端（意图理解/结果表达）外移至 LLM+Harness 宿主。
- **N2 设计原则"LLM 只做转译，规则留在契约"**：意图卡是外置大脑唯一合法输出物；范式路由由 EMC 确定性执行——防跑偏的机制本质。
- **N3 过渡策略——内部意图 Agent「冻结不拆」**：修正"抛弃"的执行口径为**冻结退役**：现有 ai_qa 链路停止增强、保留运行（静态演示期的产品面），待外置链路（工具面+意图契约）建成并验证后切换、再拆除。立即拆=静态演示也翻车。
- **N4 红线联动强化**："外接大脑不得绕过工具面直取数据"红线在意图外置架构下升权——需求契约 + 工具面就是这条红线的机制化载体。

### 并入现有排期（不新开专项）

- **N5 意图卡 schema + 结论口径声明 → 并入 PT-CB4 T2 口径注册表设计**（纸面设计·与 B 素材表/F 指路候选正好衔接；不实施代码）。
- **N6 意图外置架构（意图契约+转译协议）→ 并入 MCP v1 设计输入清单**（B/C 线后·与薄服务门面一体设计）。
- **N7 输出验证层 → 守卫管线第二道闸的设计预留位**（结论口径校验·与"观察者必须放行"纪律同批成形）。

### 暂缓

- **N8 外置大脑实连验证**（等工具面+契约就绪；静态演示不依赖）。
- **N9 拆除内部意图 Agent**（外置链路建成并切换后）。

### 反对与修正

- **N5a 修正"抛弃"表述**（同 N3）：立即抛弃会使静态演示失去问答链路且无替代——冻结→建成→切换→拆除，四步走。
- **N6a 修正"接的不只是 LLM 大脑"的隐含期待**：外置宿主（dsh 等）仍受周级 breaking 风险——意图外置后 EMC 对宿主的依赖**变深**（意图理解也在外面），因此工具面+契约的宿主无关性（MCP 标准）是唯一护栏，不得走 dsh 专有协议。

## 四、对开发方向与内容的调优（落地清单）

1. **PT-CB4 不变**，T2 注册表设计增补两字段素材：**结论口径声明**（输出验证素材）+ 意图卡草字段（尺度/主题/时点/区域/期望结论形态——与能力目录字段同表）；
2. **MCP v1 设计输入清单 +1**：意图契约（意图卡 schema + 范式路由契约化说明 + 转译协议）；
3. **排期主干不变**：治理（PT-CB4）→ 蒸馏（C 线）→ 工具面+意图契约（MCP v1）→ 外置实连验证 → 切换拆旧；
4. **ai_qa 现有链路冻结令**：除 bug 修复外不再增强（省下的投入转治理线）。
