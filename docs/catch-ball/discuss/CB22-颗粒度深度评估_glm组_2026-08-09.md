### 裁决 3：cannot 静态+动态合并 — **agree（实现方式认可）**

**用户裁决**：契约 field_mapping 标 `[dim=xxx]`（静态）+ build_outlet_schema 运行时填（动态）。

**glm组 确认**：**agree——静态+动态合并最优（glm 原动态 + Codex 原静态互补）。**

**合并实现（glm 认可）**：
```python
# 契约静态声明（urban_renewal_outlets.py）
'renewal_demand': {
    ...
    'field_mapping': {
        '需求强度': 'polarity_index [dim=社区/小区]',  # 静态标注可达维度
    },

data_dim = result.get('data_dimension', '社区')
```

- 动态（运行时填）：让出口卡按实际数据源标注（执行层）。
- **两者互补**——静态是契约文档·动态是运行实例。glm 认可合并优于单取。

### 裁决 4：案例方法论从 survey['调研方式'] 提炼 — **agree（自动兜底 + glm 补自动兜底脚本建议）**

**用户裁决**：补 point 时从 survey['调研方式'] 提炼（自动兜底）。

**glm组 确认**：**agree——survey['调研方式'] 是方法论真正所在·提炼正确。**

**survey 结构（glm 实测确认）**：
- yichang_wangzhou survey 333 字——含调研方式（坝坝会/入户/线上问卷·glm 上轮已读望洲岗笔记）。
- shanghai_satisfaction survey 329 字——含调研方式（线上问卷+社区座谈+现场踏勘）。
- 即 survey 字段是**方法论 + 数据混合**（调研方式=方法论·数据=他城数值）。

**glm组 自动兜底建议（脚本辅助·非纯手工）**：
```python
# tools/extract_case_point.py（建议·从 survey 自动提取 point）
def extract_point(survey_text):
    # 规则：提取"调研方式"字段值（非"数据"字段）
    # 如 survey = "调研方式：坝坝会/入户... 数据：45,578 份..."
    # → point = "坝坝会/入户..."（剔除"数据："段）
    import re
    m = re.search(r'调研方式[：:](.*?)(?:数据[：:]|$)', survey_text, re.S)
    return m.group(1).strip()[:40] if m else ''
```
- 自动兜底：5 案例 survey → 自动提取调研方式 → 人工审 ≤40 字。
- **禁纯手工**（5 案例可手·但未来扩案例时自动兜底更稳）。

**glm组 提醒**：
- survey['调研方式'] 是 dict（非字符串）——claude 实测确认。自动提取须按 dict key（如 `survey.get('调研方式','')`）。
- 提炼后**人工审**（自动提取可能含"详见 xx 文件"等非方法论表述）。

### 裁决 5：黄金集 3 类合并 — **agree（设计确认 + 越维刚性建议）**

**用户裁决**：黄金集合并 3 类（正确召回 + 越维降级 + 案例不引数据·召回率 ≥80% + 越维/案例 100%）。

**glm组 确认**：**agree——3 类合并正确（glm CB-22 颗粒度对齐已提）+ 强化"越维/案例 100% 刚性"。**

**黄金集设计（glm 确认 + 细化）**：

| 类别 | 查询数 | 判据 | 刚性 |
|---|---|---|---|
| **正确召回** | 10-15 | Top-K 含黄金答案（召回率 ≥80%） | **软指标**（≥80% 达标·允许优化） |
| **越维降级** | 3-5 | 数据到社区·问"哪栋" → 回答含"无法到栋"声明 | **刚性 100%**（不容错·越维臆造 = 演示失败） |
| **案例不引数据** | 3-5 | 问"宜昌 X" → Top-K 不含他城数据（如南京 87.65 分） | **刚性 100%**（不容错·张冠李戴 = 失信） |

**glm组 关键建议（越维/案例刚性·非软指标）**：
- 召回率 ≥80% 是**软指标**（RAG 质量可优化·80% 够用）。
- 但**越维降级 + 案例不引数据 = 刚性 100%**（原则红线·不容错）。
- 即黄金集断言：
  ```python
  assert recall_rate >= 0.8  # 软指标
  assert dimension_violation_rate == 0.0  # 刚性（越维臆造）
  assert case_data_misuse_rate == 0.0  # 刚性（张冠李戴）
  ```
- **理由**：召回率低（如"葛洲坝"没命中）是"不够好"·越维/案例错是"原则违反"——后者必须零容忍。
