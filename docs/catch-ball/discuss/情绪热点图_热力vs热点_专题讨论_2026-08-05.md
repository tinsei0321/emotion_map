## 〇、执行摘要（结论先行）

**核心命题**：用户要的「城市情绪·舆情热度·类似情绪评论的高程/地势感」的图，在 GIS 专业语境中的正名 = **热力图（核密度分析 KDE）**——连续密度曲面。它与「**热点分析（Getis-Ord Gi\*）**」是**两个物种**：一个是描述性密度可视化，一个是推断性显著性检验。当前项目把两者都做了，但**语义错位**：名为「情绪热点(Gi*)」的工具表达的是显著聚集（推断），不是用户要的"舆情热度地势"（描述）。

**现状三轨（2026-08-05 代码实查）**：

| 轨道 | 端点 | 核心逻辑 | 渲染 | 业界归属 |
|---|---|---|---|---|
| 情绪地形 | `/spatial/terrain` | `create_terrain_mesh`（core/spatial_analysis.py）：KDE（带宽 250m·栅格 60m）等值面→分层 fill-extrusion；高度=密度×强度、颜色=区域极性 | `frontend/js/heatmap-tool.js` runTerrain | **热力图（KDE）** |
| 情绪热点 | `/geo/hotspot` | `hot_spot_analysis`（core/spatial_analysis.py F_001）：esda G_Local + KNN k=8 → **逐点** Gi* Z → hot/cold/ns | `frontend/js/toolbox/hotspot-tool.js`：纯程序化无 UI；class→极性重映射 hot=Very Negative 红 / cold=Very Positive 绿 / ns=灰 | **热点分析（Gi\*）** |
| 热力图 | — | `heatmap-tool.js` 实际**委托 runTerrain**（与地形同款 KDE mesh）；`ai_qa/tool_contracts.py` 中 density=连续密度面（彩虹色带语义） | — | **热力图（KDE）** |

**错位点**：
1. 用户要的「舆情热度·地势感」= KDE 热力面（情绪地形已在做），而当前名为「情绪热点」的 Gi* 工具是显著性检验——**名字与诉求错位**；
2. Gi* 当前是**逐点**输入（原始评论点 + score），业界惯例是**网格聚合后做 Gi\***（降噪、有单元语义）；逐点 Gi* 结果受点密度/噪声影响大，效果"不太对"的主因候选；
3. Gi* 的 hot/cold → 红(负)/绿(正) 是**产品层自造映射**：Gi* 的 hot 只代表"高值聚集"，与"负面情绪"无天然对应——语义可商榷。

**待拍板**：「情绪热点图」最终定位 = KDE 热力面 / Gi* 热点 / 双图层叠加（详见第四节焦点问题）。

## 一、概念基座：热力 vs 热点（客观论述）

### 1.1 术语界定（GIS 专业语境）

| | **热力图（Heatmap）** | **热点分析（Hot Spot Analysis）** |
|---|---|---|
| 学名 | **核密度分析（Kernel Density Estimation, KDE）** | **Getis-Ord Gi\*** 局域空间统计 |
| 本质 | 密度**可视化**（描述性） | 显著性**检验**（推断性） |
| 回答 | "哪里密集/稀疏"（连续强度） | "高值/低值在哪发生**显著**聚类？置信度多高？" |
| 输出 | 连续平滑密度曲面（像地形/高程） | 每要素 z 分数 + p 值 + hot/cold/ns 分级 |
| 依赖 | 点的位置（可选权重） | 位置 + **数值字段**（如情绪得分） |
| 业界工具 | ArcGIS「核密度分析」/ QGIS Heatmap 插件 | ArcGIS「热点分析 (Gi\*)」/ QGIS Spatial Statistics |
| 显著性 | 无 | 有（z/p/置信度 90/95/99%） |
| 产品例 | 微博热度图、打车热力图、百度迁徙 | 犯罪热点（警力配置）、疾病聚集、POI 零售中心识别 |

> ⚠️ **术语陷阱（正是本项目困惑来源）**：中文互联网常把任何密度图叫"热点图"；QGIS 的 Heatmap 插件中文名也常被译作"热点地图"，但它的算法就是 **KDE**——此"热点"非彼"热点"。GIS 专业里"热点分析"特指 **Gi\* 显著性检验**。另有"点击热图"（Web 点击量）是 Web 分析概念，与 GIS 无关。三者勿混。

### 1.2 原理与公式区别（通俗）

**热力图（KDE）= 给每个评论"盖山包"**：每个数据点上方放一个核函数（通常是高斯钟形曲线），所有点的"钟"叠加成连续曲面，评论密的地方山高。

```
f(x) = (1/nh) Σᵢ K((x−xᵢ)/h)
K = 核函数（如高斯核）；h = 带宽（山包宽度，决定平滑度）
```

只描述"山高不高"，**不做统计判断**。

**热点分析（Gi\*）= 给每个要素"考统计"**：检验"该要素及其邻居的值，是否显著高于/低于全局期望"——偏离除以波动得 z 分数，按置信度分级。

```
Gi* = [Σⱼ wᵢⱼ xⱼ − X̄ Σⱼ wᵢⱼ] / [ S √((n Σⱼ wᵢⱼ² − (Σⱼ wᵢⱼ)²)/(n−1)) ]
xⱼ = 邻域要素值；wᵢⱼ = 空间权重（距离/邻接）；X̄ = 全局均值；S = 全局标准差
```

是**推断**："聚集是随机的还是真的？有多可信？"

**一句话**：热力画"山高不高"，热点标"这座山高得反常吗"。

### 1.3 业界做法（已核实 · 出处标注）

| 来源 | 要点 |
|---|---|
| ArcGIS 官方文档（热点分析 Gi* 工作原理） | "对每一个要素计算 Gi* 统计，通过 z 得分和 p 值知道**高值或低值要素在空间上发生聚类**的位置" |
| ArcGIS 密度分析 | 密度分析 = 点密度/线密度/**核密度**三种——核密度即热力图 |
| QGIS | "热点地图(Heatmap)"课程/工具实际实现 = **核密度分析 Kernel Density**（术语混淆的现实例证） |
| 学术：基于 POI 大数据的城市零售业空间热点分析（经济地理 2018） | **KDE 核密度分布图（连续面）+ 局域 Getis-Ord Gi\*（显著性）两者并用**——"KDE 识别显著高于周围栅格的中心区域，再以 Gi* 定量验证局部空间相关性" |
| 学术：POI 分布热点分析的网络核密度估计（测绘学报） | 基于路网距离的 KDE 用于热点密度确定 |
| r/gis 社区共识 | "KDE 比较主观（数值背后没有硬性统计）；热点分析比较客观（有显著性检验）" |

**结论**：学术与产品通行做法 = **KDE 热力面打底（连续密度·张力） + Gi\* 热点验证（显著性·定位关注区）双图层**——这正对应情绪地图演示逻辑链的「表现力环 + 有用性环」。

## 二、现状诊断（claude组 实查 · 待独立核实）

### 2.1 三轨实现细节

| 轨道 | 关键文件 | 实现要点 |
|---|---|---|
| 情绪地形（KDE 热力面） | `core/spatial_analysis.py` create_terrain_mesh · `api/routes.py:309` · `frontend/js/heatmap-tool.js` | 高斯带宽 250m、栅格 60m；高度=`_level`（密度×强度）、颜色=`_norm`（区域极性 terrain-9）；EMC density 技能委托此端点（`frontend/js/heatmap-tool.js:826-877`） |
| 情绪热点（Gi*） | `core/spatial_analysis.py` hot_spot_analysis（F_001）· `api/geo_routes.py:657` · `frontend/js/toolbox/hotspot-tool.js` | esda G_Local + KNN k=8 权重（无岛屿）；逐点输入 + value_col='score' + invert；输出点层 + Gi_Z/hotspot 分类；纯程序化入口 generateHotspotForAI（无 dialog/UI）；class→极性重映射（hot=Very Negative 红 / cold=Very Positive 绿 / ns=灰），复用离散 5 色极性色带 |
| 契约层 | `ai_qa/tool_contracts.py:31-34,260-266` · `ai_qa/paradigm.py:301-315` | 已明确区分：density=连续密度面（彩虹色带·宏观）；hotspot=逐点 Gi* 冷热点（微观）——**契约本身正确，执行与命名错位** |

### 2.2 已确认的问题（候选根因）

1. **命名/语义错位**：「情绪热点(Gi*)」≠ 用户要的"舆情热度地势"（KDE）。Toolbox 里没有面向用户的 KDE 热力入口（热力=地形=同一端点，用户感知上只有"热点"没有"热力"）。
2. **逐点 Gi\* 噪声**：逐点 Gi* 对点密度敏感（点少的区域 z 波动大），且每个原始评论点是"一个样本"——业界惯例是先网格聚合（每格一个值）再 Gi*。这可能就是"逻辑和效果都不太对"的技术根因。
3. **hot/cold 极性映射是自造语义**：Gi* 只检验"高值/低值聚集"。把 hot 映射为"Very Negative 红"需要前提：score 高=负。invert=true 即为此服务——但 Gi* 的 hot 与"负面"之间隔着"score 的语义"，讨论时须明确。
4. **无 UI 入口**：hotspot 纯程序化（EMC 委托），Toolbox 无按钮——用户（业内同行演示）点不到它。

### 2.3 已排除的（不用重做的部分）

- 情绪地形（KDE mesh）本身的方向是对的（=热力图）——重做不是推翻地形，是厘清边界与命名；
- EMC density 委托链（dumb tool 复用 Toolbox）正确，不推倒。

## 三、焦点问题（待 claude组 / Codex / glm组 三方讨论收敛）

### 焦点 1（最高优先）：「情绪热点图」的最终定位

用户诉求 = 舆情热度 + 高程/地势感。三方案：

| 方案 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| **A. KDE 热力面** | 「情绪热点图」= KDE 连续密度面（现有地形升级/改名），Gi* 降级为 EMC 专用 | 语义正中用户诉求；表现力（张力/地势）最强；业界舆情产品一致 | Gi* 的"定位关注区"价值被弱化 |
| **B. Gi* 热点** | 保留逐点 Gi*（修正为网格聚合），作为"情绪热点图"主图 | 显著聚集=可辩护的"关注区"（对规划决策有用） | 不是连续地势感，与用户描述不符；微观尺度 |
| **C. 双图层** | KDE 热力面打底（舆情热度）+ Gi* 热点标注（显著聚集） | 学术业界通行做法；表现力+有用性双全 | 实现工作量最大；前端图层叠加管理 |

**初步倾向**：C（双图层）——符合业界惯例与演示逻辑链，但 MVP 可从 A 起步、B 叠加。**请两组独立评估。**

### 焦点 2：Gi\* 的输入粒度（若保留）

当前逐点输入。业界惯例 = 网格聚合后 Gi*（复用 `/geo/grid_pois` 或 zonal 单元，每单元一个极性值 → Gi*）。请评估：
- 逐点 vs 网格聚合 Gi* 对本项目数据的适用性（评论点密度不均、宜昌范围）；
- 网格粒度建议（50-100m / 500m 对齐 tool_contracts 的 density mode=3d 语义？）；
- KNN k=8 vs ArcGIS 距离带权重的差异风险（当前注释已注明 KNN 防岛屿）。

### 焦点 3：Gi\* 的 hot/cold → 极性色映射是否成立

当前 hot=Very Negative 红 / cold=Very Positive 绿 / ns=灰。请评估：
- Gi* 检验的是"score 高/低聚集"——把 hot 解释为"负面热点"需 score=负向得分（invert=true）。这个语义链是否站得住？
- 若焦点 1 走 C（双图层），KDE 层已表达极性颜色（_norm terrain-9），Gi* 层应表达"显著性"而非重复极性色——两层的视觉语义如何分工？

### 焦点 4：命名与契约统一

当前「热力图/情绪地形/情绪热点」三轨命名混乱（热力=地形=同端点；热点=Gi*）。请评估统一方案：
- 面向用户（Toolbox/演示）的命名建议；
- `ai_qa/tool_contracts.py` + `ai_qa/paradigm.py` 的 density/hotspot 契约描述是否需同步调整；
- EMC 委托链是否需调整（generateHeatmap/Grid/TerrainForAI 与 hotspot 的边界）。
