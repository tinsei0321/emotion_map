## 一、复核①两大核心裁决

### 1.1 P2/P3 对调（内容先行·重排序条件触发）——**复核成立·吸收**

| 研判论据 | 本组复核 |
|---|---|
| 基线 9/10（office 实测） | **家机复跑一致**：`py tools/rag_eval.py --k 5` → 召回 9/10=90%（目标 ≥80% 软指标）·越维 2/2·案例 2/2·`[OK] 黄金集整体通过`。双机同数本身即证据（索引为各机本地产物·独立构建出同结果=可复现） |
| R43 绕插座 = 覆盖缺货非排序失准 | 台账 R43 原文核过（「观察=fs 宿主直读文件绕 rag_query」）。行为学判读成立：货在但排乱时宿主的行为是反复调 rag_query 翻页，不是弃用 |
| 90%>80% 软目标·排序尚非最痛失败模式 | 成立。600+ 条后候选拥挤、精排边际收益才放大——规模驱动逻辑对 |
| 触发条件写死可证伪 | 成立（内容+BM25 后 Recall@5<95% 或精确名词类未全对 → 重启） |

**本组补强证据（研判未用）**：当前唯一未命中题「葛洲坝片区体检有什么问题」的失败模式 = Top-5 全被更新域 fact 占据（fact×1.2 权重副作用 + 精确词无专路）。这个失败模式**泳道②的 BM25 + 权重可观测化即可解**，与重排序无关——即「当前实际观测到的失败模式恰好落在对调后先做的那一半」，顺序对调不是理论推演而是打在实测痛点上。

### 1.2 「重排序不违笨中间」——**复核成立·吸收（附 4 条护栏）**

内核判读（本组为该内核的沉淀方·把关视角）：铁律原文禁的是「内嵌 **LLM 推理**」「**动态决策**」——判据是**不确定性/不可测/失控**，不是「含神经网络权重」。cross-encoder 重排序器是**固定权重确定性打分函数**（输入问句+候选 → 输出分数·不生成·不决策·不进循环），与检索层里已在跑的 BGE embedding **同类同性质**——embedding 也是神经网络，若 embedding 合规则 reranker 合规。zcode 判读正确。

**护栏 4 条（建议写入 P2 重启任务书·防实施走样）**：
1. **纯打分不进控制流**：reranker 只产出分数，禁触发再检索/自适应策略/任何分支决策——管线恒为「召回→融合→精排→取 Top-K」机械接线；
2. **零 LLM API·零 token 生成**：仅本地 CrossEncoder（`sentence_transformers` 复用·不新增 FlagEmbedding——研判已裁·本组同意）；
3. **可关路径同受回归覆盖**：`rerank=False` 降级路径必须同样跑黄金集（防「关掉后更差没人知道」）；
4. **模型版本入档**：reranker 模型名+版本写进 build meta（沿 `embedding_model` 字段先例）·换模型视同破坏性变更=全量重建+黄金集回归。

### 3.2 v1 需修的三处（本组新发现）

**修-1 · P0-3 门禁「断言动态化」会开门即红（设计缺陷）**
「断言从 GOLD_SET 动态算期望」若= 逐条满分期望，则门禁从 P0 起就红：现状 9/10（1 条真实挂）+ P0 扩容刻意加入的精确名词类新题（BM25 落地前必挂）→ 红灯持续到泳道②完成。**开门即红的门禁会被绕过（红旗疲劳）·毁掉 P0 本义**。
修法：门禁断言=**对 `docs/rag-baseline.md` 入档基线零退化**（P0-2 产出的基线文件→测试读文件比较）+ 刚性判据（越维/案例）100% 动态计数；**满分断言留给收口批总验收**（计划 §三收口「黄金集扩容后全绿」与此正交·正好分层）。

**修-2 · 泳道②验收是动靶（①②并行的度量学问题）**
①持续入新条目、②改检索算法·同一索引上「Recall@5 ≥ 基线+10pp」在语料膨胀中测不准（基线是 364 条时测的·验收时可能已 500 条）。
修法：**双层验收**——开发期给 eval 加 `--index <dir>` 参数指向 P0 时点索引快照（`DATA/rag_index` 拷贝·冻结语料）测增量归因；①②合流后重建索引重测回归（收口批总验收本有此位·补一句「泳道②验收数字须标注测量语料时点」）。

**修-3 · 泳道③白名单跨泳道缺口（互斥表自违）**
E-3 体验件落点：X1 四徽标 = `tools/rag_index.py`（search 结果加字段——②段）；X2 低置信标志 = `api/aiqa_routes.py`（顶层字段）；X3 guidance = `tools/mcp_server_emc.py`。三文件现均**只列在泳道②白名单**——③按文执行即越权。两泳道同属本组且时序错开·实际冲突为零·但表必须自洽。
修法：泳道③白名单补三文件·注「②收口后独占」。
**附带利好（grep 实证）**：`api/aiqa_routes.py:129` 原样透传 `results[]`——X1 只需 `search()` 结果 dict 加字段，**路由零改动即自动达前端 payload**（前端冻结不渲染新字段·符合 X1「仅后端与 MCP」定位·无碍）。
