## V8 · 整体执行序 — agree（依赖链确认 + 2 风险）

```
P0-1 豁免记录 → P0-3 先扩 eval（前提）→ P0-2 diagnose 加类（eval gate）→ P0-4 加速器 + P0-5 合流（同批验证）→ P1 概念库 → P2 防回归 → P3 出处 → P4 双轨基线 → P5 边界标注
```

**依赖确认**：
- ✅ P0-3 eval 复采是 P0-2 前提（**先扩 eval 再改 prompt**·豁免条件 2）·eval 不过则回滚（豁免 gate·**实施窗口内 eval 是 gate 非并行**）
- ✅ P0-5 合流依赖 P0-2（枚举）·P1-2 重建索引依赖 P1-1（素材先建）·P2-3 依赖 P0-5 ·P3-3 依赖 P3-1
- ⚠️ **风险 1**：P0-4（加速器）与 P0-5（合流）双入口**同批验证**（两入口走同一 `_assembleKnowledgeQA`·防行为分叉）
- ⚠️ **风险 2**：P0-2 改 diagnose 后·**模板命中 gate 0.6**（`harness.js:92-105`）可能受影响（新增类改变 Flash 模板选择分布）——eval 复采须含 gate 检查（定稿验证第 1 条已列 ✓）
- ✅ P0-6 暂缓（用户拍板·flash 保持）·路径跑顺后复审——agree
