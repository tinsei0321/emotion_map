## 一、逐项核对

### 1. 三层定稿 4,800/42,871 的 9 归并类构成是否正确（建议类是否误入）？

**结论：agree（构成正确）+ disagree（"建议类混入"判断不成立）——矛盾 2 是误读**

「建议-交通出行」的"建议-"是**事件-领域类命名前缀（该类主导事件型）**，不是行级事件类型。实测该类安全 1,681 件的事件类型构成：

| 事件类型 | 件数 |
|---|---|
| 投诉 | 1,518 |
| 求助 | 163 |
| **建议** | **0** |

**建议类零混入**。类内混合证据（`12345_问题详表_12类.md`：交通设施类 9,145 件 = 投诉 5,716(62.5%) + 建议 1,471 + 求助 1,958）：一个"投诉占 62.5%"的类被命名为"建议-"，正是命名字段与行级字段撞词导致的误读源。9 类命名映射：投诉-物业管理 10,557 = 住房+物业管理两项目类型合并；投诉-安全隐患 5,194 = 城市更新+安全消防合并；投诉-街道环境 3,473 = 施工管理+街面秩序合并。

### 2. board 直切 48,123（安全 5,005/民生 43,118）实测是否可复现？

**结论：agree（完全可复现）**

`诉求类型_归∈{投诉,求助}` × `board` 直切（无其他条件）：
- 安全 5,005 = 投诉 4,601 + 求助 404
- 民生 43,118 = 投诉 42,255 + 求助 863
- 合计 48,123（另有 board=其他 22 件，投诉 14+求助 8，Codex 未计——正确，因它不属于两板块）

### 3. 452 差异的根因（矛盾 499 + 建议类归位？）

**结论：partial——根因是矛盾/社会排除（452），与建议类无关**

- 大类_归=矛盾纠纷 250 + 社会治理 249 = 499 件，其中**投诉型 449 + 求助型 3 = 452 件**（咨询 42+建议 5 = 47 件本就不在"投诉+求助"内）
- 三层定稿口径（表头已写明「投诉+求助（排除矛盾纠纷/社会治理 499）」）剔除这 452 件（board 分布：安全 205/民生 247）→ 恰为 5,005−4,800=205、43,118−42,871=247、合计 452。**逐数闭合，无残差**
- **矛盾 1 的 22 件残差同时定位**：三层定稿分子 47,693 = 投诉+求助 & 非矛盾/社会（含 board=其他 22 件，全部在求助-公共服务类：投诉 14+求助 8）；而 4,800+42,871=47,671 是再叠加 board∈两板块。22 = 47,693 − 47,671，即"进了分子、不进两板块"的 board 其他行——**不是随机生成残差，是口径层级差**，建议文档按此改注

### 4. 数据层应保留哪套口径作权威？

**结论：保留三层定稿（47,693/4,800/42,871/83.3%），即"方案 C：不改口径、修文档"——方案 A/B 均不推荐**

- **反对方案 B（剔建议类重定数）**：前提不成立——口径内建议类实测 0 件，剔 1,681 = 错删 1,681 件投诉+求助
- **不推荐方案 A（切 board 直切 84.0%）**：① 用户 2026-08-13 已定稿 83.3%，page2/PPT/Excel 已按此制作；② board 对矛盾类按问题主题归类（环境污染纠纷→民生、堡坎纠纷→安全），纠纷调解类计入"两板块"语义勉强，排除更符合"急难愁盼城市更新问题"定义；③ 三层定稿全部数字本次实测**精确复现**（9 类×3 列全对，见附录），数据本身无错
- **四处硬伤的正确归因**：不是数据错误，是**文档缺三处口径注解**（见二）

## 二、审计新发现（文档缺陷·建议 Codex 修文档而非改数）

1. **类名前缀无注解（矛盾 2 之根因）**：9 类「求助-/建议-/投诉-」前缀未注明"主导事件型命名、非行级事件类型"，本次连主开发都误读，必须在三层表/问题详表/page2 表D 加注
2. **总览"其他 9,572"构成注算术错误**：「咨询 6,856+建议 2,206+矛盾 499+表扬/其它 58」= 9,619 ≠ 9,572，超 47（矛盾类中咨询 42+建议 5 被双算）。正确构成 = 非投诉求助 9,120 + 矛盾类投诉求助 452 = 9,572
3. **22 件残差注不准确**：page2 表B/表D 脚注写"生成残差"，实为"求助-公共服务类中 board=其他的 22 件计入分子 47,693、不进两板块 4,800/42,871"，应按口径层级差改注
4. **口径公式未展开**：三层定稿完整口径 = `诉求类型_归∈{投诉,求助} AND 大类_归∉{矛盾纠纷,社会治理}`，建议在三层表头写全公式（现在只写了文字描述）

## 三、矛盾 4（page4/page6 口径链）修复口径（供 Codex 执行参考）

## 四、总结论

**三层定稿数据层无硬伤，全表精确复现；Codex 四处"硬伤"实为一处误读（矛盾 2）+ 两处已知口径层级差被误标为残差（矛盾 1/3）+ 一处真实的口径链混接（矛盾 4，需按三层定稿同链修复）。建议维持 83.3% 口径，修 4 处文档注解 + 两条页面口径链，不改任何数据。**
