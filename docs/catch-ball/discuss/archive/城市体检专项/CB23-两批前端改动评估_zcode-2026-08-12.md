## 批1·12345投诉点L1强度分析

### 要点1：preferConfidence 语义——对L2数据有无误伤？

**结论：agree ✅（无误伤·调用范围严格隔离）**

**证据**：
- `range-presets.js:92`：`detectColorMode(fc, item.l1 ? { preferConfidence: true } : {})` —— **仅 l1 标记的 preset 项传入 preferConfidence**
- `import.js:633`：`const polKey = opts.preferConfidence ? null : findKeyByRole(sample, 'polarity')` —— preferConfidence 时跳过 polarity 检测→强制走 confidence 分支
- **main.js 导入路径不传 opts**（`detectColorMode(fc)` 无第二参数）→ 所有用户手动导入的 L2 数据不受影响 ✅
- **隔离边界清晰**：preferConfidence 仅在 `range-presets.js` 的 preset 加载路径生效·main.js 导入路径永不触发 ✅

### 要点2：L1极性过滤实现——与L2路径隔离？

**结论：agree ✅（完全隔离·双路径不交叉）**

**证据**（heatmap-tool.js 三层隔离）：

| 层 | L2路径 | L1路径 | 隔离 |
|---|---|---|---|
| resolveSource（L848） | `level === 'L2' ? _POL_LETTER[polarity] : null` → group内拆子层 | `null` → 返回完整fc（不拆子层） | ✅ |
| filterFc（L850） | `level === 'L2' ? polarity : null` → _POL_MAP极性筛 | `null` → 不筛（跳过L2过滤） | ✅ |
| L1独立过滤（L723-728） | 不执行（`level !== 'L2'` 条件排除） | `P/N/O/NO` 映射→独立过滤 | ✅ |

**L1极性映射验证**：
```javascript
{ P: ['Positive','Very Positive'],      // 积极
  N: ['Negative','Very Negative'],      // 消极
  O: ['Neutral'],                       // 中性
  NO: ['Neutral','Negative','Very Negative'] }  // 中性+消极（去积极）
```
- 映射逻辑正确·NO=排除积极（Positive+Very Positive）保留其余 ✅
- L1 ramp 不变（橙色·深浅表达强度）·仅过滤点集·不改颜色体系 ✅

### 要点3：hm-subset「中性+消极」选项——L2时会否出现？

**结论：agree ✅（L2时hm-subset锁死ALL·NO选项不会出现）**

**证据**（heatmap-tool.js L466-476）：
```javascript
locked = level === 'L2' ? 'ALL' : null;  // L2锁ALL
if (locked) { sel.value = locked; sel.disabled = true; return; }  // 锁死+禁用
if (level !== 'L2') { allOn(); sel.disabled = false; return; }    // 非L2放开
```
- **L2路径**：hm-subset `disabled=true` + `value='ALL'` → 用户无法切换 → NO选项不触发 ✅
- **L1路径**：hm-subset `disabled=false` + `allOn()` → 全选项可用（含NO） ✅
- **无交叉风险**：L2锁死后下拉不可交互·即使HTML中有NO option也不会被选中 ✅

### 要点5：数据侧——l1_confidence=score 复制列

**结论：agree ✅（可接受·但中转版CSV未见l1_confidence列）**

**实测发现**：12345情绪地图中转版（57265行25列）中**无 `l1_confidence` 列**——有 `score`/`polarity`/`is_intense_flag` 但无 `l1_confidence`。

**推断**：`l1_confidence` 可能在 preset GeoJSON 生成时由 API/服务端添加（=score 的复制），不在中转版CSV中。如 detectColorMode 通过 `findKeyByRole(sample, 'confidence')` 查找——如果 preset GeoJSON 的 properties 含 `l1_confidence` 则命中 confidence 分支。

**建议**：claude 确认 preset GeoJSON 的 properties 中是否含 `l1_confidence` 字段（API manifest 层添加）。如果不含·则 detectColorMode 的 confidence 分支不会被命中（polKey=null 后走 needsAnalysis 灰点）——这将导致 12345 点层变灰而非橙色L1。

## 批2·range组放开钉底

### 要点4：range组放开钉底的副作用

**结论：partial ⚠️（reorderGroupSegment允许拖·但applyGroupOrder的PINNED可能重置）**

**证据**：

**reorderGroupSegment（state.js L987-989）**：
```javascript
if (fromCat === 'ai') return;  // ai恒钉最末·range可拖
```
→ range 可以被拖动到其他分类位置 ✅

**但 applyGroupOrder（state.js L960）**：
```javascript
const PINNED = ['range', 'ai'];  // ← range 仍在PINNED中
```
→ applyGroupOrder 执行时，range 仍被强制移到末尾（ai之前）

### ⚠️ 潜在冲突
- **reorderGroupSegment** 允许用户拖动 range 到其他位置（如 l2 数据上方）
- **applyGroupOrder** 下次执行时（如新增图层/切换可见性触发），会把 range **重置回末尾**
- 用户可能体验到"拖上去后又跳回来"

### 需claude确认
1. **applyGroupOrder 是否在 reorderGroupSegment 后立即调用**？如果 reorderGroupSegment 后不触发 applyGroupOrder → 用户拖动生效（直到下次 applyGroupOrder）
2. **PINNED 是否应改为 `['ai']`**（移除 range）？如果意图是 range 可自由拖动 → PINNED 不应含 range

### 建议
- **如果意图是 range 完全可拖**：将 `PINNED = ['range', 'ai']` 改为 `PINNED = ['ai']`，range 参与 _groupOrder 正常排序
- **如果意图是 range 可拖但有保底**（拖到中间但不在ai之后）：保持现状但标注"range拖动在下次render时可能重置"

### 其他副作用检查
- **z-order语义**：列表上→下=地图顶→底 ✅（range拖到上方=地图顶层=边界压分析图上面）
- **与其他分类互斥**：reorderGroupSegment 操作 _groupOrder 数组·不影响其他分类的内部排序 ✅
- **渲染冲突**：range 面层（polygon）在点层上方渲染·不影响点层热力图（不同图层类型） ✅
