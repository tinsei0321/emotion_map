## 〇 一句话结论

用**候选 A**（双高 → 问题指标高 → 诉求声量高），层内排序键 = **该层证据的量**（体检层/双高层按体检点降序、诉求层按诉求件数降序），并立一条口径纪律「**密度定资格、量定顺序**」；港务不设独立正榜，用「表尾任务量前五 + 三段式点名 + 诊断序/实施序讲解口径」三件套保住存在感——不加一个权重，也不让任何一轨消失。

## 一 总评

1. **用户四项原则是对的、可执行的**：优先级只落在「数据来源」维度（体检=客观定量硬指标 ＞ 12345=主观个人意志），方面（安全/民生）完全平等、体检和热线同覆盖两方面——这排除了「安全优先」或「方面加权」两条歧路，排序只剩一个自由变量（来源序），候选 A 就是该原则的无权重编码，无需更复杂结构。
2. **本轮 bug 根因 = 两个叠加**：① 层顺序「诉求声量高」排在「问题指标高」前面（与体检优先原则相反）；② 层内用「任务量=体检点+热线件」混加排序——热线件量纲约为体检点的 5 倍（5,717 件 vs 1,035 点），混加必然由热线主导，体检社区被压到层尾。**修这两处即解决问题，不需要任何权重。**
3. **已实测确认的后果（诚实交底）**：
   - 现行表「问题指标高」5 坑按任务量键，把**镇境山（体检 82 点·全口径第 4 多）与幸福路（65 点·第 5 多）直接挤出 TOP20**——这是现行键最不可辩护的一处，换键后两者必须回榜。
   - 港务诉求 417 件在「诉求声量高」层内也只是**第 3**（朝阳路 594、万达 501 在前）；且港务自身数据已从 sjoin 修复前的 1,153 件变为 417 件——「港务前 10」的原始语境一半已被数据更新消解。用户本轮接受其跌出前 10，是干净的了断。
4. **「诉求声量高」确实需要防误读机制**（Q3 答案：要标注，不要独立正榜——详见 2.3）。

**独立抽验（只读实测）**：体检矩阵总点数 深圳路 107 / 西峡 91 / 金安岭 84 / 镇境山 82 / 幸福路 65 / 新隆康路 62 / 果园路 51 / 桥北 37 ✓；12345 九类矩阵（安全+民生，剔除「其他」）全量 TOP12 = 朝阳路 594 / 万达 501 / 港务 417 / 建设 372 / 岳湾路 225 / 大学路 222 / 伍临路 221 / 张家湾 187 / 宝联 156 / 体育场路 136 / 枫香树 126 / 营盘路 117 ✓（宝联、营盘路已属双高层，诉求层前 10 与现表一致）；现表诉求层第 10-12 行（伍临路 221 → 大学路 222 → 岳湾路 225）**非件数降序**，排序键不透明，需查（见 P1-7）。

## 二 逐条建议（含具体排序规则）

### 2.1 Q1：排序结构 → 候选 A（附两条纪律）

**排序规则（全表一条链）**：

```
分层（资格·密度判定）：双高 → 问题指标高 → 诉求声量高 → 其余
层内（顺序·证据量降序）：
  双高 / 问题指标高 → 体检点降序
  诉求声量高       → 诉求件数降序
禁：任何混加（体检点+热线件）作排序键
```

- **为什么是 A 而不是 B**：A = 「体检＞12345」原则的直接编码（体检高的层整体在诉求层之上），一句话可讲：**「先看体检报警，再看群众呼声」**。两个 B 变体评估后不推荐：
  - B1「体检量全局主排（分层只作标注）」——丢了密度资格（大社区霸榜回归），也丢了已拍板的「双高/单轨」分层叙事，推倒重来成本高；
  - B2「问题指标榜 + 诉求声量榜并列两张榜」——弱化单一优先级主线，20 行变 40 行，违背「一眼懂」；留作备查附录形态，不进正页。
- **为什么混加是错的**：热线件 ~5 倍量纲于体检点，「任务量」混加让热线永远赢——这正是本轮把西峡/金安岭/果园路压到 16-20 名的机制。任务量只作**并列列**（实施口径），不作排序键。
- **「密度定资格、量定顺序」**：层资格由密度判定（防大社区霸榜的正确位置在门槛，p75 或拍板口径不变）；层内顺序用「量」（好讲解：「107 个隐患点第一」比「每百栋 150 点第一」直白，且小分母社区不会靠密度冲层内头部）。这条一句话写进表下图例，排序逻辑当场可辩护。

**重排预演（体检层取 8 坑示例·实测数字）**：

| 总序 | 层 | 社区（键值） |
|---|---|---|
| 1-5 | 双高（体检点降序） | 营盘路 37 → 宝联 29 → 汕头路 17 → 胜利四路 16 → 胜利二路 9 |
| 6-13 | 问题指标高（体检点降序） | 深圳路 107 → 西峡 91 → 金安岭 84 → 镇境山 82 → 幸福路 65 → 新隆康路 62 → 果园路 51 → 桥北 37 |
| 14+ | 诉求声量高（件数降序） | 朝阳路 594 → 万达 501 → **港务 417（总序≈16）** → 建设 372 → 岳湾路 225 → 大学路 222 → 伍临路 221 → 张家湾 187 → 体育场路 136 → 枫香树 126 |

### 2.2 Q2：层内排序键 → 体检量（点），不用密度

- **体检层/双高层用体检量（点）**：理由三条——① 资格已由密度把关，顺序再用密度=双重摊薄、且小分母噪声回到层内头部；② 好讲解（量=任务量直读）；③ 与「不加权重」精神一致（量就是原始计数，不加不减）。
- **不用体检密度作层内键**：密度是资格键不是顺序键；若用户更看重层内「严重度」，改用密度需同步恢复「楼栋<20 低置信标注」防线（现 TOP20 恰好已无 8 栋社区，是件数口径的红利，别丢）。
- 诉求层同理：按诉求件数降序（现表 10-12 行不单调，需修正，见 P1-7）。
- 密度保留为**并列列**（资格证据）；任务量保留为**并列列**（实施序）。

### 2.3 Q3：港务与「诉求声量高」的防误读 → 三件套，不设独立正榜

**结论：要标注，不要独立榜（PPT 正页）**。理由：独立正榜会与总榜抢焦点、单页行数翻倍；「诉求声量高」层的存在本身 + 三件套已足以传达「不是不重要，是证据类型不同」。

三件套（全部零权重）：

1. **表内层小标题带解释半句**：「③ 诉求声量高·12345 视角（体检未报警·10 个）」——把「为什么排在体检层之后」的答案写在小标题里，防误读的第一道也是最主要一道。
2. **表尾「任务量前五」小字行**：朝阳路 594 / 万达 501 / 港务 417 / 建设 372 / 岳湾路 225 件——港务以第 3 名出现，明确它在「实施序」里的分量。
3. **三段式②句点名**：「12345 热线显示，朝阳路、万达、港务等社区诉求声量居前（前三）……」，正文出现即存在感。

**讲解口径模板（给讲解人，也写进 md）**：「体检优先是**诊断序**——先排底线隐患；任务量是**实施序**——更新项目往诉求最密的地方落。港务 417 件在任务量榜第 3，是实施阶段最大的工作对象之一；它不在总榜前 10，是因为它的问题是『诉求型』不是『隐患型』，两条序各答各的问题。」（= CB-33「绝对量=任务量·强度=优先级」双列共识的叙述化。）

- 完整独立「诉求声量榜」放 **4' 分析报告附录**，不在 PPT 正页。
- 诚实附注：港务在诉求声量层内是第 3 不是第 1（朝阳路/万达在前），别写成「港务诉求第一」——表述错误会在答辩被抓。
