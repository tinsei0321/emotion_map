## 二、逐焦点评估

### 焦点 1 · 热点表达方案：Gi* vs 局部密度分位 vs 网格聚合计数

**结论：partial（三方案无一单独最优；主=加权聚合/密度·次=局部密度分位·Gi* 降为辅助显著性标注）**

**一句话证据**：体检数据是**普查型全覆盖摸排**（非抽样），Gi* 的零假设「空间随机分布+推断显著性」语义错位——126 点全 ns 已实锤，诚实 ns 图面零张力，破坏演示逻辑链第一环；而 EMC 已有加权 KDE 密度（`create_square_grid`·F_006·分位 levels 出张力）与 H3 六边形聚合（`create_hex_grid`·F_004），复用即达「强度集聚→关注区→排序」。

**展开论证**：
1. **Gi* 语义错位（承重论据）**：Gi* 为抽样推断设计（检验空间聚类显著性）；体检为普查型数据（每栋每小区全摸），显著性检验的信息量低——「42 栋结构隐患」本身就是普查结论，不需要推断「这 42 栋是否显著聚集」。用 Gi* 主图 = 把推断统计强加给普查数据，且输出「全 ns」时前端无张力。
2. **局部密度分位（dens_norm 先例）**：`sim_performance_data.py:437` 已用 `dens_norm`（局部密度归一化）驱动 `_spatial_confidence`——先例成立，是「无值字段/恒权」时的兜底表达。但纯密度丢失**量级差异**（两个社区各 5 点、缺口总量 13000 vs 20，密度图无差别）——不能作为唯一主图。
3. **加权聚合/密度（主方案）**：`density` 工具契约已支持 `weightField`（tool_contracts.py:32·默认 emotion_intensity）→ 体检轨传缺口数值列（停车泊/小学学/新能源…）即得「缺口强度集聚面」——张力图面 + 关注区定位 + 排序三合一，完全对齐演示逻辑链与宏观诊断；且描述性统计（聚合强度）天然守住「不精确归因」（不宣称统计显著）。
4. **网格聚合计数**：H3（F_004）与 `create_square_grid` 已实现 point_count/mean 聚合——可作「点位分布」次级表达，但纯计数同样丢失量级（同纯密度问题）。

**定稿建议（采纳进阶段 1'）**：
- 体检轨热点表达**主图 = 加权密度/聚合**：`density` 传 `weightField=<缺口数值列>`（停车/学位/充电桩）或「隐患栋数=1」权重（结构/燃气/围护等栋级层）；**实施注意**：`create_square_grid` 当前权重列硬编码 `emotion_intensity`（spatial_analysis.py:940 附近 `pts['emotion_intensity']`），需参数化 `weight_field`（含归一化规则：缺口值直接归一化·栋数恒 1）——小扩展，属适配器/工具改动，非新算法。
- **次级 = 局部密度分位**：无值字段层（如燃气 6 栋、乱停 4 路）用密度分位兜底（dens_norm 先例·诚实标注「相对集聚·非统计显著」）。
- **Gi* 保留为辅助显著性标注**：出图时附「样本量百级·无统计显著热点·以强度集聚表达关注区」诚实文案；不删除 hotspot 工具（情绪轨仍为主用），体检轨不复用为主图。
- **前端图例/文案**：密度图例用「强度」而非「显著」；报告观点表述「XX 区/街办缺口总量占比」「XX 组团集聚」——描述性语言，禁「显著热点」字样。

### 焦点 2 · 街办边界来源：高德 API / zcode 补 / 行政区拆分 + 社区 1682 过滤

**结论：partial（优先级 zcode 查源 > 高德 API > 自拆最劣；社区按 SSXZQH 过滤可行但须与体检 61 名单对齐）**

**一句话证据**：`admin_street` 文件缺失已实锤（manifest 声明但磁盘无 `街道.geojson`）；体检口径 16 街办（口径清单 #8）是官方工作口径，补源首选的**权威性排序**：zcode 源数据（3_gis 26 shp + 2 GDB）若有街办面层最权威零 API；高德街办边界为 GCJ-02 需逐顶点转 WGS84（项目红线 #2 的多边形版）；自拆无官方依据会造「假街办边界」。

**定稿建议（采纳进阶段 1'）**：
1. **补源优先级**：
   - **P0 zcode 查源**：请 zcode 在 `3_gis数据`（26 shp）与两个 GDB 中查街办/社区面层（`_INDEX.md` GDB1 9 图层 / GDB2 22 图层现无街办社区层，大概率没有，但必须先查——零成本零 API）；有则 zcode 转 WGS84 交付，口径与体检报告一致。
   - **P1 高德行政区划 API**（`/v3/config/district?keywords=<区>&subdistrict=3&extensions=all`·4 区 × 街办级）：AMAP_KEY 已在 `.env`；注意：① 返回边界为 GCJ-02 → 逐顶点 `gcj02_to_wgs84` 转换（新增 polygon 转换工具或复用点转换逐顶点）；② 高德街办=乡镇街办级，与体检「街办」基本对齐；③ 报告标注「街办边界来源：高德行政区划·演示口径」。
   - **P2 行政区拆分**：**不推荐**（无官方依据·造边界·除非报告明确标注「示意边界」）；不投入适配器设计。
2. **社区 1682 过滤**：按 `SSXZQH`（所属县市代码）4205 前缀 + 4 区代码（西陵/伍家/点军/猇亭）过滤 → 派生小层入库（87MB → 几十 KB）；**过滤结果须与体检 61 社区名单核对**（民政社区编码 ≠ 体检报告汇总口径——61 社区为体检口径·可能含归并/命名差异），以报告名单为准做交集并标注差异（守口径纪律）。
3. **manifest 漂移顺带修**：`DATA/boundaries/presets/manifest.json` 声明了不存在的 `街道.geojson/更新单元.geojson`——presets manifest 只登记实际存在文件或加 `missing` 标注，防 AI 问答误选（`list_presets` available 标记依赖文件存在）。

### 焦点 3 · hotspot 权重规范：质心点层必须带真实变化数值

**结论：agree（固化进适配器输出约束 + hot_spot_analysis 加常数守卫·通用修复）**

**一句话证据**：常数权重 → `G_Local` 方差 0 → Gi_Z=NaN 静默全 ns（claude 实测 RuntimeWarning 实锤）；`hot_spot_analysis`（spatial_analysis.py:85）`values.astype(float)` 无守卫——修复使**情绪轨上传层恒权同样受益**，非体检轨专属。

**定稿建议（采纳进阶段 1'）**：
1. **适配器输出约束（固化）**：每个质心派生层强制 `value` 列——映射规则：缺口类 = 缺口数值（停车泊/小学学/新能源/电动自）；栋级隐患类 = 恒 1（每栋=1 隐患单位·语义即「栋数集聚」）或 dscs/dcmj（若有强度语义）；覆盖率面 = 指标值本身；导出 schema 校验 `value.std() > 0`（非恒 1），校验失败显式报错防静默退化。
2. **hot_spot_analysis 常数守卫（通用）**：`value_col` 序列 `std == 0`（或 NaN 占比过高）时显式 `raise ValueError`（或 `trace_log` 告警 + 返回提示「常数权重无法做 Gi*」）——新追踪 ID **MOD_SPATIAL.F_010**（现有 F_001~F_009 + D_001~D_004·buffer_analysis F_005 已占·分配前 grep 确认）。
3. **权重≠解决显著性弱**：权重规范解决「静默 NaN」，不解决「百级样本显著性弱」——后者由焦点 1 主图方案（加权聚合/密度）承担；Gi* 仅在权重有真实梯度且 n 较大时作辅助。

### 焦点 4 · zonal 非情绪排序：加指标数值降序 fallback

**结论：agree + 补一条语义修正（须补 `{col}_sum`·mean 会颠倒总量口径）**

**一句话证据**：现有 fallback `polarity_index → point_count`（geo_routes.py:369-372）对体检轨退化为**按点数排序**（西陵 108 点恒第一）；而 CHK-I05 口径是**总量**（「西陵占约 70%」）——按 mean 会颠倒（伍家岗 18 点 mean 309.9 > 西陵 108 点 mean 162.8·总量则西陵 ~17580 > 伍家岗 ~5580），`aggregate_by_polygons` 现只产 `_mean/_std` 无 `_sum`。

**定稿建议（采纳进阶段 1'）**：
1. **zonal_stats 加显式 `sort_by`**（请求参数·如 `停车泊_sum`/`停车泊_mean`）；fallback 链 = `sort_by` → `polarity_index`（情绪轨）→ 首 agg_col 聚合列 → `point_count`；响应 `sort_by` 注明语义（总量/均值）。
2. **`aggregate_by_polygons` 补 `{col}_sum` 输出**（缺口规模排序用·总量口径）；适配器/报告默认按 **sum**（对齐 CHK-I05 总量占比），按 mean 场景显式传参并标注「单位缺口强度」。
3. **top_n 语义随排序**：按数值降序取前 N = 「关注区排序」（演示逻辑链第四环）——报告观点与图例一致（「西陵 108 点·缺口总量 ~1.76 万·占 76%」「伍家岗 18 点·均值 309.9·强度高但总量小」双口径并列·诚实不越维）。
4. **新函数追踪编号**：端点/聚合扩展若新增公开函数（如 `sort_zonal_rows`）→ MOD_SPATIAL.F_011 起 / api 层按现有规则（grep 最大 +1）。
