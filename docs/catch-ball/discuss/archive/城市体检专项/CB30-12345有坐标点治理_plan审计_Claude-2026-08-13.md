## 二 逐焦点

### 焦点 1：三大类事件定义是否合理？

**结论：partial（方向对·两处需修）**

一句话证据：现有诉求类型_归列（投诉 46,870/咨询 6,856/建议 2,206/求助 1,275/表扬 6/其它 2）已治理完成，无需引入 polarity 重判；用户定稿口径是"3 类事件（投诉、建议、求助）"，其中求助已含咨询（求助+咨询合计 8,131·14.2%）。

定稿建议：
1. **不引入 polarity 判投诉**——Plan 表里"投诉（polarity Very Negative/Negative）"是两套轴混淆（polarity 是情绪分析列·与事件类型不同轴）。直接用诉求类型_归列：投诉=诉求类型_归=投诉；求助=诉求类型_归∈{求助,咨询}；建议=建议。
2. **"其他"不列为第四大类**——用户定稿叙事是"3 类事件落图"（page4/page6 开篇），表扬+其它 58 件作口径注单列（不计入三大类），与三层定稿口径（其他 9,572 含表扬 58）一致。

### 焦点 2：9 类映射闭合正确？

**结论：agree（实测全部闭合 ✅）+ 1 处命名对齐**

一句话证据：实测五类民生归并 = 14,797+7,359+11,452+6,981+8,603 = 49,192 ✅；安全四类 = 4,249+2,895+687+215 = 8,046 ✅；跨板块拆分（交通 2,895+6,277=9,172 / 管网 4,249+704=4,953 / 环境 215+3,365=3,580）与归并类实测一致。

定稿建议：9 类命名与用户 page6 五类定稿对齐——Plan 用"噪声扰民/停车问题/住宅问题/出行问题/物业管理问题"，用户定稿是"噪声/停车/住宅/出行/物业"（page6 五类归并已定稿）。建议表内统一用用户定稿名（括注 project_type 归并），防跨文档命名漂移。

### 焦点 3：region 区质心 6,923 算不算可落图？

**结论：disagree Plan 的处理（必须三级分级·P0）**

一句话证据：region = 区级质心兜底坐标（非真实诉求位置）——直接进社区/村 sjoin 会把 6,923 条诉求**全部错配到区质心所在的 1-2 个社区**，产生虚假聚集社区，破坏 top10 表与打点图的真实性。

定稿建议（三级分级）：
- **ok（11,207）** = 可落图 → 参与社区/村 sjoin、打点图、top 表；
- **region（6,923）** = 仅区级可落 → 只做区级分布统计（"西陵区 X 条"式），**不参与社区/村统计**，打点图可选弱化呈现（区质心标记）；
- **miss（39,135）** = 不可落图 → 仅全量口径。
- 与既有 page4/page6 口径链的关系：此前"命中 1,376/7,340"是 high+medium 精确点位口径（已排除 region）——新 Plan 若改用 ok 全量 11,207，口径链数字会变，需在 page4/page6 一并更新并注清新旧口径关系。

### 焦点 4：社区/村分别统计口径是否正确？

**结论：partial（基本正确·补 2 条规则）**

一句话证据：174 社区面 + 18 村面 sjoin 是既有成熟做法（page4 曾用·"城市优先去重"），但 Plan 未写两点关键规则。

定稿建议：
1. **重叠去重规则**：村面与社区面边界可能重叠 → 先 sjoin 社区（优先）再 sjoin 村，落双面的点按"城市社区优先"去重（page4 既有规则·写入 Plan）；
2. **县市点处置**：18,130 有坐标点含 12 个县区（夷陵/当阳/点军/猇亭等·非 174 社区+18 村覆盖范围）——这些点不命中任何社区/村，应单独统计"县市分布"（区级），不得静默丢弃或强配。Plan 需补一条"中心城区外点 → 区级统计"。

### 焦点 5：全局同步范围是否完整？

**结论：partial（补 3 项）**

一句话证据：Plan 列了中转站补列 + DATA 点数据/Excel/md，但缺治理可复现性、版本登记、与既有口径文档的衔接说明。

定稿建议补充：

2. **manifest 版本 bump**（中转站 1.5.x → 1.6.x·登记新列与点数据文件）；
