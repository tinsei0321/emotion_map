## 一 总评

1. **候选 A 是「数据来源可信度」唯一的无权重编码，三方共识、无异议。** 优先级只落在来源轴（体检=客观实测 ＞ 12345=主观意志），安全/民生等权、双轨同覆盖——这把排序压成一个自由变量（来源序），候选 A 即该原则的字典序（=按字母顺序逐键比较，先比第一键再比第二键）实现，无需更复杂结构。任何加权分都是把"好讲的分层"换成"要解释参数的黑箱"，一致否决。

2. **本轮 bug 根因 = 两个叠加（与 dsh 一致）**：① 层序把「诉求声量高」排在「问题指标高」之前，与体检优先相反；② 层内用「任务量 = 体检点 + 热线件」混加排序——热线件量纲约为体检点的 5 倍（全量约 5,717 件 vs 1,035 点），混加必然由热线主导，体检社区被压到层尾。**改这两处即解决，不需要任何权重。**

3. **claude组对「量 vs 密度」之争的裁定——这是本评估的核心增量，结论：层内用绝对量，且给出 dsh 未触及的承重级理由。** zcode 主张体检层强制按原始密度（理由：金安岭 56 栋小分母，按量掉到第 3、按任务量垫底第 10，"全场最密社区在自己层里排末位 = 打脸客观优先"）。**这条推理有一个被放大的等式错了：把"客观优先"等同于"客观层内某社区必须第一"。** 正确的理解是——**客观优先 = 层序**（体检层整体排在诉求层之前），层内谁第一是次要的局部顺序。金安岭按量排体检层第 3、总序约第 8，仍在 TOP10、仍带「客观隐患高」标签，**客观优先原则毫发无损**。zcode 把"层内第一"绑死到"客观优先"，是把层间原则错套到层内顺序的过度推论。基于此修正，体检层内用绝对量（量）而非密度，有四条独立理由（见 2.2）。

## 二 逐条建议（含具体排序规则）

### 2.1 Q1 排序结构 → 候选 A（字典序两键·附辩护）

**排序规则（全表一条链·零权重·两键）**：

```
第 1 键  数据来源层（资格·密度/EB 判定）：双高 → 体检高 → 诉求高 → 其余
第 2 键  层内顺序（见 2.2，极简两键）
禁：任何"任务量 = 体检点 + 热线件"混加作排序键（热线量纲 5× 体检，混加 = 热线主导 = 本轮 bug 元凶）
```

- **为什么是 A 而不是 B**：A = "体检＞12345"原则的直接编码，一句话可讲——**"先排客观体检报警的，再排群众主观呼声的"**。两个 B 变体评估后不推荐（与 dsh 同判）：
  - B1「体检量全局主排（分层只作标注）」——丢了密度资格门槛（大社区靠楼栋多霸榜回归），也推翻已拍板的"双高/单轨"分层叙事，成本高。
  - B2「客观榜 + 主观榜并列两张」——弱化单一优先主线，20 行变 40 行，违背"一眼懂"；完整主观榜留作报告附录备查，不进 PPT 正页。
- **零成本加成·层标签重命名**（采纳 zcode，让来源差异自己说话、不加权重只改字）：
  - 「问题指标高」→ **「客观隐患高·诉求未暴露」**
  - 「诉求声量高」→ **「主观诉求高·体检未印证」**
  - 「双高」→ 保留 + ★（仅双高用星，符号勿通胀）

### 2.2 Q2 层内排序键 → 本源绝对量（裁定 dsh「量」✓ vs zcode「密度」✗）

**结论：体检层族（双高 + 体检高）一律按体检点降序；诉求层按诉求件数降序。密度（原始密度 / EB 密度）一律只作并列列、不进排序键。**

| 层 | 层内排序键 | 落序（实测·假设体检层取 8 坑） |
|---|---|---|
| 双高（5） | **体检点**降序（贯彻体检优先到底） | 营盘路 37 → 宝联 29 → 汕头路 17 → 胜利四路 16 → 胜利二路 9 |
| 体检高（8） | **体检点**降序 | 深圳路 107 → 西峡 91 → 金安岭 84 → 镇境山 82 → 幸福路 65 → 新隆康路 62 → 果园路 51 → 桥北 37 |
| 诉求高（10） | **诉求件数**降序 | 朝阳路 594 → 万达 501 → 港务 417 → 建设 372 → 岳湾路 225 → 大学路 222 → 伍临路 221 → 张家湾 187 → 体育场路 136 → 枫香树 126 |

> **两键贯穿，各层用"本源最直白的绝对计数"**：客观层族用客观计数（体检点），主观层用主观计数（诉求件）。密度、任务量都退为并列列（密度 = 资格证据 + 严重度旁证；任务量 = 实施序参考）。

**为什么绝对量、不用密度——四条独立理由：**

1. **「客观优先 = 层序」原则澄清（核心反驳 zcode）**：客观优先体现在**层序**（体检层整体压在诉求层前），**不等于**体检层内某社区必须第一。金安岭按量排体检层第 3、总序约第 8、仍在 TOP10、仍带「客观隐患高」标签——原则毫发无损。zcode「金安岭必须密度第一否则打脸客观优先」把层间原则错套到层内顺序，是过度推论；其"按任务量金安岭垫底第 10"的论证也站不住——垫底是**任务量混加**（已被三方一致否决的键）造成的，不是绝对量造成的，不能拿一个已废弃的键来为密度键背书。

2. **绝对量零派生、零隐含参数，最契合"不加权重"精神**：密度本身虽不是加权（加权 = 给维度赋系数；密度 = 归一化消除规模差，二者不同，这点 zcode 对），但**密度引入了"分母基底选择"这个隐含参数**——`preview_intensity_rank.py` 里体检用"/百栋"、诉求用"/千栋"（量纲不统一），且分母在"楼栋 / 居住用地面积 / 行政面积"三种基底间切换（line 52-60）。**"不加权重"的精神应延伸到"不加隐含参数"**，绝对量（点 / 件）是唯一零参数、零派生的选择。答辩被问"密度为什么除以楼栋不除以面积"，绝对量方案无需回答。

3. **好讲解 + 答辩可验证**：「深圳路 107 个体检问题点，全市最多」——107 是可数的原始数字，领导一眼懂、可现场核；「金安岭每百栋 150 处」是派生指标，需解释分母来源，易被追问。汇报场景下绝对量完胜。

4. **资格已由密度/EB 把关，层内再用密度 = 同把尺子量两次**：能进"体检高"层本身就证明该社区 EB 收缩后密度达 p75 阈值（密度资格已确认）；层内顺序再用密度排序，等于把同一把尺子用第二遍，而绝对量提供**补充的、不同维度的信息**（哪个社区绝对工作量最大 = 实施序线索）。密度做并列列保留严重度信号即可，不必当排序键。

**吸收 zcode 的合理内核（金安岭密度高是真信号，不埋没）**：金安岭 56 栋 84 点 = 每百栋 150 处，是**结构性密集隐患**，这个信号有价值——但价值在"呈现"不在"排序"。落法：金安岭行在密度并列列显示 150/百栋（全场最高），讲解口径补一句——**「金安岭问题点总数排第三，但楼栋少、每百栋隐患密度全场最高，是结构性问题最集中的片区」**。这样密度信号不丢、排序键却稳。镇境山同理（密度 105/百栋，主图红星、换键后回榜，跨页对齐）。

**诉求层用件数不用密度，同理**：12345 = "主观个人意志"（用户原话），主观意志的天然度量是**声量**（多少人打电话 = 件数），不是密度。"朝阳路 594 件诉求"是声量直读；港务 417 件 = 诉求层第 3，合理。这也让两键规则对称好讲：客观层族排客观计数、主观层排主观计数。

### 2.3 Q3 港务与「诉求声量高」防误读 → 两件套，不设独立正榜

**结论：要防误读，但不设独立正榜（PPT 正页）。** 把"客观隐患"与"主观诉求"两个价值维度压进同一线性榜，必然有人排在后面——港务（诉求第 3）落约第 16 名是典型。若不加说明，扫表者会误读"诉求高块 = 低优先、可缓办"，错置港务/朝阳路/万达这类真实诉求集中区的回应。防法是**标注 + 脚注**，不是分榜。

**为什么否决独立正榜（与 dsh/zcode 一致）**：两张主榜让观众问"到底哪张是真的"——汇报大忌，且稀释"客观优先"主线。诉求高的"独立性"在主表内表达足矣；完整主观榜放报告附录作底账（CB-33 既定的"绝对量 + 强度双列并呈"），不算新增正页榜。

**两件套（全部零权重·比 dsh/zcode 三件套更精简，保住"好讲"）：**

1. **港务行内绝对量标注（防答辩最危险一问）**：港务是答辩最可能被追问的点（"港务 417 件怎么排到 16 名？"）。**在港务那一行的评估列旁直接标灰小字「诉求件 417·全市第 3」**——不是表尾小字、而是行内，被问时一眼可见。诉求高块其他高件数社区（朝阳路=1、万达=2）同理标「诉求绝对量第 N」。密度排让港务在块内第 7，但行标"绝对量第 3"同屏可见，声量不会被密度埋没。

2. **双价值一句话脚注（定调·解绑"榜上在后 ≠ 不重要"）**：表尾或汇报句写明——**「体检高 = 客观隐患优先整治；诉求高 = 主观诉求集中须回应。两者都是行动对象、同属高优先，只是处置逻辑不同：一处隐患、一应诉求。」** 一句话把"线性榜的先后"与"价值的重要性"解绑。这是 zcode 三件套里最有力的那一条，单拎出来即够用。

> dsh/zcode 的第三件（表尾任务量前五 / 三段式点名 / 块内子榜）属于"可选加强"，汇报时间充裕再加；核心防误读靠上面两件套已足。**讲解口径模板**（给讲解人，也写进 md）：「体检优先是**诊断序**——先排底线隐患；诉求声量是**实施序**——更新项目往诉求最密的地方落。港务 417 件在诉求榜第 3，是实施阶段最大工作对象之一；它不在总榜前 10，是因为它的问题是『诉求型』不是『隐患型』，两条序各答各的问题。」（= CB-33「绝对量 = 任务量·强度 = 优先级」双列共识的叙述化。）
