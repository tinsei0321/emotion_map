# CB-22 · 「分类 → 回答范式」映射（架构级讨论发起）

> **发起方**：claude组 | **日期**：2026-08-09 | **CB 轮次**：CB-22（EMC 机制完善·用户质疑问题判断机制）
> **背景**：EMC 人工测试失败两轮（RAG 冷加载超时 → 模板错位）·暴露**机制结构性缺陷**：问题分类正确·但**分类结果未映射到正确的回答范式**——全走 finalStep（FINAL_TEMPLATE·图层导向）·RAG 问答被强塞分析模板。
> **用途**：三组深入设计「分类 → 回答范式」映射·根治模板错位 + 完善问题判断机制。

## 〇、用户质疑（核心）

> 我很怀疑 EMC 对问题判断的能力和机制，是否合理或是否完善？

**claude 初步判断**：分类机制工作正常（`_quickIntent` 正确返 rag_query）·但**分类 → 回答范式映射缺失**——不同问题类型没有映射到对应的回答范式·全走 finalStep（图层导向）。

## 一、现状全貌（已核实）

### 问题分类（已有·正常）
| 分类 | 触发 | 判定 |
|---|---|---|
| `general` | CONCEPT_KW/INVENTORY_KW/GREETING_KW（概念/清单/问候） | quick-general 短路（harness.js:940） |
| `rag_query` | RAG_QUERY_KW + 知识词（知识检索） | RAG 短路（harness.js:978） |
| `gis_operation` | GEO_VERB_KW（纯 GIS 操作） | runTemplatePath（:525） |
| `emotion_analysis` | diagnose（情绪分析） | runTemplatePath/runChainPath（:525/:617） |
| `knowledge_query` | KNOWLEDGE_QUERY_KW（B 路径·CB-22b） | 待建 |

### 回答范式（现状·缺陷）
| 分类 | 回答范式 | 问题 |
|---|---|---|
| general | finalStep（FINAL_TEMPLATE）·靠「纯问答排版」段兜底 | 图层导向模板·LLM 可能走图层 |
| **rag_query** | **finalStep（FINAL_TEMPLATE）·无纯问答信号** | **图层主出口→「分析图已生成」·本次失败** |
| gis/emotion | finalStep（FINAL_TEMPLATE·图层主出口） | ✅ 正确（分析产图层） |

**缺陷**：**所有分类都走 finalStep（一模板扛所有）**·FINAL_TEMPLATE 为分析（产图层）设计·RAG/general 问答被强塞·靠 LLM「纯问答排版」段兜底（不可靠·LLM 优先执行图层主出口）。

## 二、拟议「分类 → 回答范式」映射（草案·待两组设计）

```
intent 分类（已有）→ 回答范式（缺失·本次设计）：
  general（概念/清单）   → 纯文字直答（finalStep 纯问答段·已有 quick-general 注入）
  rag_query（知识检索）  → 确定性组装（知识引用·条目式 + 来源 + 维度声明·零 LLM·glm B 方向）
  knowledge_query（B）   → 确定性查询直答（query_knowledge_base·零 LLM·CB-22b）
  gis_operation         → finalStep 图层（分析模板·正确·不动）
  emotion_analysis      → finalStep 图层（分析模板·正确·不动）
```

**核心**：**「分类 → 范式」明确映射**——分析类走 finalStep（图层）·问答/知识类走确定性/纯文字·**不再全塞 finalStep 让 LLM 猜**。

## 三、待两组讨论焦点

1. **映射完整性**：上述 5 分类 → 范式映射是否完整？缺什么分类/范式？
2. **rag_query 范式**：确定性组装（glm B·零 LLM·条目式+来源+维度）vs 注入指令让 LLM 走纯问答（Codex A·最小改动）——**根治 vs 治标**·怎么选？
3. **knowledge_query（B 路径）**：确定性查询直答·与 rag_query 关系（B 先 RAG 后·收窄 RAG）？
4. **实现方式**：范式映射怎么落地（harness 各短路分支独立·还是编排层统一）？
5. **承重红线**：FINAL_TEMPLATE 是否保持不动（分析类专用）？D019 守卫？
6. **回归影响**：改映射会否影响现有 general/gis/emotion 路径？
