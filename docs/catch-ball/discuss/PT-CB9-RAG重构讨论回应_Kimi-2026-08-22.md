## 一 议题 2 深答：A2 路由附注的「双跳浪费」——真实存在，但可设计消除

### 1.1 先把双跳的成本结构摆清楚

担心的链路：用户问精确口径（如「社区数口径到底 174 还是 193」）→ 宿主调 rag_query → 拿到向量素材+附注「精确值以 kb_facts 为准」→ 宿主为保险再调 kb_facts → **两次调用+两份来源**。

对用户的三层真实代价：
1. **延迟**：宿主 agent loop 多一跳，回答慢一拍（3080 流式下用户盯着看·感知明显）；
2. **不一致风险**：向量素材与注册表精确值若措辞有别，宿主写结论时左右互搏——用户看到的回答反而更犹豫；
3. **免责声明通胀**：自然语言附注混在结果里，宿主可能原样转述——用户看到「以下答案可能不准，请另行核实」类废话。

**但删掉附注更糟**：宿主拿向量召回素材当精确口径引用 = 口径错误，而「结论必须可辩护」是宪法级红线（两阶段路线·十条工程原则第 5 条）。所以问题不是「附注要不要」，是「附注怎么长」。

### 1.2 我的方案：两道防线·附注从自然语言改结构化字段

**主防线（调用前分流·零双跳）**：A2 的核心价值其实不在附注，在**工具描述里的路由契约**——「精确名词/口径数字→kb_facts；叙述/方法/对比→rag_query」写进两个工具的 description 后，有工具选择能力的宿主（dsh/Codex 都够格）在**调用前**就分流了，根本不发生双跳。这道防线是纯契约文本·零运行时成本，应作为 A2 的主交付物。

**二道防线（调用后改道·非双跳）**：宿主仍然误调 rag_query 且命中口径类时，附注兜底。但附注形态建议从自然语言改为**结构化字段**：

```
caliber_ref: { kind: 'caliber_class', suggest: 'kb_facts', topic: '<命中主题>' }
```

理由：
1. **宿主是机器**——自然语言附注每个宿主理解不一（dsh/Codex/未来壳三种解析）；结构化字段让宿主**确定性改道**（检测到 `suggest` → 直接改调 kb_facts·一次到位），「双跳」变「改道」，用户只感知一次干净调用；
2. **防免责声明通胀**——结构化字段不混入素材文本，宿主不会把 disclaimer 当内容转述给用户；
3. **窄面原则维持**：只在命中口径类（K 卡/G 卡 topic）时出现，叙述类命中零开销。

**结论**：设计得当，双跳浪费≈零（调用前分流为主·改道为兜底）；若只做自然语言附注，浪费真实存在——这是我把「支持」降为「有条件」的唯一条件。

## 二 议题 4 深答：H1 followup_cue 派生规则——什么追问对用户最有价值

### 2.1 先还原用户的追问场景

用户在 3080/壳对话框问完知识问题（如「什么是留改拆」）拿到答案。**好 cue = 用户本来想接着问但没组织好语言的方向**。从 EMC 业务场景（规划/体检/城市更新）看，用户的自然追问路径只有三条：
1. **从概念到落地**：「留改拆」→「宜昌哪些社区是改造类」（知识→数据）；
2. **从维度到相邻维度**：社区安全 → 社区服务（知识地图的边）；
3. **从口径到案例**：这个算法/口径 → 用它算过的真实案例。

### 2.2 三类派生规则评价与排序

| 规则 | 价值判定 | 理由 |
|---|---|---|
| **维度相邻**（dim 相邻主题） | **最有价值·排第一** | 就是知识地图的边·用户视角的「相关主题」·与场景路径②完全同构 |
| **口径关联**（K 卡引用） | **有价值·排第二·文案要翻译** | 口径对非专业用户是黑话——cue 文案必须是「这个数是怎么算出来的」而非「参见 K-C1」（用户沟通纪律第 2 条：禁裸用内部编号） |
| **小节邻接**（同文档相邻小节） | **最弱·误导风险最高·降级为兜底** | 文档结构是作者的组织方式，不是用户的兴趣结构——相邻小节可能是修订记录/附录/免责声明。仅在前两类无产出时使用，且须过滤 meta 类小节（修订/附录/索引） |

### 2.3 四条设计红线（防误导的硬约束）

1. **cue 必须有据**：每条 cue 指向的目标（相邻 dim 主题/关联卡）**在库里真实存在才发**——派生时先验证目标有 chunk。空 cue 是误导的开始（用户点了没货 = 对知识地图失去信任）；
2. **cue 是问题不是答案**：文案=疑问句方向，**不含任何事实断言**——cue 里夹带事实 = 绕过口径校验的灰色通道（口径纪律的洞）；
3. **2-3 条上限**：选择过载也是误导——4 条以上用户当噪音扫过；
4. **排序固定**：维度相邻 > 口径关联 > 小节邻接（价值序即展示序）。

### 2.4 无 cue 时：省略字段（支持主手）

空数组的语义是「问过了·没有」，省略字段的语义是「未提供」。选省略字段，两个理由：①**诚实**——「本轮无 cue 可给」和「老版本没这功能」在消费者侧无法区分时，省略让「能力缺失」与「结果为空」不混淆；②**契约演进惯例**——CB 体系新增字段一贯缺省省略，老消费者（dsh 现版）无感兼容。空数组还会诱使宿主写「遍历空列表」的多余分支。

### 2.5 补充：H1 与前端既有 `_followupCue` 的关系（防重复造）

提醒一句：前端 ai_qa 已有 `_followupCue` 分类器（harness.js:67·CB-22f D4·追问衔接五类词表）。H1 是 **MCP 侧返回结构**的 cue（知识结构派生·喂宿主编排），`_followupCue` 是**壳内侧追问意图分类**（用户话术识别）。两者层级不同不冲突，但 v1.2 任务书应写一句边界——**H1 的产物（cue 列表）未来可作为 `_followupCue` 的候选源之一**，避免壳阶段两套追问建议打架。

### 议题 1 · A1 前注维护成本（有条件）
成本值不值看前注算什么资产。按沉淀四分法（两阶段路线 §三部分）：**前注文本=权威资产（进 git 版本化），向量索引=派生资产（脚本重建）**。主手方案「重建命令化」如果只命令化索引构建、前注每次重建重新调 DeepSeek API，则双机/跨时重建可能产出**不同前注**（模型版本/温度/措辞漂移）→ 索引内容漂移 → 黄金集结果不可复现——这正是 R52 审计过的「索引漂移无门禁」问题的换皮复发。
所以条件一条：**前注生成物随知识源入库（chunk_id → ctx_prefix 映射表进 git），索引重建只重算 embedding 不重生成前注**；新增/修改 chunk 才增量生成。双机流程：git pull 得前注 → 一条命令重建索引 → 黄金集门禁验证。API 成本只在知识源变更时发生·可控。

### 议题 5 · H2 载荷最小集（支持·补一字段）
最小集（query 摘要/命中数/口径 refs）与 ACP v1 `tool.end` 的「果摘要/口径标签」语义对齐·支持。建议补 `top_dim`（命中主维度）：dim_counts 在返回结构里现成（零成本），壳对话框显示「查知识库·命中 3 条·主维度 社区安全·口径 K-C1」——维度信息让用户判断「查偏了没有」，价值远高于其成本。反对再加更多（score 分布/chunk 摘要=结果内容不是过程信息·越界进 tool.result 的职责）。

### 议题 7 · Q-A/Q-B 维持（支持）
Q-A 快档 10s 进 pytest：**慢门禁=被跳过的门禁**（开发组行为规律·10s 是「每 commit 都跑」的心理上限）；全量手动档留给回收前。Q-B 验收封顶条款：防「顺手再做点」的范围蔓延，与「不增加无谓排期」纪律一致。

## 四 产品性挑战：六增补里用户价值最虚的一件 + 一个补位建议

### 4.1 最虚 = A3 可选重排档
老实说：小语料 <1k chunk，混合检索 overfetch top20 后候选集已经很小，cross-encoder 的边际收益在几十条量级的黄金集上**大概率测不出统计显著差异**——A/B 实证很可能得出「无显著差别」然后默认 False 收场。那这 0.5d 就是给「业界标配」四个字交的税。
但我不投反对：默认 False+参数位的设计让它零用户风险，「实证后定默认」姿势也对。两个收紧建议：①**排期放六增补末位**（A1/A2/H1 的用户/质量收益先落袋）；②**A/B 判据写死**：「Recall@5 提升 <5% → 默认 False 归档·不重开」——防「做了就想用」的沉没成本心理（这是工程纪律不是技术问题）。

### 4.2 补位建议：v1.2 任务书写一条用户故事
六增补里真正用户可感知的只有 H1（「查完有路」）和 H2（「过程可见」）；A1/A2/A3/H3 都是质量与工程件。这本身合理（RAG 重构是底座工程），但建议 v1.2 定稿时把 H1 的用户故事写进任务书开头——「本轮重构后，用户问完知识问题会看到 2-3 个可追问方向」——让用户拍板时看得见「这轮给我带来什么」，也让回收验收有一条**可演示**的用户侧口径（对齐用户沟通纪律第 1 条：讲清背景/收益·不只抛术语）。

### 4.3 对整体路线的一句肯定（防误读）
「治理优先于暴力检索 + 明确不采用清单」这段评审是本轮最有专业含量的判断——小语料场景把 GraphRAG/ColBERT 挡在门外，比把它们请进来更需要定力。无异议。
