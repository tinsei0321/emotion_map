## 二 机制设计（主题卷宗制·`discuss/_ARCHIVE.md`）

**归档判据**（非日期）：收敛定稿落盘 + 实施完成 + 无待办 → 该主题过程稿可归。
**触发时机**：CB 轮收官（终审通过）时收敛方顺手归当轮过程稿——防堆积重演。
**四步动作**：① `git mv` 进卷宗（保历史）② 更新 `_INDEX.md` ③ 卷宗 `_DIGEST.md` 补行 ④ 全仓 grep 被移文件名·同步引用路径。
**digest 纪律**：只做导览（每主题一行结论 → 指向现行权威源），**不复制权威内容**——口径注册表/CLAUDE.md/总账仍是单一权威源。
**在途保护**：卷四/卷五永不自动归档；归档清单必带排除表（关键词 + 日期上限）——批一实测拦下 2 个 08-21 的 DSH 件。

## 五 对 RAG 线的专项指引（zcode 重点）

### 5.1 你的在途文件受保护，不会被移动

卷五定义 = CB22 系（RAG 三支柱/知识问答/蒸馏）+ CB-38/39 数据线 C 线交叉件 + **PT-CB9 RAG 重建全系**。归档机制带排除表（RAG/蒸馏/重建等关键词）+ 日期上限，批一~批四清单均显式避开。**你正在写的 PT-CB9 文档一个都不会动。**

### 5.2 语料边界重申：归档件与 digest 都不是蒸馏源

CB-38 收敛定稿已采 dsh 纪律「**蒸馏源禁 discuss 取数**」。本机制与之对齐：

- `discuss/` 顶层、`archive/` 卷宗过程稿、各 `_DIGEST.md` —— **全部不入 RAG 索引**；
- RAG 语料仍从权威源取（`docs/urban-renewal-plan/` 提炼笔记 + `ai_qa/outlet_kb/` + 未来按 PT-CB9 计划扩充的权威源）；
- **推论：本次归档对 RAG 索引零影响、零重建需求**——`tools/rag_index.py` 四源不含 discuss，134 件的移动不触碰任何索引路径。

digest 的作用 = **帮人导航到权威源**（如「83.3% 三层定稿 → 口径注册表」），不是给机器喂数。语料规划若需要「权威源清单」，digest §一的指针表可作为人工参考起点（见 §六 Q3）。

### 5.3 作废口径与 RAG 口径防线的接口

CB-38 定稿的口径防线三层 + 作废数字清单仍在口径注册表。卷一 digest §三 镜像了 4 条作废口径，其中「87.9% / 5,615」确认已在注册表作废清单；**「合并双高 26（CB-32 初版）」「page7 密度版（08-14）」两条疑似未入注册表**——若属实建议补录（单一权威源·防 LLM 综合时误引旧口径）。此为小工作量顺手项，归属口径注册表维护方（你或后续批次）。

PT-CB9 终审通过 + 实施完 + 零待办后，其过程稿按四步动作归入卷五卷宗（届时卷五转「待归」，仍由用户触发）。**现在无需任何预归档**；终审/定稿文档永远常驻顶层（含你的 v1.2 终版判决）。
