### 焦点 2：解决方向取舍 — **B 为本 / A 为门 / C 可选增强**

| 方向 | glm组 定位 | 理由 |
|---|---|---|
| **B 新工具 generate_point_layer** | **必做·核心** | 工具层封闭是根因之一·无 B 则 A 识别了意图也无法执行。渲染样板（`shared.js:130 defaultPaint` / `:176 addToolboxLayer`）+ 地点解析（`geocode.py:188 search_place`）均已就绪·claude组 估「约 30 行装配」合理（镜像 lookup_place 的 `/api/v1/place/search` × N + 合成 point fc + addToolboxLayer） |

### 焦点 3：承重红线边界 — **走独立新意图，不动 diagnose 三值 / FINAL_TEMPLATE**

这是 glm组 与 claude组 候选方向的关键分歧点，详述：

**claude组 候选**：「在 knowledge_qa 内部加图层升级分支」或「独立新意图」二选一。

**glm组 判断：必须独立新意图（如 `layer_from_knowledge`），禁止在 knowledge_qa 内开图层分支。**

理由（基于 CB-22 三支柱 + 承重红线）：

1. **CB-22 铁律「知识问答成功路径禁图层」**（KNOWLEDGE §2「纯回答稳定性三支柱」+ `_assembleKnowledgeQA` 注入指令第 4 条「不要生成分析图层/{{show:图层}}/4×5 归因」）：knowledge_qa 的范式是 **RAG→LLM 综合→纯文字**。若在其内部开「图层升级」分支，等于**在同一条成功路径里混入图层出口**，破坏三支柱②（EMC 架构 = 分类→范式映射的纯净性）。用户 CB-22 定铁律正是防「知识问答被带偏出图层」——反向在知识问答里塞图层，同样违背精神。

2. **架构清晰度**：knowledge_qa = 文字出口范式；layer = 图层出口范式（`PARADIGM_MAP` `emc-patterns.js:57-63`：`knowledge_qa→knowledge_qa` / `gis_operation→layer`）。新意图 `layer_from_knowledge` 应映射到 **`layer` 范式**（图层出口），与 knowledge_qa 的文字出口**分立**——保持「一个意图一个出口范式」的架构纯度。

3. **diagnose prompt 是否需动？— 需加 intent 枚举值（增量·非改现有）**：
   - 当前 intent 4 值（general/gis_operation/emotion_analysis/knowledge_qa，prompts.py:200）。
   - 加 `layer_from_knowledge`（第 5 值）= **增量加类**，符合 KNOWLEDGE §1 承重红线「diagnose 永不动」的 **2026-08-09 豁免条件①「增量加类」**（CB-22 三层架构已立先例：knowledge_qa 就是这么加的）。
   - **不改不删现有三值** → 不撞红线。
   - **必须记录豁免**（豁免条件②③：eval 复采通过 + 静态断言守现有判据文本）。

4. **FINAL_TEMPLATE 是否需动？— 不需要**。FINAL_TEMPLATE 是 finalStep 文字出口模板；新意图走 layer 范式（工具产图层 + 简述 observation），不经 FINAL_TEMPLATE 长文综合。**FINAL_TEMPLATE 保持不动**（撞红线风险归零）。

**续作识别怎么处理？** claude组 方向 A 提到「识别为续作/图层升级」。glm组 建议：**不扩 `_isResumeCue` 正则**（加「标记/地图」会污染——「解释这个地图」「地图是什么意思」也命中 → 误触发）。改为**让 diagnose LLM 判**（NL 意图判断归 LLM·CB-22 用户拍板）：diagnose prompt 的「多轮续作」段（prompts.py:226-231）加一条规则——「上轮 knowledge_qa + 本轮含『标记/地图/位置/落到/标到』+ 指代词（这些/那些/刚才）→ intent=layer_from_knowledge」。**意图判断归 LLM，正则只做加速器不做判定主体**。
