## 〇 一句话合并结论

**两份报告零对抗、高度互补，合并后根因链完整闭合**：慢 ≠ 思考长，慢 = **步数 × 每步固定税**（Qoder 钉死配置层根因：reasoning_effort=max 让"改一个变量名"也付推理档起步价）+ **上下文线性膨胀**（zcode 钉死工具面根因：46 工具/41 无关·cacheRead 每步 +1.9k）；解法不是"禁止思考"的 prompt 契约，而是**effort 分档、预算封顶、工具粗粒度化、模板固化、模式即预设**五机制。**「约束思维发散的最好办法是让不需要思维的任务不进思维循环」——这句话定为后续一切工作方向的总纲。**

## 一 共识清单（两份独立得出·权重最高）

1. 慢的主因 = 步数 × 每步固定税，非思考长度（reasoning token 极小·单步思考短但步数多）；

## 三 核心议题一：步数多 × 上下文重 怎么解决

**诊断已闭环，解法按收益排序落地为五条（每条带预期量化）**：

1. **模板固化（收益 ~80%）**：把 800m 脚本参数化为模板（grid_size/数据源/区域口径三参数 CLI）——第二次同类任务 1-3 步、30-90s。**"已知怎么做"的任务永远不进思维循环**；
2. **模式 effort 分档（收益 ~50%）**：数据分析类会话默认 effort=low/medium，max 仅留给显式的复盘/方案设计类请求（本次 56 步若全用 medium/low，仅固定税一项就从 9.5 分钟降约一半）；
3. **工具面收敛（收益 ~40%）**：任务型 profile 只挂必需工具（46→≤10）——cacheRead 降一个量级、每步 prefill 时间税同步降（zcode 证据 C3 的直接解药）；
4. **预算契约（防尾风险）**：全任务 reasoning 总预算（如 50k token）+ step 预算（侦察≤8/脚本≤15/调试≤8）——超预算降档续跑并告知，杜绝未来 30 分钟级任务；
5. **批量下发+断言替代回验**：独立探查/编辑批量并行；调试期用脚本内 assert 替代"跑完读文件确认"（step 29/36/43 同形命令跑三遍的根治）。

**上下文层**：F4 转 dsh 调研（是否有 context 压缩/摘要机制·长任务 30+ 步时真问题）。

## 四 核心议题二：如何判断"简单分析" vs "深入研究"（用户定调：多数任务=分析·无研究要求不发散）

**设计原则：模式即预设（按钮），不是意图分类器（路由）。** 这是本议题的第一条红线——我们自己的病史（EMC 封闭意图分类 = Whac-A-Mole·R3/R4 已证）刚被「A 是按钮不是路由」解决，绝不能在模式层重建一个"这句话是分析还是研究"的分类器。

**落地设计（双模预设·默认分析档）**：

| | **分析档（默认）** | **研究档（显式）** |
|---|---|---|
| profile | `emc-analysis`：flash + effort low/medium + 工具子集（G10 八件·无 pwsh/editor 或只读受限）+ step 预算 ≤10-15 | `emc-research`：effort high/max + 全工具 + 无 step 预算 + 可探索代码 |
| 行为 | 执行-验证-交付（assert+结构化输出·零探索） | 侦察-调研-方案-编码-总结（本次 56 步形态合法存在） |
| 适用 | 已知怎么做的任务（聚合/出图/统计/查询） | 未知路径/多方案对比/系统评估/复盘 |

**升级信号（不用 AI 判·三条机械规则）**：
1. **显式词**：用户话里含 研究/调研/探索/对比方案/系统评估/为什么 → 直接研究档；
2. **阻塞升级**：分析档内遇到硬阻塞（数据源歧义/口径不明/工具不可用）→ **停下问一次**（呼应评估"长任务 2 检查点"·1 次澄清换整条返工保险）；
3. **任务库沉淀**：任务模板化后，"分析"=选模板执行，天然零发散——模板库越厚，研究档出场越少。

**与用户定调的映射**：「尽可能准确、快速执行，不主动发散」= 分析档默认；「研究类要求」= 研究档的三个触发信号。**判断力从"模型每句话猜"移到"模式选择+阻塞检查点"两处，可验证、零分类器。**
