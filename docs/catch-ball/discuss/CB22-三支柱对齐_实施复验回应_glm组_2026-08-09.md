### B3 · 素材含 markdown 表格/换行 → 注入后条目式编号保留？— **confirmed（编号清晰）**

**注入格式核实**（harness.js:1019-1021）：

### B5 · 知识问答指令 vs FINAL_TEMPLATE 图层导向·LLM 先读谁？— **⚠️ 风险标注（须用户实测确认）**

**这是 glm 核心挑战（W1 延伸）——指令优先级实证**：

**LLM prompt 结构**（build_final_prompt）：
```
FINAL_TEMPLATE 正文（:127-160）
  ├─ 三句骨架（:134 图层主出口·严禁只给文字）  ← 强约束·在前
  ├─ 排版/内联模板/语言风格
  └─ 纯问答排版（:152 无工具操作时）            ← 弱判据

  └─ 【本次为知识问答·严禁图层】（:1023 强标记）  ← 强标记·在后
```

**glm 优先级分析**：
- FINAL_TEMPLATE :134"图层是主出口·严禁只给文字"——**prompt 正文·在前·LLM 先读**。
- ctx.context :1023"本次为知识问答·严禁图层"——**动态注入·在后**。
- **冲突时 LLM 可能先受 :134 图层导向影响**（第二根因正是此机制——本次失败的根因之一）。

**vs 第二根因**：
- 第二根因：无强标记 → LLM 全走图层导向。
- 修正后：有强标记 :1023 → LLM **可能**走知识问答·但**优先级风险仍在**（强标记在后·图层导向在前）。

**glm 判定**：⚠️ **指令优先级风险**——强标记是必要的（比无标记好）·但**不能保证 LLM 100% 听**（图层导向在前 + 强标记在后·LLM 可能混读）。
- **这是用户手动检查的核心看点**——复测"宜昌有哪些更新项目"·看 LLM 真走知识问答（条目式+引用）还是仍出图层导向（"分析图已生成"）。
- **若仍出图层导向**——说明强标记优先级不够·须升级（如 FINAL_TEMPLATE 加条件判据·或 ctx.context 注入 prompt 头部而非 context 段）。
