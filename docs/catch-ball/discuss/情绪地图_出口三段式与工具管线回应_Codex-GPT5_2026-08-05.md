### 焦点 1（最高优先）：新三段式 vs 现有出口机制

**判定：agree（B+C 组合方向）+ 修正（落地路径必须呈现层重组，不能动 finalStep prompt 模板）**

### 焦点 2：「观点 vs 结论」在 LLM/prompt 层的实现

**判定：agree（区分成立且必要）+ 两个基线未核实的有利事实**

证据与建议：
1. **用户提问已在 finalStep 上下文**：stages.finalStep 组 messages = `[...history, {role:'user', content: ctx.question}]`（frontend/js/ai_qa/stages.js:463-466），后端 answer 阶段以 context/tool_history 建 prompt（ai_qa/router.py:114）。LLM 写"观点"所需的"用户问的什么"现成——**无需改 prompt 模板**；若要强调"先答提问、再述结果"，在 harness 的 ctx.context 注入一行呈现指令即可（该层不受 D019 门禁约束，见二·遗漏 3）。
2. **真正的落地难点是风格张力，不是上下文**：用户要"第二段结论更专业学术"，但现状 finalStep 语言风格是"简短 3-5 句·通俗"（prompts.py FINAL_TEMPLATE「语言风格」节）+ manifesto 回答公约 3"不写学术八股（问题定性→数据证据→结论建议 那套）"（manifesto.py 八·回答公约）。**同一个 LLM 输出无法同时满足"通俗简短"与"专业学术"**。
3. **建议分层**：观点段 = finalStep 现状输出（通俗、面向用户、答提问）；结论段 = 后端确定性聚合的"客观描述"（模板化学术论述：区域/数值/归因/建议，可入库可复核），或由 finalStep 续写但通过 ctx.context 注入"学术化指令"（不撞 D019）。**推荐前者**——结论段确定性生成，正好对齐"Smart 两端 + Dumb 中间"（结论是结果的客观转述，LLM 增值主要在观点）。
4. **重复/矛盾防护**：applyQualityDefense（harness.js:290）是代码防线，可加一条确定性规则"观点段与结论段的数值/地名一致性校验"（同一指标引用不冲突、禁编造），不碰四态裁定。
5. **视觉层级**（前端呈现）：观点 = 强调卡（大号/加粗）· 4 要点 = 信息卡（方法/数据/结果/结论四栏）· 结论 = 学术段落（引用块/小标题）——零 LLM 成本。

### 焦点 3：第三段「一键入库参数」——更新需求调研场景指标细化
