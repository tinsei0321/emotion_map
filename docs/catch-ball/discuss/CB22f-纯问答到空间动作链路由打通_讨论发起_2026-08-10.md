## 〇、一句话结论

**EMC 的精髓 = 纯问答不是终点，而是空间动作链的起点。当前断链：纯问答文本中的地理/归因信息未被结构化「识别」，衔接层只有「标记」一个入口，FC 无 knowledge 契约导致变体问法根本进不了问答通道。本轮要打通「识别（文本地理/归因信息 → 结构化中间产物）→ 消费（追问意图 → 工具/动作链）→ plan+execute（多步工具编排）→ 空间图层+结论」的完整路由——这是其他平台做不了的差异化护城河。**

## 一、用户北极星（三组须锚定·最高优先级）

> **纯问答不只是生成答案文本为结束**。EMC 的独特价值 = 在纯问答文本之后，**根据用户要求衔接工具调用**：
> - 文本中的**地理信息**（地名/片区/坐标）·**归因信息**（字段/指标/极性/数据列）→ 能「**识别 + 消费**」
> - 通过**追问**实现「**plan + execute**」——形成**完整动作链**
> - 例：问「宜昌城市更新项目有哪些」→ 文字答案（55 项目/分片区）→ 追问「能在地图上标记吗」→ 已实现（CB-22d）→ **追问「哪些片区项目最集中/分析一下葛洲坝片区/对比伍家岗和西陵」→ 应继续衔接工具（密度/聚合/对比）出图层+结论**

**对三组的锚定意义**：这不是「加一个功能」，而是把「问答→空间分析」做成**体系化路由**——其他平台（DeepSeek 等）只有文本，EMC 能把文本变成空间动作。这是**突破口/护城河**，评估时以此为准绳。

## 三、Plan 草案（claude 初判·请两组详细评估）

### A · 路由打通（D1/D2·纯问答可达）

1. **FC prompt 加 knowledge 选型契约**（[router.py](ai_qa/router.py) `build_fc_sys_prompt`）：when = 城市更新/城市体检/政策/指标/案例类**纯问答**（无 GIS 操作意图·问「有哪些/是什么/多少/政策/做法」）→ 选 `knowledge_qa`；有空间操作意图 → 仍走 geo 工具
2. **`_normalizeFcDiagnose` 加 knowledge_qa 映射**（[stages.js:361](frontend/js/ai_qa/stages.js#L361)）：toolName 知识类 → intent=knowledge_qa → 合流 `_assembleKnowledgeQA`（[harness.js:1234](frontend/js/ai_qa/harness.js#L1234)）
3. **扩 RAG_QUERY_KW 词表**（[emc-patterns.js:47-50](frontend/js/ai_qa/emc-patterns.js#L47-L50)·缓解非根治）：补「城市体检/更新项目/有哪些问题/是什么/多少」类词序变体
4. 验证：桩测断言变体问法 → RAG 通道（非 GIS/GAP）

### B · 动作链「识别+消费」（D3/D4·EMC 精髓）

5. **识别层（文本 → 结构化中间产物）**：`_assembleKnowledgeQA` 出答案时，同步提取文本中的**地理实体清单**（地名/片区 + 可选坐标）+ **归因字段清单**（指标/极性/数据列）→ 存 `ctx.extracted`（结构化·非文本片段）——复用现有 names 提取 + jieba/POI 匹配
6. **衔接层（追问意图 → 动作链）**：`_markupCue` 升级为**通用追问衔接**——上轮 knowledge_qa + 追问含「标记/地图/点位」（→ generate_point_layer·已实现）**或**「分析/密度/分布/对比/归因/最集中」（→ 从 `ctx.extracted` 消费地名/片区 → 衔接 density/zonal/compare 等工具链）
7. **plan+execute 动作链**：复用 runAllToolCalls/族 A 编排——「标记 → 分析 → 对比」多步链（追问一句·执行整链·单次结论）
