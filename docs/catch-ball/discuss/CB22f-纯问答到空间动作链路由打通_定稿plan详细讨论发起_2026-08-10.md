## 二、待两组详细讨论焦点（6 个实施级悬点·非重新评估）

### 焦点 A：动作链深度下限（claude 收敛取舍·请定稿确认）
- claude 采纳 glm「先 1 步」（Phase1 本轮 = 文本→单工具·Phase2 多步链）。
- **Codex 原建议**：本轮验收下限 2 步（知识问答→单工具）·演示目标 3 步（问答→标记→分析/对比）·「标记→密度」语义边界（标记层≠情绪 L2 层·分析步须预载 L2）。
- **悬点**：① 本轮验收下限 = 1 步链是否够？若用户浏览器实测想看「标记后分析」·1 步是否显单薄？② 若 2 步（问答→标记→分析）进本轮·分析步的 L2 数据前提（预载 vs 诚实提示）怎么处理——是否超本轮 scope？

### 焦点 B：FC 伪工具方案 B 守卫细节（Codex 推荐·请细化）
- claude 采纳 Codex 方案 B：`TOOL_CONTRACTS` 加 `{skill:'knowledge_qa', tool:'knowledge_qa', category:'knowledge', when:None, params:[]}`·`exclude_categories` 默认扩 `('concept','knowledge')`·`_normalizeFcDiagnose` 加 toolName→knowledge_qa 映射。
- **悬点**：① `when=None` 的伪工具如何确保不进 `GEO_TOOL_CATALOG`（derive_geo_catalog 只收有 when 的）——需加什么守护断言？② FC 空 tool_calls 但 content 含 `[intent:knowledge_qa]` 的兜底（方案 A 兼容）是否仍需保留？③ 铁律 11 三处同步（contracts/SKILL_DEFS/prompts）具体范围——`knowledge_qa` 无工具参数·SKILL_DEFS 是否需要条目？还是显式豁免不进前端？

### 焦点 C：识别层 ctx.extracted 组装粒度（合并方案·请细化）
- claude 合并：fact 结构化字段（region/topic/year/keywords）meta 透传为主 + note/case source 溯源兜底 + 零 LLM 组装。
- **悬点**：① `ctx.extracted` 具体结构 `{geo:[{name,dim}], attrs:[{field,value?}]}`——粒度到「实体清单」还是「实体+字段+指标」？② 从 fact 的 `region` 提取地名 → 用 place_layer `_core_entities`/`forward` 匹配还是直接透传 region 字符串？（防 region 是「片区」类聚合名）③ note/case source 溯源（glm 建议）文件名含地名的提取规则——具体 regex 边界？④ 空 geo 的轮次（无实体）→ 追问「分析葛洲坝」时诚实 request_upload 还是提示「上轮无实体」？

### 焦点 D：衔接层优先级排序（glm 三角色·请细化）
- claude 采纳 `_quickIntent`（首轮）/_followupCue（追问）/_deterministicRecover（兜底）三角色。
- **悬点**：① 具体执行顺序：`_followupCue` 在 orchestrate 哪里插入（FC 前）？与 `_markupCue` 现状（harness.js:1130）的关系——替换还是并存？② 双条件守卫（priorTurn.intent=knowledge_qa AND 词表命中）——「分析葛洲坝片区」首问（非追问）怎么防被 followup 拦截？（应走正常 diagnose→FC→数据门）③ `_deterministicRecover` 扩展范围——哪些高置信词直接构造 diagnose？与 FC 正常时 followup 只做引导注入的关系？

### 焦点 E：执行顺序确认（claude 采纳 Codex P2 先行·请确认）
- claude 采纳 **P2→P1→P3→A→B→D**（Codex：P2 一行独立修复先行·低风险先做掉）。
- **glm 原建议**：P1 先行（标记准确度是动作链「标记」环节基础）→A→B→P2/P3→D。
- **悬点**：P2 一行独立于 P1/A 先行是否合理？（Codex 主张 P2 无依赖可先·glm 主张 P1 是地基）·P1 是否应提前到阶段 0 因 A/B 依赖 P1 实体质量？请两组收敛一个顺序定稿。
