## 一、北极星对齐

### 1.1 对齐判定：agree——这是用户原话级北极星（护城河）

- 用户指令原文：纯问答「不只是生成答案文本为结束」·「文本中的地理信息、归因信息的相关坐标、字段等内容能『识别+消费』」·「通过追问实现『plan+execute』·形成完整动作链」——这是产品差异化主张（DeepSeek 等只有文本），不是功能项。
- 与本仓已验证资产完全同构：CB-22d 已把「知识问答→标记」打成第一版衔接（harness.js:1130 `_markupCue` + :1142-1148 FC 引导 + :1846 `_deterministicRecover`）·B3 飞轮 26 例 88.5% 历史最佳·多步问（clip+density）已 PASS——「文本→工具」骨架存在，本轮是把单入口扩为体系化路由。
- **风险提示（诚实标注）**：护城河成立的前提是「动作链每步都诚实且不卡」——用户实测过「停半途/卡读秒」类根因（CB-22d B1 零命中零 LLM 出口正是为此）。动作链越长，挂起/假结论暴露面越大；本轮验收必须把「0 挂起 + N/M 诚实」作为硬标准（见焦点 8）。

### 1.2 动作链边界定义（建议三组收敛的判据）

| 追问类型 | 衔接 | 不衔接（纯文本） |
|---|---|---|
| 标记/定位（标到地图/点位/把 xx 标） | `generate_point_layer`（已实现） | — |
| 分布/密度/集中（哪些片区项目最集中/热力分布） | `density`/`hotspot`（**消费情绪 L2 点层**·见 1.3） | 概念问「什么是热力图」 |
| 归因/排序（分析葛洲坝片区/哪个最差） | `zonal_stats`/`rank` | 无实体可消费且无 L2 数据 → 诚实提示数据前提 |
| 对比（对比伍家岗和西陵） | `compare_regions` | 「对比」后接概念/政策 → 搜索/纯答 |
| 裁剪/缓冲（把 xx 范围裁出/周边 500m） | `clip`/`buffer`（需 boundary 层） | — |
| 政策/指标/数字（有哪些/多少/政策） | `knowledge_qa`（本轮 A 打通） | 无实据词概念问 → general 直答 |

- **衔接判据（双条件）**：追问含空间消费意图词（上表左列）**且**可消费实体存在（`ctx.extracted.geo` 非空 或 L2 点层就绪）；缺任一 → 诚实说明而非硬衔（防「分析一下葛洲坝片区」在无数据时落 request_upload 断层——见 1.3）。
- **深度**：本轮验收下限 = 2 步链（知识问答 → 单工具）；演示目标 = 3 步链（问答 → 标记 → 分析/对比）；「标记→密度」语义边界见下。

### 1.3 动作链数据前提（claude组 草案未显式标注·必须讲清）

- `density`/`hotspot`/`zonal_stats`/`rank`/`compare_regions` 消费的是**情绪点层（L2）**（tool_contracts.py:35 density preconditions「点层」；stages.js:363 `_NEEDS_POINT` 数据门）。`generate_point_layer` 产出的**项目点位层不是情绪层**——「标记 → 密度」在语义上不能直接把标记层当密度输入（除非本轮改 density 消费语义·**不建议**·超 scope）。
- 因此演示链建议：知识问答 → 标记（无数据依赖）→ 分析/对比（**预载 L2-T1 演示数据**或先触发数据加载）。`_dataGate` 对分析类追问的 request_upload 是**正确行为**（诚实），不是断链——断链在于「有 L2 数据时仍因 D1 路由落不到工具」。

### 焦点 3：D3 识别层 — **agree 缺口 + 确定性富矿方案（不新增 LLM 调用）**

- 缺口核实：`ctx.extracted` 全仓无此结构（rg 零命中）；现只靠 FC 从 ≤400B `final_excerpt`（panel.js:1614 `(t.final||'').slice(0,400)`）提取 names（harness.js:1143-1146）。

- **设计（确定性优先·零新增 LLM）**：
  1. `rag_index._load_facts` meta 增存 `region/topic/year/keywords`（type='fact'）→ `search()` 透传（tools/rag_index.py:275-282 加字段）→ 索引重建一次（235 条·分钟级）。
  2. `_assembleKnowledgeQA`（harness.js:87-170）拿到 _ragResults 后**确定性组装** `ctx.extracted = { geo: [region 实体去重 + place_layer 匹配（复用 CB-22e `_core_entities`/`forward`·零新词表）], attrs: [topic/year/dimension/keywords 转字段清单] }`——不依赖 LLM 从生成文本反提取（文本会改写·结构化源更稳）。

  4. 兜底：非 fact 来源轮次（note/case）→ place_layer 规则匹配 rag text；仍空 → 不硬造（诚实）。
- **是否需要用户确认再消费**：不需要（追问本身即授权；「Smart 两端」= LLM 判追问意图·「Dumb 中间」= 确定性消费）；但链执行前 observation 展示「将按上轮实体 X/Y 执行」·防静默误消费。
