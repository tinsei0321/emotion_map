- 落点：`build_outlet_schema.py` 新增纯函数 `priority_score(row)`
- 规则（升级现有"polarity_index 降序"单一规则）：
  ```
  priority = 强度项（负向极性·权重 0.5）
           × 覆盖度项（point_count 归一·权重 0.3）
           × 主题契合项（domain/element 命中·权重 0.2）
  ```
  - 强度项 = 负向程度映射（-2~2 → 0~1·越负越高）｜覆盖度项 = point_count/全域 max（缺省 0.5）｜主题契合项 = rows 含 domain_top/element_top 且有值=1·空=0.5
- 接入：`_build_card` 对 `renewal_sequence` 卡补 `fields['优先级']`（score 排序 + Top1 说明）·保留原 polarity 值供深读

## 一、待两组评估的焦点（逐条 agree/disagree/partial）

### 焦点 1：P1-1 需求强度分级阈值（±0.15/±1 对齐 valenceOf）

- 分级 = 高(≤-1) / 中(-1~-0.15) / 低(>-0.15)——负向程度 = 需求强度。
- **请两组**：阈值对齐 valenceOf（前端极性判定）是否合理？三档够不够（还是需四档/五档）？"低"档含中性/积极是否语义正确（需求强度应为 0 或"无显著需求"而非"低"）？

### 焦点 2：P1-2 复合优先级权重（0.5/0.3/0.2）

- 强度×0.5 + 覆盖度×0.3 + 主题契合×0.2——升级"polarity 降序"单一规则。
- **请两组**：权重分配是否合理？覆盖度用 point_count 全域归一（缺省 0.5）对不对？主题契合 1/0.5 是否粗糙？有无更优确定性方案（如不复合·分级排序）？

- **请两组**：口径标注够不够？（是否还需在出口卡 limitations 明示案例为参照非基准？）

### 焦点 4：P1-4 CSV 导出（export_outlet_card_csv）
