## 一 查阅记录（真读·链接附）

### 必读 1：Neo4j《What is Agentic RAG? A Developer's Guide》
链接：https://neo4j.com/blog/agentic-ai/what-is-agentic-rag

要点核取：
- 定义：agent 自主决定**何时检索、查哪个源、结果是否足够**——plan→tool selection→retrieve→evaluate 循环，直到 grounded context 充分或触发停止规则。
- 五模式：ReAct（起点）/ Router（生成前分流）/ **Corrective（检索不足→换源而非重查）** / Adaptive（复杂度分流）/ Multi-agent（单 agent 明显不胜任才用）。
- 对本讨论最关键的两句：①「**并非所有任务都需要 agentic 循环**——反思与迭代只有针对具体缺口才有价值，否则徒增成本」；②agentic 的故障面在规划/工具调用/验证/编排/停止逻辑**多个环节**，评估需要 loop depth / tool call success / stop reasons 级埋点（Ragas/LangSmith 级观测）——**这是 B 方向的真实前置成本**。

### 必读 2：Karpathy LLM wiki as agent memory（AAIF·Angie Jones）
链接：https://aaif.io/blog/karpathys-llm-wiki-as-agent-memory（Karpathy 原始 gist：https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f）

要点核取：
- 三层结构：`raw sources → wiki → schema`——**raw 不可变（agent 只读不写）**；wiki 是 LLM 维护的 markdown 知识层（index.md 导航 + log.md 时序日志）；schema（AGENTS.md）是维护规则（防重复/陈旧衰减/更新既有页而非新开/记录操作）。
- 关键洞察：这套结构映射六类记忆（semantic/entity/episodic/summary/procedural），其中 **procedural memory = schema 层**——「怎么维护知识」本身写成规则文件。
- **EMC 映射（我的判断）**：EMC 已有同构三层——raw=`docs/urban-renewal-plan` 原档（不可变·X-01 登记只读它）；wiki=事实卡/概念卡层（urban_renewal_knowledge.py 等三库·当前纯人写）；schema=`rag-loader-contract.md` + `rag-corpus-map.md` 五步 + R24。**C 方向不是新建结构，是把 wiki 层的写入权从纯人工开一条「agent 草拟+人审」的缝。**

### 补盲 1：RAPTOR（开场报告未覆盖）
论文：RAPTOR: Recursive Abstractive Processing for Tree-Organized Retrieval（Stanford·ICLR 2024）
链接：https://arxiv.org/abs/2401.18059 · 代码：https://github.com/parthsarthi03/raptor

- 机制：chunk 嵌入→GMM 聚类→LLM 摘要→对摘要再嵌入再聚类，自底向上建**多抽象层级的摘要树**；查询时树遍历或 collapsed-tree 平铺检索（论文实测 collapsed 更优）；QuALITY 基准配 GPT-4 绝对准确率 +20%。
- 与 EMC 的关系（双向）：
  - **反向验证**：EMC 的事实卡层（68 卡）本质上是**手工建的 RAPTOR 顶层**——从 282 个 note chunk 人工蒸馏的高层摘要节点。泳道②给它 ×1.2 加权（rag_index.py:526-530）正是「高层节点优先」的手动版。RAPTOR 证明了这个分层直觉是学界实证有效的。
  - **正向启示**：主题级问题（「宜昌体检整体结论是什么」）正是 RAPTOR 高层节点的擅长面，也是当前 chunk 级检索的弱面。但 374 chunk 的小语料上自动聚类摘要的边际收益存疑（与我对 A3 重排的「最虚」判断同理）——**登记为语料长厚后的候选，现在不动**。

### 补盲 2：A-MEM Agentic Memory（开场报告未覆盖）
论文：A-MEM: Agentic Memory for LLM Agents（Rutgers·NeurIPS 2025）
链接：https://arxiv.org/abs/2502.12110 · 代码：https://github.com/agiresearch/A-mem

- 机制：Zettelkasten 卡片盒法的 agent 化——每条新记忆生成结构化笔记（keywords/tags/contextual description）→ 嵌入召回近邻 + LLM 判定建链 → **memory evolution：新记忆触发对既有记忆属性的改写**，网络持续自组织。LoCoMo 基准超 MemGPT 等 SOTA。
- 对 EMC 是**一半是灵感、一半是警示**：
  - 灵感：结构化笔记（keywords/tags/context）≈ EMC 事实卡的 keywords/topic/year 字段（已在位）；卡片互链 ≈ 我 L1 建的 lineage（`src:<文件>#<节>`·67 卡）——方向一致。
  - **警示**：memory evolution（agent 自主改写旧记忆）在 EMC 语境 = **口径漂移温床**。EMC 的演进权必须拆成「提案-审批」两段：agent 可提 evolution 提案（旧卡 X 应更新为 Y·引句 Z），落笔权在人。这是我 D3 设计里「演进提案位」的直接依据。

### D2（A/B/C 采否·B 的边界）——partial（B 缓议·但换理由）

**B 的裁定边界我的判断：工具内 agent 不算把大脑搬回来——可用三判据辩护：**
1. **循环封闭**：retrieve-evaluate-revise 循环收敛在单次 MCP 调用内，不跨工具编排（编排权仍在 Harness）；
2. **输出契约不变**：返回仍是结构化 rows+caliber，不产结论性叙事（G-2 不破）；
3. **预算硬顶**：步数/时间上限写死在工具内（dsh 的 15 步硬预算同思路）。

**但 B 仍应缓议——理由从「边界」换成「需求证据 + 观测埋点双缺」：**
- **需求证据不足**：黄金集基线 10 miss 中 5 条「精确术语被枢纽身份卡顶位」已由泳道② BM25/RRF 治掉（rag_index.py:533-550）；96.7% 后剩余 miss 没有证据表明是「检索循环不够聪明」造成的。Neo4j 文原话：「反思与迭代只有针对具体缺口才有价值」——缺口未指认，不建循环。
- **观测埋点缺失**：Neo4j 文明示 agentic 故障面跨规划/工具调用/验证/编排/停止逻辑多环节，需要 loop depth/tool call success/stop reasons 级埋点。EMC 的追踪体系（tracker.py）是单调用级的，没有循环级观测——**内置 agent = 引入一个无法调试的故障面**。要开 B，先把循环级埋点建了；而埋点建设本身就该等真有循环需求时一并做。
- 结论：B 缓议，触发条件写死——「指认出具体 miss 模式需要循环检索 + 循环级埋点方案随件附」两条齐才立项。

### D3（C 的治理管线：agent 写入审批位设计）——重点题·详细设计

**设计原则：不新建议程，把现有三件资产串成分级分流管线。** agent 写入审批位 = 三级分流，每级都有 EMC 已验证的机制承载：

| 级 | 写入类型 | 审批位 | 承载机制（现成） |
|---|---|---|---|
| **L1 自动通过** | **派生资产**：从已 active 语料确定性重算的产物（ctx_prefix 重生成、lineage 补标、chunk 重切分、索引重建） | 无人审·可重建即正确 | L3 的一体化 `--build`（前注增量生成零 LLM 调用·rag_ctx_prefix.generate）+ 双环境纪律「派生资产只记重建命令」 |
| **L2 人审必过** | **事实层写入**：新事实卡/新口径数字/结论性叙述/新旧卡演进（A-MEM evolution 的 EMC 版） | **全审·非抽检** | X-01 登记管线：R24 引句 verbatim + 三分法（现行/历史/待裁）+ B2 三原则自审（单源不泛化/数值带时点）——提案进 **inbox 目录**（草拟层），主手批次验收落笔 |
| **L3 待裁队列** | agent 自评不确定项 | 主手裁决 | X-01 待裁清单机制（L3 已实操：总纲 status 等 3 项待裁模式成立） |

**关键设计决策四条：**

1. **写入走 inbox 草拟层，不直写语料**——复用 EMC 已有的 inbox 哲学（dsh 投递 spec 到渲染收件箱·前端消费：render-contract.md 既定模式）。agent 产出 `kb_inbox/draft_<日期>_<主题>.md`，格式强制带：引句 verbatim + 来源 src:file#sec + 三分法标注 + B2 自审三问。人审后迁入正式库，草稿留档（谱系可查）。
2. **事实层全审而非抽检**——L1 的 03-10 误读是实证：语义判定连执行者（我）都会错（38 chunk 误标），抽检放不过这类系统性误读。白名单源自动通过的诱惑要顶住——**「可信来源」≠「可信转述」**，转述层永远是风险层。
3. **superseded 标注权永不自动化**——作废判定（X-01 式）只给人。agent 可提 superseded 提案（必须带 R24 引句 + 替代口径指针），裁定权在主手。理由：superseded 是「说某事实不再是事实」，错标的代价（L1 的 38 条误标把现行口径打成作废）远大于漏标。
4. **口径注册表是 agent 禁区（只读）**——agent 提案可引用注册表卡 ID（如「与 K-04 冲突」），不能写注册表。注册表是口径宪法，写入权=用户级。

**与 X-01/口径注册表的关系一句话**：X-01 管线（逐值 grep→引句→三分法→登记）从「一次性治理动作」升级为「agent 提案的验收 SOP」；口径注册表保持人写，agent 的所有事实层写入在验收时必须过「与注册表冲突检查」这一闸（可自动化：数值冲突 grep 提示，判定仍归人）。

### D4（A 的 CRAG 轻量实现面）——agree（返回结构加字段就够，别跑二次检索）

**最轻形态 = 确定性置信代理 + 已有改道字段，零二次检索零 LLM：**
- **confidence**：search() 已有 score（RRF 融合分 rag_index.py:558 / 余弦分），用 top1 绝对值 + top1/top2 margin 双指标做三档（高/中/低）——阈值定为可观测参数（沿 fact ×1.2 的「可观测起步不拍死」先例，rag_index.py:527 注释）。
- **retry_cue**：复用 followup_cues 的三表确定性派生（mcp_server_emc.py:106-147），低置信时返回「建议换 kb_facts（精确口径）/细化问题（加维度词）」——这正是 Neo4j 文 Corrective RAG 的「换源」语义，且 EMC 的换源目标（kb_facts↔rag_query）在 A2 路由里已定义，caliber_ref 改道字段（我 OPUS-5 回应的提案）天然是承载。
- **真跑二次检索 = B 方向**（循环内嵌），缓议——A 只做「告知不足」，不做「自行补救」，补救决策留给外脑。这正是「Agentic-ready 服务」定位的自洽。

### D5（96.7% 零退化红线）——agree（无条件+一个验收范式）

红线确认：任何方向不得造成 rag_eval 96.7% 退化。补一个已验证的验收范式（我 L3 的红线三连）：**任何动 loader/检索/语料的改动，验收 = `--build` → 全量 pytest → `py tools/rag_eval.py` 逐类比对**。两条子纪律沿用 L3 先例：①golden 期望不因方向改动而自改（期望本身含作废数字→待裁报主手）；②索引重建是验收动作不是交付物（派生资产纪律）。

## 四 一句补位（产品视角）

用户之问「RAG 是否拥有 Agentic 特性」背后是对「RAG 会不会越来越聪明」的期待。A+C 组合给出的回答比 B 更诚实：**EMC 的 RAG 不做自己的大脑，但会让自己的知识越来越厚、越来越可信（C），让每一次检索越来越有自知之明（A）**——聪明留给外脑，厚与可信才是 RAG 的本分。这也与 EMC×dsh 两阶段路线的精神一致：权威源不动，能力插座越磨越亮。
