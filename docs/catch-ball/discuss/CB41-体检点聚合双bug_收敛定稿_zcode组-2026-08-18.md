## 一、根因定案（双链闭合·三方一致）

- **B013**：后端计数无罪（复算=客观表头部逐字吻合）；罪在前端着色轨——L0 无极性点层被塞进情绪热度色带 grid-warm（0=#8B0000 暗红→1.00=#FFDF00 亮金黄）+ 点数字段 `_grid_h` → **点数越多越浅、零点(30/174)最深红**；第二入口 toolbox zonal 更退化（全员 `_grid_norm=0.5` 整层同色）。传播面（dsh 补充·核实属实）：`generateGridForAI`（square+zonal）/`generateZonalForAI`/3D 柱体/时间轴均复用同一情绪轨着色；rank 对 L0 诚实报错（能力缺口·非本 bug）；area-stats 不受影响。
- **B012**：`tip-popup.js:433-435` 社区归属点=要素中心（无 `_center` 退化 bbox 中心）而非鼠标位置·174 面首命中即返 → **34/174 社区 tip 错名**（22 错名+12 无归属·清单见发起文档 §2.3）。连带（dsh 补充·核实属实）：point 分支早退不清 `#tp-community` → 点层悬停残留上一社区名。

## 三、实施计划（P0 本轮）

### P0-A · B013 计数着色分叉

1. `grid-tool.js`
   - `preprocessGrid`：新增 `p._count_norm = log1p(point_count)/log1p(maxAll)`（零点=0·与高度曲线解耦）；
   - `gridStyle(level, polarity, palette, reverse, semantic)` 新增第 5 参（可选·缺省=旧行为）：`semantic==='count'` → field=`_count_norm`·ramp=grid-warm·**强制 reverse=true**（低浅高深）；
   - UI 路径 `generateGrid`/`generateGrid()`（dialog）：新增「着色语义」选择（点数(临时)/极性·默认按 level 推导·用户选择优先）→ 传 semantic → paint 记 `_ui.semantic` + `zeroIsNoData`；
   - `generateGridForAI` **零改动**（不传 semantic=旧行为·契约不动）。
2. `state.js`：不动（复用 grid-warm）。
3. `map.js` `_gridColorExpr`：`p.zeroIsNoData` → case 特判 `field=0` 返透明 `rgba(0,0,0,0)`·其余 interpolate 不变（2D fill 与 3D extrusion 共用·一并生效）。
4. `index.html`：grid 对话框加「着色语义」卡片（两个选项胶囊·同既有 buf-cap 设计语言）。

### P0-B · B013 第二入口（toolbox 面域聚合 UI 路径）

5. `toolbox/shared.js`：`buildZonalFc(rows, boundary, semantic)` 可选参——count 模式写 `_count_norm`（rows 内 point_count 求 max·log1p 归一）；`defaultPaint(tool, kind, semantic)`——count → gridField=`_count_norm`+grid-warm 反转+`zeroIsNoData`。
6. `toolbox/zonal-tool.js`：`_execute` 可选 `params.semantic`（缺省=旧行为·ForAI 不动）；UI `generateZonal` 自动推导（rows 无 polarity_index → count）+ toast 提示「无极性字段 → 按点数着色（临时分析图）」；toast 文案「极性 choropleth」改自适应。

### P0-C · B012 tip 三修

## 七、增补（08-18 实施·用户复测后）· B014 计数根因

用户复测反馈「中央密集社区完全无填充」——5.259 前端修复的零点透明语义**忠实暴露了更深一层的后端计数 bug**（新立 **B014**）：

- **根因**：`/spatial/aggregate`（grid 指定单元后端）`name_col=null` → 自动推断面名称列=`社区` → 命中 CB-23 membership 值匹配快速路径；体检合并点文件为**异构属性**（600 要素带 `社区` 列·1696 不带）→ `from_features` 联合成列后 74% NaN → 空值行被整行丢弃（2296→600·136/174 社区清零·中央清零=无填充）。`/geo/zonal_stats` 因硬编码 `polygon_name_col='name'` 幸免——故 CB-41 排查期复算未暴露（当时只验了该路径）。
- **修复**（混合策略·严格档）：① membership 有值 → 值匹配（CB-23 语义不变）；② 空值且非 `geocode_status=region` → 回退几何 sjoin（仅取面 geometry 防列污染）；③ 空值且 region → 丢弃（质心无定位意义·保护延续）。
- **验证**：checkup 2296 点 → sum 2283/非零 144/零点 30/TOP8=客观表头部逐字吻合；12345 民生基础 6487 点/148 社区（5.251 口径一致·CB-23 不回归）；CB-23 老测试同步新规范（region 判别收紧为显式标记）；pytest 全量 **372 passed + 3 skipped**。
- **教训（复盘入 B014）**：排查期只验证了「函数直调 + /geo/zonal_stats」两条同构路径，未覆盖 grid 指定单元的 `/spatial/aggregate` 路由（from_features 异构联合列场景）——**多入口工具须逐入口验证**。
