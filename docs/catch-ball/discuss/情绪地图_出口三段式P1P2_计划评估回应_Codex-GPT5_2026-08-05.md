## 一、逐焦点评估

### 焦点 1：P1-1 需求强度分级阈值（±0.15/±1）

**判定：partial（阈值对齐正确·"低"档语义需修）**

证据与建议：
1. **阈值对齐合理**：valenceOf 五级阈值 = ±1.0/±0.15（frontend/js/state.js:329-338），后端分级用同一阈值避免"前端显示偏消极、后端标需求中"的错位；边界一致（pi<=-1 → 高、pi<=-0.15 → 中，与 valenceOf `v<=-1.0` 深红 / `v<=-0.15` 中红逐字对齐）。
2. **三档够**：演示与行业需求摸排表（高/中/低）一致，不扩五档。
3. **"低"档语义错误（需修）**：`pi > -0.15` 同时含中性（-0.15~0.15）与**积极（>0.15）**——积极区域无更新需求，标"低需求"语义错误。建议改**四值**（UI 仍可渲染三档）：
   - 高：`pi <= -1`；中：`-1 < pi <= -0.15`；低：`-0.15 < pi <= 0.15`（中性附近）；**无显著需求**：`pi > 0.15`（积极）。
   - 接入 `_build_card` 时"无显著需求"值 + 阈值说明一并可溯源；`test_demand_intensity_grading` 边界用例补 `pi=0.2`（积极→无）与 `pi=0`（中性→低）。
4. 建议级：`grade_demand_intensity` docstring 注明"阈值与 frontend/js/state.js:329-338 valenceOf 对齐"，防两处再漂移。

### 焦点 2：P1-2 复合优先级权重（0.5/0.3/0.2）

**判定：partial（复合方向对·3 处实现细节需修）**

证据与建议：
1. **权重分配合理**：强度 0.5 > 覆盖度 0.3 > 主题契合 0.2，符合"需求紧迫度=情绪强度为主、样本量为辅、归因信息为修正"的产品语义；升级单一"polarity_index 降序"（urban_renewal_outlets.py:51）方向正确。
2. **覆盖度归一需改**：`point_count/全域 max` 受离群格支配（1 个 5000 条热格把其余格压到 ~0）；且**缺省 0.5 语义矛盾**——缺 point_count 的行得 0.5，可能高于真实低覆盖行（10/5000=0.002 < 0.5）。建议：
   - 归一改用 **p95 替代 max**（对齐 grid-tool `_grid_h = (pc/p95)^γ` 的鲁棒做法，frontend/js/grid-tool.js:146-159）；
   - **缺省改为"缺失不参与加权"**（其余两项权重重归一），或保守取 0.3——不要用 0.5（高于多数实值）。
3. **主题契合 1/0.5 粗糙**：改三值 `0/0.5/1`——`domain_top+element_top 都有=1 / 仅一者=0.5 / 全空=0`（空=不加分，语义更诚实；4×5 归因是 DEMO 规则，L3/L4 接管后移除，此处保持简单即可）。
4. 建议级：权重定义为模块常量表（`PRIORITY_WEIGHTS = {'intensity':0.5,'coverage':0.3,'topic':0.2}`）便于调参；`test_priority_score` 补"缺 point_count 行不因缺省 0.5 反超实值行"的回归用例。

### 焦点 3：P1-3 case_library measure_note 口径标注

**判定：agree（方向对·需补出口卡 limitations 明示）**

证据与建议：
1. **measure_note 够用为起点**：case_library 现为三段式结构（survey/emc_angle/benchmark）+ indicator_link + source（case_library.py:1-20），补"感知维度非官方评分"标注 + "不新造数据"边界正确。
2. **补充（关键）**：除每案例 measure_note 外，**出口卡 limitations 应统一追加一句"行业案例为对标参照·非评分基准·数值口径以当地官方发布为准"**——因为出口卡会被用户拿去"对标对表"，案例数值若被误当基准会误导。落点：`build_outlet_schema.py` `_build_card` 的 limitations 数组统一追加（确定性，非每案例），即"案例级标注（measure_note）+ 卡级声明（limitations）"双层。
3. 守卫归属澄清：measure_note 是 case_library 结构字段，**不属于 validate_outlet_fields 的"聚合产物消费"检查范围**（该 CI 查 field_mapping 引用的产物字段，validate_outlet_fields.py:5-12）；measure_note 的结构守卫应放 `tests/test_outlet_kb.py`（case 必含 source/measure_note 断言），计划中"validate_outlet_fields 消费守卫"仅适用于需求强度等级/优先级（它们是卡字段，断言放 test_outlet_schema.py 卡结构即可）。

### 焦点 4：P1-4 CSV 导出 + 宁夏 13 表映射

**判定：partial（字段设计基本够·需补脱敏与边界说明）**

证据与建议：
1. **字段设计**：interface/fields/data_base/task_link/limitations 够"入库"骨架；建议加 **outlet_id / name / scale 三列**（入库行标识 + 尺度字段——"一键入库"到行业表需要行级出处）。can/cannot 可并入 limitations 备注列。
2. **脱敏红线（必补）**：core/export.py 已有 `desensitize` 脱敏参数（SENSITIVE_FIELDS，:211-213）——`export_outlet_card_csv` 必须显式复用（出口卡字段含 place_name 地名、issue_label 等，虽非 PII 但须防未来字段扩展带入评论原文/用户信息）；测试断言导出列不含敏感字段。
3. **BOM 复用**：core/export.py:164 已有 utf-8-sig BOM 实现（Excel 兼容），复用即可，计划表述正确。
4. **宁夏 13 表映射——不铺满**：现 CONTRACTS 映射 5 张 renewal 表（问题清单/需求分析、更新对象分布图、实施计划表、更新内容统计表、更新项目统计表，urban_renewal_outlets.py:17-88）；其余 8 张（基础数据/产权/资金/规划目标等）属**边界诚实"不能测"**范围。P1-4 产出应是"文档确认 5 张可映射表一一对应 + 明确其余 8 张为何不映射（需普查/详规/资金评估）"，**不是强行补全 13 表**——否则违反 outlet_kb"能/不能双栏"边界原则（outlet_kb/__init__.py:5-10）。

### 焦点 5：P2 地点 scale 标注范围

3. 建议级：地理定位标注文本建议含来源置信度（place_name_source）——CB-15 已提供，顺手带上不增加成本。
