### F2 RAG 数据层级设计

**结论：单库 + domain 标签，不目录分库。**

理由（按权重排序）：
1. 用户问题天然跨域——「双高社区有哪些更新项目」一次检索须同时命中体检 fact + 更新 fact，物理分库会把这类问题逼成两次检索+合并，得不偿失；
2. 规模不支持分库收益：295 条 → 沉淀后预估 <600 条，BGE 暴力检索毫秒级，分库只增加构建/维护双成本；
3. `meta.jsonl` 是自由 JSON 行，加 `domain` 字段**零 schema 改动**；过滤需求放 `search()` 可选参数（后续 EMC 意图路由注入），不动加权逻辑。

配套决策：
- **四类型够用**：口径/制度类 → fact（topic=`口径`）或 concept。禁造第五类型（术语纪律·无检索失败证据不扩）。
- **「宜昌市基础数据」域：设，但以口径卡形态（domain=`base_geo`）**：193/174/130/1682 四套社区口径对照、街办统一「街办」、EPSG:4326 基准、GCJ-02 一票否决、presets 清单、exchange reference-only PII 约定。这是把 E1 类口径混淆知识化的出口。
- **落位最小改动**：① `_load_notes` 按 `00-宜昌专项/`→`urban_checkup`、其余规划目录→`urban_renewal` 推断 domain；② fact 侧新建 `ai_qa/outlet_kb/urban_checkup_knowledge.py` 承接体检域增量（不动存量 67 条，避免大迁移），存量两域混装文件按 id 前缀补 domain 标注；③ `search(query, k, domain=None)` 可选过滤；④ note/fact 头部口径块（F4）随 build 落 meta。

## 二b EMC bug 清单表态（E1-E7）

### E1 鼠标悬停社区 tip 错误 — 真 bug · P1 · 先建 buglog B012 占位

发起方说「需用户提供复现细节」——同意，但**不必从零等**：本轮已在代码与数据侧找到三条具体嫌疑 + 一份前人诊断残留（`SCRIPT/_tmp_scan_community_names.py` + `_tmp_scan_out.txt`，未入库的工作区文件），按可能性排序：

1. **格心归属（最可能）**：`frontend/js/tip-popup.js:433-435` `fillContent` 对 cell 层用 `centroidOf(feat)`（**格心**）做社区归属，不是鼠标位置。大格跨社区边界时，悬停格的任意角落都显示「格心所在社区」——用户感知就是「社区错了」。修复方向：`bindTipPopup` 把 `e.lngLat` 传入 `fillCommunity`，用光标点判定。
2. **面重叠 + 首命中即停**：前人扫描实测 **174 社区面存在 3 对两两重叠 >1000 m²**（金斗山×锦江 170,056 m² = 较小面 13%；沙河×锦江 81,825 m²；沙河×兴安 8,910 m²）。`fillCommunity` 遍历 features 取**首个**包含点的面（`if (name) break`）→ 重叠区显示结果取决于数组顺序，必然出错。修复方向：数据侧修拓扑去重叠（治本，同时消除 zonal 统计重复计数隐患）；代码侧临时取「面积更小/更具体的面」或重叠区双值标注。
3. **口径错位**：社区四套口径并存（193/174/130/1682），且 `tip-popup.js` 注释写「配置库社区 193」而 preset manifest `checkup_cfg_community` 实为 **174（去 19 村）**——若用户拿 193 或 130 口径的图层对照 tip 显示，名字「对不上」即报错。修复方向：base_geo 口径卡 + tip 社区行标注口径来源（174 城市社区）。

次要嫌疑（一并核查）：`pointInPolygon` 只测外环 `poly[0]`（带洞面误命中）；若用户场景是**悬停社区面层本身**，`map.js:1004 showRangeTooltip(lngLat, layer.name)` 只显示**图层文件名**而非光标下社区名——若是这个，修复 = hitTest feature 的名称列（SQMC/社区）显示。

排期：用户复现采集 15 min → 定位 0.5 d（三嫌疑逐一排除）→ 修复 0.5 d。
