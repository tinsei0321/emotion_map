# 平台化愿景登记与任务重排（zcode·2026-08-23·用户令）

> **用户愿景（原话要点·08-23）**：情绪地图项目本身也是一个「壳子」——RAG 越来越丰富后·这个壳子可以变成其他专业垂域 Agent。例：基于城市体检数据+12345 政务热线数据的「**城市体检医生 Agent**」·践行「**无体检不更新**」行业动态·分析定位城市问题→评估→策划城市更新项目。重点：**基于本项目开发逻辑创造可能性·为可能性搭建现在的框架·最终形成「城市规划大模型平台」**。
> 本件=愿景登记（宪法级）+ 任务重排。双支柱 RAG 方向视为随本令终裁通过（愿景建立在「RAG 越来越丰富」之上）。

## 一 愿景的架构翻译（四层·与既有资产对账）

```
城市规划大模型平台（愿景实体）
 └─ 垂直域 N 个（可插拔）：情绪地图（垂域①·城市的连续主观体检）/ 城市体检医生（垂域②·无体检不更新）/ 未来…
     └─ 每个垂域 = 一个「垂直域档案 Vertical Profile」：
        数据包（preset/点层）+ 知识库（垂域 RAG 语料）+ 口径注册表（K/G 卡）+ 身份卡/人设 + 工具预设
     └─ 交互壳子（8080·ACP 对话框——壳阶段在建）+ Harness 外脑（可换）+ RAG 双支柱（方向已定）
```

**自洽性核账（为什么这不是推倒重来）**：
- 平台层资产**已是垂域无关的**：18 件 MCP 工具（zonal/buffer/rank/trend…分析内核通用）、RAG 检索管线（BM25+RRF+路由）、治理管线（R24/三分法/B2 三原则）、渲染契约、ACP v1——全部换垂域零改动；
- 垂域层资产**已是可打包的**：口径注册表/身份卡/语料地图白名单/preset——本就按「宜昌专项」目录组织=天然的垂域档案结构；
- 概念同源：垂域①「情绪地图=城市的连续主观体检」与垂域②「体检医生=无体检不更新」共享**检查→诊断→策划**同一管线——平台核心循环。

## 二 对在途方向的三点增强（不是改向·是升维）

1. **壳阶段架构升维**：v0.9 的 Q2（壳与现前端）增「垂直域可切换」维度；**新增 Q5=垂直域抽象层契约**（Vertical Profile 的边界定义——一个垂域的实例化清单）→ 进 Qoder 联合评审。
2. **RAG 双支柱增「垂域可复制」要求**：支柱二（受治理记忆化知识库）的治理管线设计为**垂域通用**（管线机制平台层·语料内容垂域层）——语料地图白名单制天然支持。
3. **平台路线图落位**：壳阶段（在途）→ 垂域②试点（城市体检医生——数据已齐：体检 77 项+12345 全在库）→ 平台抽象层固化（从两垂域归纳 Vertical Profile 契约）。**先两垂域后抽象**（从实例归纳契约·不先造空框架——R26 架子先行纪律的垂域版）。
