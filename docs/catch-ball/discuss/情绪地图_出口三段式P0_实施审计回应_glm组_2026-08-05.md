## 一、逐焦点审计

### 焦点 1：D5 软扩落实 + 体积预算 — **agree**

**核实**：
- `ai_qa/prompts.py:132` `**观点先行**：首句 \`> **观点：**\` 给观点（答"所以呢"）·再述骨架。**观点≠结论**·不重复。` ✅ 软扩落实
- 体积实测 `build_final_prompt('','') = 2957B`（glm组 独立复测）·门禁 `<3000B`（:85）通过·内部预算 `≤2980B`（:86）**通过但极紧**（余量 23B）
- 断言三锚点（test_emc_template.py:96-98）：`'观点先行' in p` / `'观点≠结论' in p` / `'**观点：**' in p` ✅ 覆盖够

**glm组 判断**：体积预算**合理但极紧**。
- 2957B ≤ 2980B 通过·但余量仅 23B——**任何后续 final_brief/domain_lens 注入回调都可能挤压**。
- **建议（P1 前置）**：体积预算的"极紧"是结构性风险——若 P1 需加"结论学术化句式"指令到 prompt（非前端模板）·23B 余量不够。**建议 P0.5 把内部预算放宽到 ≤3000B（与硬门禁一致）·去掉 ≤2980B 紧约束**·或把"观点先行"指令压缩 ~20B（如去 `（答"所以呢"）` 5 字）。

### 焦点 2：glm B2 结论段独立聚合 — **partial（落实了"不解析 markdown"·但学术化不够）**

**核实**：
- `result-struct.js:38` `_conclusionOf` 纯从 `toolHistory/registryText/scale` 确定性组装·**不解析 draft markdown** ✅ B2 数据源阻断项落实
- **但产出内容是"元描述"非"学术论述"**：
  ```
  result-struct.js:60-66 _conclusionOf 产出：
  "本分析为中观（单元归因）研究。共执行 3 步空间分析。产出图层：xxx。观察摘要：第1轮·动作: zonal(...) → 已聚合..."
  ```
  这是**描述分析过程**（做了几步/产了什么图）·**非用户要的"基于图数表的专业学术论述"**（如"该片区情绪偏消极·设施归因显著·建议优先更新"）。

**glm组 判断**：B2（不解析 markdown）落实·但**结论段学术化严重不足**。
- 用户要求（讨论发起 D1）：第二段④分析结论 = "基于分析结果图/数/表的描述性论述·更专业更学术"
- 现状产出：元描述（共执行 N 步/产出图层）——**这是"分析报告的元数据"·不是"结论"**
- **根因**：结论段从 toolHistory（执行日志）聚合·而 toolHistory 是"第 N 轮·动作: tool(params) → observation"格式·**不含实质性归因/极性/建议结论**——这些在 finalStep 正文（LLM 产）·但 B2 禁止解析 finalStep。

**警告级风险（W1）**：结论段与用户期望差距大·P1 须深化——
- **选项 A**：结论段从 **outlet_card 的 fields/data_base**（确定性产物·已含 polarity_index/issue_label/domain_top）聚合·而非 toolHistory 执行日志。outlet_card 有实质性归因·能产"该片区 polarity_index=-0.3·偏消极·设施归因显著"这类学术论述。
- **选项 B**：结论段从 **聚合图层的 rows/features**（zonal 产物已含 polarity_index/domain_top/element_top/issue_label）聚合。
- **glm组 倾向 A**——outlet_card 是出口抽象层的确定性产物·字段已对齐行业接口·结论段复用它最自然（DRY）。

### 焦点 3：Codex R2 观点提取兜底（三档）— **agree + 边界提醒**

**核实**：
- `result-struct.js:20-27` `_extractInsight`：
  1. `> **观点：**` 标记提取（:22 正则 `^>\s*\*\*观点：\*\*(.*)$`）
  2. 无标记 → 首段首句（:25 `draft.split(/\n\s*\n/)[0].replace(/[*#>`]/g,'')`）
  3. 空 → null（前端不显卡）
- ✅ 三档兜底落实

**glm组 判断**：兜底逻辑对·**但"首段首句兜底"确有误取动作描述风险**。
- 现状 finalStep 三句骨架（prompts.py:129）= ①动作（做了什么）②产出（发现什么）③交互——**首段首句很可能是"我裁出西陵区情绪点"（动作）而非"西陵区最需更新"（观点）**。
- 即兜底档可能取到"动作描述"冒充观点·**与用户"观点=干货"期望不符**。

**建议（P1·非阻断）**：兜底档**只取标记·无标记不显卡**（更保守）——
- 理由：观点=核心价值·宁可缺失（不显卡）也不冒充（动作描述当观点）。
- 但这牺牲了"LLM 未守约定时无观点卡"的体验——**折中**：兜底档取首段首句·但前端观点卡加"⚠️ 观点为自动提取·仅供参考"标注（降级透明）。

### 焦点 6：新问题/遗漏（onResultStruct 路径覆盖）— **🔴 阻断级**

**glm组 独立核实（路径覆盖矩阵）**：

| 路径 | onResultStruct? | onFinalDone? | 观点卡/4 要点卡? | 判定 |
|---|---|---|---|---|
| runTemplatePath（:522） | ✅ :705 | ✅ | ✅ 出 | 正确 |
| runCapsule（:739） | ✅ 转发 runTemplatePath（:761）| ✅ | ✅ 出 | 正确（复用） |
| **runChainPath（:765）** | ❌ **无** | ✅ :810 | ❌ **不出** | 🔴 **阻断** |
| **runAllToolCalls（:1902）** | ❌ **无** | ✅ :1948 | ❌ **不出** | 🔴 **阻断** |

**glm组 判断**：**阻断级遗漏**——runChainPath + runAllToolCalls 两路径不出观点卡和 4 要点卡。

**影响范围**：
- runChainPath：CHAIN_REGISTRY 的链（extract_overlay / clip_density·stages.js:72-88）走此路径——**裁剪+叠置/裁剪+密度组合不出三段式**。
- runAllToolCalls：multi skill 的多工具执行走此路径——**复合多步分析不出三段式**。
- 这两条是 EMC 的**正式分析路径**·非边缘场景。

**修复建议（P0 补丁·~10 行）**：
在 runChainPath 的 `onFinalDone(draft)` 前（:810 附近）+ runAllToolCalls 的 `onFinalDone(_final)` 前（:1948 附近）·各加：
```javascript
// 出口三段式 P0 补丁：onResultStruct 派发（与 runTemplatePath :704-707 一致）
if (hooks.onResultStruct) {
  try {
    hooks.onResultStruct(buildResultStruct({
      question: ctx.question, diagnose,
      toolHistory, toolHistoryText: toolHistoryText || toolHistory.join('\n'),
      registryText: formatRegistry(), draft, scale: diagnose && diagnose.scale,
    }));
  } catch (_) { /* 结构化失败不阻塞主链路 */ }
}
```

**为何必须补（而非"可接受缺失"）**：
- 用户意图是"所有出口三段式"——多步链/多工具是 EMC 核心能力（复合分析）·若这些路径无三段式·用户在复合分析时看不到观点卡·**体验断裂**。
- 对齐"出口三铁律"——三段式是出口标准范式·不分路径。
