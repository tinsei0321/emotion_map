## 四 增量吸收与合并

### 4.1 「大脑端口」契约（zcode·采纳为架构前提）

控制面协议（start/send/status/stop 四动词+事件流+状态对象）**由 EMC 侧定义**，dsh 插件=第一个**驱动/适配器**。收益三条全采：dsh breaking 隔离在适配器层；与「入口可替换」同构升级为「大脑可替换」；成本≈0。**朋友实践（Codex 指挥各 CLI）恰好证明这套动词对多大脑通用**——未来 claude/codex 理论上也可做驱动。

### 4.2 审批语义（zcode 第四前提 + dsh 机制供给 + 我方抽验落位）

- zcode 三选一裁定采纳：**v1=仅只读工具+白名单写操作**（禁「全 allow」默认）；ask 透传留 v2；
- 机制落位（我方抽验）：ACP `session/request_permission` + 桥客户端按策略自动应答——**审批策略实现在 EMC 侧桥里，dsh 零改造**；
- 条款化进 C12-⑩。

### 4.3 「A 是按钮不是路由」（zcode·采纳为设计红线）

A 通道=快捷按钮/任务模板形态（**不出现在对话流·零意图判断**）；B 通道=对话框默认且唯一语言入口。此设计直接杜绝「薄壳重建意图分类器」（R3/R4 已证明那条路不收敛）——与本专题最深的教训对齐。

### 4.4 宪法 C12 条款集（claude S1-S7 + zcode ⑩⑪⑫ 合并·十条版）

S1 实例生命周期单向门 / S2 send 全审计（载荷全文+返回过 PII 过滤入 trace）/ S3 模式白名单+确认令牌（creative 须 confirm token·MCP 层 `confirm=true` 参数为 dsh组 建议形态）/ S4 插件最小权限+人审（AI 起草可以·产物必须人工评审+锁版本）/ S5 数据面正道（控制面不得绕 G10·send 只允许 dataset_id 引用）/ S6 降级显式（B 断→A 兜底+用户可见提示）/ S7 密钥与日志纪律沿用 / ⑩ 审批语义显式声明（三档·禁全 allow 默认）/ ⑪ 溯源标注（结果带 `brain: dsh@session_id`）/ ⑫ 数据回流对偶（送出过脱敏·回传渲染走 render 契约）。

**生效时点**（claude 条款·采纳）：B 变体转正时生效；用户个人工作流用法不受强制——但**只要经 EMC 产品链路全条生效**。

### 4.5 ACP 系路线（dsh组·采纳·替代「Web Host 插件」路线）

理由全采：stdio 常驻无 HTTP 层·与「不自动开浏览器」天然吻合·MCP 转发本就是 stdio 同形直连少一跳。**我方补充一条实施约束**（§1 新发现1）：G10 工具接入须经 dsh **profile 全局 MCP 配置**（ACP 会话拒挂外部 server）——写进 spike 设计注记。
