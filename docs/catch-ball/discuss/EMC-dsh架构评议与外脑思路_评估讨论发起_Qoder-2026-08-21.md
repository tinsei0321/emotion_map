## 二 架构评议 · 做对了什么

### 2.1 控制面/数据面分离——整条链路最有价值的一刀

- **数据面**：G10 八工具（list_data / rag_query / kb_facts / outlet_card / zonal_stats / buffer / rank / render_spec），dsh 作为消费者经 MCP 取数出图；
- **控制面**：`dsh_start / dsh_send / dsh_status / dsh_stop` 四动词，EMC 薄入口驱动 dsh。

两域契约分属不同 server、互不污染。对比业内常见做法（把遥控指令和分析工具混进同一个 MCP server），这一刀切得干净，也让「大脑可替换」（zcode 大脑端口契约）成为可能。

### 2.2 方向选择：协议级消费，不是整体寄生

`docs/todo.md:254` 记录的三式演进——整体寄生（否决）→ 协议级消费（形态3 主路）→ 大脑外挂（08-18 轮）——说明主动放弃了「把 EMC 重构成 harness 形态」。这是对的：EMC 的核心价值是**确定性编排**（harness.js + 契约 + 双 LLM 审查 + 三态出口契约），把它换成 Cordis 自主循环等于自毁护城河（`docs/ai-qa-design.md` 第 5.5 章「由 harness 代码强制，非靠模型自觉」正是此意）。

### 2.3 「A 是按钮不是路由」——整场讨论含金量最高的红线

R3/R4 已用失败证明封闭意图分类是 Whac-A-Mole。用**形态区分**（A=快捷按钮/参数面板，不出现在对话流；B=对话框唯一语言入口）替代**意图分类**，是结构上消灭问题。零意图分类、零新词表、零新降级树——建议升格为全项目设计宪法条款，不止用于薄壳。

### 2.4 B 变体「实验保留」+ 五条件转正——成熟的供应链风险定价

「产品入口押 preview 期第三方」被显式定价（R1 实锤：近 600 commit 16 次 breaking，集中在插件承重层），不预置承诺、让需求敲门。这比多数产品团队的 roadmap 纪律好。且本周事实证明定价准确（见 §三.3.1）。

### 2.5 审批语义（第四前提）抓到了真坑，且解法正确

「无人值守的审批门」是 harness 遥控场景最易被忽略的安全缺口。解法利用 ACP `session/request_permission` 在桥侧自动应答、dsh 零改造（收敛文档 §一抽验 2）——用现成机制供给补语义缺口，是正确的工程姿势。C12 十条宪法（含 ⑩审批三档禁全 allow / ⑪溯源 `brain: dsh@session_id` / ⑫数据回流对偶）质量高。

### 2.6 工程纪律的实证价值

G10 接入的每一步都有 file:line 实证（配置指引 §1.1 全部来自本地仓实读）；`failOnStartupError: true`、`toolCallTimeoutMs: 60000` 覆盖冷启动 8-10s、RAG 预热阻塞 stdio 的冒烟注意事项——这些细节说明执行侧的纪律是真的，不是文档装饰。

## 三 架构评议 · 必须诚实指出的问题

### 3.1（最重）执行基座的脆弱性已从纸面风险变成三次事实

08-18 讨论中「breaking 集中在插件承重层」还是推断，本周连续兑现：

1. **rc.8 merge 后插件体系直接崩**（黑屏双根因：缺 `export const inject` + 未跑 build:web 版本错配）——merge 536 提交即触发；
2. **插件源码目录丢失**，只能靠任务书+复盘文档整体重建；
3. **重建版仍有 API 误读**（`startSession()` 契约返回 `void` 却被当 Promise 取 sessionId，`contract/workspaces.ts:30`），以及 Codex 定稿附录 B3 新挖出的**第三方插件 monkey-patch 宿主 API**（dsh-better-sidebar 0.12.2 拦截 `workspaces.openPath`，`interceptOpenPath: true` 默认开）——**集成面的破坏源不止 dsh 上游，还有 profile 里的其他第三方插件**。

含义：集成面（cordis 插件 + profile 装配 + 构建链 + 第三方插件共存）落在 dsh 生态最不稳定的层上，且**没有书面的版本锁定与升级验证策略**。B 变体转正条件 2「dsh 脱 preview」短期不会发生，真正紧迫的问题是：**入口插件这条已存在的集成面，如何把每次 dsh/第三方更新的修复成本压到最低**（锁版本清单 + 契约冒烟脚本 + 升级走独立 profile 验证），这比继续讨论 B 变体优先。

### 3.2 MCP 在两个方向上的角色必须分清，别笼统说「通过 MCP」

- **数据面（dsh → EMC 工具）**：MCP 是行业标准选择（Claude Code / Codex / Cursor 同构），已验证，无异议。
- **控制面（EMC → dsh 大脑）**：**MCP 是 request/response 工具协议，不适合承载长时 agent loop 的事件流**——status 轮询、流式中间态、审批往返都是补丁式凑合。08-18 收敛其实已答对（选 ACP 系：stdio 常驻、自带 `session/prompt/cancel/request_permission`，MCP 只做薄转发）。

**建议把「ACP 是机制，MCP 是门面」写成显式口径进任何后续设计文档**，防止实施时退化回纯 MCP 轮询方案——这是本轮评议唯一一条「纠偏于未发」的建议。

### 3.3 五跳链路的延迟账从未算过

链路：UI → 薄后端 → MCP → ACP 桥 → dsh loop →（dsh 再调 EMC MCP）→ render。已知实测数据点：空间工具冷启动 8-10s（配置指引 §二.5）、RAG 预热 20-30s（start.bat:32 口径）、dsh 一轮 agent loop 普遍 10-60s。**对「分析师工作台」可接受，对演示场景致命**——评委等 30 秒看不到图，叙事再好救不回。目前无任何文档给出延迟预算与降级口径（B 超时多少秒回落 A）。

### 3.4 流程开销与工程量倒挂（组织层风险）

文档清点：外挂大脑一个**零代码**议题产出 6 份文档约 110KB（发起+三组回应+收敛+工作台）；PT-CB6 一个入口按钮产生 15+ 份文件、跨四组、历时四天，期间源码还丢过一次。CB 机制的验证价值真实存在（Qoder 审计抓到 4 项 MEDIUM；Codex 附录又挖出 better-sidebar 拦截与 URL 路径解析两层根因），但**讨论/交付比已超出健康区间**。参赛项目的时间是最硬约束。

### 3.5 入口做完了，「大脑内容」是空的（当前最高优先）

阶段二一行未动。现状：用户点按钮 → 新会话 → 欢迎卡说「我是 EmotionMap Copilot」→ **这个 Copilot 并不知道自己是 EMC**（无 system prompt 人设）、**没有 EMC 知识**（身份卡未加、RAG 索引仍 08-18 旧）、**没有工具偏好口径**。入口价值 = 按钮 × 灵魂，目前乘数为零。阶段二恰好是 EMC 仓内低成本动作（1 条 FACTS 卡 + 1 次 RAG 重建 + profile preset 配置），投入产出比远高于任何新链路讨论。
