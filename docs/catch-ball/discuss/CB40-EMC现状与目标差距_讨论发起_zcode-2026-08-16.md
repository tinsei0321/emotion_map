## 〇 一句话结论

**EMC 的入向链路（问→诊断→工具→图数观点）架构成熟、演示已基本可用（约 80%）；但「立项根本目标」的最后一公里——出向行业对接（约 25%）与知识库厚度（约 30%）——仍有实质距离。CB-39 的 24 批次覆盖约三分之二的欠账（其中 P0+A 线已落地）；**CB-39 之外存在三件未排期的结构性缺口**：①出向文件级格式化（行业导出·纲领自认的立项风险点）②前端测试体系（34 JS 零单测·项目唯一公认真短板）③持续数据流接入（「连续主观体检」的产品命名 vs 2024 年横截面现实）。

## 一 评估标尺（预期目标的准确校准·源 CLAUDE.md 纲领）

评估「离预期目标多远」先定义目标。CLAUDE.md 三层纲领构成标尺：

1. **出口抽象层（项目最底层逻辑·立项根本目标）**：EMC 的每个答案必须对接行业明确接口（体检/更新/规划的表、指标、任务板块）——「EMC 找市场，非市场找 EMC」。三铁律：①EMC 找市场接口 ②三段式线性（意图 agent→结果 agent→**成果范式 agent·第三段**）③定性+定量+地理按尺度。
2. **三支柱纯回答稳定性（CB-22 顶层铁律）**：①本地知识库完备度 ②EMC 架构（分类→范式映射）③LLM 归纳总结能力——缺一不可；产品定位=本地化聚焦的专业知识蒸馏（本地化+聚焦+专业+可追溯·区别于网络搜索）。
3. **Smart Agent / Dumb Tool / 确定性编排器内核**：聪明只在两端（理解+表达）、执行最笨最稳、编排器不调 LLM 不推理。

辅以目标客户画像（CLAUDE.md）：业内同行（当前演示对象·宏观假设生成）/ 事企业单位（体检更新对接·结论性报告·「未来编入城市体检指定项」）/ 城市运营单位（情绪云图·像看气象图一样监测）。**评估须分客户画像分别量距**，不能单维打分。

## 二 四维度现状实测（含代码证据与 CB-39 已落批次修正）

### 2.1 入向链路（问→诊断→工具→图/数/观点）——约 80%·最成熟

**已就位（架构+代码双证）**：

- 三角色内核完整落地：19 个契约工具（`TOOL_CONTRACTS` 实测 19 条）、intent 三路由（emotion_analysis / knowledge_qa / gis_operation·`stages.js:187-198` 含 outlet/decision_type 强信号仲裁）、确定性编排器（harness.orchestrate·三态出口代码裁定）。
- 纯问答路径已通：CB-22f 方案 B 落地（knowledge_qa 伪工具·`tool_contracts.py` 5 处 / `stages.js` 6 处 / `harness.js` 12 处消费）——「禁全塞 finalStep 一模板扛所有」已修。
- FC 工具选择实测 100%（CB-08·12/12）；工具契约单一源 + 前端镜像 + 守卫校验（CB-04 立案·CB-39 P0-2 已真身解析）。
- 降级体系：四态出口契约 + 三级降级 + finalStep 超时兜底（CB-22h/i 系列修复后）。

**剩余缺口（在「可信度」不在「能力」）**：

- **B002/B004 finalStep 假结论（CRIT·open）**——EMC「说做了但没做」，比功能缺失更伤演示可信度。CB-39 D1 白名单裁定已排（zcode 反评价建议 v1 收窄为图层名白名单+observation 格式校验·数字白名单降 v2 防误杀）。
- 参数填充仍是路由瓶颈（CB-08 结论：FC 选型全对·buffer.center / overlay.layer_a,b 常缺）——few-shot 优化方向已定未深做。
- B008 / B012 / B013 / UI-09 / PRED-09 等 UI 级 bug 线（CB-39 D2 同场修·B013 条目待建）。
- ~~phase=L4 错标 / L4 空壳 / key 静默断路~~——**CB-39 P0-1 已修**（真实 phase 标签·df.attrs·key 空显式报错·L0 骨架隔离 SCRAPER/experimental）。

### 2.2 知识库 / RAG（三支柱①）——约 30%·当前最大欠账

- **现状实测**：索引 295 条（fact 67 / note 214 / case 5 / concept 9·维度 512）；体检域仅 **15 条 CHK-\* fact**（URP 更新域 52 条）。
- **黄金素材未入**：紧急任务产出 93 文件（page1-7 成文 md、口径矩阵、17 项宏观率值、双轨对照）全部还没进 RAG——现在问「2024 体检安全韧性发现什么问题」，可检索素材严重不足。
- 三支柱②架构路由、③LLM 综合已就位；**木桶短板明确在①素材完备度**。
- **补齐路径已排未实施**：CB-39 数据线 B2-B4（口径注册表+复核门）→ C1-C5（domain 三域+存量 214 note 回溯+体检 fact 增量+图层卡片 26+张+白名单+指纹+黄金问题验收）全部针对此欠账。**B 线开工在即——此维度预计 CB-39 完成后从 30% 拉到 70%+**。
- 结构性遗留（CB-39 后仍存）：知识库的**持续更新机制**——素材是静态快照，「可成长知识库」（CLAUDE.md 设计哲学第三节）的增量更新流程未定型。

### 2.3 出向链路（出口抽象层·立项根本）——约 25%·最远且未排期

分两层看（注意：CLAUDE.md「出向链路=0」表述已过时·见第五节文档漂移）：

- **答案级对接（已起步·Wave 0 落地）**：出口契约库两域聚合（`outlet_kb/__init__.py:21-31` OUTLET_CONTRACTS 体检+更新+METRIC_MAPPINGS）；CB-16 Wave 0 确定性出口卡组装（`api/aiqa_routes.py:84-93`·「结果范式 agent·第三段」）+ 前端渲染（`panel.js:293`）+ 触发词镜像（`emc-patterns.js:81`）+ 真实字段映射（防空卡·CB-16 P2 修复）。即：EMC 回答能标注「这个结果能填进行业哪张表」。
- **文件级导出（=0·立项风险点）**：`core/export.py` 实测无任何行业格式——「结果→能直接填进编制流程/体检报告的表/文件」链路未打通；三段式第三段的完整形态（Wave 3 多卡）未完；「未来编入城市体检指定项」的交付物形态未定型。**此缺口不在 CB-39 任何批次**——CB-39 做完它依然是缺口，且它是纲领标注的「立项成败关键」。
- 结构性缺失论证已完备（软指标可信性缺口·可量化太硬/可感知太飘/可评价太泛）：理论侧成熟，**工程侧停在 Wave 0**。

### 2.4 稳定性与质量基建——约 65%（CB-39 P0 已改善）

- **已改善**：后端测试基线 **366 passed + 3 skipped**（CB-39 P0-2 守卫通电贡献 +46）；9 个 validate_* 守卫进收集；15 个追踪 ID 补注册；SKILL_DEFS 手抄漂移消除（truth-parsed·compare drift 被当场抓到=机制生效实证）；~~单线程 serve~~ 待 P1-3；~~3.13/3.14 漂移~~ 待 P1-5。
- **未动**：**前端 34 个 JS 文件零单测**（项目唯一公认真短板·KNOWLEDGE §2——飞轮 e2e 是唯一防线）；E2 office 底图单源依赖（D4 批）；双环境索引一致性（E12 指纹断言在 C5）。
