## 一 D1-D5 逐条表态

### D1 特性对照表判定 + 「迭代循环归属外脑」边界论证 —— **agree（含一处表述修正与一处推理跳跃警示）**

**支持证据（三方独立汇流）**：

1. **A-RAG 论文的三原则判定表（Appendix A·Table 4）是学界标准级佐证**：判定 agentic 的三原则——Autonomous Strategy（策略自主）/ Iterative Execution（迭代执行）/ Interleaved Tool Use（交错工具使用）——**全部落在 agent loop 层，无一落在检索工具层**。A-RAG 自己的三个检索工具（keyword_search / semantic_search / chunk_read）全是纯被动工具：无内部循环、无自评、无状态编排。A-RAG 用实验证明：agentic 性 100% 来自循环层，工具层只需要「分层 + 友好」（其结论原话："future research should focus on designing agent-friendly interfaces rather than complex retrieval algorithms"）。**「智能放循环层、接口保持简单分层」正是 EMC「迭代循环归属外脑」的学界镜像。**

2. **Letta/MemGPT 的架构定位原话**："While retrieval (or RAG) is a tool for agent memory, it is not 'memory' in of itself"——RAG 是 agent 记忆的**工具**而非记忆本身。Letta 四层记忆（message buffer / core memory blocks / recall / archival）中，EMC RAG 的位置恰好是 archival memory 的访问面，而 EMC 的身份卡+口径卡 ≈ core memory blocks（pinned context）。大脑（记忆的组织者/编辑者）与档案（被检索的知识）分层清楚。

3. **A-RAG 主表的反向印证**：把「智能」塞进检索管线的方法（GraphRAG/CRAG/Self-RAG 等）在统一评测下不稳定——GPT-4o-mini backbone 下 GraphRAG 在 MuSiQue 仅 26.4%（低于 Naive RAG 的 38.6%）；而「接口分层 + 循环自主」组合在 GPT-5-mini 下全基准最优。管线智能是脆弱的，循环智能是可扩展的（其 test-time scaling 实验进一步支持）。

**对抗审查两点（重点义务）**：

- **（a）推理跳跃警示**：A-RAG 论文的 agent loop 在 RAG 系统**内部**（研究原型自含 agent）——它证明的是「循环优于管线」，**没有证明「循环必须外置」**。循环放哪一层（RAG 服务内 vs 外置 Harness）是 EMC 自己的产品架构决策（可换脑/契约权威/ACP 语义），论文只能为「循环存在且应独立于检索算法」背书。建议收敛文档引用 A-RAG 时写清这一跳：**「A-RAG 证明循环层与工具层应分离；EMC 进一步裁定循环层放外置 Harness——后者依据是架构裁定与 ACP 契约，非论文」**。不写清这一跳，B 方向的辩护者可以用「A-RAG 自己就内含 loop」来反驳。
- **（b）中间地带修正**：A-RAG 的 Context Tracker（已读 chunk 去重·重读返回零 token 通知）是**服务端有状态机制**——它说明「工具内有非编排性的智能」不等于 agentic、也不违反外置裁定。去重/缓存/预热/词表校验/守卫（EMC 的 G-2、K-C1 校验、superseded 过滤）都属此类。对照表 §二「检索质量自评 ❌候选增量」建议改写为「**服务深化项（非 agentic 增量）**」——避免把「让检索服务更好用」与「让检索服务变 agent」混为一谈；EMC 检索服务按 A-RAG 三原则本就**不应该** agentic，这不是缺陷是定位。

**B 轻内置 agent：反对引入（比主手「缓议」更硬一档），否决理由换成可验证的技术理由**：

1. **ACP 契约 v1 先被破坏**：契约规定 `tool.begin/end` 粒度下限=「每次调用」（`docs/acp-contract-v1.md:21`），状态对象 `toolcall` 以单次调用为单位（§三）。若 rag_query 内部多轮循环，外脑与壳看到的「一次工具调用」实为黑盒多轮——**ACP 过程可见性（H2·壳阶段对话框的基石）在 B 落地那天就失真**，这比「大脑搬回来」的哲学争议更早兑现、也可客观验证。
2. **与 A 功能重叠且 A 更干净**：followup_cues/retry_cue 是「把 agent 判断所需的材料返回给 agent」，内置循环是「替 agent 判断」——前者保持编排权在外脑、责任边界清晰（口径/线索由 EMC 权威出，策略由外脑出）。
3. **测试面盲区**：96.7% 门禁是端到端的；工具内循环的中间轮退化在门外不可见——回归防护出现结构空洞。
4. **保留例外口**：若未来出现无法承担循环的无脑消费方（headless 脚本/定时任务），B 可重议——**前置条件 = ACP 契约先补「复合工具调用」语义**（工具内多轮须发子事件流）。把这个例外口写进收敛裁决，B 就从「悬而未决」变成「有明确重开条件」。

**C LLM Wiki 化：支持规划、护栏先行，两点补强**：

1. **Letta 的 core memory blocks 给 C 记忆学基础**：wiki 化本质是把「core memory 的写入权」从纯人审扩展到治理管线——EMC 已有 core memory 形态（身份卡/口径卡 pinned 在人设与 grounding），C 是让这个层从静态变活。
2. **sleep-time compute 提供架构选项**：Letta 的异步记忆整理（sleep-time agents 空闲期主动重组记忆块·非阻塞）映射到 EMC：**写入管线不必会话中同步**——「会话产出 → 暂存 → 空闲期整理 → 人审位 → 入库」的异步五步与现有五步人审流程兼容，还规避了「边对话边写」对会话延迟的拖累（呼应 OPUS-5 报告 B4 的时机纪律）。
3. **治理特色是真差异化**：Karpathy 式 wiki 是自由写，EMC 是治理写（B2 三原则 + 谱系 + 口径卡 + 人审位）——这是学界方案没有的工程贡献，C 落地时值得沉淀为短文（学习线产出）。

### D3 C 的治理管线设计原则 —— agree + 审批位三档建议

- **审批位不应是「全自动 vs 人审」二选一，应按写入对象的风险等级分三档**：
  ①**白名单源自动**（低风险）：已有结构化事实卡的**字段级更新**（如某事实卡加 keyword/修 region）——kb_facts 已有 query/keyword/topic 结构化入口，字段更新可规则校验后自动入库；
  ②**人审抽检**（中风险）：分析结论回写为新知识条目（EMC 分析产出→素材卡）——抽检比例可调（如 20%），其余带 `status=active` 直入但谱系标注「agent 回写·未全审」；
  ③**全人审**（高风险）：新口径卡 / 修改口径注册表 / 取代既有事实的写入——必须人审，且触发被取代条目转 `superseded`。
- **与 X-01/口径注册表的关系：管线必须复用 PT-CB9 已建的 status/lineage 字段**（`tools/rag_index.py:189-190` `_governance` 查表标 superseded 的成熟先例）——wiki 新条目天然带谱系指针，「新结论取代旧结论」由管线自动转 superseded（这是 FaithfulRAG 式事实冲突的治理版实现，见补盲②）。
- **管线校验规则一条**：写入内容过「durable phrasing」检查（OPUS-5 B2 三原则的规则化：一次证据不泛化 / 数值必标时点 / 转述与原文分层）——规则检查即可，不需要 LLM。

### D4 A 的 CRAG 自评轻量实现面 —— agree（返回结构加字段就够，反对真跑二次检索）

- **学术依据**：A-RAG 失败模式分析（Appendix D）显示 agentic 架构下 82% 失败是**推理链错**（entity confusion 40-71% / wrong strategy 仅 28-29%），检索不到的失败占比大幅下降——**外脑循环本身就是纠错机制，检索侧自评的边际收益被循环覆盖**。CRAG 式「检不好→重写→二次检索」是管线时代的补丁，循环时代其功能与外脑的再检索重复。
- **具体形态（确定性派生·零 LLM·零二次检索）**：rag_query 返回已有 `dim_counts/top_dim/elapsed_ms`（`tools/mcp_server_emc.py:392-397`）——加两个规则字段：
  ① `coverage_hint`：top_dim 集中度（单维占比>60% →「查询面窄，建议换 kb_facts 或相邻维度」）；
  ② `thin_result`：命中数<k 且分数低 → retry_cue「细化关键词或改精确查询（kb_facts）」。
  followup_cues 的三张小表骨架（`ai_qa/rag_cues.json`）可直接扩展。
- **一处已达标确认（同时修正本组 OPUS-5 报告 B3 的表述）**：开场报告 §二「检索质量自评 ❌」可补注——**superseded 读时过滤已实现**（`tools/rag_index.py:486`「superseded chunk 预置过滤」+ BM25 仅对 active 建·L1 泳道产出）。本组 OPUS-5 报告 B3 写的「读时降权」在 EMC 已落地为「预置硬过滤」；**真正的剩余增量不是降权而是「历史素材可见性策略」**——当前=静默过滤，备选=标注呈现（「历史口径」可被对比问检索到，FaithfulRAG 的冲突显式建模支持后者）。建议增量运营批二选一裁定。

### D5 96.7% 零退化红线确认 —— agree（红线成立且可守，附一个隐性红线盲点）

## 二 补盲两篇（真读真引·报告未覆盖）

### 补盲① HippoRAG 2：《From RAG to Memory: Non-Parametric Continual Learning for LLMs》（[arxiv 2502.14802](https://arxiv.org/abs/2502.14802)·ICML 2025）

**核心内容**：把 RAG 推向「人脑长期记忆」的三能力面——factual（事实记忆）/ sense-making（语义理解）/ associative（联想记忆）；在 HippoRAG 的 Personalized PageRank 基础上加深段落整合与 LLM 在线使用；联想记忆任务超 SOTA embedding 模型 7%，且事实与语义能力不劣化（此前 GraphRAG 类结构增强方法的事实能力显著低于标准 RAG——该论文解决了这个「结构增强换记忆类型」的退化问题）。定位=**非参数持续学习**（知识进外置记忆而非进模型参数）。

**对 EMC 的三点启示**：
1. **「RAG→记忆」是学界认定的范式终局方向**——C 方向（wiki 化=记忆化）走在正道上，不是旁门；
2. **associative memory（联想/关联检索）是 EMC 未覆盖的能力面**：口径间的关联（K-C1 五种社区口径的适用关系、领域×要素的矩阵关联）天然是图结构——但 EMC 已裁定小语料不采 GraphRAG，HippoRAG 2 的 PPR 轻量关联检索是远期候选（语料长厚后再议·**列为远期观察项不入排期**）；
3. **「非参数持续学习」给 EMC 知识库策略产品学背书**：知识增长走知识库+治理管线而非微调模型——与 EMC 全部现有实践一致。

### 补盲② FaithfulRAG：《Fact-Level Conflict Modeling for Context-Faithful RAG》（[arxiv 2506.08938](https://arxiv.org/abs/2506.08938)·ACL 2025）

**核心内容**：现有 faithful RAG 靠提示词/解码策略**压制**参数知识来强制造对检索内容的忠实——但压制破坏模型内部知识结构、增加误读风险；FaithfulRAG 改为**事实级显式冲突建模**：识别检索内容与参数知识的事实级差异 → 自思考过程推理并整合冲突事实 → 再生成。实验超 SOTA。

**对 EMC 的三点启示**：
1. **「冲突显式建模优于压制/过滤」的通用结论**：EMC 的对应问题不是「参数知识 vs 检索内容」冲突，而是**语料内新旧口径冲突**（superseded vs active）——FaithfulRAG 支持把当前「静默过滤 superseded」升级为「标注呈现」（对比问可检索历史口径），即 D4 末尾的可见性策略二选一，学术依据在此；
2. **写入时的事实级查重可借鉴到 C 管线**：新结论入库前先与在库事实做事实级冲突检测（冲突→进人审队列而非静默入库）——比「入库后靠过滤兜底」前置一层；
3. ACL 2025 接收=方法学成熟度背书，可放心引用。
