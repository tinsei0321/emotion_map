## 〇、为什么现在做（现状已变化·推翻 CB-14 结论）

**CB-14（08-03）判定「现阶段不建 RAG」**，理由：① 知识库仅 150KB 静态注入够用 ② 确定性哲学冲突 ③ DeepSeek embedding 硬阻塞。

**但现状已根本变化**：

| 维度 | CB-14 时（08-03） | 现在（08-09） |
|---|---|---|
| 知识库规模 | ~150KB 源码静态注入够 | **L0 资料库 875 文件** + 项目库/体检数值/GIS——**远超静态注入** |
| 需求形态 | 语境注入（概括性回答） | **具体数据检索**（"葛洲坝 12 项目/51.33 亿投资"） |
| 数据形态 | 纯知识文本 | **结构化数据**（项目库/指标/GIS 图层）适合向量化 |
| 用户诉求 | 未明确提出 | **明确要「准确应用知识库回答」** |

**结论**：CB-14 的「痛点不是知识超限」前提已不成立——现在是「知识很多，但 EMC 检索不到」。RAG 时机已到。

## 一、目标

让 EMC 能**准确检索并回答具体数据类问题**（项目清单/指标值/案例详情/政策原文），而不只是概括性行业知识。

## 二、数据源（向量化对象）

| 数据源 | 内容 | 形态 |
|---|---|---|
| **L0 资料库** `docs/urban-renewal-plan/` | 政策/指标/项目库/体检数值/案例/GIS 图层 | markdown 提炼笔记 + 结构化 |

## 三、技术路线（受约束选择）

**约束**：现有 provider（DeepSeek/火山 Ark/讯飞）都是 chat 模型·无 embedding（CB-14 硬阻塞仍在）。

**候选**：

| 方案 | embedding 来源 | 可行 | 说明 |
|---|---|---|---|
| **A 火山 multimodal embedding** | 火山引擎（CLAUDE.md 已提·volcengine-vision 支持） | ✅ 需验证 | 现成 MCP·可复用 |
| **B 智谱 embedding** | 智谱（zai 栈·全局可用） | ✅ 需验证 | 智谱优先策略 |
| **C 本地 embedding**（sentence-transformers） | 本地模型 | ⚠️ 需装依赖 | 离线·无 API 成本 |

**推荐**：先验证 A（火山 multimodal embedding·可向量化多模态）+ B（智谱）——沿用「智谱优先·火山备选」的 MCP 策略。

## 四、架构（符合 AI·Copilot 内核）

```
L0/outlet_kb 数据 → 向量化（embedding）→ 向量库（本地持久化）
                                        ↓
EMC 问答：diagnose 识别「数据检索类意图」→ 调 RAG 检索工具（Dumb Tool）
                                        ↓
检索 Top-K 相关片段 → 注入 prompt（Smart 生成回答）
```

**符合内核**：
- **Smart（LLM）**：意图识别（"有哪些项目"→ 检索意图）+ 回答生成
- **Dumb Tool**：`rag_search`（确定性检索·返回 Top-K 片段）——新 dumb tool
- **Orchestrator**：机械接线（diagnose 意图 → 派 rag_search → 注入）

**关键设计**：
1. **检索工具 `rag_search`**：query → embedding → 向量相似度 → Top-K → 返回片段
2. **注入边界**：只注入 Top-K（不撞 final_brief 体积守卫）+ 标注来源（防幻觉）
3. **触发时机**：diagnose 识别数据检索意图（项目/指标/案例/政策）→ 触发
4. **不碰承重**：diagnose prompt / 四态出口 / @track 不动·新增工具走 tool_contracts 注册

## 五、待确认（进 CB）

1. **技术选型**：火山 multimodal embedding vs 智谱 embedding vs 本地——验证后定
2. **向量库**：本地持久化（sqlite-vss/chroma）还是内存
3. **检索粒度**：按笔记/按段落/按结构化条目
4. **触发范围**：哪些意图触发 RAG（项目/指标/案例/政策全文 vs 分析类不触发）
5. **与现有注入的关系**：L1 继续注入（语境）+ RAG 补数据检索（互补·非替代）

## 六、执行节奏（本周重点）

1. **验证 embedding 能力**：火山/智谱 API 实测（claude·P0）
2. **落方案进 CB**：发两组评估（架构/选型/触发）
3. **建向量库 + rag_search 工具**：claude 实现

6. **更新知识库**：L0 提炼笔记 → 向量化
