## 一、现状（claude 调研）

### 问题 1 · 素材分类术语硬造

**URP-P01 现状**（`urban_renewal_knowledge.py:17-19`）：
```
'name': '2025-2027 更新典型片区和机制建设项目（55 个）',
'detail': '...典型片区类 43 个 44.93 亿（87.5%）——污水"厂网一体"示范区 16 个 20.14 亿 / 葛洲坝片区 12 个 11.07 亿 / 夷陵三峡移民老城片区 12 个 6.15 亿 / 红星路-二马路历史文化街区 3 个 7.57 亿；机制建设类 12 个 6.39 亿（12.5%）'
```

- 「典型片区类」「机制建设类」分类标签 = **笔记提炼者的归纳**（codex_0819:43）·非源文档正式分类术语
- 用户判定：**非正式/非专业表达·不能要**——业内人士看到「典型类/机制类」会觉得不专业
- **「不用强行用『概念』来分类」**：分类术语若源文档无正式依据·**不造分类名·直接罗列事实**

### 问题 2 · 来源标注排版

- 现状：来源标注是 LLM 回答里的普通文本（如「（来源：《宜昌市中心城区城市更新专项规划260713》）」）·**与正文同字号同色·显眼**
- 前端渲染：`panel.js:551` `window.marked.parse(text)` → innerHTML（marked v12·不净化 HTML）
- 用户判定：来源标注**重要但非关键**·应**弱化**（小号+浅灰）·保持排版整体性

## 二、待两组讨论焦点（agree/disagree + 证据·可交叉挑战）

### 焦点 1 · 素材分类术语去硬造（问题 1）

- **修复方向**：URP-P01 detail 去「典型片区类/机制建设类」分类标签·**直接罗列事实**：
  ```
  2025-2027 拟实施城市更新项目 55 个·总投资 51.33 亿元：
    污水"厂网一体"示范区 16 个 20.14 亿 / 葛洲坝片区 12 个 11.07 亿 /
    夷陵三峡移民老城片区 12 个 6.15 亿 / 红星路-二马路历史文化街区 3 个 7.57 亿 /
    其他项目 12 个 6.39 亿
  ```
  （43 个 = 污水 16+葛洲坝 12+夷陵 12+红星路二马路 3 之和·无需分类标签·数字自明）
- **延伸纪律（深化概念归纳纪律）**：素材卡**不得硬造分类术语**——源文档无正式分类·就描述事实·不归纳分类名（如「典型片区类/机制建设类」这种笔记归纳的非正式标签·不入素材）
- 问题：修复方向对吗？「其他项目 12 个」这种表述可以吗？还是直接用数字不加类别词？

### 焦点 2 · 来源标注排版弱化（问题 2）

- **修复方向（claude 初案）**：回答渲染后 DOM 处理——对「来源：...」模式包裹 `<span class="answer-source">`·CSS 小号（0.85em）+ 浅灰（主题色淡化）·随文弱化不突兀
  - 实现：panel.js 渲染后（marked.parse 后）·用正则/DOM 遍历对来源模式加 span·CSS 在 ai_qa.css
- 判定点：
  - 包裹方式：渲染后 DOM 处理（对「来源」模式加 span）vs LLM 输出约定标记（如 `〔来源：...〕`）·哪个更稳？
  - 样式：小号 + 浅灰·多少 em/什么色？（主题 light/dark 都要适配）
  - 是否换行：随文弱化（不换行）vs 独立行？——保持排版整体性
- 问题：claude 初案（渲染后 DOM 处理 + 小号浅灰）对吗？样式参数斟酌？
