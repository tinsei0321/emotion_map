## 三 执行纪律

1. **红线不变**：diagnose prompt 永不动（冻结期自然满足）/编排器确定性（冻结维持）/契约单一源（G8 派生=机制化）/三支柱（平台表述：砍任何一根·平台可信度崩塌）。QA 主链路零新能力=「演示阻断 bug 例外条款」内修 CRIT（B002/B004·CB-39 D1 批优先级上升）。
2. **门禁**：`py -m pytest tests/ -q` 全绿不退化（基线 366+3·阶段演进重录）；每批先验证后推送。
3. **分支策略（2026-08-19 用户纠正版）**：**实施批一律走分支 `EMC_harness_dsh`**；main 只经用户授权合并（原「实施回归主干」表述作废·08-18 晚 main 曾被误快进推送·纯增量无破坏·已纠正）。
4. **追踪 ID**：新工具面（MCP server）为 infra 级新模块——ID 分配**开工前整体规划**（守「连续不跳号·勿擅自加 ID」红线：从 tracker 注册表现有最大号顺延·勿造空号）；MOD_AIQA 内新函数 F_020 起照旧。
5. **沟通纪律**：面向用户产出全业务名称（AGENTS 2026-08-18 条款）；每批完成通俗一句汇报。
6. **台账**：专题台账随批更新；CB-41 转正后 cb-index/cb-journal/goal-status（含新增「产品入口」维度）同步落账。
