## 一、验证① · zonal 对「指标数值字段」聚合 —— ✅ 就绪（零改动）

**方法**：真实停车缺口点层（`体检_小区_停车泊位缺口.csv`·140 点·WGS84）+ 行政区 preset × `aggregate_by_polygons(agg_cols=['停车泊'])`。

**实测结果**（点层 126 有效点·`停车泊` 缺口数值 [4-2600]）：

| 行政区 | 点数 | 停车泊_mean | 停车泊_std |
|---|---|---|---|
| 伍家岗 | 18 | **309.9** | 593.6 |
| 西陵 | 108 | **162.8** | 300.6 |
| 点军 | 0 | 0 | 0 |
| 猇亭 | 0 | 0 | 0 |

**结论**：
1. `aggregate_by_polygons(agg_cols=[...])` 已支持任意数值列——`agg_cols=['停车泊']`（中文截断列名直接传）→ 输出 `停车泊_mean/_std`，**不依赖 score/polarity 情绪字段**（spatial_analysis.py:246 `_num=[(c,c) for c in agg_cols...]`）。
2. zonal_stats 端点 `req.agg_cols` 已透传（api/geo_routes.py:365-367）。
3. 前置注意：体检 CSV 数值列 dtype 为 str → 须 `pd.to_numeric(errors='coerce')`（已实锤·`停车泊` dtype=str·missing 值 NaN）——与 memory「聚合必须 numeric coerce」一致，适配器 L1 导出时处理。
4. 西陵 108 点占 77% 缺口 → 与 CHK-I05「西陵占约 70%」吻合 ✓（数据一致性交叉验证）。

**阶段 1' 动作**：适配器 agg_cols 传 checkup 数值列名即可·无新增聚合代码。

## 二、验证② · 面层质心化后 hotspot 可用性 —— ⚠️ 有条件可用（两坑）

**方法**：结构隐患面层 42 面 → `.centroid` 质心 42 点 → `hot_spot_analysis(value_col=...)`。

**坑 1（致命）· 常数权重 → Gi* 静默 NaN**：面层质心每点权重=1（无数值字段）→ `G_Local` 对常数序列计算 → 方差=0 → `z=(stat-expected)/sqrt(var)=0/0=NaN` → **全 42 点 hotspot='ns'·Gi_Z=NaN·RuntimeWarning「invalid value in divide」**。**体检面层若不带真实数值权重直接跑 hotspot 会静默退化**。

**坑 2 · 稀疏点层显著性弱**：用真实变化数值重跑——
- 停车缺口 126 点（值 [4-2600]·std 357.7）：Gi_Z ∈ [-0.48, 0.92]·**全 ns·0 显著热点/冷点**
- 危旧房 250 点质心（权重=dscs 层数 1-6）：**222 ns + 28 tend_hot·0 显著**

**原因**：体检点层稀疏（百级 vs 情绪 L2 万级）·Gi* 显著性对 n 敏感。管道跑通（无 NaN·KNN k=8·1.7s）但产出「诚实全 ns」。

**结论**：hotspot 管道就绪·但**阶段 3 若用 hotspot 表达体检热点需**：① 质心点带**真实变化数值权重**（危旧房 dscs/面积、缺口数——不能恒 1）② 稀疏数据显著性弱 → **需决策热点表达方案**（候选：Gi* 原样出 ns vs 局部密度分位分级·参考 memory `confidence-local-density` 先例——amap POI weight 恒 1.0 无梯度时用局部点密度分位 dens_norm）。

## 三、验证③ · 边界 preset 可用性 —— ⚠️ 街道缺失（阶段 3 返工风险）

`list_presets()` 实扫：

| preset_id | 状态 | 要素 | 阶段 3 用途 |
|---|---|---|---|
| `admin_district` | ✅ | 西陵/伍家/点军/猇亭 **4 区**（无夷陵） | 行政区 zonal ✓ |
| `admin_street` | ❌ **缺失** | — | **街道 zonal ✗**（fact：云集街办 24 栋/西陵 16 街办口径） |
