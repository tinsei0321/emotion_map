## 〇、一句话结论

**文档根因判定"方差小"部分对·但 glm组 实测发现**更深的根因——score 是 **U 形多峰离散分布**（0~0.2 占 40.6% + 0.9~1.0 占 29.7%·中间少）·这是 5 级极性分类的副产物·**与 Gi\* 的连续正态假设根本不匹配**。方案选择：**不建议 B（换 polarity_index·逐点数据无此列 + invert 语义混乱）·建议 A（降阈值 + 软分级）优先·C（网格+polarity）次之**。更根本的修正方向：**Gi\* 不适合 EMC 的极性分类数据**——长期应考虑换更适合离散/分类数据的聚集方法（如 DBSCAN 密度聚类按极性分组·或核密度 KDE 已有）。本轮修正可行（A 软分级·保统计诚实）·但须标注置信度档位 + 长期方法重审。

## 一、逐焦点评估

### 焦点 1：全 ns 根因判定 — **partial（方差小对·但有更深层根因）**

**文档判定**：score std 0.377（方差小）+ 阈值 1.96 严 + KNN 漂移。

**glm组 独立核实（实测 xiling_wujia_L2_T1·2500 点）**：

**① 方差小——部分对·但不是主因**：
- score std=0.391（glm组 实测·与文档 0.377 接近）——**看似不小**（0~1 值域 std 0.39 算中等）。
- 但 **score 分布是 U 形多峰**（非正态）：
  ```
  0.0-0.2: 40.6% （Very Negative·score 集中 0~0.20）
  0.4-0.6: 17.7% （Neutral·集中 0.42~0.58）
  0.9-1.0: 29.7% （Very Positive·集中 0.81~1.0）
  中间（0.2-0.4 / 0.6-0.8）: 仅 8.5%
  ```
- 这是 **5 级极性分类映射到 0~1 的副产物**——每个极性档 score 集中在窄区间（Very Neg 0.06±0.05 / Very Pos 0.95±0.05）·档间有断层。

**② 更深根因（文档未提）：Gi\* 假设与输入变量类型不匹配**：
- Gi\* 原设计：**连续变量**（温度/房价/犯罪率）的局部均值 vs 全局期望。
- score 实际是：**离散 ordinal 变量**（5 级极性映射 0~1·非连续情绪强度）。
- Gi\* 计算"局部均值偏离全局期望"——但 score 的"期望"（0.457）落在 Neutral 档·而 Very Neg（0.06）和 Very Pos（0.95）都偏离·**它们是"类别"非"统计异常"**。
- 结果：Gi\* 把"极性类别聚集"要么误判为热点（类别同质区 z 高）·要么类别分散致 z 全小（EMC 当前情况）——**统计假设根本不成立**。

**③ KNN 漂移 + 阈值严——次要因素（文档已提·glm组 同意）**：
- KNN k=8 邻居 50m~2.5km（50 倍跨度）——空间尺度不一致·权重不稳定。
- 阈值 1.96（p<0.05）对 U 形分布过于严格（分布非正态·1.96 的 p 值假设失效）。

**glm组 根因补充判定**：
| 根因 | 文档 | glm组 | 主次 |
|---|---|---|---|
| 方差小 | ✓ 主因 | ✗ 部分对（std 0.39 中等·非极小） | 次要 |
| **分布多峰/类型不匹配** | 未提 | ✗ **主因**（U 形离散 vs Gi* 连续正态假设）| **主因** |
| KNN 漂移 | ✓ | ✓ | 次要 |
| 阈值严 | ✓ | ✓ | 次要 |

**网格化未改变全 ns 的解释**：网格化把多峰 score 平均成 score_mean·**平滑了多峰但未改变"局部 vs 全局期望偏差小"的本质**（全局期望和局部均值都向 0.457 收敛）·所以 Z 分布几乎不变·全 ns。✅ 文档判断正确。

### 焦点 2：修正方案（A/B/C）— **disagree B·建议 A 优先 + 长期重审方法**

**方案 A（降阈值 + 软分级）**：
- 做法：保 1.96 显著性 + 加"|Z|>1.0 倾向聚集"软分级（90% 档）。
- glm组 判断：**✅ 推荐优先**——
  - 演示可见热点（|Z|>1.0 标注·用户看到聚集区）。
  - 统计诚实（软分级标"90% 档·非 95% 显著"·与 1.96 档视觉区分）。
  - 改动最小（_classify_hotspot 加档位·不改 Gi* 公式）。

**方案 B（换 polarity_index）**：
- 做法：用 polarity_index（-2~2·std 大）替代 score。
- glm组 判断：**❌ 不建议（3 个阻断）**——
  1. **逐点数据无 polarity_index 列**：L2 CSV（xiling_wujia_L2_T1）的原生列是 `score`（连续）+ `polarity`（5 级分类字符串）·**无 polarity_index**（它是聚合层派生字段·spatial_analysis.py:277-282）。逐点 Gi* 用 polarity_index **需要先从 polarity 映射数值**（Very Neg=-2...Very Pos=2）——这是额外预处理·非"换列"那么简单。
  2. **polarity 数值化是离散 ordinal·非连续**：映射 -2/-1/0/1/2 后 std=1.736（确实大）·但**仍然是离散变量**·Gi* 的连续正态假设**仍不满足**。换 polarity_index 没解决焦点 1 的深层根因（类型不匹配）。
  3. **invert 语义混乱**：现状 invert=True 做 `1.0 - values`（为 score 设计·0~1 基准）。对 polarity_index（-2~2）：`1.0 - (-2) = 3.0`（基准 1.0 无意义）·语义不直观。正确 invert 应是 `-values`（负号翻转）·需改 invert 逻辑。

**方案 C（网格 + polarity + 降阈值）**：
- 做法：500m 网格 + polarity_index value_col + 阈值 1.65。
- glm组 判断：**⚠️ 次之（B 的阻断 1/2/3 仍在）**——
  - 网格层有 polarity_index（聚合计算）·阻断 1（无原生列）在网格层解。
  - 但阻断 2（离散 ordinal）和阻断 3（invert 语义）仍在。
  - 若做 C·须：① 网格用 polarity_index（聚合层有）② invert 改 `-values` ③ 阈值 1.65（90%）。
  - 改动最大（网格 + value_col + invert + 阈值）·收益不确定（离散变量 Gi* 仍存疑）。

**glm组 长期建议（超出本轮但须提）**：
- **Gi\* 可能不适合 EMC 的极性分类数据**——它是为连续变量设计的。
- 替代方案：
  - **KDE 核密度按极性分组**（已有 density 工具·分别跑 positive/negative 密度面）——天然适合"哪里消极密集"。
  - **DBSCAN 密度聚类按极性分组**——找"负面点密集区"·不依赖连续假设。
- 这两个比 Gi* 更贴合 EMC"情绪热点 = 某极性的空间聚集"语义。
- **建议**：本轮用 A（软分级）救急演示·**长期（热点图重做 P2/P3）评估是否换 KDE/DBSCAN 替代 Gi***。

### 焦点 3：演示价值 vs 统计严谨 — **agree（软分级不是放水·是合理的置信度档位选择）**

**glm组 判断：agree——降阈值/软分级不是"放水"·是统计实践中合理的置信度档位选择。**

**理由**：
1. **置信度档位选择是分析者决策**——0.05（1.96）/ 0.10（1.65）/ 0.20（1.28）都是统计实践中常用的·非"造假"。
2. **EMC 场景不是学术发表**——是规划辅助工具·90% 置信度（"|Z|>1.0 倾向聚集"）对"聚焦关注区"足够。
3. **诚实标注即可**——软分级在视觉/属性表上标"倾向聚集（90% 档）"·与"显著热点（95%）"区分·用户知情。
4. **对齐演示逻辑链**——全 ns 导致"热点图无热点"·用户看不到关注区·**演示链断裂**。软分级让图面有张力（聚焦关注区）·这是用户核心诉求。

**关键边界**：
- ✅ 合理：标"倾向聚集（90% 档）" + 视觉区分（如浅色/虚线 vs 深色/实线）。
- ❌ 放水：把 1.96 改 1.0 但仍标"显著热点（p<0.05）"——**禁虚假标注**。
- ❌ 放水：为出热点而 cherry-pick 参数（如只对某区域降阈值）——**禁选择性应用**。

**glm组 建议**：软分级方案诚实落地——
- 三档：显著热点（\|Z\|>1.96·p<0.05·深色实线）/ 倾向聚集（\|Z\|>1.0·p<0.16·浅色虚线）/ 不显著（ns·灰）。
- 属性表 `hotspot_tier` 字段标档位·`Gi_Z` 原值保留（可溯）。

### 焦点 4：距离带权重能否救 KNN 漂移 — **partial（能部分救·但治标·且 P2 后置）**

**glm组 判断：partial——距离带能缓解 KNN 尺度漂移·但治标不治本（深层根因是变量类型不匹配）。**

**距离带（DistanceBand threshold=500m·transform='R'）vs KNN（k=8）**：
- KNN k=8：每个点取最近 8 个·**不管距离**——城市密集区 8 个邻居在 50m 内·郊区在 2.5km·**尺度不一致**。
- DistanceBand 500m：取 500m 内所有点·**尺度统一**——密集区邻居多（权分散）·稀疏区邻居少（权集中）·**尺度一致但邻居数变**。
- 距离带**更符合"步行尺度聚集"语义**（500m = 5 分钟步行·社区尺度）。

**能否救全 ns？**
- **部分**——距离带统一尺度后·密集区的"负面聚集"可能 z 更高（邻居多 + 同质→ z 大）。
- **但不解决变量类型问题**——score 仍是 U 形离散·Gi* 假设仍不满足。
- glm组 判断：距离带**值得一试**（改权重方式是小改动）·但**不要期待它单独解全 ns**（变量类型才是主因）。

**是否提前做（P2→P1）？**
- **不建议提前**——P1 应先做 A（软分级·救急演示）·距离带是 P2 实验项。
- 理由：A 已能让演示有可见热点·距离带是"优化 z 分布"的实验·不阻塞演示链。
- 若 A 软分级后演示效果仍不足·再提前做距离带实验。

### 焦点 5：改动范围（P1 内参数化 vs 独立）— **agree（P1 内参数化·小改）**

**glm组 判断：agree——P1 内参数化·_classify_hotspot 加档位 + value_col/threshold 参数化。**

**改动范围核验**：

  2. `_classify_hotspot` 加档位输出（hot/tend_hot/ns 三档·或 hot/tend_hot/cold/tend_cold/ns 五档）。
  3. `hot_spot_analysis` 加 `threshold` / `soft_threshold` 参数透传。

**是否需独立评估？**
