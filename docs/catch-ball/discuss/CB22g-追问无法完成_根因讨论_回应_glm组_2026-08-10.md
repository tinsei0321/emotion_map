## 一、根因独立取证（含 FC 失败直接证据）

### 1.1 FC 秒回失败根因——前端 fetch 层·非 LLM·非后端 fc_diagnose 分支

**trace 证据（claude 已取证·glm 独立核实代码链路）**：
- `MOD_AIQA.F_005`（fcDiagnoseStep）10 次·0.2-0.3ms 秒回·**trace 无 MOD_LLM.F_002 错误在此会话** → 排除 LLM 401/网络（LLM 失败会有 MOD_LLM trace）。
- 0.2ms = fetch 立即 reject（连 HTTP 响应都没拿到·非后端返错·后端返错至少要 RTT）。

**glm 独立核实的代码链路**：

| 层 | 文件:行 | 证据 | 结论 |
|---|---|---|---|
| 前端 fetch | `api.js:95` | `fetch(\`${BASE}/chat\`, ...)`·BASE=`/api/v1`（api.js:3） | fetch 同源 `/api/v1/chat` |
| 前端超时 | `api.js:89` | `setTimeout(() => _ac.abort(...), 12000)` | 12s 超时·**0.2ms 远早于超时**·非超时 |
| 前端 HTTP 错误 | `api.js:96` | `if (!r.ok) throw new Error('FC HTTP ...')` | HTTP 4xx/5xx 才 throw·但需先拿到响应（非 0.2ms） |
| serve 反代 | `serve.py:199-226` | `_proxy_api`→urllib 转发后端 :8000·后端连不上返 **502** | 502 要等 urllib 连接尝试·非 0.2ms |
| 后端 fc_diagnose | `router.py:78-112` | `_fc_gen()` 把 LLMError/Exception **全包成 SSE `data:{"error":...}` 帧**·不让 HTTP 失败 | 后端分支异常**不会**致 HTTP 500·FC 秒回非后端分支抛错 |

**glm 根因判定（关键）**：

0.2ms 秒回 = **fetch 本身立即 reject**（fetch promise reject 在 HTTP 响应到达之前）。可能原因（按概率）：
1. **serve :8080 根本没起 / 用户开 file://** → fetch `/api/v1/chat` 立即 fail（无服务监听）。**最可能**——用户可能直接双击 html 或 serve 没起完整。
2. **serve :8080 起了但后端 :8000 没起** → serve 反代时 urllib 连 :8000 失败返 502·前端 api.js:96 `!r.ok` throw → stages.js:352 catch → degraded。但 502 要等 urllib connect 超时（~1s）·非 0.2ms。**次可能**。
3. **浏览器跨域/CORS**（如用户改了端口或开了 dev server）→ fetch 预检失败立即 reject。**可能**。
4. **AbortController 立即 abort**（ctx.signal 已 aborted）→ api.js:91 `if (opts.signal.aborted) _ac.abort()`。**可能**——若 harness 传了已 aborted 的 signal。

**glm 排除**（重要）：
- **非 LLM 401 被吞**——trace 无 MOD_LLM 错误·且 LLM 失败走后端 `_fc_gen` 的 LLMError 分支返 SSE error 帧（router.py:107）·前端 api.js:115 `if (obj.error) throw`·这是拿到响应后的 throw·非 0.2ms。
- **非后端 fc_diagnose 分支被 CB-22f 改动破坏**——router.py:65-112 的 `_fc_gen` 用 try/except 兜住所有异常（LLMError/Exception）·即使 `build_fc_sys_prompt` 或 `contracts_to_tools_schema` 抛错·也只返 SSE error 帧·不会致 HTTP 500。CB-22f 阶段 2 的改动（knowledge 契约/prompt 增量）**不会破坏后端路由**。

**glm 结论**：**FC 秒回失败是前端 fetch 层问题·须用户浏览器 console 取直接证据**（console 的 Network tab 看 `/api/v1/chat` 的 Status：`(failed)` = 服务没起/跨域·`502` = 后端不可达·`200` 但 SSE error = 后端分支异常）。**claude 怀疑"后端路由被改动破坏"不成立**——后端 fc_diagnose 异常全包成 SSE 帧·不会致 fetch 秒回。

**挑战 1：claude 怀疑"后端 router.py fc_diagnose 被 CB-22f 改动破坏"——glm 核实不成立·为什么？**
