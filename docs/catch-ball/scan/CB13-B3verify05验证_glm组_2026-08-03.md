## 第二部分：四项核验

### §1 PRM-08 根因定案（核心）

**现象**：`tools=extract_feature`（单工具）+ `boundary[ERR]`。问句「对比西陵区与伍家岗区范围内情绪极性差异」。

#### 1.1 排除项（先证伪两个误判方向）

**❌ 非 select_template 路由退化**。`paradigm.py:519` compare 路由条件 `decision_type=='对比' 或 问句含「对比/比较/VS/vs」`——问句首字即「对比」，关键词分支**必然命中** → template=compare。报告 `tpl=compare` 也证实路由正确。

**❌ 非测量层（3abb503）未生效**。3abb503 的修复（`test-cases.js:84-96` `_boundarySeen` append 收集 + `p.boundaries` ≥2 区时填充）逻辑完整且对路——但它只解决"compare 正确执行（zonal_stats×2）时测量能捕到两区"。本轮 tools=extract_feature **根本没走 zonal_stats**，所以 `_boundarySeen` 为空、`p.boundaries=undefined` → 断言 fail。**测量层修复没失效，是它守的前提（compare 执行）没成立**。

#### 1.2 定案根因：FC 阶段工具选择偏离（compare_regions → extract_feature）

**证据链**：
1. 测试断言（`test-cases.js:338`）：`expectBoundary='西陵.*伍家'`，要求 `p.boundary` 或 `p.boundaries` 同时含两区名。
2. 参数收集（`test-cases.js:86-96`）：`_boundarySeen` 只收集请求体的 `boundary`/`boundaries` 字段。
3. **extract_feature 的请求体无 `boundary` 字段**（契约 `tool_contracts.py:170-186`：params = `layer, where, as, keep`）→ `_boundarySeen=[]` → 断言必然 fail。
4. compare_regions 的 params = `boundaries(≥2 preset_id), agg_cols, layer, range`（`tool_contracts.py:152-167`）→ 若执行 compare，`_boundaries` 会被收集。

**结论**：FC 把 compare 问句的工具选成了 extract_feature（裁面而非对比聚合）。select_template 判对了 template=compare，但 **FC 阶段的工具选择与 template 路由脱钩**——FC 看 sys prompt 的「工具选择决策」+ 各工具 `when`，独立做选型，未消费 template 信号。

#### 1.3 FC 偏向 extract_feature 的强假设（**证据不足·仅假设**）

> ⚠️ 本轮 audit 的 `chat_phases` 为空 dict、`chat_body_keys=None`、trace.log 只记 ID 不记 FC payload——**FC 的实际请求/响应无留存**。以下为代码级推断，需 claude组 带 session 复跑 + console/网络面板取证方能定案。

- **假设 A·sys prompt 规则抢答**（`prompts.py:83`）：
  > **工具选择决策①**：「某范围内」=clip（点）/extract_feature（面）
  
  问句含「**范围内**」三字 → 这条规则可能在 compare 工具被考虑前就把 LLM 引向 extract_feature。
  
- **假设 B·extract_feature 的 `when` 含强示例**（`tool_contracts.py:170-177`）：
  > examples：`正:裁出西陵+伍家岗 where=MC/in/西陵区,伍家岗区`
  
  「西陵+伍家岗」组合在 extract_feature 的示例里高频出现，可能强化 LLM 对两区场景的 extract_feature 偏好。

- **假设 C·compare_regions 的 `when` 偏抽象**（`tool_contracts.py:154`）：
  > `when: '区域对比：≥2 个区/街道/单元并排对比情绪与归因，给差异方向'`
  
  缺「范围内」「极性差异」等问句实际用词的锚点，对模糊匹配不如 extract_feature 强。

#### 1.4 对照：RST-L02 同句却 PASS 的解释

RST-L02（`test-cases.js:361`）用**完全相同**的问句 `'对比西陵区与伍家岗区范围内情绪极性差异'`，但断言不同——只查 `pass: true` + `newLayers`，**不断言 boundary 参数**。所以即使 FC 同样选了 extract_feature，RST-L02 只要产了 2 层就 PASS。这解释了同句不同判：**PRM-08 是参数正确性轴（严查 boundary），RST-L02 是成果范式轴（只查产层）**。

> 推论：FC 对这句问句**稳定选 extract_feature**（RST-L02 也走 extract_feature 但不断言工具/参数故 PASS）。这反而支持"假设 A/B"——FC 的偏向是**系统性的**，不是偶发。
