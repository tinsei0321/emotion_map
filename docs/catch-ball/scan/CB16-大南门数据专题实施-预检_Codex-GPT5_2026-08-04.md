## 二、四预检问题

### 1. level='L3L4' 会被下游误伤吗？—— 数据层不误伤，前端有 2 个知晓点

全仓 level 消费点核验：
- **后端**：`get_layer_points`/`resolve_points` 不查 level ✅（用户判断正确）；`list_point_layers` 仅把 level 暴露进 `/geo/catalog`（信息性，LLM 可见）；SCALE_PARADIGM 的 `city_checkup_level` 是尺度字段，与数据层 level 无关。
- **前端**：
  - `harness.js:384` R5 胶囊防线：只放行 L1/L2，**L3L4 追问胶囊会被丢弃**（仅影响 UI 追问胶囊，非数据层；若出口卡片链路不走胶囊则无影响）；
  - `panel.js:683` 胶囊渲染 `c.level || 'L1'` 兜底；
  - `state.js:776-786` `layerLevel`/`levelPointColor` 对未知 level 返回灰色兜底，不崩；
  - **新风险点**：density 工具契约 `level` 枚举 = `['L1','L2','L3','L4']`（tool_contracts.py:48），不含 'L3L4'。但 density AI 路径走**前端可见层**（tools.js:1286 generateHeatmapForAI），本轮 ermawu 只走后端 /geo（zonal/aggregate），不走 density——风险实际低。**建议：本轮不动（非契约轮），SCAN 记一笔，后续若前端加载 ermawu 或 LLM 传 level='L3L4' 再处理（扩枚举或前端归一化）。**

### 2. backfill 一次性脚本 vs 改生成器重跑 —— 对路

赞成**一次性 backfill、不动生成器**：T1/T2/T3 是 seed 2606 确定性产物，已有数据是验证基线，重跑引入"环境差异污染已验证数据"的风险而收益为零；backfill 只加两列、数据本体零改动，可审计。
**建议**：按 `id_e` 匹配（实测同序唯一）而非纯位置；脚本加校验——行数=geojson feature 数、坐标域 sanity（宜昌约 111.2-111.5E / 30.6-30.95N）、幂等（重跑不重复加列）；CSV 保留 utf-8-sig BOM（三文件实测均带 BOM，pandas 默认读取与既有 yichang 同机制，无碍）。

### 3. manifest 兼容性 —— 结构兼容，但文件位置是关键补充

`load_preset`/`list_presets` 从 `_PRESETS_DIR = DATA/boundaries/presets` 解析 `item.file`（range_selector.py:293/:317）。既有条目可用性实测：admin_district ✅ / admin_community ✅ / land_* ✅ / admin_street ❌ / renewal_unit ❌（后两者文件缺失）。结构（group/items/{id,label,file,nameField}）与计划条目完全兼容；`nameField='name'` 与 load_preset 的 name 副本科逻辑兼容（nf 已在 columns 则不覆盖）。
**⚠️ 必须补**：把 `大南门二马路滨江片区.geojson` **复制**进 `DATA/boundaries/presets/`（勿移动——根目录文件被 test-cases loadRange 直接 fetch 引用）。

### 4. 时间轴 manifest 缺失影响发现吗？—— 不影响

`/geo/catalog`（geo_routes.py:45-51）只依赖 `list_point_layers()` + `list_boundaries()`（presets manifest），**不读 `_time_manifest.json`**；`resolve_points`/`get_layer_points` 也不读。ermawu 注册后即被 catalog 暴露、可被 resolve_points 加载——时间轴后置无影响 ✅。（未来时间轴恢复时按 T 切换才需要 time manifest，届时再补。）
