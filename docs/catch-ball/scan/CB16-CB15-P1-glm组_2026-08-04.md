## 第一节：4 子项逐项预检

### A. buffer 中文 POI 修复：✅ 后端 fallback 对路

**根因核实**（glm组 独立）：
- `geo_routes.py:537` `center = resolve_boundary(req.center)` ·`resolve_boundary`（geo_registry.py:146-181）只认 `preset_id`(str) 或 `GeoJSON`(dict)
- 中文"奥体中心"是 str 但非 preset_id → `load_preset('奥体中心')` 返 available=False → `FileNotFoundError` → 400

**草案**：后端 fallback——resolve_boundary 失败时调 search_place（中文名→POI 坐标→点缓冲）。

**glm组 判断：后端 fallback 对路（优于前端预解析）**。

**理由**：
1. **AI/前端共用一处**——buffer 是 AI 工具（FC 选型后后端执行），若前端预解析需在 tools.js:1211 前插 search 调用，但 AI 路径（runToolCall）和手动 dialog 路径都要各改一处。后端 fallback 一处覆盖全路径。
2. **search_place 已就绪**（geocode.py:188-235）——返回 `[{name,lng,lat,...}]`·坐标 WGS84·本地+高德双源。复用零新基建。
3. **fallback 语义清晰**——"center 不是 preset/GeoJSON 时·尝试当中文名搜"是合理的降级链。

**边界建议（glm组 补充）**：
| 边界 | 处理 | 理由 |
|---|---|---|
| **多命中取首** | `search_place(center, limit=1)[0]` | buffer center 是单点·首命中（forward 按分数降序）= 最佳匹配 |
| **search 无命中** | 诚实报错 `400 center 无法解析：{center}（非 preset/GeoJSON/POI 名）` | **禁编造坐标**（EMC 诚实铁律）·让用户重试/换名 |
| **坐标系统一** | search_place 返回 WGS84（:192 注释明示）→ buffer 内部 proj.to_crs(4546) | 已统一·零额外处理 |
| **fallback 只对 str center** | `if isinstance(req.center, str) and not preset: try search` | GeoJSON(dict) center 不走 fallback（已是坐标·无需搜） |

**实现位置建议**（geo_routes.py:536-537 改）：
```python
try:
    center = resolve_boundary(req.center)
except (FileNotFoundError, ValueError):
    # CB-15 P1：str center 非 preset → 尝试中文名 search_place 取坐标
    if isinstance(req.center, str) and req.center.strip():
        from core.geocode import search_place
        hits = search_place(req.center.strip(), limit=1)
        if not hits:
            raise HTTPException(400, f'center 无法解析：{req.center}（非 preset/GeoJSON/POI 名）')
        h = hits[0]
        center = gpd.GeoDataFrame({'name': [h['name']]},
                                  geometry=[Point(h['lng'], h['lat'])], crs='EPSG:4326')
    else:
        raise
```

### B. 评论↔POI 批量反查：✅ sjoin_nearest 对路·需定列名策略

**现状核实**：
- place_layer.reverse（place_layer.py:441-466）逐点 O(n·4310)（遍历 all_pois 算 haversine）·**不可批量**
- /geo/nearest（geo_routes.py:613）用 `gpd.sjoin_nearest(tgt_proj, pts_proj, distance_col='distance')`——**B 的范本**

**草案**：新 `attach_nearest_poi(points_gdf)`·layer 点 × all_pois sjoin_nearest·批量落 nearest_poi_name/id。

**glm组 判断：sjoin_nearest 对路（O(N·M) → O(N+M) 有空间索引）·列名须加新列禁覆盖**。

**性能核验**：
- sjoin_nearest 依赖空间索引（rtree/pygeos）·4310 POI × N 点·有索引 = O(N+M+k)·毫秒级
- 无索引退化 = O(N·M) 暴力·**须确认 rtree 已装**（glm CB-15 P0 已提醒·Wave 2 测试应已覆盖）

**列名策略（glm组 关键建议）**：
| 选项 | 判定 | 理由 |
|---|---|---|
| **加新列 `nearest_poi_name` / `nearest_poi_id`** | ✅ **推荐** | 不污染既有 area_seed/spatial_hotspot（sim 期标注·保历史）·下游可选消费 |
| 覆盖 area_seed | ❌ **禁** | 破坏既有字段语义·sim 数据回归风险 |

**落列位置建议**：
- 新列：`nearest_poi_name`（str）+ `nearest_poi_dist_m`（float·距离米）+ 可选 `nearest_poi_category`
- **不加到 L1/L2 CSV 文件**（避免改生成器）·而是**运行时附加**（聚合时或端点返回时 sjoin_nearest 落到 GeoDataFrame）

**实现位置建议**（core/spatial_analysis.py 新函数）：
```python
@track("MOD_SPATIAL.F_009")

    from core.place_layer import get_place_layer

    pts_proj = points_gdf.to_crs('EPSG:4546')

    j = gpd.sjoin_nearest(pts_proj, poi_proj, distance_col='nearest_poi_dist_m')
    # 落列（按 index 对齐回 points_gdf）
    ...
```

**范围建议（glm组 倾向后置 B 到 Wave 3）**：
- A/C/D 是"让地点进 AI 问答管线"的核心（治 LLM 不可见地点 + buffer 中文失败 + 出口卡落点）
- B 评论↔POI 批量是"评论级地点关联"——更偏数据增强·非问答路径阻塞。**可后置**。

### C. lookup_place AI 工具：✅ 纯前端调两端点对路

**草案**：TOOL_CONTRACTS 新条目 + tools.js TOOLS 方法（纯前端调端点）+ SKILL_DEFS + GEO_VERB_KW + track ID。

**glm组 判断：纯前端调两端点对路（不新增后端 TOOL_CONTRACTS 条目）**。
