### 3. 契约 when 两模式 + alias — **partial（when 落地·alias 解析断裂）**

| 核验点 | 结果 | 证据 |
|--------|:---:|------|
| `when` 明写两模式 | ✅ | `tool_contracts.py:209` when 含"多图层 concat + 单层 dissolve + overlay union 勿代替"三段明示 |
| `params_str` 含 layers | ✅ | `:210` `'layers(多图层) 或 boundary(单层), by(字段) \| all'` |
| `failure_modes` 加 overlay 警告 | ✅ | `:213` "多图层合并勿用 overlay union（字段后缀冲突）" |
| `layers` 参数 alias 含 `layer_list` | ⚠️ | `:216` alias 声明 `['layer_list', 'layers_list']`——**但 alias 未实际解析**（见下） |

**🔴 alias 解析断裂（新发现·partial 原因）**：

契约参数定义声明了 `layers` 的 alias 为 `['layer_list', 'layers_list']`，但：

1. **后端 `validate_tool_call`**（`tool_contracts.py:510`）：one-of 检查在 alias 解析**之前**执行——`not fixed.get('layers')` 检查的是字面 key `layers`，LLM 若用 `layer_list` 则该 key 不存在 → one-of 触发拒绝。`validate_tool_call` 全函数无 alias 解析逻辑（`:513-540` 的循环只查 `fixed.get(name)`，不查 alias 反向映射）。

2. **前端 `normalizeParams`**（`stages.js:14-26`）：`_PARAM_ALIAS` 和 `_TOOL_ALIAS` 均不含 `layer_list → layers` 映射——alias 只在契约 dict 里声明，前端硬编码别名表不消费它。

**运行时验证**（`validate_tool_call` 直调）：
```
validate_tool_call('merge', {'layer_list': ['L011','L012']}) → ok=False
  → layers=None（alias 未解析·one-of 触发拒绝）
```

**严重度评估：低**。原因：
- `when` 字段已明确指示 `merge(layers=[id1,id2,...])`——LLM 应直接用 `layers`（规范名），而非 `layer_list`（别名）
- `layer_list` 是 LLM 在旧版（无 `layers` 参数时）的猜测——现在 `layers` 已是正式参数 + `when` 明示，LLM 用规范名的概率高
- 但这是一个**声明的 alias 实际不生效**的诚实性缺口——如果 LLM 仍用 `layer_list`（V4 Flash 概率性行为），会被拒绝

**修复建议**（后端 3 行）：在 `validate_tool_call:510` one-of 检查前，先做 alias 反向解析：
```python
# one-of 检查前·先解析 merge alias（layer_list/layers_list → layers）
if tool_name == 'merge':
    for _alias in ('layer_list', 'layers_list'):
        if _alias in fixed and 'layers' not in fixed:
            fixed['layers'] = fixed.pop(_alias)
```

## 条件项（需浏览器验证前处理）

### 条件 1（中）：alias 解析断裂（详见核验 3）

`layer_list` alias 声明但未实际解析。LLM 若用 `layer_list`（而非规范名 `layers`）→ 被 one-of 拒绝。

**修复**：`validate_tool_call:510` 前加 alias 反向解析（3 行）。
**风险**：低（`when` 已明示用 `layers`），但属"声明的能力实际不生效"的诚实性缺口。

### 条件 2（中）：autoExpand merge 路径跳过 finalStep

`_autoExpandOverlays` 的 merge 分支（`harness.js:1371-1372`）返回 `final: _obs`——直接把 observation 字符串当最终答案，**跳过了 finalStep LLM**。

```javascript
return { ok: true, rounds: 1, final: _obs, ... };
//                                      ^^^^ raw observation·非 finalStep 结论
```

用户看到的结论会是原始 observation（如"合并后得到 3 个要素，总面积 6.8 平方公里"），而非三句骨架格式化结论（动作+产出+交互按钮）。

**对比**：recover 路径（`:1235-1240`）返回 `template:'merge'` diagnose → 走 `runTemplatePath` → 后者会调 finalStep。autoExpand 路径不走 finalStep 是**不对称**的。

**修复**：autoExpand merge 分支应走 `runTemplatePath`（像 recover 一样合成 synthDiagnose），而非直接返回 raw observation。或在返回前调 `finalStep`。

**风险**：中（UX 退化·用户看到的是 observation 而非格式化结论 + `{{show:}}` 按钮）。

## 建议项（不阻塞验收）

### 建议 1：`_opMerge` layers 模式命名（`vector-tool.js:94`）

```javascript
const name = params.as || String(params.boundaryLabel || params.boundary || '合并范围');
```
layers 模式（无 boundary）+ 无 `as` 时，name 默认 `'合并范围'`——不区分"合并了哪些图层"。AI 路径（`TOOLS.merge`）传了 `as`，但 Toolbox dialog 路径若未来支持 layers 时会受影响。建议加 `|| (params.layers ? '合并'+params.layers.length+'图层' : '')`。
