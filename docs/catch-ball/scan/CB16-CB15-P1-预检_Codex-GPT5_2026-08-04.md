## 二、四子项预检

### A. buffer 中文 POI —— 后端 fallback 对路（P1）

**方案**：`/geo/buffer` 的 `resolve_boundary(req.center)` 失败（FileNotFoundError/ValueError）时 → `search_place(center)` → top-1 命中转点 center → 点缓冲。

**边界（草案需明确）**：
1. **preset 优先**：resolve_boundary 的 preset_id 路径不动；fallback 仅在 load_preset 失败后触发（"行政区"既是 preset 又是地名·preset 语义优先 ✓）。
2. **多命中取 top-1** + observation 标注来源（"已按『奥体中心』命中 XX（本地/高德）·如非所指请指定"）——诚实可纠错。
3. **无命中诚实 400**（detail："未找到地点 X·请改用已加载范围或上传"）——不硬猜（守 CB-15 定性一）。
4. **坐标统一 WGS84**：search_place 已保证 → resolve 后走既有 4546 米制 buffer（点 buffer 是天然操作）✓。
5. **fallback 不污染 resolve_boundary**：放在 buffer 端点层（catch 后分支），只增不改。

### B. 评论↔POI 批量反查 —— sjoin_nearest 对路（P1）

- `attach_nearest_poi(points_gdf)`：points（评论点）→ 4546 → `sjoin_nearest(points, poi_gdf, distance_col='distance')`——rtree 索引·4310×N 毫秒级（远优于逐点 reverse）。
- **落新列** `nearest_poi`/`nearest_poi_dist_m`——**不覆盖** area_seed/spatial_hotspot（模拟期语义锚点·覆盖会破坏 sim 兼容与既有断言）。
- 空覆盖点（远离城区）→ 空值诚实标注；distance 单位=米（4546）。
- **P1 保留建议**：评论↔POI 是"归因→地点落点"（出口卡评论集）前置，属 P1 核心；若压缩范围可 P1b 后置，但保留更符合用户下钻链。

### C. lookup_place 工具 —— "契约后端 + 实现前端"混合（P1）

- **架构**：TOOL_CONTRACTS 注册（单一权威源·CB-04 铁律）+ 前端 tools.js TOOLS 方法（调 /place/search + /reverse-geocode）+ SKILL_DEFS + emc-patterns GEO_VERB_KW + register_track_id（连续编号）——与现有工具完全同构（契约后端·执行前端）。草案正确。
- **触发词**：建议 `有什么/周边/地点/在哪/位置/附近/坐标`（现有 3 词偏窄·"奥体中心在哪"是最常见问法）。
- **工具形态**：查询型（无图层副作用）·q 或 lng/lat 二选一（forward/reverse 双模式）·返回 observation 地点清单。

### D. 归因落点模板 —— 需扩展 `+` 组合（P1）

- 方案对路（需求位置 = place_name + poi_names + issue_label 合成·"大南门·二马路（滨江公园、xx小区 等3处）·停车难"）。
- **实现要点**：现 field_mapping 的 `+` 只取首字段（`split('+')[0]`·build_outlet_schema.py:154）——需扩展为真正多字段组合（`+` 分隔 → 逐个 `_extract_emc_value` → 非空 join）。
- **回归**：既有 `test_outlet_schema` 断言 `'大南门' in 需求位置` 仍应通过（place_name 在组合内）✓；需更新断言覆盖合成格式。
- **P0 附带**：:179 陈旧文案（"CB-15 后升级 POI 双源"）——Wave 2 已双源·改"POI 双源（poi_sjoin/top_places）+ place_name_source 可追溯"。
