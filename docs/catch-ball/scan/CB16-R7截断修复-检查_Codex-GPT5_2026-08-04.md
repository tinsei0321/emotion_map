## 二、五项检查

### 1. 阈值 1500 是否合理 —— 合理，不建议动态化

- **用户场景完整通过**：模拟构造 1130 字多要素结论（需求类型/强度/位置/归因/对接/优先级）→ 不触发 R7，仅 R2 追加按钮 ✅。
- **拦得住失控长文**：2580 字失控文 → R7 触发，截断在句末（1494，最后一个句号+1）✅。
- **不建议按结论类型动态调**：静态 1500 + 结构回切已覆盖"多要素结构化长文"；动态阈值引入分类风险（误分类→漏拦或误伤），收益为零。若未来出口卡片常态逼近 1500，再评估。

### 2. 断句符 —— 够用，建议补 ！？；下限 750 合理

- 当前 `。；\n.` 覆盖绝大多数结构化结论（列表项换行 + 句号）。**遗漏 `！？`**：中文结论句末常见；缺它们时回切可能落到更远的 `\n` 或硬切 1500 中句。
- **建议（低优）**：断句符集合加 `！？`（一行改动，确定性）。
- 下限 750 合理：防"早断句符（<750）导致过度截断"；无断句时硬切 1500 兜底。

### 3. R2 后移无副作用

- `realLayers` 在函数**顶部一次性计算**（`reg.filter(...)`，applyQualityDefense 开头）——R7 的 `_hasLayers` 与 R2 用同一快照，后移不影响取值。
- R7 先于 R2 → 追加按钮不计入长度检查（正确：按钮短，且避免"截断→追加→再超"循环）。
- R3/R4/R9 均不依赖 R2 追加内容（R3 扫数字、R4 扫成败词、R9 扫动作——按钮文本不含这些模式）。R9 在 R7 前（原序未变），R9 注记被 R7 切掉是既有行为，非本次引入。
- ✅ 无副作用。

### 4. 文案场景化对路

- 有图层「详见上方图层与数据」：准确（按钮在注记后追加，用户可点）。
- 无图层「结论较长已精简·详见上方分析」：不再误导（旧文案"详见上方图层"在无图层时是谎言）；"详见上方分析"略循环（分析即被截断的结论本身），可选改为纯「结论较长已精简」——低优。

### 5. 关键：{{show:}} 按钮在截断后保留 ✅（含边界分析）

- **主路径**：draft 无 `{{show:}}` + realLayers 非空 → R7 截断 → R2 条件 `!/\{\{show:/.test(final)` 命中 → 追加完整按钮（模拟：按钮出现在截断注记**之后**）✅。
- **draft 自带 {{show:}} 在截断点前**：保留完整，R2 跳过（不重复）✅。
- **draft 自带 {{show:}} 在截断点后**：被切掉 → R2 重新追加 ✅。
- **切中间残句**：实际不可能——断句符 `。；\n` 不会出现在中文图层名内，切点 c 必为断句符，不可能落在 token 内部（`.` 理论上可在英文名内，但图层名为中文 UI 标签，可忽略）✅。
- **窄窗残留（低优·建议硬化）**：若 `\n4.\n` 标题恰好落在 [最后句号, 1500] 窗口内且之后无断句符，回切可能落在标题后的 `\n` → 悬空「4.」仍可能出现（实测构造确认）。**建议一行硬化**：截断后 `final.replace(/\n\d+\.\s*$/, '')` 剥除悬空列表编号行。
