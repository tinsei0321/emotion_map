**核验**：

**无副作用**：`CSV_T2/T3` 仍为定义未用（同改动前）；L1 CSV 体积大但被 `await` 覆盖，仅用例耗时增加（~1-3s）。

## 二、改动② PRM-08 compare `_allToolCalls` 重写 —— 正确·治根因

**diff**（`frontend/js/ai_qa/harness.js:1471-1478`）：compare 分支在 `_bs.length >= 2` 时把多 call `_allToolCalls` 重写为 `[{name:'compare_regions', params:{boundaries:_bs}}]`。

**核验**：
1. **调用顺序（关键）**：`deriveMissingParams` 挂在 G1 参数补全层（`harness.js:1036`），在 `runAllToolCalls` 分发（`:1077`）**之前**——重写必然生效，不会再被 FC 多 call 批量执行绕过。✓
2. **模式对齐**：与 clip 分支（`:1436-1439`，PRM-10 同款）和 zonal 分支（`:1464-1466`，PRM-07 同款）逐字同构——`{name, params}` 结构、覆盖条件（`_allToolCalls.length > 1`）一致。✓
3. **边界（请求关注点）——区名 <2 时安全**：`_n.length >= 2`（问句可抽出 ≥2 区名）与 `_bs.length >= 2`（实际派生成功 ≥2）双闸。任一不满足 → 不重写、也不设 `p.boundaries` → FC 原 calls 原样走 `runAllToolCalls`。这是**保守兜底**（派生不确定时不动 FC 意图），不产生崩溃或错误注入。✓
4. **误改风险**：重写仅在 compare 分支条件内触发（问句含 对比/比较/vs + tool≠compare_regions 或 boundaries<2 + 双区可派生）。非对比问句零触碰；FC 已正确返回 `[compare_regions]+boundaries≥2` 时分支根本不进入。✓
5. **已知限制（非本次引入）**：复合问句（"对比两区 + 次级操作"）会被折叠为 compare 单 call、丢弃次级 call——与 clip/zonal 分支的既有取舍一致，属模式级已知行为，不单列修复。
6. **根因闭合**：PRM-08 的机制是 FC 出 `extract_feature×2`（多 call）→ `:1077` 批量执行绕过强制 compare。重写后：问句含 西陵区/伍家岗区 → 行政区层逐区派生 → `_bs=2` → 重写为 compare_regions 单 call → 走 compare 确定性执行（zonal_stats×2 + compare）→ `_extractParams` 可捕获双区（3abb503 测量端终于有数据可测）。**上轮"测量修复 ≠ 执行修复"的缺口本次补上执行侧。**

### 3.3 体积实测（**与请求描述不符，需修正口径**）

| domain_lens | final_brief 实测 | final prompt 实测 |
|---|---:|---:|

**每域实际 ~1.6KB**（政策方向 2 条带 gist + 术语 4 条带解释 + 底线 2 + 项目类型 5 + 情绪归因焦点 + 4×5 主归属），是宣称 0.6KB 的 2.7 倍。典型情绪分析 1-2 域 → 每问 +1.6-4KB；4 域全命中上限 +7.2KB。

### 3.4 是否该限"仅归因类问句"？—— 我的判断：**当前不需要硬限，但要观察**

- **自然门控已存在**：注入仅当 domain_lens 为非空非 general。GIS 操作/概念问 → `general` → 不注入；情绪分析类（zonal/rank/compare）→ 具体领域 → 注入。`_deriveDomainLens` B 部关键词兜底可能让个别工具问句也命中领域（如含"规划/社区"关键词的密度问），但覆盖面小。
- **归因速查对聚合/排序/对比类都是适配骨架**（4×5 主归属正是这些问句的结论落点），硬加 `decision_type∈{归因,排序,对比}` 门控反而有"漏注"风险（如 zonal+4×5 归因被误排）。
- **建议**：保留现条件，**以 B3-verify-06 延迟与答案风格为观察哨**——若纯"统计/出图层"答案被带偏（堆政策话术）或 p95 明显回升，再加 `decision_type` 门控。可选项：`seen.slice(0,2)` 限 2 域（真实 FC 单域为主，4 域全注罕见），把上限压到 ~4KB。

### 3.5 渲染质量

实测 urban_renewal 速查块：主管/政策方向(带 gist)/术语(带解释)/底线指标/项目类型/情绪归因焦点/4×5 主归属——**"政策→情绪→项目"链条完整**，信息量足支撑归因结论；比全 4 域 `brief_text`（1.1KB·无政策方向/归因焦点）更适合 finalStep。选用 `final_brief` 而非 `brief_text` 正确。✓
