## 一、gate 连锁假说修正

### glm组 上轮假说（不成立）

> "gate 全局开关 + localStorage 跨 session 累积 miss → 命中率跌 < 0.6 → 所有 single 模板被挡 → while-loop 连锁"

**铁证推翻**：`ai_qa_template_stats_v1 = {}` → `hits=0, misses=0, samples=0 < 10` → `_tplHitRateReady()` `:118` `return true`（冷启动放行）→ **gate 恒 PASS**。

**glm组 上轮 case 7-8 推断（"gate FAIL 窗口"）是错误的**——gate 从未 FAIL。while-loop 的集中性（case 7-8 被 single-tool 包围）有其他解释：**case 7-8 的 FC 返回了 unknown/multi**（特定问句触发的 FC 行为），而前后 case 的 FC 返回了 single 模板。这不是 gate 振荡——是 **FC 对特定问句的概率性输出差异**。

### 修正后的 case 7-8 解释

```
Case 1-5: FC 返 single 模板（zonal/buffer）→ 单工具路径满足 → runTemplatePath
Case 6:   FC 返 valid 但可能 ask_user（GAP = 无工具执行）
Case 7-8: FC 返 unknown/multi → _tdef.category ≠ 'single' → 单工具路径不满足 → while-loop
Case 9-10: FC 返 single 模板（clip/extract）→ 单工具路径满足 → runTemplatePath
```

**while-loop 集中性 = FC 对 case 7-8 问句返 unknown/multi·对其他问句返 single**——与 gate 无关。

## 二、Codex 替代定案确认

### 定案：FC 成功但返 unknown/multi → 单工具路径不满足 → while-loop

**glm组 确认成立**。代码路径已核实：

1. FC 返 `unknown` → `:209-210` `normalizeCard` 归一为 `'unknown'`（SKILL_DEFS 有 `unknown` 条目·category='unknown'）
2. `:1062` `!diagnose.degraded && diagnose.template` → `template='unknown'` 是 truthy → 进 `:1062` 块
3. `:1063` `_tdef = SKILL_DEFS['unknown']` = `{category: 'unknown', ...}`
4. `:1064` `_tdef.category === 'single'` = **false**（category='unknown'）→ 跳过 runTemplatePath
5. `:1081` `diagnose.chain` = 无 → 跳过 runChainPath
6. `:1082` `template === 'multi'` = false（是 unknown 非 multi）→ 跳过
7. `:1086+` → **直落 while-loop**

同理 FC 返 `multi` → `:1064` category='multi' ≠ 'single' → `:1082` template='multi' → 查 CHAIN_REGISTRY → 未命中 → **while-loop**

**recover 不触发**（`:973` `_deterministicRecover` 只在 `diagnose.degraded` 时调用·FC 成功 = 非 degraded）。

### 关键缺口：recover 只在 FC 失败时触发

```
FC 失败（degraded）→ :973 _deterministicRecover → 模式 A-G 覆盖
FC 成功返 unknown  → 非 degraded → 跳过 recover → 单工具路径不满足 → while-loop
```

**FC 成功返 unknown = 比 FC 失败更危险**——FC 失败至少 recover 兜底；FC 成功返 unknown 则 recover 跳过·直落 while-loop。这是 Codex 定案的核心洞察。

## 三、修复优先级确认

| 优先级 | 修复 | glm组 判定 | 理由 |
|:---:|------|:---:|------|
| **P0** | **recover 扩展触发**（FC 成功返 unknown/multi 时也触发 recover·不只 degraded） | **agree Codex** | 根治本次回潮——FC 成功返 unknown 目前无兜底·直落 while-loop。recover 扩展 = 给 unknown 一个确定性出口 |
| **P1** | gate per-template 判断（unknown 才受 gate） | **agree 但降级** | gate 连锁假说不成立（gate 恒 PASS）·但 gate 结构性缺陷（全局开关）仍是潜在风险——localStorage 有累积时可能翻转。P1 不阻塞 |
| ❌ | 回退 1ddac28 | **disagree** | 两组一致：1ddac28 不改 gate/recover 入口 |

### Codex P0 定序认同

**agree Codex 的 P0 定序**：recover 扩展触发 > gate per-template。

理由：
- 本次回潮根因 = FC 成功返 unknown 无兜底（recover 缺口）→ P0 修 recover
- gate 连锁是**潜在风险**（当前 samples=0 不触发）→ P1 防御
- recover 扩展 + gate per-template **不冲突·应都做**——recover 修直接根因·gate 修潜在风险

### recover 扩展触发的具体建议

```javascript
// 当前（harness.js:973）——只在 degraded 时触发
if (!diagnose || diagnose.degraded) {
  // ...
  const _recovered = _deterministicRecover(ctx);
  // ...
}

// 建议——FC 成功返 unknown/multi 时也触发 recover
if (!diagnose || diagnose.degraded || 
    (diagnose.template === 'unknown' || diagnose.template === 'multi')) {
  // degraded 或 unknown/multi → 尝试 recover
  const _recovered = _deterministicRecover(ctx);
  if (_recovered) {
    diagnose = _recovered;  // recover 命中 → 用确定性 diagnose 替代
  }
}
```

**注意**：recover 应在 `:1014` `deriveMissingParams` **之前**触发——因为 deriveMissingParams 依赖 valid template（`:1343` `const tool = method[0]`），unknown/multi 的 method 可能无有效 tool 名。或者 deriveMissingParams 内加 unknown/multi 检查·先路由修正再 derive。
