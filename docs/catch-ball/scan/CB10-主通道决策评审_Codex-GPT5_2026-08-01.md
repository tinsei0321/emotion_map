## 一、五个分歧点的独立判断

### 分歧 1：A vs B 架构取舍 —— **选 A**

**理由**：B 的核心赌注（改 FC prompt 让 Flash 稳定输出多 tool_calls）在实证上不成立——07-30 已试过（`SESSION_2026-07-30.md` P02："根因：Flash function calling 天然倾向单 tool_call"，`b2bdca9` 促多 call 后 `0073990` 回退），且 L01 明确"每次改 prompt 都可能触发 LLM 输出格式变化"。这是**模型能力限制**，不是 prompt 工程能可靠克服的；B 的收益是低概率、高成本（行为回归风险 + 全量重验）。

A 的缺点（正则覆盖盲区）是真实的，但**缓解路径便宜**：匹配逻辑收敛为单一函数 + 命中遥测（见分歧 2/4）。不做 A 而做 B，等于用一个高概率出问题的改动换一个低概率收益。

**补充定位修正**：与其说"双通道并存"，不如明确三层定位——**确定性补全 = 常态主通道**（Flash 单 call 是常态，多步执行实际都走它）；**LLM 多 call = 性能机会通道**（偶尔加速）；**`_deterministicRecover` = 失败兜底**。三个不是对等通道，是不同触发条件下的同一目标（完成多步）。

### 分歧 2：正则补全去留 —— **必须保留（无论 A/B）**

两个层次都必须留：

1. **`_deterministicRecover`（FC 失败兜底）**：`stages.js:312-314` 显式 `no_tool_calls → degraded`，无它则整问失败。这是失败路径的生存线，删除等于把 EMC 挂在 LLM 可靠性上。
2. **inline / `_autoExpandOverlays`（成功路径单 call 补全）**：Flash 单 call 是常态，无它则多步根本不执行。即使未来走 B（LLM 多 call），LLM 仍会大量单 call，补全依旧必需。

**退役条件**（B 下也不退役，只有遥测满足才退役）：某模式命中计数趋近零 + LLM 多 call 已覆盖该场景，两者同时成立才删对应规则。

### 分歧 3：半成品修复后的新现状 —— **部分满足族 A，但"统一"未达成**

a5eb3e1 **满足了族 A 的时序需求**（全步骤完成 → 单次答案，不再先渲染半成品），这是实质进步。但"统一多步执行"仍是目标而非现状，证据：

1. **覆盖仍窄**：内联扩展只触发 `extract_feature` 首步 + 区/用地模式（`harness.js:522-525` 的触发正则）。`merge→clip`、`filter→density` 等其它多步形态在成功路径仍无补全；
2. **成功路径无 union/merge 分支**："合并 N 类用地"的 union 链只在 `_deterministicRecover` 模式 C（失败路径）存在，FC 成功时 LLM 单 call 选 merge/overlay → 仍会半途而废；
3. **内联路径无 N/M 完成度判定**：内联扩展失败只 push 一条 `扩展-X: overlay 异常` 到 toolHistory（`harness.js:543`），没有 `runAllToolCalls` 那套"仅完成 X/Y 步"确定性追加——部分失败时 finalStep 仍可能写出完整结论，R4 只拦固定矛盾短语。

**结论**：A 可以定型，但族 A 闭环还需 3 件小事（见最终建议）。

### 分歧 4：`_deterministicRecover` 分工 —— **分工合理，但存在不对称**

触发位置（失败兜底 `harness.js:810-819` vs 成功补全 `harness.js:894-901`）互斥、无冲突，分工本身正确。**不对称点**：

- 模式 A/D（单用地+双区 / 多类用地）的成功路径等价物刚补齐（inline/autoExpand）；
- 模式 C（merge/union 链）**没有成功路径等价物**——成功路径 autoExpand 只做 intersection；
- 模式 B（zonal 归因）无成功路径问题（它是单工具，不属于多步）。

建议把"构建 overlay 补全链"抽成成功/失败两路共用的同一函数（含 intersection + union 两个 mode），消除不对称和三分重复。

### 分歧 5：演进路径 —— **A 定型 + B 作为模型换代后的评估项**

同意项目方方向，补充顺序：

1. 先把 A 的 3 件小事做完（统一补全函数 / 成功路径 union 分支 / N/M 判定全覆盖）；
2. 加命中遥测（inline/autoExpand/recover 各自命中计数，进 episode 或 console 可查）；
3. 遥测驱动退役（命中趋零 + LLM 多 call 覆盖 → 删对应规则）；
4. 模型换代（更强的 FC 能力）后，再评估"促多 call"（B）——届时 prompt 改动风险与收益比会重算。

## 二、最终架构建议

### 主通道定型方案（A + 三层定位）

```text
多步执行主通道（定型）：
  FC 诊断（1 次）
    ├─ LLM 多 tool_calls → runAllToolCalls        [机会通道·加速器]
    ├─ 单 tool_call + 成功 → 内联扩展 / autoExpand  [常态主通道·确定性补全]
    │      └─ 完成度：统一 N/M 判定（所有通道）
    └─ FC 失败 → _deterministicRecover 模式 A/B/C/D [失败兜底]
  └─ 全步骤完成后 → 单次 finalStep → 质量防线
```

### 三个必做的收尾（A 闭环）

| # | 动作 | 文件 | 理由 |
|---:|---|---|---|
| 1 | 抽共享补全函数 `buildLanduseCompletion(question, firstLayerName, mode)`（intersection + union 两分支），inline / `_autoExpandOverlays` / recover 模式 A/C/D 全部改调它 | `frontend/js/ai_qa/harness.js` 或新 `completion.js` | 消除 3 份近似重复；模式 C 的成功路径等价物顺带补齐 |
| 2 | N/M 完成度判定从 `runAllToolCalls` 提升为共享出口（inline 扩展路径也追加"已完成 X/Y 步"） | `frontend/js/ai_qa/harness.js` | 内联部分失败时结论层仍能确定性声明，不被 LLM 措辞掩盖 |
| 3 | 补命中遥测：inline/autoExpand/recover 各自命中计数 | `frontend/js/ai_qa/harness.js` + episode | 为遥测驱动退役提供数据 |

### 演进路径

**B 不做当前投入**——降级为"模型换代后评估项"。演进顺序：收尾 3 件事 → 遥测 → 条件退役 → 换代后重估 B。

### 风险提示

- **43s 延迟**：B002 43s 高于设计的复杂问 15-20s 预算。`runTemplatePath` 路径没有 while-loop 的 30s 总预算（`harness.js:743` 的 deadline 只在 while-loop 生效），建议给单技能路径加一个 45-50s 总预算兜底，防未来 4+ 步场景拖死。
- **内联触发正则**（`harness.js:522-523`）是又一条内联正则——收尾 #1 时应一并移入共享函数/注册表，避免重蹈"词表集中、逻辑散落"。

## 三、一句话结论

**选 A 定型**：Flash 单 tool_call 是模型现实，"促多 call"（B）是低概率高成本的赌注；A 的半成品修复已解决时序问题，再补"统一补全函数 + union 分支 + N/M 判定全覆盖"三件小事即可闭环族 A；正则补全全程保留，用遥测驱动渐进退役，B 留待模型换代后再评估。
