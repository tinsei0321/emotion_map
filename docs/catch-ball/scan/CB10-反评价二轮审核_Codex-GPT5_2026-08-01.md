## 三、分歧点评估

### 分歧 1：P0-1「计划→执行」管道（最大分歧）

**判定：对方案A/B 取舍 = agree；对"B005 走 `_allToolCalls` 覆盖缺口" = partial（机制不成立）**

事实核实（全部确认项目方陈述正确）：

- `executePlans` 死代码：全仓库仅定义（`harness.js:1320-1360`），零调用；git 历史显示调用点在 `176ff65/f4845b3/f3e30aa` 引入后已被移除。
- `_allToolCalls`→`runAllToolCalls` 是 D057 修订后的执行通道（`stages.js:331-340`、`harness.js:890-901`）。
- plans[] 是 CPD 的设计输入（`arch/08-cpd-engine.md` D054），保留概念有设计依据。

取舍评估：

- **删死执行器 + 留 CPD-RESERVED：合理**。死代码会诱导后人"直接调它"——而它是错误修复路径（plans[] 的 params 为 LLM 生成、未校验），删除比保留安全。
- **"走 `_allToolCalls` 覆盖缺口"不成立**，两条证据：
  1. Flash 天然倾向单 tool_call——项目方自己的 07-30 教训（`SESSION_2026-07-30.md` P02："根因：Flash function calling 天然倾向单 tool_call"）；当前 FC prompt 第 3 行还写"多步骤请求→先做第一步，系统自动补全后续"（`router.py:55`），`_allToolCalls` 几乎恒为 1 项。
  2. `_deterministicRecover` 只在 FC 失败时触发（`harness.js:810-819`：`if (!diagnose || diagnose.degraded)`），B005 是成功路径，模式 D 打偏位置。

**推荐**：B005 确定性补全走成功路径的 `_autoExpandOverlays` 扩展——把 `_mentioned.length < 2 && !_isWildcard → return null`（`harness.js:1252-1255`）放宽为"≥1 个用地关键词 + 问句含区名/刚产出边界层"→ 为单用地生成 1 条 `overlay(boundary ∩ 商业用地)`。现有 `_firstLayerName` 排除逻辑（`harness.js:1262`）可防重复叠置。`_allToolCalls` 保留为机会通道，不承担主修复责任。

补充：`0073990` 一次删掉 plans 产出指令、domain_lens 输出指令、CB-09 M2"多要素提取"段；当前 `ctx.plans` 只有后端自建的 rank=1 单元素（`router.py:96-105`）。**CPD-RESERVED 目前是空骨架**——若 CPD 要复活，plans 产出指令必须同步恢复。建议记入 KNOWLEDGE，避免下轮再报死代码。

### 分歧 2：发现2「编排器泄漏智能」

**判定：partial——需把"确定性兜底"拆成两类，项目方辩护只覆盖失败路径**

项目方引用 07-30 P03 教训（`stages.js:312-314` 显式 `no_tool_calls → degraded`，真实存在）为确定性恢复辩护。该辩护仅对失败路径成立：

| 机制 | 触发时机 | 判定 |
|---|---|---|
| `_deterministicRecover`（`harness.js:1161`） | 仅 FC 失败（`harness.js:810-819`） | agree 项目方：失败兜底务实必要，保留 |
| `_autoExpandOverlays`（`harness.js:1248`） | 成功路径（`harness.js:894-901`） | disagree 归为"妥协"：是成功路径计划补全，泄漏本体 |
| `_matchPlanToQuestion`（`harness.js:22`） | 成功路径追问复用 | 同上，泄漏 |
| `_deriveDomainLens` B 部（`stages.js:393`） | 成功路径兜底 | 同上，泄漏（A 部已因 prompt 无指令恒空） |

**平衡建议（不上方案B）**：集中词表到单一模块（同意项目方，最低线）+ 给成功路径机制设边界：① LLM 多 tool_call 时优先 `runAllToolCalls`，auto-expand 只做注册表兜底；② auto-expand 模式（用地/合并/单用地+双区）收进可测试常量注册表，新问法进注册表不进内联正则；③ 加 auto-expand 命中遥测，持续为 0 的模式可退役。完全删正则（方案B）与 Flash 单 tool_call 现实对抗，属大重构，现在不值得。

### 分歧 3：P0-3 计划完成度守卫

**判定：方向 agree；落地方式 partial（context 注入 ≠ 结论约束，M 的来源要挂对）**

核实：`runAllToolCalls` 已有 failedSteps 注入 + 零图层守卫（`harness.js:1302-1307`：`_failNote` + `已完成 N 步·成功 X 层` 进 context）。需补两点：

1. **M 的来源**：`_allToolCalls` 单 tool_call 常态下 M=1，守卫空转；真正的 M 来自 P0-1 的 auto-expand 链（预期步数）。守卫挂"实际执行通道的预期步数"，不挂 plans[]——同意项目方。
2. **"够诚实"不够**：N/M 只进 finalStep context（LLM 可选输入），不是结论确定性声明。`applyQualityDefense` R4 只拦"成功说失败/失败说成功"矛盾（`harness.js:300-306`），不要求结论必须含"未完成/失败"。推荐代码层在最终结论**确定性追加**「已完成 X/Y 步（第 N 步失败：原因）」——不依赖 LLM 措辞，与 R4 互补。

### 分歧 4：P0-2 极性纪律恢复

**判定：agree（拍板方案正确）+ 三个实现条件**

"不要动 FC prompt"教训（`SESSION_2026-07-30.md`："当前 4 行版是经过多轮回归验证的最稳定版本" + L01"每次改 prompt 都可能触发 LLM 输出格式变化，需要回归测试"）针对的是**重写**，不是还原。恢复 `31e2a00` 原文是 revert 式还原，风险等级不同。三个条件：

1. 恢复**已验证原文**（`git show 31e2a00 -- ai_qa/router.py` 可提取精确文本），含"默认全部三极性·严禁自行缩窄"完整两句，非只加标题；
2. **行为回归验证**：浏览器复测 B006/TC-25，不只内容断言（L01 本质是"prompt 改了就测行为"）；
3. **内容断言守卫**：把 `router.py:52-59` 内联 `sys_content` 抽成 `build_fc_sys_prompt(context)` 小函数，测试直接调它断言 `'极性范围纪律' in p and '严禁自行缩窄' in p`——比 grep 锚点（行号会被重构破坏）抗重构，与 `test_final_prompt_stays_lean` 模式一致。

**关键补充**：`0073990` 一次删掉**四段**已验证内容（极性纪律 / plans 指令 / domain_lens 指令 / CB-09 M2 多要素提取段，git show 删除行可见）。P2-2 守卫清单覆盖四段，每条一段断言。

### 分歧 5：P0-4 `test_final_prompt_stays_lean`

**判定：agree（先瘦身后放宽）+ 补充：先分解静态/动态再决定**

核实：测试用 `build_final_prompt('', '')` 空上下文（`test_emc_template.py:83-86`），3616B 是**静态模板超标**，非运行时 grounding 膨胀。`FINAL_TEMPLATE`（`prompts.py:116-159`）构成：三句骨架/诚实/格式/内联模板/追问胶囊(~360B)/**语言风格（最大块 ~700B，7 条）**/推理风格/纯问答排版/人民城市理念。测试 docstring 写"<2KB"、断言却"<3000"，本身已有 1KB 漂移（顺带修）。

D019 是**设计意图**（瘦 = prefill 延迟 + LLM 注意力聚焦），不是可放宽数字。推荐：

- 先无损瘦身：语言风格块 7 条并 3-4 条（核心"禁工具名/禁英文列名/中文专业词"，后三条合并）；"人民城市理念"改运行时条件注入（仅概念问注入，`_quickIntent general` 路径），全量省 ~150B；胶囊规格保留。静态模板目标 ≤2KB。
- 若新规则必须保留，则**分解守卫**：静态 `FINAL_TEMPLATE` 一守卫（≤2KB）+ 运行时注入单独测。
- **不建议直接放宽到 4KB**——等于放弃 D019 防线，下轮回灌从这开始。

### 分歧 6：范围取舍

**判定：partial——B008/B006-B defer 合理；B007 类型守卫建议随 P0-1 一起**

- B008（MED，前端渲染）、B006-B（样式/UX）defer：**同意**。非核心链路、需设计参与。
- B007（HIGH）defer：**不同意全量后置**。理由：① P0-1 自动多步执行会把类型错配**静默放大**（每步可能产空层/错层），稀释 P0 收益；② B007 与 B002/B005 同族（"声称 X 产出 Y"），类型门低成本高收益；③ clip 已硬解析点层（`tools.js:1025-1028`），加"类型一致性校验"仅几行 guard。建议：类型校验随 P0-1 同包，契约文本强化留 P1，至少排在 B003 前。
