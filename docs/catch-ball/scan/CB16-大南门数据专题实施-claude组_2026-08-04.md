## 第二节：4 项预检逐项判断

### 预检 1：level='L3L4' 是否被下游误伤？✅ 不误伤

**全仓 level 消费点搜索结果**（`grep -rn "level" frontend/js/ai_qa/*.js`）：

| 位置 | 代码 | 消费 level？ | 对 'L3L4' 影响 |
|---|---|---|---|
| `harness.js:384` | `if (c.level !== 'L1' && c.level !== 'L2')` | **是·硬白名单** | ⚠️ 但只过滤**追问胶囊**（capsule）·非数据层 |
| `harness.js:400` | `if (!capsules.some(c => c.level === 'L2'))` | 是·胶囊多样性 | 同上·仅胶囊 |
| `harness.js:720` | `_forceDeliberate: capsule.level === 'L2'` | 是·胶囊属性 | 同上·仅胶囊 |
| `panel.js:683` | `c.level \|\| 'L1'`（chip 渲染） | 是·胶囊渲染 | 同上·仅胶囊 |
| `tools.js:1298` | `level: params.level \|\| (...)` | 是·点层 source 标记 | **此处是关键** |

**关键核实 tools.js:1298**：这是点层加载时打 `level` 标记（`_vl.level`）的地方。需确认 ermawu 的 'L3L4' 在这里如何流转。

**判断**：
- `geo_registry.py` 数据层（`get_layer_points`/`resolve_points`）**完全不查 level**——只读 CSV 取 lon/lat + 保留富归因列。level 仅是 `_POINT_LAYERS` 元组的第 3 位标签，**不被任何数据加载逻辑消费**。
- `harness.js:384` 的 R5 白名单只作用于**追问胶囊**（LLM 生成的 next-step 建议），不作用于**数据层加载**。ermawu 作为数据源被 zonal/density 加载时，根本不经过胶囊路径。
- **结论**：level='L3L4' 在数据层零影响。交接卡判断正确（"R5 只过滤 UI 追问胶囊·resolve_points 不查 level"）。

**唯一提醒**：若未来 LLM 给 ermawu 数据生成追问胶囊时填 `level='L3L4'`，会被 R5 剔除（降级为无胶囊）。这是**期望行为**（L3L4 不参与追问链），非 bug。但需在测试中确认 ermawu 场景的胶囊不被 LLM 错误标记为 L3L4（应标 L2 或不标）。

### 预检 2：backfill 补坐标列方式 ✅ 方向对·最大风险已排除

**核心风险（交接卡未提）**：CSV 有 `text`（评论全文），geojson properties 也有 `text`。若 CSV 行与 geojson feature 顺序不一致，backfill 会把**坐标错配到错误评论**——静默数据污染（坐标对但评论对不上，分析结论全错）。

**实测结果（claude组 独立核实·用 id_e 校验）**：

| 层 | geojson features | csv rows | **id_e 序完全一致** |
|---|---|---|---|
| T1 | 700 | 700 | ✅ True |
| T2 | 800 | 800 | ✅ True |
| T3 | 900 | 900 | ✅ True |

**结论**：行序严格对应，按 geojson feature 顺序提取坐标追加到 CSV 是**安全的**。最大风险排除。

**backfill 方式选择（一次性脚本 vs 改生成器重跑）**：

| 方式 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| **一次性脚本** `SCRIPT/backfill_ermawu_coords.py` | 保 T1/T2/T3 已有数据不变（seed 2606 确定性）·可审计·不触碰生成器逻辑 | 新增脚本文件需维护·生成器下次重跑仍无坐标（需同步改生成器或文档化） | ✅ **倾向此方案**（用户偏好·保数据稳定） |
| 改生成器重跑 | 根治（生成器产出含坐标的 CSV） | T1/T2/T3 全部重新生成·即使 seed 不变也有漂移风险（依赖版本/库）·破坏已有数据 | ❌ 风险高 |

**追加建议（claude组 独有）**：
1. **backfill 脚本必须含 id_e 一致性断言**——读 CSV id_e 列与 geojson feature id_e，断言完全一致后才追加坐标。防未来数据变更（如生成器改了、CSV 手动编辑）后行序漂移导致静默污染。一行 assert 换零风险。
2. **保留 utf-8-sig BOM**（交接卡已提·正确）——现有 CSV 有 BOM（表头首字符 `\ufeff`），pandas `read_csv` 默认识别，但手写脚本写文件须显式 `encoding='utf-8-sig'`，否则下游 catalog 读表头会多 `\ufeff` 前缀。
3. **坐标列位置**：建议追加到末尾（lon,lat 最后两列），不插中间——保 CSV 既有列顺序（tools.js:958 富归因列识别按列名不按位置，但插中间会破坏任何硬编码列索引的下游）。
4. **生成器修复的文档化**：backfill 是一次性补丁，生成器（`SCRIPT/` 下产出 ermawu 的脚本）下次重跑仍无坐标。建议在 backfill 脚本头部注释标明"生成器 ermawu CSV 缺坐标的根因 + 本脚本为一次性补丁 + 生成器修复 TODO"，避免下次重跑又缺坐标。

### 预检 3：边界登记进 manifest 兼容性 ✅ 兼容

**manifest 机制核实**（`range_selector.py` + manifest.json）：

- `list_presets()`（:285）读 manifest.json 原结构 `[{"group","items":[{id,label,file,nameField}]}]`·按 group 分组返回。
- `load_preset(id)`（:304）按 id（非 group）查找·返回 `{available, geojson, nameField}`。
- nameField 用于 `resolve_boundary`（`geo_registry.py:165-167`）给面域加 `name` 副本。

**交接卡方案**：加到「城市更新单元」组 `{"id":"damanmen_area","label":"大南门·二马路滨江片区","file":"大南门二马路滨江片区.geojson","nameField":"name"}`。

**兼容性核实**：
- 结构与 renewal_unit 完全一致（id/label/file/nameField 四字段）✅
- file 名含中文——现有 manifest 已有中文文件名（行政区.geojson/街道.geojson）·`load_preset` 用 `os.path.join(_PRESETS_DIR, item['file'])` ·Windows/POSIX 路径兼容（已有先例）✅
- nameField='name'——大南门 geojson 单要素属性 `{'name':'绘制多边形'}`·nameField 指向 name 列 → `resolve_boundary` 加 name 副本（已有则跳过）✅
- **label '大南门·二马路滨江片区' 含间隔号 `·`**——JSON 字符串合法·`list_boundaries` 原样透传·前端渲染无影响（已有 label 含 `·` 先例如 '宜昌 L2 · T1'）✅

**结论**：完全兼容。唯一观察——大南门 name 值是"绘制多边形"（非"大南门·二马路滨江片区"）。这意味着 zonal_stats 输出的单元名会是"绘制多边形"而非片区名。**建议**：若希望输出显示片区名，可考虑：① 手动改 geojson 的 name 属性为"大南门·二马路滨江片区"；② 或在 manifest 加 aliasField（但现有机制无此字段·成本高）。**非阻塞**——"绘制多边形"作为单元名虽不美观但功能正常，LLM 仍能按 boundary_id（damanmen_area）抽取分析。建议作为 P1 优化（改 geojson name 属性）。

### 预检 4：时间轴 manifest 不做的影响 ✅ 不影响发现

**_time_manifest.json 缺失的影响范围**（交接卡问）：

`/geo/catalog` 端点由 `list_point_layers()`（`geo_registry.py:72`）+ `list_boundaries()`（:92）组成——**两者都不读 _time_manifest**。list_point_layers 遍历 `_POINT_LAYERS` dict·list_boundaries 遍历 `list_presets()`。

**结论**：
- ermawu 注册进 `_POINT_LAYERS` 后·`list_point_layers` 即返回它·`/geo/catalog` 即包含它·**LLM 可发现**。
- damanmen 注册进 manifest 后·`list_boundaries` 即返回它·**LLM 可按 boundary_id 抽取**。
- **_time_manifest 缺失不影响 ermawu 被 EMC 问答发现**。时间轴 manifest 只影响时间序列分析（T1→T2→T3 演化）的自动识别·与"发现数据 + 出出口卡片"是两件事。交接卡判断正确（"后置"）。

**唯一提醒**：若演示场景涉及"大南门 T1→T3 更新成效对比"（时间演化），则需时间轴 manifest。但本轮目标是"更新需求分析出出口卡片"（单时点·T3 最新）·不涉及演化·后置合理。

### 5.3 backfill 脚本核心逻辑建议

```python
# SCRIPT/backfill_ermawu_coords.py 核心逻辑（伪代码）：
import json, csv, shutil

for t in (1, 2, 3):
    csv_path = f'DATA/performance/ermawu_l3l4_T{t}_result_csv.csv'
    gj_path  = f'DATA/performance/ermawu_l3l4_T{t}_result_geojson.geojson'
    
    # 备份
    shutil.copy(csv_path, csv_path + '.bak')
    
    # 读 geojson 坐标（按 feature 顺序）+ id_e
    gj = json.load(open(gj_path, encoding='utf-8'))
    coords = [(f['properties']['id_e'], f['geometry']['coordinates']) for f in gj['features']]
    
    # 读 CSV
    with open(csv_path, encoding='utf-8-sig', newline='') as fh:
        reader = csv.DictReader(fh)
        rows = list(reader)
        fieldnames = reader.fieldnames
    
    # ★ 关键断言：id_e 序完全一致（防行序错配）
    csv_ids = [r['id_e'] for r in rows]
    gj_ids  = [c[0] for c in coords]
    assert csv_ids == gj_ids, f'T{t} id_e 序不一致·backfill 中止'
    
    # 追加 lon/lat（末尾·不在 fieldnames 则加）
    for fn in ('lon', 'lat'):
        if fn not in fieldnames: fieldnames.append(fn)
    for r, (eid, (lon, lat)) in zip(rows, coords):
        r['lon'], r['lat'] = lon, lat
    
    # 写回 utf-8-sig
    with open(csv_path, 'w', encoding='utf-8-sig', newline='') as fh:
        writer = csv.DictWriter(fh, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)
    print(f'[OK] T{t}: {len(rows)} 行补坐标')
```
