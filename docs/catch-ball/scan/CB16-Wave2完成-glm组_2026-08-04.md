### ② _dedup_pois 去重：🔴 有 bug（同名异址误删）

**实测代码**（place_layer.py:326-346）：
```python
_seen = set()
out = []
for _p in pois:
    _nm = _p.get('name', '').replace(' ', '').replace('（', '(').replace('）', ')')
    _dup = _nm in _seen                    # ← ① 先查 name 是否见过
    if not _dup:
        # 坐标容差判断                            ← ② 只有 not _dup 才进这里
        for _q in out:
            if _q.name == _nm and <30m:
                _dup = True; break
    if not _dup:
        _seen.add(_nm)                     # ← ③ name 进 _seen（不含坐标）
        out.append(_p)
```

**🔴 bug 根因**：`_seen` 只存 name·第二条同名 POI（即使坐标差几十公里）发现 `_nm in _seen` 为 True → `_dup=True` → **直接跳过，坐标容差判断根本没跑**。

**glm组 构造实测**：
```
输入 4 条：万达广场(111.29,30.70) + 万达广场(111.35,30.75 远) + 万达广场(111.2901,30.7001 近) + 710生活小区
预期：3 条（远址保留 + 近址去重 + 710）
实际：2 条（万达广场×2 被删只剩 1 + 710）← 远址万达广场被误删！
```

**影响**：
- **同名异址连锁店/分店**（万达广场多门店、麦当劳连锁、xx银行网点）被误删 → POI 完整性受损。
- **严重程度**：P1（非 P0 阻塞）——核心下钻链（grid place_name/poi_names）不受影响（CBD 等密集区 POI 同名少·且坐标容差对近址有效）。但数据完整性是 EMC 诚实度的基础·建议修。

**修复建议**（逻辑顺序调正）：
```python
@staticmethod
def _dedup_pois(pois):
    out = []
    for _p in pois:
        _nm = _p.get('name', '').replace(' ', '').replace('（', '(').replace('）', ')')
        _dup = False
        # 坐标容差优先判断（同名 + <30m 才重复）·名同址异是两条（连锁店）
        for _q in out:
            _qm = _q.get('name', '').replace(' ', '').replace('（', '(').replace('）', ')')
            if _qm == _nm and abs(_q.get('lng',0)-_p.get('lng',0)) < 0.0003 \
                         and abs(_q.get('lat',0)-_p.get('lat',0)) < 0.0003:
                _dup = True; break
        if not _dup:
            out.append(_p)
    return out
```
**改动**：去掉 `_seen` name 集合·改为对 out 线性扫描（name+坐标容差）·O(n²) 但 n=4310·~9M 比较·毫秒级可接受（_load 只跑一次）。或优化：按 name 分组后组内查坐标（O(n)）。

**注**：实测 all_pois=4310 去重了 187 条——其中可能含误删的同名异址 POI。修后 all_pois 可能略增（恢复误删的连锁店）。
