# 第一部分：测试飞轮机制与流程全面 check

## 一、机制现状总览（核验）

飞轮是**三层互补**结构：

| 层 | 载体 | 用例量 | 断言方式 |
|---|---|---|---|
| 单测 | `pytest tests/`（~25 文件） | 220 pass + 5 skip | 纯代码断言 |
| 定向 E2E | `tests/browser/test_*.py`（Playwright，自管 serve） | ~12 个脚本 | 硬断言（网络层 2×geo 调用+200+rows）+ 软断言（回答文本 WARN） |
| 在线飞轮 | `?test=1`（test-board.js + test-cases.js + e2e-seam.js） | no-llm ~45 + llm 250+（意图 100 / 工具 100 / 参数 10 / 成果 / Smart / CPD / UI / FC 全链路） | 分阶段信号（exit-badge / template / tools / newLayers / renderedNew）+ 误杀/漏判投票 |
| 离线批量 | `tests/browser/flywheel_audit.py`（B0-B3） | B0=45 no-llm / B1=100 意图 / B2=100 工具 / B3=25 综合 | 三路采集（DOM 行态 + fetch 日志 + 报告落盘） |

**核心机制核验结果**：

- 隔离性好：测试 seam 仅 `?e2e=1` dynamic-import（`e2e-seam.js` 头注释），生产零测试代码；`?test=1` 同理（`tests/_index.md`）。✅
- 信号化断言是亮点：`llmRun` 抓转译链（`test-cases.js:15-70`），`_assertTool` 增加 `renderedNew`（地图真渲染 source 差值）判"标 OK 实际地图空"（`test-cases.js:277-290`）——治了 FC-12 类假阳。✅
- 误杀/漏判投票已采集（`test-board.js:383-388`），报告头带"误杀=X 漏判=Y"。✅
- 报告 EMC-SUM v1 + JSON 双落盘（`serve.py /_test/report`），仪表盘读 `/_test/reports` + `/_test/buglog`（`serve.py:333-345`）。✅
- bug 闭环：bug-collector skill（Smart 标准化 → Dumb `_gen_index.py`）设计正确。✅

## 二、意见（按五块）

### 2.1 机制层（用例集与断言）

**意见 F-1（高）：「计划命中」指标语义已漂移，应重新定义或移除。**
`test-board.js:390-391`：`_pl = r.method.length`（diagnose method 派生步数），`newLayers >= _pl 即 planHit`。但 D2（5.207）的 method 对 FC 单工具路径派生为 1 步（`harness.js deriveDiagnoseMethod`），且 plans[] 通道已停供——该指标在"多 tool_calls + autoExpand"新架构下不再代表"计划 vs 实产"。07-29 报告 `计划命中=10/16` 的可信度存疑。建议改为按**实际执行通道**统计：`_allToolCalls.length`（LLM 多 call）或 autoExpand 链长，且要求"实产层数 ≥ 计划步数且无失败步"才算命中。

**意见 F-2（高）：断言不覆盖"产物正确性"——B006-B/B008 类 bug 飞轮永远测不出。**
当前 llm 断言验证"选对工具 + 落图 + 渲染"（转译链信号），不验证：消极热力图是否真用消极色板（computeStyle 分支）、overlay 结果几何是否正确、产物是否继承源图层样式、2D/3D 是否正确匹配视角。FC-03/FC-05（工具对但步骤多/层错）会被判 pass。建议：对密度/overlay/clip/merge 四个高频工具加**产物语义断言**（参数→色板钩子、输出 feature 数与字段校验、样式继承断言）。

**意见 F-3（中）：llm 用例数据形态单一。**
e2e-seam `loadPoints` 走 `detectColorMode` polarity 分支（`e2e-seam.js:55-61` 生成积极/中性/消极三子层），贴近真实上传；但无"非 polarity 结构"（单层全量点 / 无 polarity 字段）用例——KNOWLEDGE 已记录 CB-08 F2.0 教训（飞轮 L2-group 结构测不出独立上传）。建议补 2 个数据形态用例。

### 2.2 流程层（运行节奏与回归）

**意见 F-4（高）：llm 全量回归不是"可日常跑的回归"——必须拆分。**
B1/B2 各 100 例 llm（每例 ~10-90s + DeepSeek 费用），B3 曾卡死（`emc-fix-progress.md` 明示"B3 后台曾卡死·已改定向验证"）。现状是 250+ 例只能当"发布前批次"，日常 commit 只有 no-llm 45 + pytest。建议拆分三档：**smoke**（no-llm 45 + 关键 llm 10 例，每次 commit）/ **regression**（llm 意图+工具精选 30-40 例，每日或每 N commit）/ **full**（B1-B3，发版验收）。并先修 B3 卡死根因（批处理超时/资源），否则全量永远不可信。

**意见 F-5（中）：llm 单次失败 ≠ 回归（Flash 概率性），缺自动复测。**
现有 [R] 单例重跑按钮（`test-board.js:327-333`），无自动重试。建议失败例自动重跑 1 次、仍失败才计 fail，报告标注 `flaky`（首次过/二次过）。

### 2.3 方法层（断言与指标）

**意见 F-6（中）：no-llm 45 例的"存在性断言"过弱，长期红无主。**
CPD-03~08/10、UI-09、PRED-09 共 9 例长期失败（08-01 no-llm 报告），类别在 CPD/UI/谓词，**未进 buglog、无修复归属**。80% 的"稳定"里藏着 9 个已知失败。建议：飞轮失败必须二选一——建 buglog 条目或进显式 defer 清单（含原因与负责人），否则 pass% 失去参照意义。

**意见 F-7（低）：误杀/漏判投票数据无消费方。**
`test-board.js:387-388` 已统计，但未发现回喂断言的机制。建议每月用投票数据校准断言（投票"误杀"多 → 断言过严需放宽；"漏判"多 → 断言过松需收紧）。

### 2.4 UI + 交互层

**意见 F-8（中）：失败 → buglog 转化靠人工"喊一声"，断链。**
bug-collector skill 明确"仅手动触发、不做自动监听"（`SKILL.md`），这是正确设计；但失败行没有"记录 bug"入口，复盘时需手抄。建议：`flywheel_audit.py` 增加 `--collect`（失败例自动生成 buglog 草稿，人工确认入库）；test-board 失败行加"记录"按钮（走同一工作流）。

**意见 F-9（低）：仪表盘缺"跨次趋势"。**
`_test_reports_summary`（`serve.py:348-365`）返回报告列表，`_renderDashHTML` 只展示 latest + KPI + 失败清单（`test-board.js:166-183`），无 pass% 时间曲线 / 失败 ID 去重统计 / 复发热力图。建议加：pass% 趋势线 + 失败 ID 跨次去重（哪些失败是新增 vs 复现）+ 与 `_trend.md` 联动。

**意见 F-10（低）：UI 交互本身合格。** FAB + 类别勾选 + 运行/仪表盘 tab + 行内 V/X 投票 + [R] 重跑 + 报告下载，分层清晰。维持即可。

### 2.5 问题修复方式（buglog 闭环）

**意见 F-11（高）：`_gen_index.py --check` 时间戳分钟级脆弱（上轮验收已报，未修）。**
`render_summary` 含"最后更新：HH:MM"，`--check`（`_gen_index.py:548-552`）逐字节比对 → 同分钟后必红，CI 守护实际失效。建议：比对时忽略"最后更新"行。

**意见 F-12（中）：`_regression.md` 只覆盖 B001，resolved 条目应全量进回归关注。**
B010/B011 已入 `resolved/`，但回归清单仍是单条。`render_regression`（`_gen_index.py`）按 resolved 生成——建议复核它是否自动收录 B010/B011（当前生成文件未见），若未收则是生成器条件过窄。

**意见 F-13（低）：修复记录靠人工填，缺 commit 校验。**
buglog"修复记录"引用的 commit 无"必须是当前分支祖先"校验。建议 `--check` 增加：修复记录 commit hash 必须是 HEAD 祖先（防文档写了一个不存在的修复）。

## 二、问题族拆解

### 族 A：多步计划-执行管道断裂（架构级 · 最棘手）

**表现**：B002（多类用地裁剪——假结论/半成品）、B004（筛选点层"只说不做"）、B005（多步只做一半）、FC-21/23/24（多步 0 层）、B002 半成品 answer（overlay 执行不稳 + 先渲染半成品答案再后台跑）。

**根因链**：
1. plans[] 管道从未接通（`07d57c1` 禁用 plans→胶囊；CB-10 删 `executePlans` 留 CPD-RESERVED）——"计划"概念没有活消费方；
2. 多步执行依赖两个替代通道：LLM 多 tool_calls（Flash 天然单 call，`SESSION_2026-07-30.md` P02 教训）与正则补全（`_autoExpandOverlays`/`_deterministicRecover`，覆盖有限）；
3. CB-10 加了模式 D + 单用地扩展 + 完成度 N/M 追加——B005 定向验证通过（9.7s），但 **B002 的"先渲染半成品答案再后台补 overlay"时序割裂未修**（todo.md 记待修）。

**判定**：这是唯一真正的架构级根因。下一步根治 = 统一"多步执行 = `_allToolCalls` 通道 + 全步骤完成后再出答案"，让半成品答案不再先于全步骤渲染。

### 族 B：LLM 意图/参数概率性失败（模型行为层）

**表现**：B003（数据清单慢/螺旋——已修短路）、B006-A（极性缩窄——已修纪律）、B007（图层类型错选——已修 guard）、FC-02（切换消极→错选 zonal）、FC-08（buffer 1→0 层）、FC-09（overlay 1→0 层）、FC-10（clip 1→0 层）、FC-12（无点数据仍跑）。

**根因链**：Flash 单次 FC 概率性（no_tool_calls / 选错工具 / 参数错）+ grounding 信息密度不足（图层类型/极性结构/数据来源标注）+ 契约描述质量（`when` = FC description）。

**现状**：来源标注（B003）、极性纪律（B006）、类型 guard（B007）、契约 when 修正（B001）——**每次发现补一条**，未形成系统。FC-02/08/09/10 在 07-29 llm 报告仍 ERR。

**判定**：中短期靠补丁+守卫收敛可行（守卫已有 `build_fc_sys_prompt` + 断言）；长期应结构化 grounding（图层类型/字段角色/极性结构显式列出）+ FC 纪律段版本化。**与族 E 同源**（都是"让 LLM 少猜"）。

### 族 C：确定性恢复/词表正则覆盖盲区（中间件层）

**表现**：`_autoExpandOverlays` 曾需 ≥2 用地关键词（已修单用地）；`_deterministicRecover` 现覆盖 A/B/C/D 4 模式；`CHAIN_REGISTRY` 仅 2 条硬编码链（`stages.js:70-84`）。

**根因链**：把"规划"职责下放到正则 → 每种问法一条规则 → 覆盖不全 + 维护爆炸。CB-10 已集中到 `emc-patterns.js`（缓解维护），但**覆盖盲区本质未消除**（新问法仍需加规则）。

**判定**：与族 A 同源（都是"计划能力缺失的替代品"）。收敛方向二选一：让 LLM 多 tool_calls 成为主通道（改 FC prompt 促多 call + 行为回归），或把模式注册表做全并加命中遥测（命中为 0 的模式退役）。

### 族 D：产物样式/渲染契约缺失（渲染层）

**表现**：B006-B（clip/extract/overlay 产物无源图层样式继承）、B008（网格 2D/3D 未解耦）、FC-03/05（工具对但层/样式与预期不符）。

**根因链**：`generate*ForAI` 委托产物带功能参数但无"样式契约"；图例系统与 EMC 产物未统一注册；2D/3D 两套渲染语义但工具层 mode 映射单一。

**现状**：D017 `computeStyle` 只覆盖 density（`heatmap-tool.js:839-846`），未覆盖 clip/extract/overlay/merge 产物；B006-B/B008 已 defer。

**判定**：设计层缺"样式继承/样式契约"机制——不是修 bug 能解决。这是产品视觉一致性的核心债，建议在 P0 多步执行稳定后立即排期。

### 族 E：数据/字段语义猜测（数据层）

**表现**：B001（MC→name 字段幻觉——已修：`_norm_where` 拆逗号 + getFieldCard 字段自纠正 + 契约去"单要素"误导 + `validate_field_dict_sync.py` CI）。

**判定**：已收敛，低风险残留（新数据形态可能再触发）。与族 B 同源。

### 族 F：测试与质量基础设施（工具链层）

**表现**：飞轮 no-llm 56%→80% 但 llm 全量回归缺（B3 卡死）；9 个 CPD/UI 失败长期挂账；`--check` 时间戳脆弱；断言不覆盖产物正确性；计划命中指标漂移。

**判定**：详见第一部分 F-1~F-13，均为可执行改进，无架构障碍。

### 族 G：文档/流程治理（治理层）

**表现**：文档滞后（`emc-fix-progress.md` 新旧混杂、`_cb-index.md` hash 滞后 4 commits）；buglog 状态双源（已修）；"不要动 FC prompt"教训与守卫张力（已用 `build_fc_sys_prompt` + 断言解决）。

**判定**：治理层问题，靠流程规范 + CI 守卫收敛，非代码债。
