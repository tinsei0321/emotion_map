### 🆕 新发现（P2）：separator-class 误含"范"字

Node.js 双轮复现发现：**"西陵范围内"（无"区"后缀）stripped 匹配失败**。

**根因**：`tools.js:612` separator-class 正则 `/^[\s，。；、的区内范围边界]$/` 的字符类含字面字符 `范围边界`——即"范"∈ 该集合。当问句"西陵范围内"中 stripped 值"西陵"后跟"范围"，`_after.slice(0,1)` = "范" ∈ separator-class → `_bounded=true` → 拦截。

**影响评估**：
- **B3 不受影响**——B3 PRM-05/06/07 问句都是"XX**区**范围内"（含完整行政区名）·exact-match 优先命中（`q.includes("西陵区")`）·不进 stripped 轮
- **实际用户场景可能受影响**——用户可能说"西陵范围内"（省略"区"）→ stripped 匹配被"范"字误拦 → boundary 不填 → zonal fail → ask_user/while-loop
- **严重度 P2**——不是 B3 回归·但是实际使用中的潜在问题

**修复建议**（1 行）：separator-class 去掉"范围边界"字面字符（保留功能字符 `\s，。；、的区内`）：
```javascript
// 当前（有 bug）：范/围/边/界 在字符类中 → "范围内"被误拦
const _bounded = /^(路|山|街|公园|广场|大道|车站|码头|桥)/.test(_after) || 
  /^[\s，。；、的区内范围边界]$/.test(_after.slice(0, 1));

// 建议：去掉 范围边界（这些不是分隔符·是功能词·不应作 boundary）
const _bounded = /^(路|山|街|公园|广场|大道|车站|码头|桥)/.test(_after) || 
  /^[\s，。；、的区内]$/.test(_after.slice(0, 1));
```

### 极边缘（P3）：未列 3 字块词

"西陵立交桥"/"西陵体育馆" → stripped "西陵"后跟"立"/"体"·不在块词表也不在 separator → 匹配。但"立交桥"含"桥"在块词表（`^(...桥)`）→ 实际会被 `桥` 拦截。"体育馆"不拦截但非真实宜昌地名·不影响。

**F_002=8 = while-loop 仍触发 8 次（25 例中约 3-4 例走了 while-loop）**。

### 根因推测

F_002（while-loop）触发条件（`harness.js:1086` while-loop 入口）：
1. `diagnose.degraded = true`（FC 失败 + recover 未命中）
2. `_tplHitRateReady() = false`（template 命中率 gate fail）
3. `diagnose.template` 空/非 single

最可能：**FC 偶发失败（tpl=None/unknown）→ recover 未命中所有模式 → degraded → while-loop**。这是 Flash FC 的概率性行为·非代码 bug。
