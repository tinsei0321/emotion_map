## 三、新增独立发现：PRM 剩余失败的测量伪影（建议优先处理）

对 PRM 断言机制逐项核验，发现 **boundary 类失败按构造必败**（测试测量问题，非执行问题）：

| PRM 类 | 断言逻辑 | 测量伪影 |
|---|---|---|
| boundary（PRM-05/06/07/08） | `new RegExp('西陵').test(hay)`，hay = `[p.boundary, p.boundaries].join('|')`（`test-cases.js:312`）；`_extractParams` 对 GeoJSON 边界 `_sum` → `'GeoJSON{N}'`（`test-cases.js:107-117`） | **derive 填的精确区要素 GeoJSON 序列化为 `GeoJSON{1}` → 区名在 feature.properties 内部，正则永远匹配不到**——即使边界选对也必 ERR |
| cell（PRM-01/02） | `p.cell` vs expect（`test-cases.js:311`）；`_extractParams` 取 body `cell_size`（grid 请求体确实用 `cell_size`，`grid-tool.js:415`） | 测量键匹配 ✓——但 03 报告 PRM-01 tpl=?、PRM-02 tpl=extract_feature → **是路由未达 grid（FC 未选 density），不是 derive 失败** |
| radius（PRM-03/04） | `p.radius`；`_extractParams` 取 body `radius_m`（buffer 请求体确实用 `radius_m`，`buffer-tool.js:217`） | 测量键匹配 ✓——但 03 报告"buffer 1→0 层"→ **buffer 工具未真正执行/未产层**（路由已对、执行未达），非 derive 失败 |
| layer/range（PRM-09/10） | `sig.tools.includes('extract_feature'/'clip')`（`test-cases.js:313-314`） | 03 报告 PRM-09 无工具、PRM-10 走 merge+extract（未走 clip）→ **真实路由问题**（非测量伪影） |

**结论**：10 个 PRM fail 中——boundary 5 例**至少部分是测量伪影**（GeoJSON 断言必败）；cell 2 + radius 2 是**路由/执行未达**（FC 未选对工具或工具未跑）；layer/range 2 是**真实路由问题**。**G1 下一步应先修测量**（`_extractParams` 对 GeoJSON boundary 提取区名——从 features[0].properties 的 name 字段——再跑 PRM），很可能 boundary 5 例中多例转 PASS，暴露出真实的剩余失败集，避免在可能已工作的 derive 上继续空耗。
