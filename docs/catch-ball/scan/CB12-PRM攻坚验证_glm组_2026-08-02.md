## 五、新发现（非阻塞）

### 发现 1（P2）：deriveAvailable 过宽——"西陵路"误匹配"西陵区"

双向包含 `_nmStrip.includes(_qStrip)` 在区名 2-3 字时可能过宽。例：
- `_strip("西陵区")` = "西陵" → `"西陵路周边".includes("西陵")` = true → **误匹配**
- `_strip("点军区")` = "点军" → `"点军山公园".includes("点军")` = true → **误匹配**

**严重度**：低——这些不是标准宜昌行政区问句·实际罕见。但 boundary 错误填充会导致 zonal 在错误区聚合。

**建议**：原始值优先 `q.includes(nm)` → stripped 兜底（而非当前 stripped 双向）。或 `_nmStrip.length >= 3`。

### 发现 2（P2）：PRM-09 ask_user PASS 是"正确行为但非预期路径"

PRM-09 问句"筛选出商业服务业用地的面"→ FC 未选工具（`tpl=None tools=[]`）→ ask_user。断言判 PASS（诚实追问）·但**路由修正未触发**——因为 FC 失败→`diagnose.degraded=true`→`deriveMissingParams` 在 `:1340` 被 `if (!diagnose || diagnose.degraded) return` 跳过。

**这意味着**：`筛选出→extract` 路由修正**只对 FC 成功但选错工具时生效**·FC 完全失败时不生效（需 recover 模式兜底·但目前无筛选 recover 模式）。

**建议**：加 recover 模式 F（筛选→extract 兜底·仿模式 E）。不阻塞——PRM-09 断言已判 PASS（诚实 ask_user）。
