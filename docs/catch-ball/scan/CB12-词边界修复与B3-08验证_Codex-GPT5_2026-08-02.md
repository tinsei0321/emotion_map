## 二、词边界修复验证（e7cb7b9）—— **partial（2 个潜在 bug）**

### 已修复（agree）

- `tools.js:611-615`：`_after = slice(idx+len, idx+len+2)`（1-2 字符）+ 块词表 `^(路|山|街|公园|广场|大道|车站|码头|桥)`——**2 字块词（公园/广场/大道）漏拦修复** ✓（针对存储值带区后缀 + 问句"西陵公园"场景）；
- 浏览器验证（区后缀值场景）通过 ✓。

### Bug 1（潜在）：第一循环（原始值精确）绕过块词守卫

- `tools.js:595-598`：`if (q.includes(nm)) return ...`（原始值精确优先）**无词边界检查**；
- 模拟：存储值 **"西陵"**（2 字无后缀）+ 问句"西陵公园附近" → `q.includes("西陵")` = true → **第一循环直接匹配**（块词守卫只在第二循环）→ **"西陵公园"仍误匹配**；
- 浏览器验证通过是因为测试数据的存储值带"区"后缀（"西陵区"→ "西陵公园附近".includes("西陵区")=false → 落入第二循环被拦）——**真实边界数据若存在 2 字值（如 name 字段为"西陵"），误匹配回潮**。

### Bug 2（潜在）：分隔类语义写反

- `tools.js:614`：`_bounded = 块词匹配 || /^[\s，。；、的区内范围边界]$/.test(after[0])`——**分隔符（区/内/范围/的/，…）被算作"bounded（跳过）"**；
- 语义应相反：**块词 → 跳过（误匹配）；分隔符 → 匹配（合法区域边界）**；
- 模拟：存储值"西陵区" + 问句"**西陵范围内**按面聚合"（问句无"区"）→ 第一循环失败 → 第二循环 `_after="范围"` → "范" ∈ 分隔类 → bounded → **跳过 → 不匹配**（应匹配！）；
- B3 问句都是"XX区范围内"（带区 → 第一循环命中）所以未触发——但自然语言"西陵范围内的情绪"会中招。

### 修复建议（统一词边界语义）

```javascript
// 第一循环也过词边界（或在第一循环后同样检查 after 字符）
// 统一判据：after 首字符 ∈ 分隔类（区/内/范围/的/标点/空白/结尾）→ 匹配；∈ 块词（路/山/公园/…）→ 跳过
const _after1 = q.slice(idx + nm.length, idx + nm.length + 2);
const _valid = /^[\s，。；、的区内范围边界]$/.test(_after1[0] || '') || !/^(路|山|街|公园|广场|大道|车站|码头|桥)/.test(_after1);
```
