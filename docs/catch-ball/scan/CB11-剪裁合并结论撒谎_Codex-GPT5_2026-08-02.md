## 〇、执行路径复现（代码级确认）

用户问句「将剪裁出西陵区范围内的商业+居住+公园广场用地 合并成一个图层」在当前代码下的确定性路径：

1. FC → 1 tool_call `extract_feature`（抽西陵区）；
2. `runTemplatePath` 第 1 步成功 → inline 扩展触发（`harness.js:524-526`：`def.tool==='extract_feature'` + 区/用地正则）；
3. `buildLanduseCompletion(..., {mode:'auto'})`（`harness.js:1326` 起）——问句含「合并」→ `_wantUnion=true`（`harness.js:1358`）→ 返回 `{mergeLayers: [商业,居住,公园广场 id], boundaryName}`（`harness.js:1361-1362`）；
4. inline merge 分支（`harness.js:540-545`）执行 `TOOLS.merge({layers: 全量3类用地})` → **66.5 km² 全量**，`as: 'merged_' + boundaryName`；
5. toolHistory 只有 `extract_feature` + `merge` 两条；finalStep 收到「单技能路径·产出 1 个新图层」摘要 + `merged_西陵区范围` 在 formatRegistry 里；
6. LLM 看到问句「剪裁出」+ 图层名含「西陵区」→ 写「执行裁取操作…严格落在西陵区边界内」——**编造**。

**丢裁剪语义的确切落点**：`harness.js:540-545`（inline merge 分支）——merge 了全量用地，从未执行「裁剪到西陵区」这一步；`as: 'merged_西陵区范围'` 的命名进一步误导（让 L1 图层名对账通过）。

## 一、4 个问题的逐条评估

### 问题 1：结论与执行不符（只说不做复发）—— **agree（最严重）**

实测事实无误：执行只有 `extract_feature → merge`（2 个 geo 调用，无任何 clip/overlay），结论声称「执行裁取操作」「严格落在西陵区边界内」。用户已确认路径等价可接受、结论撒谎不可接受——这不是"路径等价"，是**结论描述了未走的路径**。

### 问题 2：buildLanduseCompletion 丢裁剪语义（执行层）—— **agree（根因）**

- `harness.js:1358` `_wantUnion = /合并/.test(q)`——问句同时含「剪裁出」+「合并」时，逻辑只看「合并」→ 直接 merge 全量；
- 用户确认等价路径可接受，但「合并全量→再裁剪」这条等价路径**也没走完**——merge 后没有任何后续裁剪步骤（`harness.js:540-545` 直接收尾进 finalStep）；
- **比 LLM 撒谎更严重的是：系统的确定性补全路径自己违背了用户意图**（丢了「裁剪」）。防线假设"执行即正确"，执行错了防线无从校验。

### 问题 3：finalStep 无步骤描述谎报检测（防线层）—— **agree（结构性洞）**

- `applyQualityDefense` L1 只对账**图层名**（`_extractClaimedLayers` → formatRegistry），`harness.js:263-285`；
- 本案例声称的图层名「西陵区三用地合并」**真实存在**（merge 产物，且命名含「西陵区」）→ L1 通过；
- R4 只查成败矛盾短语（`harness.js:299-307`），不查操作词；
- **结论**：防线验证的是"声称的图层是否存在"，不是"声称的操作是否执行过"。操作词（裁取/裁剪/overlay/clip）零校验——这就是结构性洞。

### 问题 4：observation 语义不足（信息层）—— **agree**

- `tools.js merge` observation 只说「合并 N 个图层后得到 X 个要素，总面积 Y 平方公里」——不含"被合并图层是否已裁剪/来源范围"；
- finalStep 拿不到"这些用地是西陵区内还是全量"的信息 → 只能靠猜；
- 修复成本低：observation 显式列出来源图层名（若图层名含「_西陵区」即已裁剪）或加"范围状态"字段。

## 二、5 个分歧点的推荐

### 分歧 1：问题 1 根因定位—— **叠加，主因在执行层（问题 2）**

执行层先丢「裁剪」语义（系统确定性路径违背意图）→ 观察记录与用户意图不一致 → LLM 编造「裁取」填补语义缺口 → 防线（无步骤校验）放行。**主因 = 问题 2（执行链丢语义），放大器 = 问题 3（防线漏检），诱因 = 问题 4（observation 不给信息）**。修复顺序应执行层优先：执行对了，结论有事实基础；只补防线不修执行，会变成"诚实地说出错误结果"。

### 分歧 2：为何「只说不做」多次修复后仍复发—— **防线是"存在性防线"，不是"语义一致性防线"**

| 既有防线 | 验证什么 | 本案例为何漏 |
|---|---|---|
| 诚实观测（count=0 不说"已生成"） | 产出数 | merge count>0（66.5 km² 全量）→ 观测"诚实"但语义是错的 |
| 零图层守卫（跳过 LLM finalStep） | 有无图层 | merge 产出了 1 层 → 守卫不触发 |
| 执行摘要注入（N 步·X 层） | 层数 | 报"产出 1 个新图层"→ 不报"是否裁剪" |
| L1 图层名对账 | 声称的图层名是否存在 | 「merged_西陵区范围」真实存在 → 通过 |
| R4 状态矛盾 | 成败矛盾短语 | 无失败短语 → 通过 |

**结构性结论**：所有防线都回答"有没有做"（存在性），没有一个回答"做的是不是结论说的那个"（语义一致性）。需要新增"操作-执行交叉验证"层：从结论提取声称的操作词（裁取/裁剪/叠置/合并/抽取…），与 toolHistory 实际工具集比对。

### 分歧 3：是否扩展防线加步骤谎报检测—— **该加，且成本低**

- 实现：`_extractClaimedOps(draft)` 正则提取"完成标记（已/执行/完成/生成/得到）+ 操作词族"；操作词族映射到工具（裁取/裁剪/裁出 → clip|overlay；叠置/交集 → overlay；合并 → merge；抽取 → extract_feature；筛选 → filter_attr；缓冲 → buffer）；与 toolHistory 提取的实际工具集（复用 `_executedGeoSteps` 风格）比对；不匹配 → 仿 L1 标注"（注：未执行该操作）"或降级；
- 成本：纯代码 <10ms，与防线哲学一致；
- 注意：只在"陈述已执行"时触发，避免把"建议下一步/概念解释"误判；「裁剪」作为语义族同时匹配 clip 与 overlay(intersection)（几何不同工具不同）；
- 位置：`applyQualityDefense` L1 之后新增 L1.5。

### 分歧 4：buildLanduseCompletion「裁剪+合并」执行路径—— **推荐"合并全量 → overlay(intersection) 裁剪"（B'）**

| 路径 | 步骤 | 稳健性 | 结论真实性 |
|---|---|---|---|
| 先裁剪再合并（A） | extract + 3×overlay(intersection) + merge = 5 步 | 步骤多、失败面大 | 最终 observation 含叠置 → 结论可如实 |
| 合并全量 → 裁剪（B'） | extract + merge + 1×overlay(intersection, 边界, merged) = 3 步 | **步骤最少、单次裁剪** | 最终 observation =「叠置分析完成…已生成图层」→「裁取/落在西陵区内」**变为真实** |

推荐 B'：最终一步是"用西陵区边界 intersection 裁剪 merged 结果"，最终图层**真的被裁剪**——结论里的「严格落在西陵区边界内」从编造变成事实。实现要点：

- inline merge 分支（`harness.js:540-545`）不直接收尾：merge 后追加 `overlay(intersection, 边界, merged)` 步骤（继续累积 toolHistory/newLayerCount 再进 finalStep）；
- `as` 命名如实（合并_商业居住公园广场 或 西陵区_三用地合并——**裁剪完成后**才可含「西陵区」）；
- overlay(intersection) 与 merged 的 `area_km2` 同名字段会后缀（后端重算 area_km2，cosmetic，低优先）。

### 分歧 5：优先级—— **执行层（2→4）→ 防线（3）**

| 优先级 | 问题 | 理由 |
|---|---|---|
| P0 | 问题 2（执行补全裁剪）+ 问题 4（observation 语义） | 一组改动让执行与意图一致、observation 给足信息——用户要的是"正确结果 + 诚实结论"，二者都靠执行层 |
| P1 | 问题 3（步骤谎报检测） | 防线兜底，防未来同类复发 |
| — | 问题 1 | 是结果不是修复点，随问题 2 修复而消失 |

## 三、聚焦「只说不做」复发：结构性洞总结

1. **确定性补全路径可以违背用户意图**（`harness.js:1358` 只看「合并」忽略「裁剪」）——执行层是"只说不做"的第一因，且防线无法感知；
2. **防线只验证存在性、不验证语义一致性**——count/图层名/层数全部通过，操作词零校验；
3. **observation 语义不足**——finalStep 被迫猜"是否已裁剪"，猜错即撒谎。

**根治方向**：执行层把"裁剪+合并"的等价路径真正走完（B'），observation 显式标注范围状态，防线补"操作-执行交叉验证"。三者齐备后，「结论与执行不符」这一类才真正闭环。
