## 二、§七 九问逐条回应

### Q1 出口差异化闭环（B1）—— **共识（方向）+ 判据具体化**

- **判定**：共识。缺口真实——`SCALE_PARADIGM` 有设计（`paradigm.py:16-60`），但结论形态差异无执行层保证，finalStep 自由发挥。
- **判据（要"执行层可观测"）**：把"出口形态"做成 finalStep 的结构化约束注入 + **R7 三句骨架按 scale 变体**：
  - 宏观（分布/把控）：句①动作 + 句②分布特征（热点/密度/覆盖）+ 句③交互——**负向约束：禁归因词汇**（原因/为什么/导致/归因/深读）；
  - 中微观（归因/排序）：句②单元排序 + 归因；
  - 微观（落点定位）：句②落点 + POI。
- **落地**：① finalStep context 注入 `scale + outlet + 允许/禁止`（prompt 层）；② 词汇负向断言入 C2 测试（宏观例 grep 无归因词——作**采样信号**非硬判据，防 brittle）；③ 出口形态字段（`outlet`）与 R7 联动。

### Q2 scale 判定强化（B2）—— **共识 + 风险对策**

- **判定**：共识。`stages.js:371` 硬编码 macro 是"一竿子插到底"的根。
- **去硬编码默认的风险**：直接删默认 → LLM 判错时出口错位且无兜底。对策是**三层**：① FC prompt 显式教"先判尺度"（分布 vs 归因，一问一判）；② **代码可知的词法兜底**（分布/整体/全域/覆盖→macro；哪区最差/原因/归因/排序→meso；公园/点位/最近→micro）——与 `_deriveDomainLens` B 部同模式；③ 兜底失败才落默认 macro（保留现状作为最后防线，而非删掉）。
- **domain_lens A 部同包**：同意（一个 prompt 段同时教 scale + domain_lens 输出），但注意两条纪律：改的是 `build_fc_sys_prompt`（fc_diagnose 分支，非 diagnose eval prompt，不撞红线）；A 部恢复 +~600B 有 L01 行为回归风险 → 浏览器复测 B006/TC-25 + 新增 scale 用例。
- **边界提醒**：`paradigm.py:460` 明确"仅 emotion_analysis 受约束"——纯 GIS 操作（依据 1）不判 scale，勿误加。

### Q3 搜索能力（B3）—— **可行，但范围必须窄**

- **判定**：方向共识，落地范围收紧：**仅纯问答（general）两类触发**——大问题（情绪地图概念/理念/四领域前沿政策）+ 聚焦问题（策略/应用/宜昌实际）。**不**用于 GIS 操作/情绪分析（不干扰执行链，不引入搜索延迟）。
- **流程**：general 短路后、finalStep 前可选 search（后端新端点 + 超时 + 降级：搜索失败→退回本地背景注入，不阻塞回答）。
- **与"禁假大空"**：搜索给宜昌实据（新闻/政策），但结果可能过时/不准确——结论建议标注"信息截至"或作参考引用，避免新谎报面。
- **成本**：新后端端点 + key + 降级链，中高。**排期放 G6b**（先 B1/B2）。

### Q4 连问拆解（B4）—— **可行，但复用现有管线，不新造**

- **判定**：共识（未实现属实）。业界做法 = **plan-then-execute**：分句识别多意图 → 独立意图队列 → 按依赖串/并行 → 合并结论；function calling 的多 tool_calls 是并行机会（EMC 已有 runAllToolCalls）。
- **关键建议**：连问拆解**不要新造执行管线**——分句（代码：按 ？/。/换行 切分 + 句数上限）→ **逐句复用现有 `orchestrate`** → 汇总 finalStep。这样每个子问自动继承所有既有防线（R9/诚实观测/N-M），成本最低。
- **约束**：60s 门槛对连问需放宽或按句计数；句数上限（建议 2-3 句/次）防拖死。
- **排期**：G6 末（B4 依赖 B1/B2——否则拆出来的子问也"一竿子插到底"）。

### Q5 排版机制（B5）—— **共识，低成本，无需新机制**

- finalStep 已有 markdown + 内联模板（`{{show:}}`/`{{chart:}}`/`{{fig:}}`）；缺的是**结构化骨架**而非渲染能力。
- 建议：Q1 的 scale 出口骨架（宏观/中微观/微观模板）+ 通用排版规则（首句结论加粗 / 要点列表 / 关键数字突出 / 3-5 句）——prompt 层约束 + R7 截断兜底已存在，扩展 R7 变体即可。B5 可并入 G6a 与 B1 同包。

### Q6 性能门槛（B6）—— **共识 + 先测量后设门槛**

- p95=66s 主要来自 LLM 串行 + **失败重试**（PRM 类参数错 → 工具 ERR → 重试轮）。**PRM 修复本身会显著降耗时**——参数填对 → 少 1-2 轮失败重试。
- 建议顺序：① 先修 PRM（G1/G2）→ 重测 B3 看 p95 自然回落；② 再查残余大头（per-phase 计时已存在，跑失败用例定位是 FC 还是 finalStep 还是工具）；③ 门槛只对"链路通畅"用例生效（失败用例耗时是修复对象，不是门槛对象）；④ 60s 门槛作为 C1 体检断言入库。

### Q7 PRM 修复策略（A1）—— **共识（derive 优先）+ 组合 + 按类归因**

- **判定**：共识，推荐组合而非单选：**确定性 derive（主）+ 契约强化（辅）+ prompt few-shot（次）**。
- **按类归因（12 个 fail 拆开）**：cell_size×2 + radius×2 + boundary×5 + layer/range×3（报告数据）——**boundary 是最大头（5/12）**，全部"代码可知"（区名→已加载面层 properties 匹配，B005 模式 D 已有先例）。
- **PRM-06 是路由错不是参数错**（应 zonal 走 extract）——与参数错分开归因、分开修（路由错归 A2 触发入口，参数错归 derive）。
- **落地**：新增"参数补全层"（`deriveBoundary/deriveCellSize/deriveRadius`）挂在 `_normalizeFcDiagnose` 之后，**成功与失败路径共用**（避免 A2 的触发分叉）；单位换算（500m/2000m/1km→数值）、"范围内"→boundary 全部代码可知。

### Q8 体检断言（C1/C2）—— **共识，推荐扩展 test_p0_repro 模式（非飞轮信号级升级）**

- 理由：飞轮信号级断言升级到"结论对账"需改大量用例 + 引入 LLM 文本判断（脆弱）；`test_p0_repro` 是**定向真实链路断言**（geo 调用序列 + 结论文本 + 耗时），更贴用户关切。
- 建议 C1 四件套全为**确定性断言**：① 产物到达（layerId/rows/结论其一）② **R9 无"未在工具执行记录"**（直接断言结论不含该标注）③ onFinalDone 已调（`_curTrace.final` 非空）④ 耗时 ≤ 门槛。10 类问句 × ≥2 例。
- **R9 补单测**：构造 toolHistory 无 clip + 结论声称"已执行裁剪" → 断言 R9 标注出现——1 个用例封死防线本身。
- C2 用户示例①/②：结论形态断言（宏观 grep 无归因词 / 中微观 grep 有归因词）作**采样信号**，标注非硬判据。

### Q9 聚焦顺序（G0-G6）—— **共识 + 两处微调**

- **同意 G0 先行**（先建测量再谈修）——这是本轮报告最正确的判断。
- 微调 1：**G3（多目标）CB-11 已修**——降级为"验证+防复发"，建议并入 G0（对账断言入库即可），不占独立攻坚 slot。
- 微调 2：**G6 拆两段**——G6a = B1+B2（出口差异化 + scale 判定，依据 3 核心，成本低收益直接）；G6b = B3+B4（搜索 + 连问，新能力，排最末）。理由：搜索/连问都在"出口差异化"之上叠加，先做地基。
