## 二、_hasSeq 正则误触发分析

**Node.js 11 例复现**：

| 问句 | _hasSeq | 预期 | 判定 |
|------|:---:|:---:|:---:|
| 先裁剪西陵区情绪点，再生成热力图 | ✅ | ✅ | 目标 case |
| 我们先看看数据，然后再做热力图 | ✅ | ✅ | 先看再做 |
| 先筛选商业用地，再排序 | ✅ | ✅ | 先筛选再排序 |
| 什么是核密度分析 | ❌ | ❌ | 概念问 |
| 500m 方格网格聚合 | ❌ | ❌ | 单步 |
| 我们再来分析一下 | ❌ | ❌ | "再"无 geo 词 |
| **先生成热力图** | **✅** | **⚠️** | **边界：单步含"先"误触发** |
| 再见/再次分析/不要再做 | ❌ | ❌ | "再"非顺序词 |

### ⚠️ 边界："先生成热力图"（低风险·自纠正）

`_hasSeq` 匹配"先"+"热力"（15 字内）→ `clip_density` 触发器也匹配 → 链 fires clip+density。

**但自纠正**：
- 链 boundary derive 需要 deriveAvailable 从问句提取区名 → "先生成热力图"无区名 → `_chainD = null` → boundary 不填
- clip 执行时 `range = diagnose.params.boundary`（null）→ clip fail → 链中断 → ask_user
- **最坏情况**：用户问"先生成热力图"→ 系统 ask"哪个范围？"——多余但非错误

**严重度**：低——"先生成热力图"不是常见问法（通常说"生成热力图"不带"先"）。且自纠正防崩。

## 三、单例不稳定分析

### 现象

> 单例多次跑不稳定——有时 clip 执行·有时工具全空

### 根因推断：FC 方差

| FC 返回 | 路径 | 结果 |
|---------|------|------|
| `template='clip'`（正确·单工具）| :1071 链前置（_hasSeq + clip_density 命中）→ runChainPath | ✅ clip+density |
| `template='unknown'`（FC 失败）| :981 recover 触发 → recover 无 clip+density 模式 → degraded → while-loop | ⚠️ 工具全空（while-loop 兜底） |
| `template='multi'`（FC 判多步）| :981 recover 触发 → recover 可能匹配其他模式 → 或 degraded → while-loop | ⚠️ 不稳定 |
| `template='density'`（FC 跳过 clip 直接 density）| :1071 链前置（_hasSeq + clip_density 命中·_deriveChainId 不依赖 FC template）→ runChainPath | ✅ clip+density |

**最可能**：FC 概率性返 `unknown`/`multi` → 走 recover 而非链前置 → recover 不覆盖 clip+density 顺序模式 → while-loop → 不稳定。

### 调试建议（上午 B3 验证前）

```javascript
// 在 :1071 链前置前加诊断 log
console.log('[seq-chain]', '_hasSeq=', _hasSeq, 'template=', diagnose.template, 
            'chain=', _chainPre?.chain_id, 'boundary=', !!diagnose.params?.boundary);

// 在 :981 recover 触发处加 log
console.log('[recover-trigger]', 'template=', diagnose?.template, 
            'degraded=', diagnose?.degraded, 'recovered=', !!_recovered);
```

**如果日志显示 FC 返 unknown/multi 时走了 recover 而非链前置** → 需要在 recover 中也加 clip+density 模式（模式 H？）。或：recover 命中后如果 `_hasSeq` → 不用 recover 结果·改用链前置。

**修复建议**（P1·如 B3 确认此路径）：
```javascript
// :981 recover 触发后·如果 _hasSeq → 跳过 recover·改走链前置
if (_hasSeq && _deriveChainId(ctx.question, {})) {
  // 顺序词 + 链命中 → 不用 recover·走链前置
  diagnose = { template: 'clip', degraded: false, ... };  // 合成最小 diagnose 让链前置触发
}
```
