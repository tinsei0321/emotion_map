## 结论摘要（先行）

1. **出口抽象层方案成立，且与 CB-15 天然前后承接**：CB-15 管"分析过程中"（网格/热点→POI 联动），出口层管"分析完成后"（结果→行业接口）。两者共享同一个数据契约：**地理定位引用（placeRef/cellRef/unitRef）**。
2. **A 六焦点**：① 架构 = **分层（C）**，但出口层核心是"确定性 schema 组装器"而非"每问一个 LLM agent"——第三段**条件触发**（outlet 判行业接口类才走），不违反铁律 B（三段是逻辑分段，不是每问强制）；② DOMAIN_OUTLETS **不动承重源**，新增 `core/outlet_kb/` 契约层做 key 关联；③ 尺度校验 = **schema 级确定性校验**（补充现有 prompt 防线）；④ CB-15 先行，但 macro/meso 出口可并行；⑤ MVP = **S6 → S2(meso) → S3**（同意报告三场景，调整实施顺序）；⑥ 出向知识库独立建 `core/outlet_kb/`。
3. **B CB-15 待收敛**：place_name 双源 = **加权投票融合**（hotspot 高权 + seed 兜底）+ `top_places` 独立字段；**cell_id = P0**（实测 square grid 无稳定 id，下钻链需要）；**lookup_place = P0**（比 sjoin 更基础）；3220 去重 = poi_id+名称坐标并集、种子优先；centralcity = 本地重生成 + 3220 兜底。
4. **C 协同**：S2 完整版依赖 CB-15 P0（top_places + 格选中联动 + 3220 接入）+ P1（评论↔POI 关联）；**meso 简化版可用现有产物先行演示**——出口价值不等 CB-15 全量完成。
5. **最大风险 = 出口层过度设计**（行业接口清单庞大）→ 先落城市更新/体检两个核心板块 + S6 先行验证"出口"价值。

**一句话：出口层是 EMC 立项的"临门一脚"，但它的第一版应该是一张可序列化的表（确定性组装 + 可选 LLM 润色），而不是又一个 agent。**

## 二、A · 出口抽象层六焦点（独立判断）

### 焦点 1：架构位置 —— 同意分层（C），但要精确定义为"确定性组装器 + 可选 LLM 润色"

**结论：`core/outlet_adapter.py`（确定性 schema 组装 + 序列化导出）+ `ai_qa/prompts.py` 新增轻量 `build_outlet_prompt`（自然语言渲染，final 之后的独立阶段）。**

独立补充三点：
1. **出口层的主体是确定性代码，不是 LLM**。更新需求分析卡的 7 要素（接口标识/数据基础/定量/定性/地理定位/对接建议/局限标注）里，接口标识、定量、归因字段、地理引用、局限标注**全部能从结果产物确定性映射**（模板化组装）；只有"对接建议的叙述"需要自然语言。所以 LLM 渲染是**可选增强**（让卡面可读），不是必需——MVP 可先做 0-LLM 版（模板 + 规则排序），LLM 版后补。
2. **第三段条件触发，非每问强制**。铁律 B 的三段是**逻辑分段**（每问不得跳过中间环节直给终极答案），不是"每问都走第三段"。第三段只在 `outlet` 判"行业接口类"（报告结论/建议清单/指标排序等）时激活——普通出图层问句不激活。这既守铁律 B（结果先于出口），又防 token/延迟回弹。
3. **挂载点不进 orchestrate 主循环**：作为 final 之后的**可选阶段**（hook/前端"生成行业对接卡"按钮 + 问答出口工具触发），零触碰 diagnose/harness 主循环/ChatRequest。

### 焦点 2：DOMAIN_OUTLETS 升级 —— 不动承重源，新增契约层

**结论：`paradigm.py` 的 DOMAIN_OUTLETS 保持不动（它是 diagnose prompt 渲染源，承重 eval），新增 `core/outlet_kb/OUTLET_CONTRACTS` 契约层，用 outlet 名称做 key 关联。**

理由：
- DOMAIN_OUTLETS 的"出口范式名"（如"更新时序排序/微更新点位识别"）是**提示词资产**，改它 = 改 diagnose prompt 承重（违反改前先扩 eval 纪律）。
- 契约层结构：`{outlet_id, 接口标识, 适用尺度, 产出 schema(7 要素), 所需产物字段(从 result agent 取哪些), 导出模板, 4×5 映射规则}`。
- 诊断卡 `outlet` 7 值枚举**保持值域兼容**（前端 `_outletLine`/stages 依赖），新增"outlet 值 × domain_lens → OUTLET_CONTRACTS"解释层，不改 ChatRequest schema。
- 出向知识库：**独立建 `core/outlet_kb/`**（不入向混放），第一个领域 = `urban_renewal_outlets.py`（对接八任务/8 领域/三级体系/四维度）。

### 焦点 3：尺度耦合强制校验 —— schema 级确定性校验（比 prompt 防线强）

**结论：新增 `validate_outlet_schema(schema, scale)` 确定性校验函数**，SCALE_GEO_TYPES 白名单 = {macro:[面域], meso:[单元面], micro:[网格/POI 点]}。

现状 `_outletLine`（harness.js:648）+ R10/R11 是 prompt/context 防线；出口层加 **schema 级校验**：组装后校验"地理定位字段类型 ∈ 尺度允许集"（macro 卡片禁 micro 落点字段非空、micro 必须有落点），校验失败 → 降级（剔除越界字段 + 标注），测试覆盖。这是确定性代码防线，不依赖模型听话。

### 焦点 4：与 CB-15 实施顺序 —— CB-15 先行，但 macro/meso 出口可并行

同意"CB-15 先行"总原则，但**细化**：出口的 macro/meso 部分（S6/S2-meso/S3）依赖 CB-15 程度低（用现有 zonal/rank + 单元名即可），可与 CB-15 P0 **并行**；只有 micro 落点类（S5/S2-micro）强依赖 CB-15（格→POI 清单 + 评论关联）。见 §四实施顺序。

### 焦点 5：MVP 范围 —— 同意 S2+S6+S3，实施顺序调整 S6 先行

**MVP = S6（体检指标对接）+ S2(meso)（更新需求分析）+ S3（时序排序）**，但顺序：
- **S6 先行**：纯宏观/中观指标映射（4×5 要素 → 体检 8 领域），**零新数据依赖**（现有聚合产物即可），最快演示"出口"价值（替代/补充满意度调查）；
- **S2(meso)**：zonal 4×5 归因 + 单元 preset + 单元内 top_places（CB-15 P0 的 sjoin 部分）——核心叙事；
- **S3**：meso 排序表（现有 rank + 模板）。
- micro 部分（S5/S2-micro 落点）等 CB-15 P0/P1 完成后做。

### 焦点 6：行业知识库出向扩展 —— 独立出向 KB，先落城市更新

**结论：`core/outlet_kb/` 独立于入向 `ai_qa/industry_kb/`**。理由：入向是"给 LLM 的权威话语"，出向是"对接行业系统的契约"——生命周期不同（入向随知识更新，出向随行业接口变化）、消费者不同（prompt vs 导出）。第一个领域 `urban_renewal_outlets.py` 对接：八项任务清单 / 体检 8 领域 35 项 / 三级编制体系 / 四维度。

## 四、C · 协同综合

### C1 数据契约：出口"地理定位"要素 × CB-15 地点信息

两份报告共享的数据契约 = **三层引用标识**（可导出、可回地图、可被出口卡引用）：

| 引用 | 结构 | 来源（CB-15） |
|---|---|---|
| `placeRef` | `{name, category, lng, lat, poi_id?, zone_id?, source}` | lookup_place / 格内 sjoin top_places / 评论↔POI 反查 |
| `cellRef` | `{cell_id, geometry}` | 网格聚合（**需先加 cell_id**） |
| `unitRef` | `{preset_id, name}` | 行政区/社区/街道 preset（geo_registry 现成） |

**出口契约的"地理定位"要素只引用这三类标识，不允许自由文本**——这是两份报告的握手点：CB-15 输出符合此 schema，出口层才能"填进行业表格 + 回地图定位"。

### C2 尺度 × 出口 × 数据认知

| 尺度 | 出口接口 | 需 CB-15 的地点信息 | 依赖 |
|---|---|---|---|
| macro | 专项规划·重点片区诊断 / S6 体检对接 | 面域级（行政区/片区排序）——**不需要 POI** | 现有 zonal/rank，零新依赖 |
| meso | 片区策划·需求分析 / S3 时序排序 | 单元面 + **单元内 top_places**（归因落点 hint） | CB-15 P0 的 sjoin top_places 部分 |
| micro | 项目实施方案·点位归因 / S5 落点清单 | 网格→POI 清单 + 评论↔POI 关联 + lookup_place | **强依赖 CB-15 P0+P1** |

### C3 S2 更新需求分析需 CB-15 哪些前置

- **meso 版（MVP 可先做）**：zonal 4×5（已有）+ 单元 preset（已有）+ 单元内 top_places（**CB-15 P0 sjoin**——"需求位置"要素的 POI 落点）。数据基础/局限标注是模板。
- **完整版（含 micro 落点 + 评论集）**：+ 格选中联动（CB-15 P0）+ 评论↔POI 反查（**CB-15 P1**）+ lookup_place（P0）。
- 结论：S2 的 **meso 卡不阻塞**（top_places 到位即可）；完整下钻链等 CB-15 P1。

## 八、判定

- **出口抽象层可行且有立项价值**：三铁律成立，"出向链路 = 0"是真实缺口；`DOMAIN_OUTLETS` + 诊断卡 `outlet` 是最自然挂载点。
- **架构**：分层（确定性组装器 + 可选 LLM 润色 + 条件触发第三段）——不是新 agent，是新出口阶段。
- **MVP**：S6 先行（零数据依赖）→ S2(meso) → S3；micro 等 CB-15 P0/P1。
- **协同**：数据契约（placeRef/cellRef/unitRef）是两份报告的握手点；CB-15 P0 与出口 P0a 可并行，阶段 2 汇合。
- **风险可控**：守住"不动承重源 + 契约收敛 + 条件触发 + 0-LLM 先行"，出口层不会变成第二个臃肿 agent。
