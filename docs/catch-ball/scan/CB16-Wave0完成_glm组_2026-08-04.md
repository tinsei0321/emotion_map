## 三、观察（低优先级·P3·不阻塞）

### 观察 1：harness.js _maybeBuildOutletCard 触发词手写而非 import

`harness.js:1550` 手写 `const _trigger = ['更新', '体检', ...]`——而 `emc-patterns.js` 已 export `OUTLET_TRIGGER_KW`。harness 顶部 import 了多个 emc-patterns 常量但**没 import OUTLET_TRIGGER_KW**。

**影响**：无功能影响（手写值与 export 值一致·同步守卫已覆盖）。但不符合 DRY——改后端 TRIGGER_WORDS 时需同时改 emc-patterns.js + harness.js 手写表（3 处同步·非 2 处）。

**建议**（P3）：`harness.js` import 加 `OUTLET_TRIGGER_KW, OUTLET_UI_EXCLUDE_KW` → `_maybeBuildOutletCard` 用 import 而非手写。

### 观察 2：result 数据收集缺 point_count

`_maybeBuildOutletCard:1561` 发送 `result = { features: lyr.fc.features }`——只有 features 路径。但 `build_outlet_schema._extract_emc_value` 对 `point_count` 检查的是 `result.get('point_count')`（顶层）·不在 features properties 里。

**影响**：`data_base.N` 可能为空（降级·不出数据基础行）。不影响卡片其他要素。

**建议**（P3）：result 补 `point_count`——从 features 总数估算或从 artifact registry 取。

### 观察 3：异步卡片无超时

`_maybeBuildOutletCard` 的 `fetch('/api/v1/aiqa/outlet_card')` 无 AbortController 超时（对比 CB-12 搜索分支加了 15s AbortController）。

**影响**：如果后端慢·卡片可能在答案渲染后延迟出现（弹出感）。但 outlet_card 端点是纯数据组装（不调 LLM·<10ms）·实际不会慢。

**建议**（P3·防御性）：加 5s AbortController（仿搜索分支）。
