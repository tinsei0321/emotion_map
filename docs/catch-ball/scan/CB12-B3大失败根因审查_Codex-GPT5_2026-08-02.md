## 一、证据链验证（3 处断裂）

### 断裂 1：msgs=12 不能确证 while-loop

- `runTemplatePath` 快路径 = FC 1 次 + finalStep 1 次；每次调用 msgs ≈ history+user ≈ 5-6 → 两次调用 ≈ **10-12 msgs**——**与 msgs=12 兼容**；
- while-loop 的证据应是**每例 LLM 调用次数 > 2 或 round 递增**（`onRound`/`agentStep` 次数），不是 msgs 数；
- **需要 log 补充**：每例 LLM 调用次数 / agent_step 轮数 / `[emc-timing]` 分段。仅 msgs=12 无法区分"快路径两调用"与"while-loop 五轮"。

### 断裂 2：timeout=0 不能排除 API 慢

- waitAnswer 90s 超时 ≠ FC 层超时：`fcDiagnoseStep` 有自己的 **12s 超时**（`stages.js:301` `FC 单轮超时(12s)`）；
- **API 慢 → FC 12s 超时 → degraded → while-loop（每轮 agentStep 30s × 5-6 轮 ≈ 2.5min）→ 用例完成（waitAnswer 未超时）**——与"timeout=0 + 1-3min + msgs 递增"完全吻合；
- 所以 timeout=0 **只排除了 waitAnswer 层**，不排除 FC 层的 API 慢——这与 16:20 是"同源 API 事件、不同落点"。

### 断裂 3：zonal 强制路由 → while-loop 的机制链不成立

- 即使强制 zonal + boundary 未填：`runTemplatePath` 内 `validateParams('zonal')` 缺 boundary → **EXIT_GAP/ask_user**（`harness.js:585` 附近 gap 路径），**不会进 while-loop**；
- while-loop 只在 `diagnose.degraded`（FC 失败 + recover 未命中）或 template='multi/unknown' 或 **`_tplHitRateReady()` gate 关闭**时进入——**a04a714 四改动没有一个能触发这三种**；
- 结论：claude组 的"强制 zonal + boundary 未填 → validateParams fail → while-loop"链条在代码层面不成立。

## 三、独立根因候选（claude组 漏掉的）

### 候选 A（最吻合）：FC 层 API 慢 → 12s FC 超时 → degraded → while-loop

- 证据链自洽：API 慢 → `streamFcDiagnose` 12s 超时（`stages.js:301`）→ `[FC] 异常: AbortError` → degraded → recover 兜底（模式 E/F 只覆盖 方格/zonal；其他问句 null）→ **while-loop**（每轮 agentStep 20-30s × 5-6 轮 ≈ 1-3min）→ 用例完成（waitAnswer 未超时）+ 0 timeout + 结论质量差（ERR 23）；
- 与 16:20 同源（DeepSeek API 事件）但落点在 FC 流式层——**需要 log 验证**：`[FC] 无 tool_calls` / `[FC] 异常` 计数是否每例 1+。

### 候选 B：Flash template gate（`_tplHitRateReady`）关闭

- localStorage `ai_qa_template_stats_v1` 跨 run 累积（clearChat 不重置）；若前几 run（04-07）unknown 模板累积致 misses > 40%（gate 0.6）→ **单模板路径全部跳过 → while-loop**；
- 概率评估：04-07 各 run tpl=? 约 2-4 例/25，累积 misses 占比约 10-15% < 40%——**门未到阈值，但需 log 核实**（`_loadTplStats` 打印 hits/misses/gateReady）。

### 候选 C：FC 流式 tool_call 装配异常

- DeepSeek 流式窗口异常（arguments 空/截断）→ `arguments_parse_fail`（`stages.js:323`）→ degraded → while-loop；需 log 核实。

## 六、一句话结论

**while-loop 退化判断方向对，但 zonal 路由不是机制**（它最多 gap/ask）；msgs=12 与 timeout=0 两条证据均不足以定案（前者兼容快路径、后者不排除 FC 层慢）；**最吻合根因 = FC 层 API 慢 → 12s 超时 → degraded → while-loop**（16:20 同源事件的不同落点）。先取证（FC 失败计数 + 轮数 + gate 状态）再决定修 FC 韧性还是 gate。
