## 二、新发现问题（修复引入/暴露）

### 问题 1（MED）：R10/R11 尺度防线对 general/概念答误标注

- `harness.js:905`：general 路径新调 `applyQualityDefense(draft, { ..., question: ctx.question })`——R10/R11 块由 `_opts.question` 触发（`harness.js:362`）；
- `_deriveScale("什么是情绪地图的 4×5 归因矩阵", '')` → 含「归因」→ **'meso'**（`stages.js:403-406`）→ **R11 触发**（`harness.js:370`）：概念答若无「区/街道/单元/片区…」字样 → 追加"⚠️ 中微观结论建议落到具体单元/落点"——**概念解释被误标**；
- 同批概念问「情绪归因的政策锚点是什么」「为什么 X」也会中招；修复前 general 路径**不跑** applyQualityDefense，此为新回归；
- **建议**：general/concept 路径传 `skipScaleDefense:true`（R10/R11 仅对 emotion_analysis 结论生效），或在 R10/R11 前判断 intent !== 'general'。

### 问题 2（HIGH）：REGION_KW 阻断"宜昌"问句进入搜索分支

- 搜索分支在 `_quickIntent(ctx.question) === 'general'` 块内（`harness.js:877`）；
- `_quickIntent` 对含「宜昌/西陵/伍家岗…」的问句**返回 null**（`harness.js:89-91` + `REGION_KW` 含「宜昌」`emc-patterns.js:43`）→ 落 FC diagnose → **永不触达搜索分支**；
- **直接影响**：搜索功能的首要场景（依据 2"聚焦问题需结合宜昌实际"——问句天然含宜昌地名）被挡死。claude组 拟定的运行级验证「问『宜昌市城市更新政策』→ 应搜索」**实际不会搜索**（走 FC 答，无实据素材）；只有概念形式（"什么是宜昌市城市更新政策"）才搜；
- **建议**：搜索触发前置到 `_quickIntent` 之外（evidence 门先判：`SEARCH_KW`/`SEARCH_EVIDENCE_RE` 命中 → 直接 general+search；未命中 → 正常 `_quickIntent` 路由）。空间问句（"宜昌西陵区情绪分布"）无实据词，不会误触发；"宜昌市城市更新政策"含「政策」→ 正确进搜索。

### 问题 3（LOW）：`search_chat` `for attempt in range(1)` + `last_err` 残留（`llm.py:442-476`）——功能无碍，建议顺手改直调。
