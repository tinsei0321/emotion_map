### 1.3 🔴 P0 Bug：体检出口契约 domain 不匹配

**根因**：

```python
# urban_checkup_outlets.py:13
DOMAIN = 'urban_checkup'   # ← 不在 domain_lens 枚举中

# stages.js:418（前端 domain_lens 解析）
# 正则只匹配 urban_planning|urban_renewal|urban_operation|urban_governance
# 不含 urban_checkup

# resolve_outlet_id:50（必要条件）
if contract.get('domain') not in domain_lens:   # 'urban_checkup' not in ['urban_renewal', ...] → continue（跳过）
```

**运行时验证**：
```python
resolve_outlet_id({'scale':'macro', 'domain_lens':['urban_planning'], 'outlet':'报告结论'}, '城市体检满意度调查')
→ None  # checkup_satisfaction 永远不触发

resolve_outlet_id({'scale':'macro', 'domain_lens':['urban_renewal'], 'outlet':''}, '城市体检报告')
→ None  # '体检' 触发词在 TRIGGER_WORDS 但 oid/name 不含 '体检' → q_hit=False
```

**影响**：S2 更新类（renewal_*）不受影响——`urban_renewal` 在枚举中。但 S6 体检类（checkup_*）完全无法触发——这意味着报告里的"S6 体检指标对接"场景在当前代码下**不可能产出出口卡片**。

**修复建议**（2 选 1）：

**方案 A**（推荐·最小改动）：体检契约 domain 改为 `'urban_governance'`（城市治理≈城市体检·4 枚举中最接近的）：
```python
# urban_checkup_outlets.py:13
DOMAIN = 'urban_governance'   # 城市体检 ≈ 城市治理维度
```

**方案 B**：domain_lens 枚举扩到 5 值（加 `'urban_checkup'`）——需改前端 `_deriveDomainLens` + FC prompt + KNOWLEDGE。改动面大·不推荐。
