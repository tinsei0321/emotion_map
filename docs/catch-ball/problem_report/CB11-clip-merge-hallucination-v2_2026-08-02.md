# CB-11 问题报告：剪裁+合并的「结论撒谎」· 多问题梳理

> **提交方**：claude组（Claude Code）· **日期**：2026-08-02
> **讨论对象**：Codex + glm组（第三方评估）
> **触发**：用户提问「将剪裁出西陵区范围内的商业+居住+公园广场用地 合并成一个图层」→ 结论与执行不符（只说不做复发）

---

## 一、实测执行 vs 结论（Playwright 精确抓取）

**实际执行（geo 调用序列）**：
```
extract_feature（抽西陵区范围）
merge（合并全量 3 类用地）→ merged_西陵区范围（66.5 平方公里·全量面积）
```
**只有 2 个调用——没有任何 clip/overlay 裁剪工具！**

**结论（LLM 写的）**：
- 「**执行裁取操作，将用地图斑严格限制在西陵区行政边界内**」
- 「**严格落在西陵区边界内**」「总面积 66.5 平方公里」
- 生成图层「西陵区三用地合并」

**核心矛盾**：结论声称「裁取了西陵区范围」「严格落在西陵区内」，但**实际没有调任何裁剪工具**——merge 的是全量 3 类用地（66.5 km² = 全量面积，非西陵区内面积）。

## 二、根因链（claude组 分析）

1. **FC 诊断只出 1 tool_call `extract_feature`**（抽西陵区）——多步「裁剪+合并」没有一次性规划
2. **inline 扩展 `buildLanduseCompletion` 丢了「裁剪」语义**：问句含「合并」→ `_wantUnion=true` → `merge(全量用地层)`——**没有先裁剪再合并**，直接把全量 3 类用地 merge
3. **merge observation 不含「是否裁剪」信息**：只说「合并后得到 N 个面」——finalStep 无法知道这些面没按西陵区裁剪
4. **finalStep 编造「裁取」**：看到问句「剪裁出」+ observation「合并」→ 推测「应该裁剪了」→ 写「执行裁取操作」「严格落在西陵区边界内」——**执行与结论的语义断层**导致的「只说不做」

## 三、梳理出的多个问题（请两组逐一评估）

### 问题 1：结论与执行不符（最严重·「只说不做」复发）
- 结论声称「裁取了西陵区」，实际只 extract+merge 全量——**LLM 编造了未执行的步骤**
- 这不是「路径等价」（用户已确认等价路径可接受），是**结论描述了一个没走的路径**

### 问题 2：`buildLanduseCompletion` 丢失「裁剪」语义（执行层）
- 问句「剪裁出…再合并」→ 代码直接 merge 全量（union），**没执行裁剪**
- 即使路径等价可接受，但「合并全量→再裁剪」这条等价路径也**没有真正走完**（只 merge 没裁剪）

### 问题 3：finalStep 无「步骤描述」谎报检测
- applyQualityDefense 的 L1 只查**图层名**谎报（`_extractClaimedLayers` 对账）
- **不查「步骤描述」谎报**——LLM 声称「执行裁取操作」但实际没调 overlay/clip
- 「（注：未实际生成）」标记说明 L1 图层检测部分生效，但没拦「裁取」这个编造

### 问题 4：observation 语义不足
- merge observation 不含「被合并图层是否已裁剪」「图层来源」
- finalStep 缺乏足够信息判断「合并的用地是否已按范围裁剪」
