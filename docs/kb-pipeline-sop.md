## 一 白话摘要（图书馆自动长厚的规矩）

RAG 知识库像一座**图书馆**，以后要让 AI 助手（agent）帮忙"往书架上添书"。但 AI 转述会出错（实证：曾把现行口径整批误标成作废·38 条）——所以立三条规矩：

1. **AI 只能写"草稿单"，不能直接上书架**——草稿进"待审抽屉"（kb_inbox），人来签字才入库；
2. **分三级审批**：复印类活儿（重建索引等"照着原样重做就对"的）自动放行；**写新事实/新数字的必须人审**（早期量小·全审可担）；AI 自己拿不准的进"待裁决队"；
3. **更新有节奏**：数据类每周刷（不进图书馆·走工具层）；知识类月/季快审；每年一次大体检（全审+作废口径大排查 X-01）。

**一句话**：图书馆允许 AI 帮忙长厚，但"写什么"由人把关——**治理写，不是自由写**。

## 二 三级审批分流表（RAG 方向 CB 收敛照抄 + 现状注记）

| 级 | 写入类型 | 审批位 | 承载机制（现成） | 现状注记 |
|---|---|---|---|---|
| **L1 自动通过** | **派生资产**：从已 active 语料确定性重算的产物（ctx_prefix 重生成 / lineage 补标 / chunk 重切分 / 索引重建 / 字段级更新） | 无人审·**可重建即正确** | L3 一体化 `--build`（前注增量生成零 LLM）+ 双环境纪律「派生资产只记重建命令」 | 已落地：`tools/rag_index.py --build` + 门禁（字段级自动档 = CB 收敛 §三吸收 Qoder 并入定义） |
| **L2 人审必过** | **事实层写入**：新事实卡 / 新口径数字 / 结论性叙述 / 新旧卡演进 | **全审·非抽检**（03-10 误读实证：系统性语义误读抽检放不过；抽检=量增后降级选项·观察项） | X-01 管线（R24 引句 verbatim + 三分法 + B2 三原则自审）→ 提案进 **kb_inbox 草拟层** → 主手批次验收落笔 | 待建：本 SOP §四 + PT-CB9R C 件 |
| **L3 待裁队列** | agent 自评不确定项 | 主手裁决 | X-01 待裁清单机制（总纲 status 等 3 项待裁模式已验证成立） | 沿用 |

**关键决策四条**（Kimi D3 + CB 收敛·照抄）：
1. **写入走 inbox 草拟层·不直写语料**——复用 EMC inbox 哲学（投递到收件箱·消费方验收）；
2. **事实层全审而非抽检**——「可信来源」≠「可信转述」·转述层永远是风险层；
3. **superseded 标注权永不自动化**——作废判定只给人（agent 可提提案·须带 R24 引句+替代指针·裁定权主手）；
4. **口径注册表是 agent 禁区（只读）**——提案可引用卡 ID·不能写注册表（写入权=用户级·宪法级确认）。

**另有一条总禁令**（CB 收敛 §三）：memory evolution **自动化反对**——agent 可提 evolution 提案（旧卡 X 应更新为 Y·引句 Z），**落笔权在人**（提案-审批两段）。

## 三 更新频率分层（用户三特征③·CB 收敛 §六）

| 频率 | 对象 | 动作 | 进 RAG 吗 |
|---|---|---|---|
| **周** | **数据层**（点层/图层/事实数据刷新） | 工具层增量·走数据管线 | **禁入 RAG**（数据走工具层·RAG 只装知识） |
| **月 / 季** | 知识层小增量（新笔记/新事实卡/新案例） | **快审**（L2 全审·量小成本可担） | 入（白名单四源） |
| **年** | 知识层全量体检 | **全审 + X-01 大排查**（作废口径逐值 grep·三分法重标） | 全量重验 + 门禁复跑 |

## 四 kb_inbox/ 目录结构（草拟层设计·实施随 PT-CB9R C 件）

> 位置建议：`docs/kb_inbox/`（与语料白名单目录同侧·提案对象 = docs/urban-renewal-plan/ 与 ai_qa/outlet_kb/）。**approval.req 首个真实消费者**（ACP 契约 v1.1 §5-4 接线点登记）。

```text
docs/kb_inbox/
├── draft_<YYYYMMDD>_<主题>.md   # 提案草稿（模板强制四件·下）
├── review_queue/                # 人审队列（事实级冲突件/待裁件移此）
└── accepted_log/                # 已迁入草稿留档（谱系可查·不删）
```

**draft 模板（强制四件）**：

```markdown
# draft_<日期>_<主题>

- 引句 verbatim：「<原文逐字>」        ← R24 纪律
- 来源：src:<文件>#<节>
- 三分法标注：现行 / 历史 / 待裁        ← X-01 式
- B2 自审三问：
  ① 本结论是单源证据还是多源收敛？（一次提及不泛化）
  ② 转述与原文是否分层？verbatim 引句在否？（确认形状≠确认细节）
  ③ 精确数值是否必带时点（year/口径批次）？趋势表述是否优先耐久措辞？

- 目标落库：<四源之一 + chunk type>    ← rag-corpus-map §一
- 冲突检查：与在库事实/口径注册表 grep 结果（有冲突 → 移 review_queue/）
```

## 五 事实级查重规则（写入前冲突检测→人审队列·FaithfulRAG 依据）

1. **写入前必检**：新条目中的每个**数值/口径数字**，在在库事实（facts + 注册表卡）中 grep——同数值域存在冲突值 → **不落库·提案移 review_queue/**；
2. **冲突判定归人**：grep 只做"数值撞车提示"（可自动化）·"谁对谁错"的裁定永远归主手（与口径注册表冲突检查同闸）；
3. **待裁处置**：冲突件挂 X-01 待裁清单·主手裁决后回写（修提案/拒/改标历史口径）；
4. 来源：FaithfulRAG 事实级冲突显式建模（CB 收敛 §二「C 事实级查重·并入」）。
