## 〇 一句话结论

**能实现，且成本低于直觉预期**：前端 vendored 的 MapLibre GL JS 是 **v5.2.0**（`frontend/vendor/maplibre-gl.js` 头部实测），原生支持 globe 投影（v5.0 引入）——不需要引任何新库、不需要换框架；默认底图=天地图影像瓦片可直接作地球纹理（raster 瓦片在 globe 下正常渲染，且天地图是 office 网络唯一可达源，载入地球在双环境都可用）；主要工作量在「载入态状态机 + 自转动画 + 飞入衔接」，约 3-5 个文件、1-1.5 天开发 + 0.5 天审查测试。唯一实质风险（globe 投影下既有 3D 图层兼容性）有零成本规避路径（飞入即切回 mercator 投影）。

## 一 需求还原（zcode 理解的口径·请用户确认）

1. **初始页面 = 载入态**：深邃太空背景 + 缓慢自转的地球（Google Earth 载入界面的观感），替代当前直接进入的宜昌主视图。
2. **地球纹理跟随默认底图**（当前 `DEFAULT_BASEMAP = 'tianditu-img-nolabel'`，map.js:44）：
   - ① 影像图（现状默认）→ **真实地球**：卫星影像贴球；
   - ② 地图风格（tianditu-vec-nolabel 浅色矢量 / positron 浅灰）→ **地板版地球**（=浅色地图贴在球面上，maplibre.org 官网首页同款观感——那本身就是 MapLibre 的 globe 官方演示）。
3. **点击「复位」按钮 → 飞入**：flyTo 宜昌默认视野（`YICHANG = { center: [111.286, 30.708], zoom: 12 }`，map.js:45 已有常量），进入主界面。
4. （待确认）复位按钮在进入主界面后是否常驻，作为「回到宜昌」的快捷键。

## 三 方案设计（拍板对象）

### 3.1 架构：单 map 实例 + 载入态状态机（不引入第二个地图实例）

```
启动：initMap → style = BASEMAPS[DEFAULT_BASEMAP] + projection: globe
      + zoom ≈ 1.6 + 启动自转 + 太空背景 + 主 UI 遮罩（侧栏/面板隐藏或虚化）
复位：停自转 → flyTo(YICHANG, zoom 12, ~3s) → moveend 后 setProjection(mercator)
      + 揭开主 UI → 载入态终结（不可逆，回到现有应用流）
```

- **为什么单实例**：避免二次初始化与样式重载；载入态本质是同一张地图的「相机 + 投影 + UI 遮罩」三要素状态，不是另一个页面。
- **为什么飞入后切回 mercator**（关键决策）：3D 网格（fill-extrusion）、deck.gl 热点叠加、cell 模式、compare 双图等既有能力全部是在 mercator 投影下开发验证的，globe 投影下不重新验证——**载入态用 globe 拿观感，主界面留在 mercator 保零回归**，风险面收敛为零。若未来想主界面也常驻 globe，另立 CB 评估。

### 3.2 自转动画

`requestAnimationFrame` 每帧中心经度 +约 4-6°/秒（缓慢）；用户任何交互（拖拽/滚轮）即暂停自转；`flyTo` 期间强制停止。代码约 30-40 行，独立小模块。

### 3.3 底图映射（需求①②的实现即「跟随」）

载入态纹理直接读 `BASEMAPS[DEFAULT_BASEMAP]`——当前默认=影像 → 真实地球；将来默认底图改为地图风格 → 载入地球自动变地板版。**用户需求①②本身就是「跟随默认底图」，不需要做两套逻辑。**

### 3.4 太空背景与星空

- **基础版（建议先行）**：容器深色背景（深空蓝黑 `#040810` 量级）+ v5 atmosphere 大气光晕 → 已具备「深邃太空 + 蓝色弹珠」观感（Google Earth 载入页主体也是纯深空）。
- **星空增强版（可选·后置）**：静态星空层（容器 CSS/canvas 置于地图画布后层，需实测画布透明性；或 bundle 一张星空图作背景）。建议基础版先行看实际观感，不满意再上星空——避免为不确定的视觉收益先付复杂度。

### 3.5 复位按钮（新增）

- **载入态**：屏幕中下方醒目 CTA「复位」（副文案如「进入宜昌」），唯一可交互入口。
- **主界面（若 D2 拍板常驻）**：右上导航区小号「复位」按钮，点击 = 同一 `flyTo(YICHANG)` 回到默认视野。

### 3.6 测试与飞轮兼容（承重细节·易漏）

载入态改变了应用启动流 → **飞轮 / B3 / Playwright e2e 用例必须可跳过载入态**：URL 参数 `?intro=0`（或 localStorage 开关）直达主界面，测试基建统一带参。不处理这条，现有用例会因「地图不在宜昌初始视野」红一片。

### 3.7 降级路径

天地图瓦片请求失败（极端网络）→ 地球无纹理 = 深色球体 + 大气光晕，**复位功能不受影响**（flyTo 与瓦片无关）。P2 可加本地单图纹理兜底（bundle 一张世界影像图作 image source）——与 E2「自托管底图」议题天然合流，可同案处理。

## 四 风险与规避

| # | 风险 | 定性 | 规避 |
|---|---|---|---|
| 1 | globe 投影下既有图层兼容性（fill-extrusion 3D 网格 / deck overlay / cell 模式在 globe 下未验证，v5 早期版本对 fill-extrusion-on-globe 有支持限制） | **唯一实质风险** | 3.1 的「飞入即切 mercator」——主界面永远 mercator，globe 只存在于载入态且载入态无业务图层 → 风险归零 |
| 2 | 星空背景 API 细节（v5 空域底色设置路径：`setClearColor` vs 容器 CSS，atmosphere 参数） | 小 | 基础版两条路都可行（实测二选一）；星空是增强项不阻塞 |
| 3 | 首屏性能 | 小 | globe z≈1.6 瓦片请求量十几个；自转 rAF 每帧 jumpTo 为官方 demo 同款常规用法 |
| 4 | compare 双图模式（`_mapB`） | 无 | compare 在进入主界面后才可能启用，与载入态无时间交集 |
| 5 | 测试基建破坏 | 中（若漏 3.6） | `?intro=0` 跳过参数，已列入方案承重项 |
