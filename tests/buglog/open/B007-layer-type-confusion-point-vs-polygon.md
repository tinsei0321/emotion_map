# B007 · 图层类型混乱 — 声称面层实际产出点层（部分新）

## 标准化用例

**问句**：「筛选出西陵区中的商业用地。」

**数据前提**：西陵区边界（面层）+ 用地_商业（面层，1 个面）

**预期行为**：
① clip 工具被选中，target=用地_商业（面层），range=西陵区边界
② 生成的图层为**面层**（polygon），而非点层
③ 图层类型与源图层一致（面 → 面）
④ 结论中描述的图层类型与实际产出一致

## 诊断摘要

**根因分析**：

LLM 在 thinking trace 中正确推理了目标（clip 商业用地面层），且结论文本中正确描述了"面层"（"产出了西陵区商业用地图层（面层）"）。但实际执行的工具调用引用了错误类型的图层——可能的原因：

1. **层引用歧义**：接地上下文中「用地_商业」（面层）和「积极情绪点」（点层）的展示名相似或 ID 混淆，LLM 在填 `layer` 参数时选错了层。
2. **工具参数校验缺失**：clip 工具未校验"被裁剪图层类型与源图层类型一致"——接受了点层输入，产出了点层输出。
3. **finalStep 与执行脱节**：finalStep 基于 plans[] 写出了"面层"结论，但未感知到实际执行的图层类型。

这与 CB-09 C4（filter_attr 层引用幻觉）的模式相似但有差异：C4 是 LLM 编造了不存在的图层名，B008 是 LLM 引用了存在但类型错误的图层。

**治本方向**：
- CB-09 P0-2：`buildContext` 加图层类型标注（point/polygon/heatmap），让 LLM 明确知道每个图层的几何类型
- 新增：clip/extract_feature 工具加「图层类型一致性校验」——裁剪面层→产出面层，裁剪点层→产出点层，类型不匹配时拒绝执行并给出明确错误
- CB-09 P1-1：finalStep context 注入实际执行的图层信息（含类型）
