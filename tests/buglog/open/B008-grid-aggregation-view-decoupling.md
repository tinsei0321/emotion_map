# B008 · 网格聚合 2D/3D 视角未解耦（新发现）

## 标准化用例

**问句**：「对当前区域做 500m 方格网聚合」（任意网格聚合问句）

**数据前提**：情绪点数据已加载 + 地图支持 2D/3D 视角切换

**预期行为**：
① 当前为 **2D 视角**时 → 生成 **2D 网格图**（平面色块，choropleth 风格）
② 当前为 **3D 视角**时 → 生成 **3D 柱体图**（extruded 3D cylinders，高度=聚合值）
③ 视角切换后重新触发聚合时，输出图层自动匹配当前视角
④ 2D 和 3D 图层的样式系统完全解耦，各自独立配置

## 诊断摘要

**根因推断**：

用户明确描述"老 bug，一直没修好"，说明这是一个已知但未根治的问题。可能的根因：

1. **图层生成时未读取地图视角状态**：`density` / grid 工具在生成图层时，未查询 MapLibre 当前 `map.getPitch()` / `is3D` 状态，直接使用硬编码的 3D 渲染配置（extrusion + height）。
2. **前端渲染层与工具层未共享视角上下文**：工具的图层生成在前端 JS 中完成（或由前端渲染），但视角状态（2D/3D）没有作为参数传入图层生成函数。
3. **样式配置中 2D/3D 未分离**：图例/样式系统可能只有一个统一的网格样式配置，未区分 2D（fill-color）和 3D（fill-extrusion-height）两种渲染模式。

**"未解耦"的具体含义**：
- 当前架构可能是：网格聚合 → 始终使用 `fill-extrusion` 图层类型 → 始终 3D 柱体
- 正确架构应该是：网格聚合 → 读取 `viewMode` → `2D` → `fill` 图层 / `3D` → `fill-extrusion` 图层

**治本方向**：
1. 前端：在触发网格聚合时，将当前视角状态（`viewMode: '2d' | '3d'`）作为参数传入
2. 图层生成器：根据 `viewMode` 选择不同的 MapLibre layer type（`fill` vs `fill-extrusion`）和样式配置
3. 图例系统：定义 2D 和 3D 两套网格样式配置，互不干扰
4. 视角切换监听：当用户从 2D 切到 3D（或反之）时，自动刷新已有网格图层的渲染模式

**严重度评估**：虽然用户标记为"老 bug"，但功能影响有限（网格图在 2D 下以 3D 显示虽不对但不阻碍使用），且修复涉及前端渲染层改动，故定为 🟡 MEDIUM。但若网格聚合是核心分析功能，应升为 🟠 HIGH。
