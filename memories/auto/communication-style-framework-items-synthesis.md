与用户技术交流（plan 摘要、变更汇报、复盘总结等）采用**逻辑框架 + 条目化要点 + 总结/归纳**的基本形式：

- **逻辑框架**：问题框定 → 推理 → 体系/方案 → 执行 → 总结（或类似清晰主线），非碎片堆砌。
- **条目化要点**：框架内用 bullets 列要点（紧凑，非长段落、非一句话）。
- **总结/归纳**：末尾一段 synthesis，提纲挈领。

**禁止**：
- "一句话版" / "口诀" / "TL;DR" / "给领导汇报体"——把技术讨论压成口语化摘要，不专业。
- 长篇大论（全文论述、冗长 prose）——同样不可。

**Why**：用户两次纠正——先反对"一句话版"（不专业、像给领导一句话汇报），再反对长篇大论（过长），最终明确要"逻辑框架 + 条目化要点 + 总结/归纳"。技术讨论既要专业体系化，又要紧凑。

**How to apply**：plan 摘要、变更汇报、复盘总结等用上述三段式结构。每次回复前自检：有框架？要点条目化？有总结？是否避开了"一句话"与"长篇"两个极端？
