经用户三次澄清确立的情绪地图**顶层设计哲学**（已写入 CLAUDE.md「项目设计哲学」节，与演示逻辑链同优先级，全项目生效）：

1. **4×5 是主题倾向分布矩阵（宏观，非指标分类清单、非精确归因）**：跨领域×跨要素**多归属**，一现象落多格是 feature（交通建设=规划×设施=更新×设施=运营×服务）。4×5 表达"这片区域情绪主题倾向"=宏观诊断信号（5.148，见 CLAUDE.md「产品本质」），勿当精确归因。**矩阵骨架稳定不动**。
2. **归因底层逻辑 = 政策→情绪→项目 方向性锚（宏观，非精确闭环）**：宏观政策指引方向 → 情绪地图用市民数据定位实际痛点/主题倾向 → 方向性锚到具体可操作项目。情绪地图核心价值 = 在政策与项目间用情绪数据**方向性牵线**（宏观诊断信号→规划者假设/排序，非精确归因；5.148）。
3. **官方话语对齐 + 补盲区**：四领域用主管权威术语；对官方忽视维度（**事件的瞬时空间影响**）前瞻占位成体系化 = 差异化价值。
4. **行业知识库（`ai_qa/industry_kb/`）= 全项目可成长基础设施**：四领域权威源 + `MATRIX_MAPPING` 多对多映射；做厚=映射丰富，矩阵稳定。
5. **城市规划 = 城市规划设计全谱**（宏观国土空间 + 中微观城市设计/景观/详规），4×5 该领域偏具体空间规划设计项目。

**Why**：我用"城市体检指标分类完整性"去质疑 4×5（提了交通缺位/事件定位/安全韧性三个"可议点"），用户纠正——这是**错标尺**：体检"指标维度"是评价打分分类（互斥穷尽），与 EMC"归因落点矩阵"（多归属）层次不同。交通是矩阵交叉 feature 非缺位、事件是补官方盲区的前瞻差异化、安全韧性的民生部分已落硬件矩阵格。

**How to apply**：
- 勿再用"官方指标维度是否完备"质疑 4×5 要素裂分/新增——这是错标尺。4×5 稳定，靠 `industry_kb` MATRIX_MAPPING 做厚多归属。
- 这套哲学**全项目生效**（演示链识别问题/客户画像话语对齐/数据模拟逆推/归因展示/EMC），不只 EMC。
- 改归因/行业知识/问题识别决策时，对照 CLAUDE.md「项目设计哲学」6 原则。
- 知识库做厚路径见 `docs/industry-knowledge-base.md`。
