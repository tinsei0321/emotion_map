情绪地图产品 = 三个网页，架构自下而上：**数据库（emotion-database）→ 控制台（emotion-console）→ 实时地图（emotion-map）**。决策 ADR-015（2026-06-27）。

- **网页① 数据库**（待开发 · 运维）：L0 采集/购买 → 治理 → L1 城市情绪数据；含 L0~L4 各类 + 时段/周期 + 语料库 + 临时数据 → 结构化"情绪地图数据库"。
- **网页② 控制台**（开发中 · α v0.1 = **当前焦点**，本仓库 `frontend/`）：规划/研究工具。数据上传/展示 + 情绪快照（总体/类型细分/时间轴）+ 分析（Overview+Table / 专业报告）。
- **网页③ 实时地图**（待开发 · 商用）：基于控制台内核 + 动态数据 + 动画/UI，实时洞察（热点/云图/AI/移动端）。

**数据流**：数据库供数 → 控制台分析 → 实时地图服务。控制台内核 = 实时地图基础，复用设计前置。

**L0~L4 双视角**：过程视角 = 分析管道（L0→L1→L2→L3→L4）；数据视角 = 各阶段产物作为数据库的数据类型分层（各阶段产物各为一类入库数据）。同一套 L0~L4，既是过程也是数据分类。

**Why**：三类角色（运维/研究/商用）场景差异大，单页会让商用/运维功能污染研究工具；职责分层 = 各页专注一类角色、可独立立项扩团队。

**How to apply**：谈"当前在做" = 控制台 α v0.1；新功能先判断归属哪页（避免商用/运维功能污染控制台研究工具）。详见 architecture.md §2.1 / ADR-015。关联 [[martin-ui-redesign]]（控制台 UI 重塑）、[[kde-loadbearing-logic]]。
